# 발표 예상 질의응답 — 쉬운 말 요약본

2026-10-27(10/27 코드·설계서 기준 최신화) · 포스코 명장님(현장·설비·안전 관점)과 AI 강사님(기술 설계·LLM 관점)이 물을 법한 질문과 답을 **핵심만, 쉬운 말로** 줄인 것이다.
숫자와 근거 파일은 원본 질의응답(팀 공유본)과 같고, 어려운 낱말은 풀어 썼다. 표시: **[명]** 명장 · **[강]** 강사 · **(후속)** 발표를 듣고 나올 만한 질문 · ⚠ 솔직하게 말할 한계.

## 먼저 알아 둘 낱말

| 낱말 | 쉬운 뜻 |
|---|---|
| 폴링 / 푸시 | 폴링 = 화면이 "바뀐 거 있어요?" 하고 일정 간격으로 계속 물어봄 / 푸시 = 서버가 바뀌면 먼저 알려 줌 |
| 트랜잭션 | 여러 저장을 한 묶음으로 처리해서, 하나라도 규칙을 어기면 전부 취소하는 방식 |
| JWT, 해시 | JWT = 로그인했다는 증표 / 해시 = 비밀번호를 원래 글자를 알 수 없게 바꿔 저장하는 것 |
| 트리거 | DB에 데이터가 들어오는 순간 자동으로 돌아가는 규칙 |
| RAG | 질문과 관련된 사내 문서 조각을 먼저 찾아서 그것을 보고 답하게 하는 방식 |
| BM25 / 임베딩 | BM25 = 질문과 같은 낱말이 많이 든 문서를 찾는 검색 / 임베딩 = 뜻이 비슷한 문서를 찾는 검색 |
| 환각 | AI가 그럴듯하지만 틀린 말을 지어내는 것 |
| 프롬프트 인젝션 | 나쁜 지시를 몰래 넣어 AI를 속이려는 공격 |
| 읽기 전용 계정 | 볼 수만 있고 고치거나 지울 수는 없는 DB 계정 |
| Supabase | 팀이 함께 쓰는 무료 클라우드 DB(PostgreSQL) |

## 1. 화면(프론트엔드)

**Q1-1 [명] 3D는 보기 좋으라고 만든 것 아닌가요?**
- 장식이 아니라 **실시간 데이터를 그대로 비추는 화면**입니다. 설비 색·움직임(가공·대기·고장·정비·막힘), 가공 속도, 공정 사이 재공 수, 병목 표시가 모두 데이터 값입니다.
- 설비 크기와 배치는 실제 치수를 썼고, 현장 큰 모니터에서 "어느 설비가 멈췄고 어디에 쌓이는지"를 한눈에 보는 것이 목적입니다. 3D가 느리면 2D 배치도로 바꿀 수 있습니다.
- 화면 → 실제 설비 조작은 **안전 원칙상 일부러 만들지 않았습니다** (보기만 하는 모니터링형까지만 구현).

**Q1-2 [강] 실시간 갱신은 폴링인가요, 푸시인가요?**
- **지금은 폴링**입니다. 3D·라인 화면은 1초마다, 작업지시서·알림은 4초마다 백엔드에 다시 물어봅니다. 접속자가 많아도 DB가 버티도록 계산 결과를 1초 동안 모두가 함께 씁니다.
- 푸시 통로 SSE(DB 변경 → 서버 → 화면 알림, 15초마다 연결 유지 신호)는 서버에 만들어 두었지만 화면은 아직 연결하지 않았고, 시연 서버가 넣는 설비 상태·알람은 알림을 끈 채 저장되어서 지금은 1초 폴링을 씁니다.

**Q1-3 (후속) [명] 알림이 너무 많으면 현장에서 무시하게 되지 않나요?**
- 알림을 **등급**으로 나눴습니다. 긴급 정지(충돌)는 화면 가운데 팝업, 공구 수명 같은 주의는 알림 목록으로 갑니다. 같은 알람이 되풀이되면 반복 알람으로 따로 판정하고, 교대 때는 흩어진 알림을 브리핑 하나로 모아 줍니다.
- ⚠ 실제 현장에서 알림 피로를 재 보지는 않았습니다. 명장님께 적정 수준을 여쭤보는 것도 좋습니다.

## 2. 서버(백엔드)

**Q2-1 [강] 왜 FastAPI와 PostgreSQL인가요?**
- FastAPI: 비서·생성기가 모두 파이썬이라 맞췄고, 자동 API 문서로 화면 담당과 주소를 맞추기 쉬웠습니다.
- PostgreSQL: DB가 업무 규칙(트리거·함수)을 직접 지킬 수 있고, 실시간 알림을 보낼 수 있고, 무료 공용 DB(Supabase)를 열 수 있어서입니다.

**Q2-2 [명] 잘못 입력하거나 권한 밖의 일을 하면 어떻게 막나요?**
- 버튼을 숨기는 것만으로 끝내지 않고 **세 겹**으로 막습니다: ① 서버가 역할별로 주소를 막고 ② 내 것·담당 공정만 보게 범위를 보고 ③ 승인·보류·출하처럼 "사람만 하는 일"은 DB 함수가 한 번 더 막습니다.
- 규칙을 어기면 그 요청은 전부 취소되고(409), 재고 거래는 추가만 가능하며, 확정된 문서는 잠깁니다. 비밀번호는 해시(scrypt)로 저장하고, 로그인은 JWT(12시간)입니다. 직원 추가·고치기·사용 중지도 관리자만 하고, 자기 자신을 중지하거나 마지막 관리자를 바꾸는 것은 막습니다.

**Q2-3 [명] AI가 DB나 설비를 마음대로 바꿀 수 있나요?**
- **없습니다.** 비서는 읽기 전용 DB 계정으로 정해진 조회 도구 14개만 씁니다. 비서가 만드는 것은 "AI비서 초안"뿐이고, 확정·승인·설비 조작은 사람만 합니다.

**Q2-4 (후속) [명] 충돌 알람에서 일일 보고서까지 이어질 때, 사람이 확정하지 않아도 넘어가나요?**
- 초안은 이어서 만들어지지만, **공장 기록에 반영되는 것은 사람이 확정한 뒤**입니다. 작업기록서를 확정해야 수리 시간(MTTR)·정지 원인·재고가 바뀌고, 그 값이 교대·일일 보고서에 들어갑니다. 확정 전 초안과 확정된 기록은 섞이지 않습니다.

**Q2-5 [명] 어떻게 검증했나요?**

| 검증 | 결과 |

| DB 시험 23개 파일 (최소 권한 계정으로도 실행) | 47/47 통과 (10/25) |
| AI 읽기 전용 계정 (쓰기·비밀번호 읽기가 막히는지) | 통과 |

| [처음으로] 4번 반복하는 동안 화면 조회 | 94번 모두 성공 |

## 3. 데이터

**Q3-1 [명·강] 화면의 데이터가 정말 실시간인가요, 미리 녹화한 건가요?**
- **녹화가 아니라 지금 만들어지는 데이터**입니다. 데이터 생성기가 공장 역할을 하며 값을 만들고, 그 값이 3D·알람·AI 비서에 바로 쓰이는 동시에 Supabase에 저장됩니다.

| 단계 | 하는 일 | 주기 |
|---|---|---|
| ① 생성 | 설비 상태·알람·재공·측정값·센서값을 만든다 | 0.25초 |
| ② 저장 | 바뀐 줄만 모아 백엔드로 보내 Supabase에 저장 (표 25개) | 3초 |
| ③ 규칙 작동 | 저장되는 순간 재공 경고·이상 징후·병목 알림, 새 알람의 등급별 알림·작업지시서 초안·반복 알람 판정 | 즉시 |
| ④ 화면 | DB 값을 읽어 3D에 반영 | 1초 |
| ⑤ AI 비서 | 이력·수량은 같은 DB에서, 지금 센서 값·설비 상태는 시연 서버의 현재 값으로 답함 → 채팅 숫자와 화면 숫자가 같음 | 질문할 때 |

- **공장 1개 = DB 1개**: 팀 공용 DB에 기록을 쌓아 누가 접속해도 같은 공장 상태를 봅니다. 저장된 값이 곧 기록이라 보고서·작업기록이 화면에서 본 값과 같습니다. 화면만 움직이는 영상과 다른 점입니다.
- 경고·알림은 DB 규칙이 만들어서, 화면이나 AI가 따로 계산하지 않아도 같은 결과가 나옵니다.
- **[처음으로]**: DB를 시연 기준 시각(10/26 09:00)으로 되돌리고 다시 쌓습니다. 기준과 생성기 시작점이 다르면 되돌리기를 거부하는 안전장치가 있습니다.
- 발표용 설정은 10/1~10/25 기록 위에 10/26 09:00~15:00 사건을 미리 짜 두고, **15:00부터 실제 시각으로** 흐릅니다.
- 실제 현장에 붙일 때는 생성기 자리에 설비 데이터 수집기를 넣으면 됩니다(입구 `/api/ingest`가 이미 있음). 모든 응답에 "생성 데이터" 표시가 붙어 가짜 값을 실제처럼 보이지 않게 했습니다.
- 계기: 처음에는 DB 시계가 멈춰 있어 채팅의 센서 값(1.1%)과 화면 값(41.8%)이 달랐고, 그래서 비서가 시연 서버에서 현재 값을 읽고 생성기 기록 전체를 DB로 보내게 고쳤습니다.

**Q3-2 (후속) [명] 시연은 3공정 중심인데 나머지 공정도 돌아가나요?**
- 네. 생산·알람·설비 상태·재공·정비·재고 기록은 1~5공정 전체에 만들어지고 3D에서도 5개 공정이 다 움직입니다. **센서 값만 3공정 설비에** 만들었습니다(불량·공구 마모·충돌이 가장 많은 곳이라 시연을 여기에 모음).

**Q3-3 [명] 측정값은 손으로 입력하나요?**
- 아닙니다. 측정기(CMM-01)가 결과 파일을 공유 폴더에 떨어뜨리면 서버가 감시하다가 자동 기록하고, 안 오면 "결과 미수신"을 알립니다. 로컬에서는 이 흐름을 확인했고, 시연 서버에서는 생성기 결과가 바로 들어옵니다(공용 DB 보호를 위해 파일 감시는 꺼 둠). 재고·로트는 QR로 조회·입고·실사·출하 확인을 합니다.

**Q3-4 (후속) [강] 무료 한도 안에서 느려지지 않나요?**
- 지금 공용 DB는 10/1~10/25 기록과 센서 값 약 84만 행으로 **약 150MB** (무료 한도 500MB).
- 양 줄이기: 센서는 3공정 설비 2대만, 평소엔 1분 값, 정지·주의 알람 앞뒤 30분만 5초 값. 속도: 접속자가 늘어도 DB는 1초에 한 번만 읽도록 계산 결과를 함께 씁니다.

## 4. AI 비서(LLM)

**Q4-1 [강] 어떤 방식을 썼고 왜 골랐나요?**

| 방식 | 어디에 | 왜 |
|---|---|---|
| 문서 찾아 답하기 (RAG) | 사내 문서 7종(195조각) 질문 | 출처(문서·절)를 붙여 사람이 확인하게 하려고 |
| 도구 호출 (조회 도구 14개) | 지금 상태·수량·이력 질문 | 숫자를 AI가 지어내지 않고 DB 값으로 답하려고 (자유 SQL은 위험해 뺌) |
| 정해진 형식으로 답하기 | 모든 호출 | 화면·문서 칸이 깨지지 않게, 받은 뒤 코드가 한 번 더 검사 |
| 말투 지시 | 문서 답변·알람 카드 | "옆자리 선배가 풀어서 설명하듯" 현장 말투 |
| 길 나누기 | 질문 입구 | 문서 질문 → 문서 검색, 운영 질문 → 조회 도구, 안전 절차 → 고정 서식 |

- **스스로 판단해 움직이는 AI(에이전트)는 일부러 쓰지 않았습니다.** 현장에서 비서가 설비·기록을 바꾸면 안 되므로 읽기와 초안 쓰기만 합니다.

**Q4-2 [강] 왜 로컬 LLM이 아니라 Claude인가요?**
- 처음엔 로컬 모델(Qwen3.5-9B, 10/08)로 시작했지만, 한국어 표현을 자주 틀리고(예: "퍼센트"↔"%", "목장갑"↔"면장갑") GPU가 필요했습니다. 10/14 같은 질문으로 두 모델을 비교하고 **10/17 Claude로 확정**, 10/23 API 호출로 바꿨습니다. 로컬로 되돌릴 수 있는 구조는 남겨 두었습니다.

**Q4-3 [강] 왜 Sonnet이 아니라 Haiku인가요?**

| 비교 | Haiku 5.5 | Sonnet 5.5 |
|---|---|---|
| 정답 절 인용 (30조각) | 73/75 | 73/75 (같음) |
| 토큰 단가 | 입력/출력 $0.10/$0.50 | $2/$10 (**20배**) |
| 실측 호출당 비용 | 약 $0.011 | 약 $0.193 (Haiku가 약 **1/17**) |
| 응답 시간 | 중앙 17.3초 | 중앙 7.9초 |

- 채팅의 모든 호출이 Haiku이고, Sonnet은 비교·평가에만 썼습니다. Haiku가 느려서 제한 시간을 130초로 뒀습니다.
- ⚠ "20배"는 **토큰 단가**, "1/17"은 **실측 호출당 비용**입니다. 어느 쪽인지 밝혀 말하세요. 호출당 비용은 정가 기준이라 실제 청구액이 아닙니다.

**Q4-4 [강] 발표 중에 Claude가 끊기면 멈추나요?**
- **멈추지 않습니다.** Claude가 실패하면 같은 질문을 Google Gemini로 바로 다시 보내 답합니다(혼잡·시간 초과면 3초 쉬고 한 번 더). 둘 다 안 되면 "비서가 지금 답하지 못합니다"를 보여 주고, 알림은 기본 문구로, 브리핑은 프로그램이 만든 목록으로 나옵니다. **AI가 없어도 공장 화면·3D·기록은 그대로 돕니다.**
- 계기: '잠금 표지 순서' 질문이 Claude 실패로 답을 못 한 일(10/24).

**Q4-5 [강] 왜 뜻으로 찾는 검색(임베딩)을 안 썼나요?**
- 알람 번호·설비 코드처럼 **글자가 정확히 맞아야 하는 낱말이 많고 문서가 작아서** 낱말 검색(BM25)이 더 안정적이었습니다. 임베딩 방식도 만들어 두고 스위치로 켤 수 있습니다. 검색이 놓치는 경우는 고장 질문엔 고장 대응 매뉴얼, 안전 질문엔 안전 작업 기준서를 통째로 주는 방식으로 보완했습니다.

**Q4-6 (후속) [강] "먼저 알린다"는 걸 무엇을 알릴지 LLM이 정하나요?**
- **아닙니다. 무엇을·언제·누구에게는 프로그램(DB 규칙)이 정합니다.** LLM은 모인 목록을 읽기 좋은 문장으로 정리할 뿐이라, LLM이 실패해도 알림은 빠지지 않고 기본 목록 그대로 나옵니다.

**Q4-7 (후속) [강] 문서를 직접 만들었으면 답을 잘하는 건 당연하지 않나요?**
- 맞는 지적입니다. 그래서 ① 문서는 Haas 매뉴얼·KOSHA 안전 기준 같은 실제 자료를 바탕으로 재구성했고 ② 튜닝에 쓰지 않은 **보류 질문 세트**로 성능을 쟀고 현장 말투 질문도 넣었습니다.
- ⚠ 처음 보는 다른 회사 문서에서는 시험하지 않았습니다. 새 회사 문서를 넣으면 그 회사 용어를 사전에 보강해야 합니다.

**Q4-8 [강·명] AI가 그럴듯하게 틀린 말(환각)을 하면?** — 여러 겹으로 막습니다.
1. 답마다 **출처**(문서·번호·절)를 붙여 사람이 확인하게 합니다.
2. 문서에 답이 없으면 지어내지 않고 **"문서에 없음"**으로 답합니다.
3. 규칙 길에서는 AI가 고친 문장의 숫자·기록 번호가 프로그램이 만든 기본 문장과 일치해야 하고, "해도 됩니다"·"리셋하세요" 같은 허락·지시 문구는 거부합니다.
4. **안전 문구는 원문 고정**: 잠금·표지 단계, 고전압 대기, 보호구는 안전 기준서 원문을 프로그램이 글자 그대로 붙이고 "AI 작성 아님"을 표시합니다.
5. 비서가 쓴 문서는 모두 "AI비서 초안"이고 사람이 확정합니다.
- ⚠ 문서 질문의 기본 길에는 숫자 대조 검사가 없고, 지시문과 고정 안전 문구가 안전장치입니다.

**Q4-9 [명] "지금 VF2-01 상태는?" 같은 걸 AI가 지어내지 않나요?**
- 운영 질문은 **DB에서 읽은 값**으로 답합니다(수량·설비 상태·안전 순서는 프로그램이 답함). "지금 병목 어디야"도 현재 병목 공정을 DB로 찾습니다. 권한 밖 정보(작업자가 묻는 MTTR·센서 값)는 값 대신 "보전 담당자·관리자만 볼 수 있습니다"만 알려 줍니다.

**Q4-10 [명] 장갑 끼고 타자 치기 어렵고 공장은 시끄럽습니다.**
- **음성으로 물을 수 있습니다.** 우리 서버의 음성 인식(faster-whisper)으로 최대 60초를 받고, 알람·설비 코드 힌트를 주어 글자 오류율을 **21% → 4%**로 낮췄습니다. 소리는 서버 밖으로 나가지 않고 저장하지 않습니다.
- ⚠ 실제 공장 소음에서는 시험하지 않았습니다.

**Q4-11 [강] 답이 느리면 기다려야 하나요?**
- 급한 것은 AI를 기다리지 않게 했습니다. 지침카드의 알람·안전 칸은 규칙·고정 서식으로 먼저 채우고 비서 문장은 뒤에 채웁니다. 보고서 초안은 정해진 시각(18:00·06:00·07:00)에 미리 만듭니다. 채팅은 '생각 중' 화면을 보여 주고 실패하면 다시 물어 달라고 안내합니다.
- ⚠ 확인 필요: 보고서 초안은 서버 스케줄러가 만드는데 배포 서버에선 꺼 두게 되어 있어, 실제로 생기는지 확인해야 합니다.

**Q4-12 (후속) [명] 작업자가 초안을 고치면 이브가 배워서 다음엔 더 잘 쓰나요?**
- 모델 자체를 다시 학습시키지는 않습니다. 대신 **사람이 확정한 문서가 DB에 기록으로 남고**, 같은 알람이 다시 나면 비서가 "같은 알람의 과거 조치"로 찾아 보여 줍니다. 모델이 바뀌는 게 아니라 **참고할 공장 기록이 쌓이는** 방식이라 누가 무엇을 고쳤는지도 확인됩니다.

**Q4-13 [명·강] 공장 데이터가 외부 AI 회사로 나가는 건 문제 아닌가요?**
- 나가는 것은 **질문, 사내 문서 조각, 생성한 운영 값뿐**입니다. 보내기 직전에 사람 이름·사번·토큰·API 키·DB 주소·서버 비밀값을 가리고, 모든 외부 호출이 한 곳을 지나서 빠지는 길이 없습니다. 서버 스위치 `EXTERNAL_LLM_APP=0`이면 외부로 한 글자도 안 나갑니다. 실제 공장이라면 반출 범위를 다시 정하고 필요하면 사내 설치형 LLM으로 바꿉니다.

**Q4-14 [강] 답변 품질은 어떻게 확인했나요?**

| 평가 세트 | 확인하는 것 |
|---|---|
| 보류 세트 | 튜닝에 안 쓴 문서 질문에서 맞는 문서·절을 인용하는지 |
| 모르는 질문 세트 | 문서에 없는 질문에 지어내지 않고 "문서에 없음"이라고 하는지 |
| 안전 재현 세트 | 안전 질문에서 안전 문구를 빠뜨리지 않는지 |
| 길 나누기 세트 | 문서 질문과 운영 질문을 올바른 길로 보내는지 |

- AI 답은 매번 조금씩 달라 각 평가를 2회씩 돌려 비교했습니다. 정답 절 인용이 Haiku·Sonnet 모두 73/75라서 단가가 훨씬 싼 Haiku를 골랐습니다.

**Q4-15 [명] AI가 "리셋하고 다시 돌리세요" 같은 지시를 하지 않나요?**
- 권한·지시 표현은 차단 목록에 걸리고, 안전 내용은 기준서 원문을 그대로 붙입니다. AI가 쓴 건 모두 "AI비서 초안"이고, 실제 조치는 담당자가 확인한 뒤 합니다.

**Q4-16 [강] 프롬프트 인젝션에는 대비했나요?**
- ⚠ **전용 테스트는 아직 없다고 솔직하게 답하세요.** 대신 피해가 커지지 않게 만들었습니다: AI는 읽기 전용 계정과 정해진 조회 도구 14개만 쓰고, 쓰기·제어 기능이 없습니다.

## 6. 배포 · 접속 · 운영

서버는 **AWS EC2 한 대**에 컨테이너 5개(caddy·web·sim·backend·assistant)를 띄우고, DB는 공용 Supabase를 씁니다. 바깥에 열린 것은 caddy의 80·443뿐입니다.

**Q6-1 [강] 심사위원이 어떻게 접속하고 보안은?**
- `https://<도메인>` 하나로 접속합니다. 나머지 컨테이너는 도커 안쪽에서만 서로 부르고, SSH는 내 IP만 허용합니다. 자동 HTTPS에 접속 비밀번호를 걸고 그 안에서 다시 앱 로그인을 합니다. 주소가 하나라 마이크(HTTPS 필수)도 됩니다.

**Q6-2 [강] 다른 사람이 결과를 재현하려면?**
- 저장소를 받고 환경 파일 3개에 비밀값만 넣어 **`./mom.sh up` 한 줄**이면 됩니다(처음 5~10분). 데이터는 같은 설정이면 같은 결과가 나옵니다.

**Q6-3 [명] 발표 당일 서버가 안 열리면?**
1. `./mom.sh status`·`logs`로 원인을 보고, 새 버전 탓이면 `./mom.sh rollback`으로 직전 버전으로 돌립니다. 2. 그래도 안 되면 확실히 켜지던 비상 태그(`emergency-1024-deploy`)로 바꿉니다. 3. 서버 자체가 안 되면 노트북에서 켜고 Cloudflare 터널로 같은 화면을 엽니다. 4. 마지막으로 시연 녹화본이 있습니다.

**Q6-4 [명] 서버를 다시 켜면 작업자가 한 기록이 사라지나요?**
- 컨테이너는 죽으면 자동으로 다시 켜지고, 시연 서버가 맡는 조작(공구 교체, 로트 보류·해제, 정비 시작·끝, 작업기록 확정 뒤 설비 복귀)은 저장 공간에 남아 다시 적용됩니다. 백엔드·비서·화면만 다시 켜는 건 DB를 건드리지 않고, DB를 바꾸기 전엔 백업합니다.
- ⚠ **시연 서버를 다시 켜면 공용 DB가 기준 시각(10/26 09:00)으로 되돌아가서**, DB에만 있는 기록(작업지시서 승인, 작업기록서, 보고서 확정, 알림 처리, 입고, 채팅 기록)은 기준 시각 이후 것이 지워집니다. 서버 한 대라 서버 자체 장애에 대비한 이중화는 없습니다.

**Q6-5 [강] 장애·한도 관리는?**
- 상태 확인 3가지: `/api/health`(DB 연결), `./mom.sh health`(시연 서버 시각·프로필), 점검 도구(읽기 주소 28개를 한 번씩 호출). 화면은 3번 연속 실패하면 "연결 끊김" 띠와 마지막 갱신 시각을 보여 줍니다.
- Supabase는 500MB 중 약 150MB. 연결 한도(15개) 때문에 백엔드 연결을 작게 잡고, 발표 중에는 AWS 서버만 공용 DB에 붙입니다. 스케줄러·파일 감시는 배포 서버에서 꺼 둡니다. 비서 호출 기록엔 질문·답 글이 남지 않지만, 채팅 기록 화면을 위해 질문과 답은 DB에 본인만 볼 수 있게 남습니다.

**Q6-6 (후속) [강] 시연은 영상이던데, 실제 시스템이 지금 돌아가나요?**
- 네. 영상은 발표 시간과 현장 네트워크 위험 때문에 녹화했고, 시스템은 AWS에 배포되어 HTTPS 주소로 접속됩니다(접속 비밀번호 있음). 질문이 나오면 그 자리에서 이브에게 묻거나 3D 라인을 보여 줄 수 있게 준비합니다. 문제가 생기면 안정 버전으로 되돌리거나 노트북 + Cloudflare 터널로 보여 줍니다.

## 7. 품질 검증 · 실패 분석 · 개선

**Q7-1 [강] 실패 사례와 고친 방법은?** — 실패의 원인을 프롬프트·데이터·로직·구조 중 어디인지 나눠 고치고, 같은 질문으로 다시 확인했습니다.

| 음성 입력 오류 | 라이브러리 버전 호환 | 버전 고정 |

**Q7-2 [강] 고친 뒤 다른 게 나빠지지 않았는지는?**
- 하나 고칠 때마다 평가 세트 전체를 다시 돌려 **기존에 맞던 질문이 깨지지 않았는지** 봤습니다. 검색 보강 옵션은 하나씩 켜고 끌 수 있어 문제가 생기면 그것만 끄고 되돌립니다. 임베딩 검색은 이득이 확실하지 않아 꺼 둔 것도 측정 결과입니다.

**Q7-3 [명·강] 아직 검증하지 못한 것은?** (솔직하게)
- **프롬프트 인젝션** 전용 테스트 없음 (차단 목록·읽기 전용 계정으로 피해 범위만 줄임) / **공장 소음 속 음성 입력** 시험 안 함 / **비용**은 정가 기준 추정이라 실제 청구액이 아님.

**Q7-4 (후속) [강] "실제 공장 검증은 앞으로의 과제"라면 지금 결과는 얼마나 믿을 수 있나요?**

| 구분 | 내용 |
|---|---|
| ✅ 검증함 | 문서 근거 답변 정확도(73/75), 문서에 없을 때 지어내지 않는지, 안전 문구 누락 여부, 시스템 안정성(GET 129회 서버 오류 0건) |
| ❌ 못 함 | 실제 작업자가 이 답으로 더 빨리 조치하는지, 실제 설비 데이터의 잡음·결측, 공장 소음 속 음성 입력 |
| ➡ 다음 단계 | 현장 전문가의 답변 검토, 알람→조치 시간 비교, 실제 설비 데이터 연결 |

## 8. 협업 · 역할

**Q8-1 [명] 역할은 어떻게 나눴나요?** (기획서 14.1)

| 역할 | 담당 |
|---|---|
| AI 비서 ① 문서 검색 (이창민) | 사내 문서 정리, 문서 검색, 출처 인용, 평가 세트 |
| AI 비서 ② 비서 동작 (정현숙) | Claude/Gemini 호출, 조회 도구 14개, 안전 고정 문구, 외부 전송 필터, 음성 입력 |
| 데이터/ML (이유림, 조장) | 데이터 생성기, 센서·설비 상태 데이터, 실시간 생성 흐름 |
| 백엔드/DB (이상혁) | DB(테이블 72개), API 168개(10/27 코드 기준), 권한·로그인, 실시간 알림 |

- 일정: 10/12 기술 회의 → 각자 개발 → 10/22~23 통합·리허설 → 10/26 발표. 접점(DB 구조, API 형식, 실시간 데이터)은 전달 메모로 맞췄습니다.

**Q8-2 [명·강] 본인은 무엇을 맡았고 직접 구현한 곳은?**
- ✏ **본인 작성란** — 맡은 역할 / 직접 구현한 기능·파일 / 가장 어려웠던 문제와 해결을 1~2문장씩 적어 두기 (코드 위치를 바로 보여 줄 수 있게).

**Q8-3 [강] Git으로 어떻게 협업했나요?**
- 저장소 하나(`Ion-Mill/semi-ai`)에서 기능 브랜치로 작업했고(원격 브랜치 약 120개), 이름은 기능 `feat/기능명-날짜`, 문서 `docs/…` 규칙입니다. 병합 충돌을 해결한 기록이 남아 있고, 발표 직전 안정 버전에 `emergency-1024` 태그를 붙여 문제가 생기면 바로 되돌릴 수 있게 했습니다.

**Q8-4 [명] 코드 말고 협업 흔적은 어디서 보나요?**
- `구현_중_수정사항/`(날짜별로 무엇을 왜 바꿨는지) · `팀과 논의/`(담당자 간 전달 메모) · `backend/docs/05_결정기록.md`(설계 결정과 이유). 예: 채팅 센서 값이 화면과 달랐던 문제는 AI 담당이 발견 → DB 담당에게 전달 메모 → 함께 고친 사례입니다.

**Q8-5 [명] 의견이 달랐던 적은? 어떻게 정했나요?**
- 가장 큰 논의는 **로컬 LLM vs 외부 API**였습니다. 보안 때문에 로컬로 시작했지만 한국어 정확도 차이가 커서 Claude로 바꿨고, 대신 보안 우려를 받아들여 외부로 나가기 전 이름·사번·토큰을 가리는 필터와 외부 호출을 한 번에 끄는 스위치를 넣었습니다. 의견이 갈리면 **같은 질문 세트로 측정해 숫자로** 정했습니다.

## 9. 기술 결정 · 발표

**Q9-1 [강] 가장 중요한 기술 결정은?**

| 결정 | 고른 것 | 버린 것 | 이유 |
|---|---|---|---|
| 답변 모델 | Claude API (+ Gemini 대체) | 로컬 Qwen3.5-9B | 한국어 정확도. 보안은 외부 전송 필터로 보완 |
| 모델 등급 | Haiku | Sonnet | 인용 정확도 같고(73/75) 토큰 단가 1/20 |
| 문서 검색 | 낱말 검색 + 용어 사전 | 뜻 검색(임베딩) | 195조각 규모에서 사내 용어 정확 일치가 중요 |
| AI 권한 | 읽기 전용 조회 도구 14개 | 스스로 작업하는 에이전트 | 설비·안전 판단은 사람이, AI는 초안만 |
| 3D 화면 | 모니터링 전용 | 화면에서 설비 제어 | 제어는 사고 위험이 커서 제외 |
| 배포 | EC2 1대 + Docker Compose | 쿠버네티스 등 | 2주·5명 규모에서 재현이 쉬움 |

**Q9-2 [명·강] 기획서와 실제 구현이 다른 부분이 있는데요?** — 먼저 인정하고 이유를 말합니다. 개발 중 측정 결과에 따라 바꿨고 이유는 수정 기록에 있습니다.

| 기획서 | 현재 | 이유 |
|---|---|---|
| 로컬 LLM 확정 (10/06) | Claude (10/17) | 한국어 용어 오류가 커서 |
| Claude를 CLI 구독으로 호출 | API 호출 (10/23~) | 동시 요청·배포에 API가 적합 |
| 외부 전송 필터 "미구현" | 구현 + 테스트 완료 | 기획서 작성 뒤 구현 |
| 외부 LLM 기본 꺼짐 | 시연에서는 켬 | 시연용이며 `EXTERNAL_LLM_APP=0`으로 즉시 끔 |

**Q9-3 [명] 실제 라인에 적용하려면?**
- ① 데이터 생성기 자리에 **실제 설비 데이터**(PLC·센서 수집)를 같은 형식으로 연결 ② 팀이 만든 사내 문서를 **실제 작업 표준·정비 기준서로 교체** ③ 서버 이중화, 외부 모니터링, 사내망 배포, 공장 소음 음성 시험.

**Q9-4 [명] 다른 제품·라인으로 넓힐 수 있나요?**
- 설비·공정·제품 정보가 DB 표로 나뉘어 있어 데이터를 추가하면 화면과 AI 조회가 따라옵니다. 다만 3D 모델과 사내 문서는 라인마다 새로 만들어야 합니다.

**Q9-5 (후속) [명] 중소기업이 쓰기엔 비용이 얼마나 드나요?**
- 서버 AWS EC2 1대, DB는 Supabase 무료 한도, AI는 가장 싼 Haiku로 호출 하나에 약 1센트(정가 기준 추정, 실제 청구액 아님).
- **월 AI 비용 추정** (2교대, 교대당 6명, 월 26일 기준, 1달러 1,400원 가정)

| 사용량 | 1인당 교대당 질문 | 월 비용 |
|---|---|---|
| 적게 | 5개 | 약 33달러 (약 4.6만 원) |
| 보통 | 15개 | 약 78달러 (약 11만 원) |
| 많이 | 30개 | 약 145달러 (약 20만 원) |

- 질문 하나는 재시도 포함 평균 1.3번 호출(약 0.014달러)로 잡았고, 사람이 묻지 않아도 도는 브리핑·보고서·카드 문장 다듬기(월 약 1,000번, 약 11달러)를 더했습니다. ⚠ 리허설 사용 기록으로 다시 맞춰 두면 좋습니다.

**Q9-6 (후속) [강] Rockwell 수치(설비 정지 -33% 등)처럼 이브의 효과를 숫자로 말할 수 있나요?**
- **없습니다.** 그 수치는 업체 발표이고 저희 성과가 아니라 시장 방향을 보여 주려고 쓴 것입니다. 저희가 잰 것은 답변 품질(인용 73/75), 응답 시간, 시스템 안정성이고, 현장 효과(MTTR 감소 등)는 실제 라인에 붙인 뒤 잴 수 있습니다.
- ✏ 리허설에서 "알람 → 지침카드 몇 초", "보고서 손으로 쓸 때 vs 초안 확정" 시간을 재 두면 가장 강한 답이 됩니다.
