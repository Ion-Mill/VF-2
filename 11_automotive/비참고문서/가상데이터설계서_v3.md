## 1. 왜 가상 데이터인가

| 필요한 데이터 | 공개된 실제 데이터 | 상태 |
|---|---|---|
| 설비 상태 + 알람 + 생산 로트 + 정비 + 검사 + 재고가 **한 라인에서 함께** 있는 기록 | 없음 | 찾지 못함 (탐색 보고서 7장) |
| Haas VF-2 실제 운영 기록 | 없음 | 찾지 못함 |
| 조각 자료 | NIST 설비 상태 기록, 4TU 생산 기록, Haas 원시 데이터 표본, 벽돌 라인 정지 기록, Haas 공구 수명 실험 | **있음 — 모양을 빌려 온다** |

그래서 **한 라인의 운영 기록은 가상으로 만들되, 숫자의 크기와 모양은 실제 조각 자료에서 가져온다.** 알람 번호, 알람 설명, 정비 항목처럼 문서에 있는 것은 실제 값만 쓴다.

## 2. 여섯 가지 원칙

| # | 원칙 | 구체적으로 |
|---|---|---|
| 1 | **실제 번호만 쓴다** | 알람 번호·이름·설명은 Haas 알람 목록에 있는 것만. 정비 항목은 Haas 정비 일정에 있는 것만 |
| 2 | **크기는 실제 자료를 따른다** | 상태 변화 횟수, 정지 시간, 로트 수량, 불량률을 3장의 실제 값 범위에 맞춘다 |
| 3 | **서로 맞아야 한다** | 알람 정지 시간 = 상태 기록의 DOWN 시간 = 작업기록서의 수리 시간. 로트 완료 수량 = 마지막 공정 양품 합. 재고 감소 = 사용 기록 합 |
| 4 | **가상임을 표시한다** | 모든 테이블에 `is_synthetic = true`. 화면 구석에 "가상 운영 데이터" 표시 |
| 5 | **다시 만들 수 있어야 한다** | 고정 난수 씨앗(seed)과 설정 파일. 같은 설정이면 같은 데이터 |
| 6 | **빌려 온 값은 출처를 남긴다** | 다른 회사·설비 값은 [참고]와 출처를 붙이고, **정상 범위만** 빌린다. 알람 기준값은 만들지 않는다. 압력은 psi와 bar를 함께 적는다 (1 bar ≈ 14.5 psi) |

## 4. 생성기 전체 구조

```
설정 파일 (config.yaml)
   │  기간, 설비, 교대, 제품, 교대 목표, 확률 값, seed
   ▼
① 기준 정보       설비, 제품(BRK-A100), 공구, 재고 품목, 사용자, 정지 사유, 예방 정비 항목
   ▼
② 생산 계획       원자재 로트 입고, 날짜별 작업지시(수량, 납기) → OP-10 투입 때 교대별 생산 로트로 나눔
   ▼
③ 시간 흐름       1분 단위로 공정·설비마다 상태를 바꾸고 부품을 다음 공정으로 넘김
   │   - 가공 → 다음 부품 / 로트 교체 셋업 / 공구 교체
   │   - 알람이 확률적으로 생김 → 정지 → (정비 필요하면) 작업지시 → 복구
   │   - 예방 정비 기한이 되면 계획 정비
   ▼
④ 파생 기록       공정 실적, 재공, 병목 기록, 검사 계획(발췌·전수)과 결과, 공구 사용량(구멍 수·이송 시간), 재고 입출고
   ▼
⑤ 문서 기록       작업지시서, 작업기록서, 교대·일일 보고서, 수정 이력
   ▼
⑥ 점검           9장 기준으로 자동 점검 → 통과하면 DB에 넣기
```

| 모드 | 쓰임 | 내용 |
|---|---|---|
| 과거 기록 모드 | 30일치 차트·지표·이력·문서 | 2026-09-01 ~ 09-30, 한 번에 생성 |
| 실시간 모드 | 시연 때 화면이 움직이게 | 몇 초마다 상태·센서·실적을 보냄. 시간을 빠르게 돌릴 수 있음 (예: 1초 = 1분) |
| 사건 넣기 | 시연 시나리오 | 버튼 하나로 7장의 정해진 사건을 발생 |

실시간 메시지는 Haas MTConnect 항목 이름(Execution, ControllerMode, EmergencyStop, Program, PartCount 등)을 따른다.

- **안전 재고 식** [참고: NCS 치공구관리 학습모듈 90쪽]: 설비에 달린 수 + 하루 사용량 × 3일분. 예: M6 탭 = 2대 + 하루 약 1.8개(부품 180개 ÷ 탭 1개당 100개) × 3일 ≈ 7.4 → 8개. 모든 품목의 계산은 15.5.
- **절삭유 보충** [참고: OSHA 절삭유 관리 매뉴얼, MSC 2023]: 교대 시작 때 수위를 확인하고, 줄었으면 약 3% 농도로 보충한 만큼 원액을 차감한다. 하루 손실은 약 10% [참고: CTE 1997 "하루 5~20%"] (15.5).
- **절삭유 원액 제품** (2026-10-05): **TRIM SC538** (Master Fluid Solutions, 반합성). 작업 농도 목표 7.0%, 관리 범위 6.5~8.5%, 농도 = 굴절계 값 × 1.4, 포장 20 L [실제: SC538 한국어 제품 자료 2~3쪽, `docs/inventory/소모품_사용량/masterfluids_TRIM_SC538_제품자료_KR_20261005.pdf`]. 6개월 교체 원액은 208 L × 7.0% ≈ 14.6 L (15.5).
- **그리스·주축 윤활유** (2026-10-05 추가): 주축 윤활유는 매월 점검 때 부은 양(L), 그리스는 새 카트리지를 끼울 때 1개를 뺀다. 그리스는 VF-2 매월 정비와 OP-40 텀블러 베어링(8시간마다)에 함께 쓴다 (안전 재고 2개, 15.5). 세척액(OP-40)과 다른 공정 윤활유는 하루 사용량을 계산할 근거가 없어 넣지 않는다 (DOC-04 4.6).
- 입출고 기록 칸은 NCS 자재창고운영관리 서식(재고관리대장·수불대장), 월말 실사·조정은 NCS 자재운영관리를 따른다 [참고].
- 시연용: 9월 말에 **축 윤활유**와 **M6 탭**이 안전 재고 아래로 내려가게 한다 (S2, S3와 연결).

## 9. 만든 데이터 점검 기준

생성기가 데이터를 만든 뒤 자동으로 점검한다. 하나라도 어긋나면 다시 만든다.

| 구분 | 점검 내용 | 기준 |
|---|---|---|
| 범위 | VF-2 하루 상태 변화 횟수 | 60~120 |
| 범위 | VF-2 RUN 비율 (30일 평균) | 55~75% |
| 범위 | 전체 불량률 | 0.5~1.0% |
| 범위 | 알람 중 조작 안내 등급 비율 | 70% 이상 |
| 범위 | 교대 실적 | 대부분 75~100개 (목표 90) |
| 맞음 | 정지 등급 알람 1건마다 DOWN 구간 1개. **OP-30** 정지 등급 알람은 작업지시서 1건·작업기록서 1건 (다른 공정은 간이 작업기록만, 기획서 5.2) | 모두 짝이 맞음 |
| 맞음 | 설비 하나의 상태 구간이 서로 겹치지 않음 | 겹침 0 |
| 맞음 | 로트 완료 수량 = 마지막 공정 양품 합 | 일치 |
| 맞음 | 모든 생산 로트에 원자재 로트가 있음 | 100% |
| 맞음 | 한 생산 로트의 OP-10 투입은 모두 한 교대 안 | 100% |
| 맞음 | 작업지시마다 로트 수량 합 = 작업지시 수량 | 일치 |
| 맞음 | 발췌 로트의 측정 부품 = 첫 부품 + 5개마다 1개, 강화 로트는 전부 | 100% |
| 맞음 | 공구 누적 사용량 = 가공 부품 수 × 부품당 사용량 (교체 때 0으로) | 일치 |
| 맞음 | 작업기록서 수리 시간 = DOWN 구간 길이 | 오차 1분 이내 |
| 맞음 | 재고 수량 = 입고 − 사용 ± 조정, 음수 없음 | 일치, 음수 0 |
| 맞음 | 교대 보고서 2개의 실적 합 = 일일 보고서 실적 | 일치 |
| 맞음 | 재공 = 앞 공정 완료 − 다음 공정 투입, 음수 없음, 한도(30개, OP-30→40은 60개) 넘지 않음. 온도 맞춤 선반 부품은 재공에 세지 않음 (5.15) | 일치 |
| 맞음 | BLOCKED 구간마다 그 시각의 뒤 재공이 한도에 차 있음 | 100% |
| 범위 | 고장이 아닌 병목 원인 ①~④가 30일 안에 각각 5.18의 빈도만큼 있음 | 모두 있음 |
| 맞음 | 생성기의 병목 기록 = 플랫폼 병목 판단 규칙의 결과 | 일치 |
| 맞음 | OP-30 알람 번호가 Haas NGC 목록에, 다른 공정 알람이 각 매뉴얼 목록에 있음 (OP-40 WSH-01·02는 [가상] 번호) | 100% |
| 맞음 | OP-30 예방 정비 항목은 모두 Haas 정비 일정(RD0080, DOC-04 적용 24개)에 있음. 다른 공정 항목은 출처 표시([실제]/[참고]/[가상])가 붙어 있음 | 100% |
| 지표 | 생성기가 계산한 가동률·MTTR·손실 수량 = 플랫폼 API 값 | 일치 |

## 10. 파일 구조와 재현 방법

```
simulator/
  config.yaml          기간, 설비, 교대, 제품, 교대 목표, 확률 값, seed
  masters/             설비, 제품, 공구(사용량 단위·한도), 재고 품목, 사용자, 정지 사유, 알람 등급(다른 공정 포함), 검사 방식 (CSV)
  generate.py          과거 기록 모드
  realtime.py          실시간 모드 + 사건 넣기
  scenarios/           S1~S6 정의 (YAML)
  validate.py          9장 점검
  out/                 생성 결과 (CSV) → DB 적재
```

- 같은 `config.yaml`과 `seed`면 같은 결과가 나와야 한다.
- 생성 결과 CSV는 저장소에 올려도 된다. Haas·Siemens 원문과 번역본은 팀 비공개 저장소에만 둔다.

## 11. 한계와 심사 때 설명 방법

| 예상 질문 | 답변 방향 |
|---|---|
| "데이터가 가짜 아닌가요?" | 운영 기록은 가상이 맞다. 알람 번호·정비 항목·안전 절차는 실제 문서 근거이고, 숫자 크기는 실제 공개 기록(NIST, 4TU)에 맞췄다. 9장 기준으로 점검했다 |
| "센서 값은 어디서 왔나요?" | 다른 Haas 설비(선반)의 실제 원시 데이터에서 정상 범위만 빌렸다. 화면과 문서에 [참고]로 표시했다 |
| "손실 수량은 정확한가요?" | 정지 시간 ÷ 기준 사이클 시간으로 낸 **추정치**이고, 계산식을 DOC-07에 공개했다 |
| "실제 설비에 붙일 수 있나요?" | 메시지 항목 이름을 Haas MTConnect에 맞췄다. 실제 설비는 포트 8082나 Q 명령으로 같은 값을 받을 수 있다 |
| "공구 수명 예측이 정확한가요?" | 실제 Haas 실험 데이터로 학습했고 R² 약 0.55~0.65로 중간 수준이라, 화면은 사용량(구멍 수·이송 시간) 기준 알림이 기본이다 |
| "로트를 왜 교대마다 나누나요?" | 자동차 협력사 추적성 기준이 교대 변경·공정 재시작 때 로트 번호를 바꾸라고 한다 (Panasonic §6.3). 우리 라인은 교대 사이에 3시간 멈춘다 |
| "전수 검사를 안 하나요?" | 평소에는 발췌, 공정이 의심되면 전수다. 협력사 품질 기준(Nemak)과 샘플링 규격(MIL-STD-1916)의 전환 방식을 따랐다 |
| "알람 기준 온도는 어디서 왔나요?" | 만들지 않았다. Haas 문서에 없기 때문이다 |

| 한계 | 내용 |
|---|---|
| 실제 분포를 모름 | Haas VF-2 실제 공장의 알람 빈도, 수리 시간 분포는 공개 자료가 없다 |
| 표본이 작음 | NIST 쓸 만한 날 2일, Haas 원시 표본 약 4시간(선반) |
| 다른 산업 자료 | 정지 기록 모양은 벽돌 라인 것이다 |

## 13. 가상 사내 문서 제작 기준

### 13.1 무엇을 만드나

흩어진 실제 문서(영어·한국어)에서 **이 프로젝트 구현에 필요한 내용만** 뽑아, 한국어로 다시 만든 사내 문서 7종(DOC-01~07). 전체를 "가상 사내 문서 세트"라고 부른다. AI 비서는 이 세트만 검색하고, 답에는 원문 출처를 붙인다.

### 13.2 넣을 내용 고르기

| 규칙 | 뜻 |
|---|---|
| **구현에 쓰는 것만** | 기능(기획서 8장)과 시연 시나리오(7장)에 실제로 쓰이는 내용만 넣는다. 자료가 많아도 다 넣지 않는다 |
| **대상 설비만** | VF-2 기본 사양, NGC 제어기 기준. 구형 제어기, 옵션 장치(팔레트 교환기, 회전 테이블 등), 대상 외 설비 문서는 넣지 않는다 |
| **분량** | 문서당 3~10쪽. 알람 코드집은 쓰는 알람(OP-30 15개 + 다른 공정 8개 + 조작 안내 10~15개)만 |
| **번역 범위** | 넣기로 고른 내용만 번역한다. 이미 한국어 원문이 있으면(Haas 알람 한국어 809개, 한국어 조작 매뉴얼, Siemens 한국어 알람) **번역하지 않고 그 원문을 쓴다** |

**문서별로 쓰는 원문**

| 문서 | 주 원문 | 원문 언어 |
|---|---|---|
| DOC-01 공정별 운영 매뉴얼 | Haas 한국어 조작 매뉴얼, HCS-80 매뉴얼, 세척기 매뉴얼, KOSHA 밀링·둥근톱·절삭유 지침 | 한국어 + 영어 |
| DOC-02 알람 코드집 | Haas 알람 목록(한국어 809개), Siemens 840D sl 한국어 알람, 측정기 오류 코드 | 한국어 + 영어 |
| DOC-03 고장 대응 매뉴얼 | Haas 고장 대응 안내(OP-30 알람 15개와 연결된 편, 552는 TG0138), 장우석 원인·조치 표, HCS-80 경보 코드표, Siemens 840D sl 알람 설명, 세척기·측정기 문제 대응 | 영어 + 한국어 |
| DOC-04 예방 정비 기준서 | Haas 정비 일정 RD0080(VF-2 기본 사양 항목), HCS-80 정비 장, 진동 바렐 매뉴얼, NPL GPG 42(측정기 중간 점검) | 영어 |
| DOC-05 안전 작업 기준서 | KOSHA B-M-25-2026, 산업안전보건기준 규칙 제92·95조, KOSHA 밀링 안전 자료, Haas 전기 안전 문단 | 한국어 + 영어 |
| DOC-06 검사 기준서 | 공차표(ISO 2768, H7), 협력사 품질 문서(Cpk, 측정 시스템 기준, 100% 검사 전환), MIL-STD-1916·KS Q ISO 2859-1(검사 강화), NIST 측정 결과 칸 구성 | 한국어 + 영어 |
| DOC-07 설비 데이터·지표 정의서 | NIST ISO 22400 지표 논문, Haas 데이터 수집 안내, 이 설계서의 [참고]·[가상] 값 | 영어 + 팀 작성 |

### 13.3 서로 다를 때 무엇을 따르나 (우선순위)

```
① 법령  >  ② KOSHA  >  ③ 해당 설비·제어기 세대의 제조사 문서  >  ④ 공식 규격(ISO 등)  >  ⑤ 다른 회사 사례  >  ⑥ 팀 가정
```

| 상황 | 따르는 것 |
|---|---|
| 안전 절차가 서로 다름 | **더 엄격한 쪽.** 둘 다 지킬 수 있으면 둘 다 넣는다 (예: KOSHA 잠금·표지 + Haas 고전압 5분 대기) |
| 같은 알람에 문서가 여러 개 | NGC 문서 > 구형 문서. 최신 개정판 > 옛 판 |
| 품질 기준이 회사마다 다름 | 공식 규격 > 여러 협력사 문서에 공통인 값 > 한 회사 값 |
| 근거 문서가 없음 | 팀이 정하고 **[가상]** 으로 표시 |

### 13.4 서식 (모든 문서 공통)

| 위치 | 내용 |
|---|---|

### 13.5 번역 규칙

| 규칙 | 뜻 |
|---|---|
| **용어집 먼저** | 번역 시작 전에 용어집(약 50~100개)을 만든다. 예: Servo Amplifier → 서보 앰프, Lockout/Tagout → 잠금·표지, Way Lube → 축 윤활유. Haas 한국어 알람 목록의 용어를 우선 쓴다 |
| **쉬운 한국어** | 현장 작업자가 바로 읽을 수 있게 쓴다. 영어 이름은 처음 한 번만 괄호로 |
| **바꾸지 않는 것** | 안전 절차, 알람 설명, 숫자(전압, 시간, 압력, 토크)는 원문 뜻 그대로. 요약하거나 새로 쓰지 않는다 |
| **단위** | 원문 단위를 두고 국내 단위를 괄호로 함께 적는다. 예: 100 psi (약 6.9 bar), 1 inch (25.4 mm) |
| **방법** | LLM으로 번역 → 담당자가 원문과 대조해 검수 → 안전·알람 항목은 다른 팀원이 한 번 더 확인 |
| **원문 복사 금지** | 긴 문단을 그대로 옮기지 않고 필요한 내용만 정리한다. 단, 안전 절차 단계 제목(KOSHA 6.1~7.3)과 알람 이름은 원문 그대로 쓴다 |

### 15.5 재고 — 안전 재고

식: **장비 부착 수 + 1일 사용량 × 3일 분량** [실제 원문: NCS 치공구관리 학습모듈 90쪽 "기본 보관량"]. 하루 180개, VF-2 2대, 근무일 기준.

| 품목 | 계산 | 안전 재고 | 바뀜 |
|---|---|---|---|
| M6 탭 | 2 + 1.8 × 3 = 7.4 | 8 개 | — |
| 드릴 Ø5.0 | 2 + 0.72 × 3 = 4.2 (한도 1,000구멍) | **5 개** | 4 → 5 |
| 보링바 인서트 | 2 + 0.45 × 3 = 3.4 | **4 개** | 6 → 4 |
| 엔드밀 Ø10 | 2 + 2.25 × 3 = 8.75 (한도 200분 = 부품 80개) | **9 개** | 4 → 9 |
| 페이스밀 인서트 | 10 (5개 × 2대) + 0.23회 × 5개 × 3 = 13.4 | **14 개** | 10 → 14 |
| 축 윤활유 | 2 × 0.95 L + 하루 약 0.02 L × 3 ≈ 2 L → Haas 판매 단위 1갤런(3.78 L)으로 올림 | 4 L | — (근거 추가) |
| 절삭유 원액 (TRIM SC538) | 하루 손실 약 10% × 탱크 416 L(208 L × 2대) × 보충 농도 3% ≈ 1.25 L/일 → 3일분 3.8 L + 탱크 1회 교체분(208 L × 7.0% ≈ 14.6 L) = 18.4 L → 판매 단위 20 L 통으로 올림 | 20 L (1통) | 교체분 6.5% → 7.0% (SC538 목표 농도), 값은 그대로 |
| 절삭유 필터 / 공기 필터 | 장비 부착 수 2 + 사용량 거의 0 | 2 / 2 개 | — |
| 주축 윤활유 | 장비 부착 수 0 (RD0080에 주축 오일 교체가 없고 보충만 있음) + 하루 약 0.02 L(0.6 cc/시간 × 16시간 × 2대) × 3 = 0.06 L → Haas 판매 단위 128 oz(3.79 L)로 올림 | 4 L (1통) | 새로 |
| 그리스 | 장비 부착 수 1 (공용 그리스건 1개에 끼운 카트리지) + 하루 약 6 cm³(OP-40 텀블러: 1.5 cm³ × 니플 2개 × 하루 2회, VF-2는 0으로 봄) × 3 = 18 cm³ ≈ 카트리지(0.41 L) 0.04개 → 1.04 → 올림 | **2 개** | 1 → 2 (텀블러 추가, 2026-10-05) |
| 6061-T6 봉재 | 공구용 식이 맞지 않음 → 하루 생산분 | 200 개분 | — |

- 절삭유 하루 손실 10%의 근거 [참고]: "증발로 하루 3~10%, 튐·미스트·끌려 나감까지 합치면 하루 5~20%" (CTE 1997, `docs/inventory/소모품_사용량/`). 보충 농도 3%는 MSC 2023 "알루미늄은 3%".
- 절삭유 목표 농도 7.0% [실제]: SC538 제품 자료 2쪽 "일반절삭가공 (Moderate duty) 6.5% - 8.5%", "7% 이상에서 작동 시 최상의 탱크 수명 및 부식 방지 제공". 포장 20 L [실제: 같은 자료 3쪽].
- 주축 윤활유 [참고/실제]: 0.6 cc/시간은 다른 회사의 공기·오일 윤활 권장값이다 (Plant Services 2002, `docs/inventory/소모품_사용량/plantservices_2002_공기오일윤활_주축베어링_Mitchell.html`). Haas 자료에는 소비량이 없다. 오일 종류·128 oz는 RD0040 [실제]. 이 속도면 한 통이 약 7개월 가므로 9월 안에 안전 재고 아래로 내려가지 않는다.
- 그리스 [실제/가상]: 카트리지 14 oz(0.41 L)와 부품 번호 99-1686은 RD0040 [실제]. 1회 주입량은 Haas 자료에 없어 g으로 빼지 않고 카트리지 단위로 뺀다 [가상]. OP-40 텀블러도 같은 그리스(XHP 222)를 쓴다 [가상]: 진동 기계 베어링에는 EP 첨가 리튬 비누 그리스·주도 2급을 권한다 [참고: FAG TPI 197 인쇄 34쪽]. 1번 누름 1.5 cm³ [참고: SKF 1077600 H 그리스건 사양], 니플 2개·하루 2회 [가상]. 카트리지 1개가 약 68일 가므로 9월 한 달에는 카트리지 교체가 0~1번 생긴다 (DOC-04 4.5).
- 축 윤활유는 실제 소비 속도(한 통이 우리 라인에서 약 4~5개월)로는 9월 안에 안전 재고 아래로 내려가지 않는다. 시연 S2를 위해 **9월 말 "보충을 빠뜨림" 사건**을 따로 넣는다 (LUBE-SM-02 "한 통이 주 40시간 기준 약 10개월~1년").
- **원자재 입고 고침:** 주 2회 × 400개(800개)는 주 소비 1,080개(6일 × 180개)보다 적다 → **주 3회 × 약 360개**로 바꾼다.

### 15.6 품질: 발췌 검사의 공정능력 계산
