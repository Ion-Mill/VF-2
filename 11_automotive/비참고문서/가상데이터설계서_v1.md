## 1. 왜 가상 데이터인가

| 필요한 데이터 | 공개된 실제 데이터 | 상태 |
|---|---|---|
| 설비 상태 + 알람 + 작업지시 + 정비 + 검사가 **한 라인에서 함께** 있는 기록 | 없음 | 찾지 못함 (탐색 보고서 7장) |
| Haas VF-2 실제 운영 기록 | 없음 | 찾지 못함 |
| 조각 자료 | NIST 설비 상태 기록, 4TU 생산 기록, Haas 원시 데이터 표본, 벽돌 라인 정지 기록, Haas 공구 수명 실험 | **있음 — 모양을 빌려 온다** |

그래서 **한 라인의 운영 기록은 가상으로 만들되, 숫자의 크기와 모양은 실제 조각 자료에서 가져온다.** 알람 번호, 알람 설명, 정비 항목처럼 문서에 있는 것은 실제 값만 쓴다.

## 2. 다섯 가지 원칙

| # | 원칙 | 구체적으로 |
|---|---|---|
| 1 | **실제 번호만 쓴다** | 알람 번호·이름·설명은 Haas 알람 목록에 있는 것만. 정비 항목은 Haas 정비 일정에 있는 것만 |
| 2 | **크기는 실제 자료를 따른다** | 상태 변화 횟수, 정지 시간, 작업지시 수량, 불량률을 3장의 실제 값 범위에 맞춘다 |
| 3 | **서로 맞아야 한다** | 알람으로 멈춘 시간 = 상태 기록의 DOWN 시간 = 정비 작업지시의 시간. 생산 수량 = 공정 실적 합 |
| 4 | **가상임을 표시한다** | 모든 테이블에 `is_synthetic = true`. 화면 구석에 "가상 운영 데이터" 표시 |
| 5 | **다시 만들 수 있어야 한다** | 생성기에 고정 난수 씨앗(seed)과 설정 파일을 둔다. 같은 설정이면 같은 데이터가 나온다 |

- **바로잡은 점:** 기획서 v0.1에는 "Haas 공개 데이터 항목에는 모터 온도 같은 값이 없다"고 썼다. MTConnect 항목 목록에는 없는 것이 맞지만, **원시 데이터 표본에는 주축 모터 온도, 공기 압력, 직류 전압이 있다.** 기획서 v0.2에서 고쳤다.

## 4. 생성기 전체 구조

```
설정 파일 (config.yaml)
   │  기간, 설비, 교대, 제품, 확률 값, seed
   ▼
① 기준 정보 만들기     설비, 제품, 공구, 사용자, 정지 사유 코드, 예방 정비 항목
   ▼
② 생산 계획 만들기     날짜별 작업지시 (제품, 수량, 납기)
   ▼
③ 시간 흐름 흉내 내기   1분 단위로 설비마다 상태를 바꾼다
   │   - 가공 → 공구 교환 → 다음 부품
   │   - 알람이 확률적으로 생김 → 정지 → (정비 필요하면) 작업지시 → 복구
   │   - 예방 정비 기한이 되면 계획 정비
   ▼
④ 파생 기록 만들기     공정 실적, 정비 이력, 검사 결과, 공구 사용 기록
   ▼
⑤ 점검               9장의 기준으로 자동 점검 → 통과하면 DB에 넣기
```

| 모드 | 쓰임 | 내용 |
|---|---|---|
| 과거 기록 모드 | 화면에 30일치 차트, 지표, 이력이 있게 | 2026-09-01 ~ 2026-09-30, 한 번에 생성 |
| 실시간 모드 | 시연 때 화면이 움직이게 | 몇 초마다 상태·센서 값을 보내고 DB에 쌓음. 시간을 빠르게 돌릴 수 있음 (예: 1초 = 1분) |
| 사건 넣기 | 시연 시나리오 | 버튼 하나로 7장의 정해진 알람 순서를 발생 |

실시간 모드가 보내는 메시지는 Haas MTConnect 항목 이름(Execution, ControllerMode, EmergencyStop, Program, PartCount 등)을 따른다. 그래야 나중에 실제 설비를 붙일 때 바꿀 부분이 적다.

| RUN | ACTIVE | 작업지시가 있고 알람이 없을 때 |
| IDLE | READY | 소재 대기, 앞 공정 대기, 작업지시 없음 |
| SETUP | (작업자 입력) | 작업지시 바뀔 때 15~40분 [가상] |
| DOWN | STOPPED + 정지 알람 | 정지 등급 알람 발생 ~ 복구 |
| MAINT | (작업지시 진행) | 예방 정비 시간 |

| 목표 범위 (VF-2 기준, 하루) | 값 | 근거 |
|---|---|---|
| 상태 변화 횟수 | 60~120회 | NIST 98~101회 [실제] |
| RUN 비율 (계획 가동 시간 기준) | 55~75% | NIST 48~72% [실제], 벽돌 라인 가동률 중앙값 67% [참고] |
| DOWN 비율 | 평소 2~8%, 큰 고장 날 15~30% | [가상] |

### 5.6 알람 이벤트 (alarm_event)

알람은 **세 등급**으로 나누고, 실제 기록처럼 **가벼운 것이 훨씬 많게** 만든다.

| 등급 [가상] | VF-2 1대당 하루 | 쓰는 알람 (Haas NGC 실제 번호) | 상태 영향 |
|---|---|---|---|
| 조작 안내 | 3~8건 | 314 서브프로그램 없음 등 조작·프로그램 관련 | 1~5분 IDLE |
| 주의 | 0~2건 | 108 축 서보 과부하, 174 공구 부하 초과, 2075 축 윤활유 저장소 비워짐, 120 공기 압력 낮음, 362 공구 수명 한계 | 5~20분 정지, 작업자 조치 |
| 정지 | 30일에 2~4건 | 992, 994, 991, 993, 103, 254, 966, 2073 | 30~180분 DOWN, 정비 작업지시 생성 |

- 비율 근거: NIST 두 날의 알람은 경고 9~10건이 대부분이고, "고장" 6건도 입력 오류였다. 설비 자체 고장은 표본에 없었다 [실제].
- 조작 안내 등급의 알람 번호는 1주차에 Haas 목록에서 10~15개를 더 고른다(프로그램·모드·도어 관련).
- 정지 시간 길이: 주의 등급은 벽돌 라인의 고장 정지(중앙값 8.3분, 상위 10% 26.7분) 모양을 빌리고 [참고], 정지 등급은 정비 작업이 들어가므로 30~180분으로 따로 정한다 [가상].
- **알람끼리의 순서**도 실제 문서를 따른다. 예: 서보 앰프 안내의 "과부하 알람 뒤에 과전류 알람이 오면 충돌 신호" → 108 → 994 → 992 순서로 만든다.

### 5.7 센서 값 (sensor_sample) — 선택

| 센서 | 정상 범위 [참고] | 이상 상황 만들기 [가상] | 연결 알람 |
|---|---|---|---|
| 주축 모터 온도 (℃) | 28~42 | 고부하 지속 시 천천히 상승 | 254 (온도 기준값은 만들지 않음) |
| 공기 압력 (psi) | 100~110 | 서서히 떨어짐 | 120, 4001 |
| 직류 버스 전압 (V) | 300~330 | 순간 하락 | 160 등 전원 관련 |
| 주축 부하 (%) | 0~185, 중앙값 38 | 무뎌진 공구일 때 상승 | 174 |
| X·Y·Z축 부하 (%) | 0~65 | 충돌 직전 급상승 | 108 → 994 → 992 |

- **알람 기준값(예: 몇 ℃에서 254)은 Haas 문서에 없으므로 만들지 않는다.** 화면에는 "정상 범위에서 벗어나는 추세"만 보이고, 알람 발생은 시나리오가 정한다.
- 공기 압력의 공식 요구값(필요 100 psi, 최소 80 psi)은 VF-2 사양 페이지에 있다 [실제]. 이 값은 화면 기준선으로 써도 된다.

### 5.8 정지 사유 (downtime_reason)

| 그룹 | 코드 예시 | 하루 건수 (라인 전체) |
|---|---|---|
| 고장 (FAILURE) | 서보·앰프, 주축, 공구 교환기, 윤활, 공압, 절삭유 | 1~3 |
| 자재 (MATERIALS) | 소재 대기, 앞 공정 대기 | 2~4 |
| 준비 (SETUP) | 작업지시 교체, 공구 교체 | 3~5 |
| 조작 (OPERATION) | 프로그램 오류, 모드 오류, 도어 열림 | 3~8 |
| 계획 (PLANNED) | 예방 정비, 휴식, 계획 없음 | 일정에 따름 |

- 그룹 구성은 벽돌 라인 정지 기록(FAILURE, MATERIALS, SETUPS-CHANGEOVERS, OPERATIONAL + 계획/비계획 구분)을 참고했다 [참고]. "조작" 그룹은 NIST 기록에서 조작 경고가 가장 많아 추가했다.
- 하루 건수는 [가상]이다. 벽돌 라인은 하루 약 7건의 비계획 정지가 있었다 [참고].

### 5.11 공구 사용과 수명 (tool, tool_usage)

| 항목 | 규칙 | 근거 |
|---|---|---|
| 공구 목록 | VF-2 한 대당 8~12개 (엔드밀, 드릴, 보링바, M6 탭 등) | [가상], VF-2 기본 공구 교환기는 20개 자리 [실제] |
| 수명 한도 | 공구별 사용 횟수 한도 (예: 탭 400회, 엔드밀 800회) | **[가상]** — Haas 고급 공구 관리 기능처럼 사용자가 정하는 값 |
| 사용 기록 | 부품 1개 가공 = 해당 공구 사용 1회 | — |
| 실제 수명 | 한도 근처에서 끝나지만 편차를 둠 (일부는 일찍 파손) | 편차의 모양은 VF-1 실험(0~149 사이클, 공구마다 크게 다름) [참고] |
| 연결 알람 | 한도 도달 → 362, 부하 급증 → 174 | Haas 알람 [실제] |

- **예측 모델은 이 가상 기록으로 학습하지 않는다.** 가상 기록으로 학습하면 우리가 넣은 규칙을 다시 맞히는 것뿐이다. 모델은 실제 VF-1 실험 데이터로 학습하고, 결과는 "실험 결과"로 보여 준다.
- VF-1 실험은 **강철(42CrMo4)** 가공이다. 우리 가상 공장은 알루미늄이므로 사이클 수 자체를 옮겨 쓰지 않고, "수명이 공구마다 크게 흔들린다"는 모양만 빌린다.

## 9. 만든 데이터 점검 기준

생성기가 데이터를 만든 뒤 자동으로 점검한다. 하나라도 어긋나면 다시 만든다.

| 구분 | 점검 내용 | 기준 |
|---|---|---|
| 범위 | VF-2 하루 상태 변화 횟수 | 60~120 |
| 범위 | VF-2 RUN 비율 (30일 평균) | 55~75% |
| 범위 | 전체 불량률 | 0.5~1.0% |
| 범위 | 알람 중 조작 안내 등급 비율 | 70% 이상 |
| 맞음 | 정지 등급 알람 1건마다 DOWN 구간 1개, 정비 작업지시 1건 | 모두 짝이 맞음 |
| 맞음 | 설비 하나의 상태 구간이 서로 겹치지 않음 | 겹침 0 |
| 맞음 | 작업지시 완료 수량 = 마지막 공정 실적의 양품 합 | 일치 |
| 맞음 | 정비 이력의 수리 시간 = DOWN 구간 길이 | 오차 1분 이내 |
| 맞음 | 모든 알람 번호가 Haas NGC 목록에 있음 | 100% |
| 맞음 | 모든 예방 정비 항목이 Haas 정비 일정에 있음 | 100% |
| 지표 | 생성기가 계산한 가동률·MTTR = 플랫폼 API가 계산한 값 | 일치 (지표 계산 코드 검증용) |

## 10. 파일 구조와 재현 방법

```
simulator/
  config.yaml          기간, 설비, 교대, 제품, 확률 값, seed
  masters/             설비, 제품, 공구, 사용자, 정지 사유, 알람 심각도 (CSV)

  scenarios/           S1~S5 정의 (YAML)
  validate.py          9장 점검
  out/                 생성 결과 (CSV) → DB 적재
```

- 같은 `config.yaml`과 `seed`면 같은 결과가 나와야 한다.
- 생성 결과 CSV는 저장소에 올려도 된다(가상 데이터). Haas·Siemens 원문은 올리지 않는다.

## 11. 한계와 심사 때 설명 방법

| 예상 질문 | 답변 방향 |
|---|---|
| "데이터가 가짜 아닌가요?" | 운영 기록은 가상이 맞다. 다만 알람 번호·설명·정비 항목·안전 절차는 실제 문서 그대로이고, 숫자의 크기는 실제 공개 기록(NIST, 4TU)에 맞췄다. 점검 기준(9장)으로 확인했다 |
| "실제 설비에 붙일 수 있나요?" | 메시지 항목 이름을 Haas MTConnect 항목에 맞췄다. 실제 설비는 포트 8082의 MTConnect나 Q 명령으로 같은 값을 받을 수 있다 (Haas 공식 데이터 수집 안내) |
| "공구 수명 예측이 정확한가요?" | 가상 데이터가 아니라 실제 Haas 실험 데이터로 학습했다. 처음 보는 공구 기준 R² 약 0.55~0.65로 중간 수준이라, 화면에서는 사용 횟수 기준 알림을 기본으로 한다 |
| "알람 기준 온도는 어디서 왔나요?" | 만들지 않았다. Haas 문서에 없기 때문이다. 센서 값은 추세 표시용이다 |

| 한계 | 내용 |
|---|---|
| 실제 분포를 모름 | Haas VF-2 실제 공장에서의 알람 빈도, 수리 시간 분포는 공개 자료가 없다 |
| 근거 자료의 표본이 작음 | NIST 쓸 만한 날 2일, Haas 원시 표본 약 4시간(선반) |
| 다른 산업 자료 | 정지 기록 모양은 벽돌 라인 것이다 |
