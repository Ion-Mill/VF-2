### 2.3 라인 기준 속도와 목표

| 항목 | 값 | 구분 |
|---|---|---|
| 라인 기준 속도 | **3.5분/개** (OP-30 7.0분 ÷ 2대) | [가상] |
| 이론 최대 | 교대당 약 137개 (480분 ÷ 3.5분) | 계산 |
| **교대 목표** | **90개** (이론 최대의 약 65%) | [가상], 65%의 근거 [참고: Hedman 외 2016, 평균 OEE 65%] |
| 하루 목표 | 180개 (2교대) | [가상] |
| **이월·총 목표** | 이월은 **같은 생산일 주간 → 야간만**: 야간 이월 = max(0, 90 − 그날 주간 실적), 주간은 늘 0. **교대 총 목표 = 90 + 이월**. 하루 목표 180은 고정이고, 야간이 못 채운 수량은 다음 날로 넘기지 않고 그날 부족으로 남긴다. 예: 주간 87 → 야간 93, 야간 86 → 하루 173 (7개 부족) (계산은 DOC-07 §4.1) | [가상: 2026-10-07 팀 UI 검토] |

- 라인 속도는 병목 OP-30(2대, 1대 7.0분)과 OP-20이 정하는 **약 3.5분/개**다. 다른 공정은 이보다 빠르다 (SAW-01 약 1.0분, 세척 약 0.8분, 측정 평소 약 0.9분). **한 설비가 멈추면 앞에는 재공이 쌓이고 뒤는 기다린다.**
- 고장 정지 1건의 손실 수량(추정) = 정지 시간 ÷ 그 설비의 기준 사이클 시간 [가상: 기획서 PRD-01].

| 교대 | 시간 | 계획 가동 시간 | 구분 |
|---|---|---|---|
| 주간 | 08:00~17:00 (휴식 1시간 포함) | 480분 | [가상] |
| 야간 | 20:00~05:00 (휴식 1시간 포함) | 480분 | [가상] |
| 교대 사이 | 17:00~20:00, 05:00~08:00 라인 정지 | — | [가상] |

- 근무일: 월~토, 일요일 휴무 [가상].
- **생산일** = 그날 주간(08:00~17:00) + 그날 밤 야간(20:00~다음 날 05:00). 일일 보고서의 날짜는 생산일(주간이 시작한 날)이다. 예: 9/15 08:00 ~ 9/16 05:00 → "9/15 일일 보고서" [가상: 2026-10-06 회의].
- 두 교대가 겹치지 않으므로 **반장끼리 얼굴을 보고 인계하지 못한다.** 대신 확정된 교대 보고서(PRD-02)와 다음 교대의 교대 시작 브리핑(AST-01)으로 인계한다 [가상].
- **보고 순서 규칙:** 브리핑의 "먼저 챙길 일", 교대 보고서의 인계 사항·필수 정지, 일일 보고서의 "오늘의 문제"는 **프로그램이 정해진 목록·기준으로 문제를 전부 모으고 정해진 순서로 정렬**한다. 비서는 그 순서대로 문장만 쓰고, 몇 개만 고르거나 순서를 바꾸지 않는다. 순서와 같은 순위 안 정렬은 **DOC-07 §10.5** [가상: 2026-10-06 회의].

### 3.1 교대 시작

**① 교대 시작 브리핑 확인 (SUP 전체, OPR 요약)** [가상: 기획서 AST-01]

| 브리핑 칸 | 확인할 것 |
|---|---|
| 지난 교대 요약 | 첫 줄 양품·손실 수량, 둘째 줄 정지·손실 원인과 이월, 셋째 줄 불량 등 나머지 |
| 먼저 챙길 일 (전체 N건) | 처리할 문제 **전부**. 머리에 "전체 N건"과 순위별 건수가 늘 보이고, 건수가 0인 순위도 "-"로 보인다 (순위 0은 "잠금·표지 중인 설비 없음"). 순서는 DOC-07 §10.5: 0 안전(잠금·표지 중인 설비) → 0-1 24시간 넘게 처리 안 된 주의 알림 → 1 긴급(처리 안 된 정지 등급 알람, 지금 DOWN) → 2 생산 위험(목표 미달·병목·납기) → 3 주의(반복 알람 2단계 → 1단계, 주의 등급 알람, 품질, 공구 수명 90% 이상·예방 정비 기한 넘김·재고 부족, 승인 대기 2시간) → 4 참고 |
| 이번 교대 | 첫 줄 **총 목표**(목표 90 + 이월), 둘째 줄 작업지시·로트, 셋째 줄 예방 정비 기한 |
| 출처 | 항목마다 붙은 기록 번호 링크를 눌러 원래 기록을 본다 |

- 브리핑은 문서가 아니라 화면이다. 항목마다 한 줄은 늘 보이고 자세한 내용만 접을 수 있다. 순위 0·0-1·1은 접지 않는다. 같은 설비·같은 원인은 한 줄로 묶는다 [가상: DOC-07 §10.5].
- 브리핑은 1분 안에 읽는 것이 목표지만, **1분에 맞추려고 항목을 빼지 않는다** [가상: 2026-10-06 회의].
- 작업자(OPR)는 현장 큰 모니터의 **현장 보기**(첫 화면)에서 3D 라인 뷰 옆 좁은 띠로 브리핑 5줄 요약과 처리 안 된 알람을 교대 내내 본다 [가상: 2026-10-06 회의].

### 3.3 교대 끝

**① 교대 보고서 확정 (SUP)** [가상: 기획서 PRD-02]

교대가 끝나면 비서가 **AI비서 초안**을 만든다. 숫자는 프로그램이 넣고, 비서는 "특이 사항"과 "인계 사항" 문장만 쓴다. **해당 교대 반장이 읽고 고쳐서 확정**한다.

| 칸 | 반장이 확인할 것 |
|---|---|
| 생산 | 목표 / 실적 / 불량 / 가동률이 화면 값과 같은지 |
| 로트 | 이 교대에 만든 로트, 완료·진행·보류 로트 |
| 필수 정지 | **고장 그룹(F01~F06)이고 5분 이상인 정지 전부** (정지 등급 DOWN 전부 + 주의 등급 알람으로 멈춘 정지), 모든 공정. 개수 제한 없음. 정지 시간 긴 순 → 손실 수량 큰 순 → 시작 이른 순. 칸: 설비, 원인, 시간, 손실 수량 — 정지 사유가 모두 확정됐는지. 순간 정지(5분 미만)는 건수·합계 시간 한 줄. 소재 대기(M01)는 넣지 않는다(흐름 정지 → 병목 칸) [가상: DOC-07 §5.4] |
| 병목 | 병목 공정·원인·시간, 속도 손실 수량 |
| 정비 | 작업지시서·작업기록서 번호, 알람, 조치 |
| 특이 사항 | 3~5문장. 사실과 다른 표현을 고친다 |
| 인계 사항 | 아래 ② 목록이 빠지지 않았는지, 보고 순서(DOC-07 §10.5)대로인지 |

- 양식 근거 [참고]: NCS 작업계획수립 학습모듈 PDF 43쪽 "작업 일보에는 공정·품목별 생산 수량과 실제 작업 시간, 당일 불량 현황과 손실 시간의 원인별 현황을 기록".

| 주간 교대 보고서 | **17:00** (주간 교대 끝) | 주간 반장이 퇴근 전 확정 → 20:00 야간 브리핑의 "지난 교대 요약"이 됨 | [가상] |

- 06:00까지 확정되지 않은 교대 칸은 원기록을 모은 값에 **"잠정"** 표시를 하고, 관리자의 [확정] 버튼은 누를 수 없으며, 확정 요청 알림은 교대 끝(17:00·05:00)에 이미 해당 교대 반장(SUP)에게 가 있다. 확정 전 그 교대 값은 브리핑·야간 이월에서도 "잠정"이다. 교대 보고서가 확정되면 그 칸을 다시 채우고 수정 이력을 1줄 남긴다 [가상].
- 일일 보고서 숫자는 06:00 기준이다. 야간 끝에 만든 로트는 08:00 뒤에 측정·판정되므로 일일 보고서 로트 칸에는 "판정 대기"로 적히고, 그 로트의 완제품 입고(§5.5)는 **다음 생산일** 보고서에 들어간다 [가상].
- 야간 반장의 05:00~06:00 확정 시간은 야간 교대(20:00~05:00) 밖이라 실제로는 1시간 연장 근무가 된다. 근무 계획에 넣을지는 **[선택 필요: 팀 — 근무 계획]** [참고: Wilkinson·Lardner 2012 "인수인계에 더 필요한 시간은 근무로 인정"].

| 작업지시 번호 | `PO-2609-001` 형식, 수량 24~60개 (중앙값 약 36개), 하루 4~5건 | [가상], 수량 모양 [참고: 4TU 실제 기록] |
| 로트 번호 | `LOT-2609-001-1`, `-2` … (작업지시 번호 + 순번) | [가상] |
| **로트 번호를 붙이는 때** | **OP-10에 투입할 때** | [가상] |
| **새 로트가 생기는 때** | 같은 작업지시라도 ① **교대가 바뀌거나** ② **원자재 로트가 바뀌면** 새 로트 | [참고: Panasonic 추적성 요구사항 7쪽 §6.3 "공정 재시작, 교대 변경, 생산일 변경 때 로트 번호 변경"] |
| 로트 수량 | 그 교대에 OP-10에 투입한 수량 (1~60개). 작업지시의 로트 수량 합 = 작업지시 수량 | [가상] |
| 원자재 로트 | 로트 1개 = 원자재 로트 1개 | [참고: IATF 16949 FAQ §8.6.5] |
| 셋업 | 로트가 나뉘어도 품종이 같으므로 **셋업은 없다** (셋업은 작업지시가 바뀔 때만, 6장) | [가상] |

- **이미 투입된 부품은 다음 교대에 뒤 공정을 지나가도 로트 번호가 바뀌지 않는다.** 공정 실적에는 그 공정을 처리한 교대가 따로 남는다 [가상: 설계서 5.5].

### 5.5 완제품 입고·출하 → 출하 조건은 DOC-06 §4.3

완제품 품목은 1개: **BRK-A100** (품목 번호 예 `FG-BRK-A100`, 단위 "개") [가상]. 주문 접수·ERP 연동은 하지 않는다 (범위 밖) [가상: 기획서 8.1].

**① 수불 규칙** [제안: 2026-10-06 회의 결정을 구체화. 근거는 오른쪽]

| # | 규칙 | 근거 |
|---|---|---|
| 1 | **입고** = 로트가 "합격"으로 판정된 시각에 그 로트의 **합격 수량**이 자동으로 들어온다. 사람이 입고를 치지 않는다 | [참고: NCS 자재창고 운영관리 PDF 37쪽 "완제품의 최종 검사가 끝나면"] |
| 2 | 보류 → **해제**된 로트는 해제 시각에 전수 검사로 고른 합격 수량만 들어온다. 폐기 수량은 들어오지 않는다 | DOC-06 §4.1 |
| 3 | 판정 대기·보류 검토·보류 로트는 완제품 재고에 넣지 않는다. 화면·보고서에는 **"보류 수량"을 따로** 보인다 | [참고: NCS 출고관리 PDF 63쪽 "부적합품은 따로 보관"] |
| 4 | **출하는 합격(해제 포함) 로트에서만** 한다. 출하 화면의 로트 목록에는 합격 로트만 나온다. **보류 로트 출하 금지** | [참고: NCS 자재창고 PDF 37쪽 "합격품에 한해 출고"], DOC-06 §4.1 "보류 = 출하 금지", DOC-06 §4.3 |
| 5 | **선입선출(FIFO):** 먼저 합격한 로트부터 출하한다. 같은 날 합격이면 로트 번호 순. 순서를 어기면 사유를 적는다 | [참고: IATF 16949 8.5.4.1 (Nemak 협력사 품질 매뉴얼 §4.10.1에 같은 문장), NCS 자재창고 PDF 44쪽 "로트 역전"] |
| 6 | 재고는 로트별로 센다. 완제품 재고 = 합격 입고 합 − 출하 합 ± 월말 실사 조정. 어느 때도 0보다 작아지지 않는다 | [참고: NCS 자재창고 PDF 37~38쪽] |
| 7 | 완제품에는 **안전 재고를 두지 않고** 부족 알림도 없다 | [가상]: 주문·납기 관리가 범위 밖이라 기준을 정할 근거가 없음 |
| 8 | 완제품을 둘 곳: 완성품 자리 FG-01 (§2.4). 보류 로트는 보류 구역 (5.4) | [가상] |

**② 출하 순서 (SUP)** [가상]

| # | 할 일 | 누가 |
|---|---|---|
| 1 | 출하 기록을 새로 만든다: 출하 번호 `SHP-2609-001` 형식, 출하처 `CUST-01` (가상 고객 코드 — 실제 회사 이름은 쓰지 않는다), 근거 작업지시, 납기일 | SUP |
| 2 | 로트 줄을 넣는다: 합격 로트 목록에서 먼저 합격한 로트부터 고르고 수량을 적는다 (로트 남은 수량 이하) | SUP |
| 3 | 시스템이 확인한다: ① 모든 로트가 합격(해제 포함) ② 로트 남은 수량 ≥ 출하 수량 ③ FIFO 순서 (아니면 사유) | 시스템 |
| 4 | **확정**하면 출하 수량만큼 완제품 재고에서 자동으로 빠진다. 확정 뒤 수정은 사유를 적는다 | SUP (출하 확인자) |
| 5 | 납기일에 보류·판정 대기인 로트는 빼고 나머지만 출하한다 (**부분 출하**, 비고에 사유). 뺀 로트는 해제·합격된 뒤 다음 출하에 넣고 "납기 지남"을 표시한다 | SUP |

- 출하는 출하를 확정할 반장이 근무하는 **납기일 주간 교대 중**에 한다 [가상].
- 로트 추적은 원자재 로트 → 생산 로트 → 검사 → **출하**까지 이어진다. 이미 출하한 로트가 나중에 의심 로트가 되면 로트 추적 화면에 출하 번호·출하처가 보인다. 고객 통보·회수는 범위 밖이다 [제안].
- 완제품의 **월 실사·조정**은 반장(SUP)이 한다 (사유 필수) [가상: 2026-10-06 회의].
- 일일 보고서 재고 칸에 완제품 한 줄이 붙는다: 시작 재고 / 입고(합격) / 출하 / 조정 / 종료 재고 / 보류 수량(참고, 재고에 넣지 않음) [참고: NCS 자재 운영관리 PDF 20쪽 표 1-1].

### 7.1 사용량 단위와 수명 한도

Haas 고급 공구 관리(ATM)는 공구 그룹마다 한도를 USAGE(사용 횟수), **HOLES(구멍 수)**, **FEED(이송 시간, 분)**, TOTAL TIME(총 시간)으로 정할 수 있다 [실제: Haas 매뉴얼 4.9.2, PDF 133~134쪽]. 우리 라인은 공구 종류마다 다른 단위를 쓴다 [가상: 설계서 5.13, 2026-10-05 결정].

| 공구 | 사용량 단위 | 부품 1개당 사용량 [가상] | 수명 한도 | 품목 번호 [가상] |
|---|---|---|---|---|
| M6 탭 (T05) | 구멍 수 (HOLES) | 4구멍 | 400구멍 (약 부품 100개) [참고] | TL-TAP6 |
| 드릴 Ø5.0 (M6 아랫구멍) (T04) | 구멍 수 | 4구멍 | 1,000구멍 (약 부품 250개) [가상] | TL-DR50 |
| 보링바 인서트 (Ø45 H7) (T03) | 구멍 수 | 1구멍 | 400구멍 (약 부품 400개) [가상] | TL-BB45 |
| 엔드밀 Ø10 (T02) | 이송 시간 (FEED, 분) | 2.5분 | 200분 (약 부품 80개) [참고] | TL-EM10 |
| 페이스밀 인서트 (T01) | 이송 시간 | 0.5분 | 400분 (약 부품 800개) [가상] | TL-FM50 |

- 공구 번호 T01~T05는 [가상]이다 (설계서 5.13). VF2-01·02가 같은 번호를 쓴다.

- 남은 수명 % = 1 − (누적 사용량 ÷ 한도). Haas ATM의 LIFE(잔여 수명 비율)와 같은 뜻 [실제: PDF 134쪽].

- 우리 라인의 ATM 그룹은 HOLES(구멍 수)나 FEED(이송 시간)로 한도를 정하므로, "사용 계수기"는 그 그룹이 쓰는 칸(HOLES 또는 FEED)의 누적 값이다 [가상: 해석]. 리셋 뒤 TOOL DATA의 LIFE가 100%로 돌아왔는지 본다.
- 참고: 알람 471(공구 **그룹** 수명 한계 도달) 설명에는 "공구 수명 화면에서 사용 횟수를 강조 표시하고 [ORIGIN]을 누름"이라는 다른 방법이 있다 [실제: 같은 알람 목록 471]. 우리 라인은 공구 1개를 바꿀 때 362 방법([0] → [ENTER])을 쓴다.
- 매크로 변수 #8001~#8200을 0으로 하면 해당 공구가 "사용 가능", 1이면 "만료"가 된다 [실제: PDF 136쪽]. 작업자는 쓰지 않는다 [가상].
- **ATM의 WARN 칸을 플랫폼 90% 알림과 맞춘다.** 모든 OP-30 공구 그룹의 WARN을 **10**으로 넣는다 [가상: 값]. 근거: WARN은 "제어장치가 경고 메시지를 보내기 전 그룹에 남아 있는 공구 수명의 최소값"이고, LIFE는 "공구의 잔여 수명 비율"이다 [실제: Haas 매뉴얼 PDF 134쪽, 영문 2025판 PDF 190쪽]. 플랫폼의 "공구 수명 90%"는 사용률이므로 남은 수명 10%와 같다 (DOC-07 9장). 그러면 제어기 화면의 **공구 수명(경고) 아이콘**과 플랫폼 교체 알림이 같은 때 뜬다 [실제: 아이콘 뜻 "남은 공구 수명이 설정 240 아래에 있거나 현재 공구가 해당 공구 그룹의 마지막 공구", PDF 111쪽].
- 설정 240(공구 수명 경고)은 매뉴얼 두 곳의 설명이 다르다. 아이콘 표(PDF 111쪽)는 "남은 공구 수명이 설정 240 아래", 설정 설명(PDF 446쪽, 영문 2025판 PDF 529쪽)은 "공구 마모가 한계 비율에 도달하면"이다 [실제]. 그래서 우리 라인은 그룹별 WARN 칸으로 맞추고, 설정 240은 바꾸지 않는다 [가상].
