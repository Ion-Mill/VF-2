> 확인 방법과 결과: `구현_중_수정사항/1025_수정간단내용.md` 66장, `1026_수정간단내용.md` 1장.

발표 직전 확인 (서버 `~/VF-2/11_automotive/deploy`에서, 2~5분):

```bash

```

질문마다 그 시각의 정답(공용 DB)을 다시 뽑아 이브 답과 비교한다. "맞음"인 질문만 쓴다. "사람이 봄"은 숫자로 가릴 수 없는 질문(OEE·문서)이라 답을 눈으로 본다.

## 3. 말투

| 이렇게 묻는다 | 피한다 (아직 틀리거나 되묻는다 — 발표 뒤 고칠 것) |
|---|---|
| "**지금** ~", "**직전 교대** ~", "**최근 7일** ~" | "**10월 24일** ~"처럼 날짜를 콕 집기 → 하루가 아니라 어제나 10월 전체로 조회한다 |
| 설비 이름(**VF2-02**)이나 알람 번호(**2075**)를 넣기 | 조건 없이 "어제 알람 몇 건이야?", "예방 정비 기한 넘긴 거 있어?" → 설비·번호를 되묻는다 |
| 한 질문에 하나만 묻기 | "정비 기한 다가오는 거 있어?" → 넘긴 것만 본다 |
| | "진행 중인 작업지시 있어?" → 완료된 것까지 진행 중처럼 나열한다 |
| | "재고 부족한 거 다 알려줘" → 부족 개수가 화면과 다르다 (화면은 안전 재고와 같은 것까지 부족) |

평가자에게 직접 물어보게 할 때는 2장의 질문을 예시로 보여 주고 "이런 식으로(지금·최근 7일·설비 이름) 물어보세요"라고 안내한다.

## 4. 주의

- **발표 중에는 서버에서 `./mom.sh up`·`./mom.sh update`를 하지 않는다.** 시연 서버가 다시 켜지면서 공용 DB가 시연 기준점으로 되돌아간다. 이브만 바꿀 때는 `docker compose up -d --build assistant` (`배포_안내.md` 4장).
- 질문할 때마다 외부 Claude 요금이 조금 들고, 질문·답이 공용 DB 채팅 기록(`chat_log`)에 남는다.
- 시연 시계는 오늘 15:00 전까지 15:00 상태에서 멈춰 있다 (최종용 설계 — `배포_안내.md` 9장). 그 전에는 값이 바뀌지 않는다.
- 발표 뒤에 고칠 것: 날짜를 콕 집는 말투 읽기, 조건이 빈 질문에 되묻지 않고 전체로 답하기, 정비 기한 다가오는 것, 진행 중 작업지시 거르기, 재고 부족 개수, 날짜 없는 OEE 안내 문장("9월 한 달"), 백엔드 알람 조회가 1건을 두 번 세는 것.
