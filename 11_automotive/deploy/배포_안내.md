# 서버 배포 안내 (AWS 리눅스 + 도커)

> 2026-10-24 작성. 평가자·팀이 접속하는 서버 한 대를 도커로 켠다. 아직 서버에서 해 본 적이 없는 **초안**이다 (오늘 밤 DB 담당과 시험하며 고친다).

## 1. 구성

| 컨테이너 | 하는 일 | 바깥에 열림 |
|---|---|---|
| `caddy` | HTTPS(자동 인증서) + 접속 비밀번호, 주소별로 나눠 줌 | **80·443만** |
| `web` | 화면 (Next.js, 3000) | 아니오 |
| `sim` | 시연 데이터 서버 (8765) — 실시간 세계 하나 | 아니오 |
| `backend` | 백엔드 (FastAPI, 8000) — 공용 DB(Supabase) 연결 | 아니오 |
| `assistant` | AI 비서 (8100) — 외부 LLM, 마이크 | 아니오 |

주소 나눔(`Caddyfile`): `/api/*` → sim, `/mom-api/*` → backend, 그 밖 → web. 브라우저는 한 주소만 부르므로 CORS 문제가 없고, 마이크(HTTPS 필요)도 된다.

## 2. AWS 준비 (한 번)

### 2-0. 무료 요금제로 할 때 (2026-10-25)

AWS 계정을 **2025-07-15 이후에 만들었는지** 먼저 본다 (콘솔 오른쪽 위 계정 → Billing → Free Tier).

| 계정 | 무료로 쓸 수 있는 것 | 이 프로젝트 |
|---|---|---|
| 2025-07-15 이후 (Free plan, 크레딧 $100 + 활동하면 최대 $100 더, 6개월) | `t3.micro`·`t3.small`·`t4g.*`·`c7i-flex.large`·**`m7i-flex.large`(2 vCPU·8GB)**. 크레딧을 다 쓰면 요금이 나가지 않고 계정이 멈춘다 | **`m7i-flex.large`로 된다** — 아래 값대로 |
| 그 전 (옛 12개월 무료) | `t2.micro`·`t3.micro`(1GB)만 | **안 된다** (컨테이너 5개 + 화면 빌드에 1GB는 모자람). 며칠만 `t3.large`(8GB)를 쓰면 몇 달러 |

무료 계정에서 바꿀 값 (아래 1~3 대신):

| 항목 | 값 | 이유 |
|---|---|---|
| 인스턴스 | **`m7i-flex.large`** (서울 리전에서 "Free tier eligible" 필터로 확인) | 무료 목록에서 메모리가 가장 큼(8GB). `xlarge` 이상은 무료 계정에서 고를 수 없다 |
| 디스크 | **30GB gp3** | 무료 한도. 이미지 4개 + 음성 모델 1.6GB + 스왑 4GB를 넣어도 남는다 |
| 스왑 4GB | 서버에 처음 들어가서 한 번: `sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile && echo '/swapfile none swap sw 0 0' \| sudo tee -a /etc/fstab` | 처음 `./mom.sh up` 때 이미지 4개를 한꺼번에 만들며(화면 빌드 포함) 메모리가 잠깐 몰린다 |
| 빌드 뒤 정리 | `docker builder prune -f` | 빌드 캐시가 디스크를 차지한다 |
| 마이크 | 그대로 시험 → 말한 뒤 글자가 늦거나 `VOICE_TIMEOUT`이 나면 `assistant.env`에 `VOICE_MODEL=small` | 2 vCPU라 `large-v3-turbo`가 느릴 수 있다. `small`은 더 빠르고 가볍지만 한국어 정확도가 조금 떨어진다 |
| 고정 IP | Elastic IP를 붙인다 (켜 둔 동안 시간당 약 $0.005, 크레딧에서 나감) | 끄고 다시 켜도 주소가 안 바뀌어 DuckDNS를 다시 고치지 않아도 된다 |
| 크레딧 쓰는 양 | `m7i-flex.large`가 시간당 약 $0.1 → 하루 약 $2~3, 일주일 약 $20 (+ 디스크·IP 몇 달러) | 발표가 끝나면 **인스턴스를 끄거나(Stop) 지운다(Terminate)**. 끈 동안에도 디스크·Elastic IP는 조금씩 나간다 |

그 밖에는 모두 무료다: Supabase(무료 프로젝트 `mom-db`), DuckDNS, HTTPS 인증서(Let's Encrypt). **AI 비서의 외부 LLM(Claude) 요금은 AWS와 따로** `assistant.env`의 API 키 계정으로 나간다.

### 2-1. 준비 순서

1. **EC2**: Ubuntu 24.04, `t3.xlarge`(4 vCPU·16GB), 디스크 80GB(gp3). 발표 며칠만 켜 둔다. **무료 계정이면 2-0의 `m7i-flex.large`·30GB·스왑 4GB.**
2. **고정 IP(Elastic IP)** 를 붙인다.
3. **보안 그룹**: 80·443은 모두에게, **22(SSH)는 내 IP만**. 다른 포트는 열지 않는다.
4. **도메인**: [duckdns.org](https://www.duckdns.org)에서 이름을 하나 만들고 그 IP를 서버의 고정 IP로 한다 (예: `my-mom.duckdns.org`).
5. 서버에 도커 설치: `sudo apt-get update && sudo apt-get install -y docker.io docker-compose-v2 git && sudo usermod -aG docker $USER` (다시 접속).


## 4. 비밀 값 넣기 (서버에서 직접, 저장소에 올리지 않음)

```bash
cp .env.example .env                       # DOMAIN, BASIC_USER, BASIC_HASH, GATE_TOKEN, MOM_PROFILE, MOM_PRESENTER_KEY, MOM_INGEST_KEY, MOM_SIM_CONTROL_USERS
cp backend.env.example backend.env         # 키 목록은 ../backend/.env.supabase.example
cp ../assistant/.env.example assistant.env # 팀 기준 스위치 그대로 두고 비밀 값만 채운다 (아래 assistant.env 설명)
nano .env backend.env assistant.env
```

- `BASIC_HASH`: `docker run --rm caddy:2 caddy hash-password --plaintext '정한비밀번호'` 결과에서 `$`마다 `$$`로 바꿔 넣는다.
- `GATE_TOKEN` (2026-10-25): `openssl rand -hex 24`로 만든 무작위 값. 접속 비밀번호를 한 번 맞히면 이 값을 쿠키(`mom_gate`, 7일)로 줘서 그 뒤로는 다시 묻지 않는다. 화면이 백엔드를 부를 때 `Authorization` 머리글에 로그인 토큰을 넣기 때문에, 비밀번호만 쓰면 화면을 옮길 때마다 다시 묻고 백엔드 호출이 막힌다. 값을 바꾸면 모두 비밀번호를 다시 넣는다.
- `backend.env`는 `MOM_DATABASE_URL`·`MOM_READONLY_DATABASE_URL`(Supabase **Session pooler 5432**, 6543은 실시간 알림이 안 됨), `MOM_JWT_SECRET`, `MOM_RUN_WORKERS=false`, `MOM_DEMO_MODE=false`, `MOM_CORS_ORIGINS=https://<도메인>`, `MOM_ASSISTANT_KEY`(assistant.env와 같은 값)가 있어야 한다.
- **시연 서버 ↔ 백엔드 연결 (2026-10-25)**: 화면은 백엔드 → DB를 읽는다. 그래서 compose가 백엔드에 `MOM_SIM_URL=http://sim:8765`·`MOM_SIM_SYNC=true`를, 시연 서버에 `MOM_DB_RELAY_URL=http://backend:8000`을 넣고, 둘이 같아야 하는 `MOM_INGEST_KEY`·`MOM_PRESENTER_KEY`·`MOM_SIM_CONTROL_USERS`는 `.env` 한 곳에서 받는다 (`backend.env`에 적어도 무시됨).
  - 시연 서버는 백엔드가 건강 확인(`/api/health`, DB 접속 포함)을 통과한 뒤 켜진다. DB 접속 값이 틀리면 시연 서버도 안 켜지니 `./mom.sh logs backend`부터 본다.
  - **켤 때마다 공용 DB(`mom-db`)가 시연 기준점으로 되돌아간 뒤 지금 시각까지 따라잡는다** ("DB 1개 = 공장 1개"). 같은 DB에 다른 사람이 중계를 켜 두면 기록이 겹친다.
  - `MOM_SIM_CONTROL_USERS`를 비우면 로그인한 누구나 [처음으로]로 모두의 기록을 되돌릴 수 있다 — 발표자 계정만 넣는다 (예: `U12`).
- **`assistant.env` (2026-10-25)**: `../assistant/.env.example`을 복사해 **비밀 값만** 넣는다. 내 PC의 `assistant/.env`를 그대로 올리지 않는다 — 오래된 파일은 팀이 켜 둔 스위치(`SENSOR_LIVE`·`PURE_RULE_WIDE`·`CTX_NARROW`·`FOLLOWUP` 등 20여 개)가 빠져 기본값(대부분 꺼짐)으로 돌고, 이브가 시연 서버의 지금 값을 읽지 못했다(서버에서 확인).
  - 넣을 값: `MOM_ASSISTANT_KEY`(backend.env와 같은 값), `ANTHROPIC_API_KEY`. `MOM_BACKEND_URL`·`SIM_SERVER_URL`은 compose가 서버 안쪽 주소로 바꿔 넣으니 예시 값 그대로 둔다. 마이크는 예시대로 `ASSISTANT_VOICE=1`.
  - **서버(최종용)는 `DOCS_SOURCE=db`로 바꾼다** (예시 파일 기본값은 `files`): `sed -i 's/^DOCS_SOURCE=.*/DOCS_SOURCE=db/' assistant.env`. 이브가 켜질 때 백엔드의 읽기 전용 `GET /api/assistant/docs`로 공용 DB의 현행 개정 사내 문서를 받는다(운영 데이터와 사내 문서 모두 공용 Supabase). DB를 못 읽으면 이미지 안 `가상사내문서/` 파일로 돌아간다(내용은 같다). `DOCS_BACKEND_URL`은 비워 둔다(서버 백엔드가 이미 공용 DB를 본다).
  - 확인: `docker compose exec assistant printenv SENSOR_LIVE PURE_TOPK FOLLOWUP DOCS_SOURCE` → `1`·`30`·`1`·`db`. 문서 출처는 `docker compose exec -T assistant python -c "import os,json,urllib.request as u; r=u.Request('http://127.0.0.1:8100/health',headers={'X-Service-Key':os.environ['MOM_ASSISTANT_KEY']}); print(json.dumps(json.load(u.urlopen(r))['corpus'],ensure_ascii=False))"` → `"source": "db"`, `"via": "main_backend"`, 조각 195, 개정 8개, `fallback` 없음 (2026-10-25 서버에서 확인).
  - **이 파일만 바꿨으면 `docker compose up -d assistant`로 비서만 다시 켠다.** 시연 서버도 이 파일(`MOM_ASSISTANT_KEY`)을 읽어서 `./mom.sh up`을 하면 시연 서버까지 다시 켜지고 공용 DB가 기준점으로 되돌아간다.
  - `STEP_LOG=1`의 기본 폴더(`C:\llm\logs`)는 리눅스에서 컨테이너 안 `/srv/assistant/C:\llm\logs/`라는 이름의 폴더가 된다(비서를 다시 만들면 사라짐). 질문이 어느 길로 갔는지 볼 때 쓴다.

## 5. 켜기·끄기

```bash
./mom.sh up          # 이미지를 만들고 켠다 (처음 5~10분)
./mom.sh status      # 5개가 Up 인지
./mom.sh health      # 시연 서버의 프로필·시연 시각
./mom.sh logs sim    # 로그 (서비스 이름: caddy web sim backend assistant)
./mom.sh down        # 끈다
```

브라우저에서 `https://<도메인>` → 아이디·비밀번호 → 화면. 처음 접속 때 인증서를 받느라 몇 초 걸린다.

## 6. 바꿀 때·되돌릴 때

```bash
./mom.sh update              # git pull 하고 다시 켠다 (직전 주소를 .prev_ref에 남김)
./mom.sh rollback            # 직전으로. 또는 ./mom.sh rollback <커밋 또는 태그>
```

- 공용 DB는 서버 코드를 바꿔도 안 바뀐다. DB를 바꾸는 일은 DB 담당이 따로 한다 (되돌릴 곳: 교체 전 `pg_dump` 백업).

## 7. 마이크 시험

처음 한 번 마이크를 쓰면 음성 모델(약 1.6GB)을 내려받는다 — **발표 전에 한 번 써서 받아 둔다**. 무료 계정(2 vCPU)에서 느리면 2-0의 `VOICE_MODEL=small`. `docker volume`(`mom_whisper_models`)에 남는다. 안 되면 글로 묻는다 (마이크는 한두 번 보여 주는 용도).

## 8. 서버가 안 열릴 때 (비상)

1. 먼저 `./mom.sh status`, `./mom.sh logs caddy`. 인증서가 안 나오면 도메인 IP·80/443 열림을 확인.
2. 그래도 안 되면 **내 노트북 + Cloudflare 터널**로 같은 화면을 열고 그 주소를 알려 준다 (노트북에서 평소처럼 서버를 켜고 `cloudflared tunnel --url http://localhost:3000`).

## 8-2. 새 통합본이 안 될 때: 비상용으로 (2026-10-24)

| 태그 | 내용 | 서버에 올릴 수 있나 |
|---|---|---|
| `emergency-1024` | 프로필 도입 **전** 원본 코드 (9월 기록 + 10/1 시연, 교대 08~17 / 20~05) | 아니오 (`deploy/`가 아직 없던 시점) |
| **`emergency-1024-deploy`** | 위 코드 + 이 `deploy/` (프로필 없는 옛 `generate.py`·시연 서버에 맞게 최소 수정) | **예** |

```bash
cd <저장소>/11_automotive/deploy
./mom.sh down
git fetch --tags && git checkout emergency-1024-deploy
cd 11_automotive/deploy && ./mom.sh up          # .env·backend.env·assistant.env는 그대로 쓴다 (MOM_PROFILE은 무시됨)
```

- 비상용에는 **프로필·최종용 실제 시각 시계·처음으로 발표자 키·오전 충돌 문서가 없다.** 화면은 10/1 08:00(9월 끝) 시연 방식이고, 새 사내 문서·데이터와 시각이 맞지 않는다. 그래도 프로필 설정 없이 확실히 켜지던 마지막 버전이다.
- 새 통합본으로 다시 가려면 `git checkout main && git pull` 뒤 `./mom.sh up`.
- 이 비상용 묶음은 옛 코드로 시연 서버 이미지를 만들고 띄워 응답(10/1 08:03)하는 것까지 이 PC에서 확인했다. 백엔드·비서·화면 이미지는 새 통합본과 같은 방식이라 서버에서 확인한다.

## 9. 최종용 시계 (G7, 2026-10-24 구현)

- `MOM_PROFILE=final`이면 시연 서버가 **미리 짠 10/26 오전 사건으로 15:00 상태를 만들고**, 지금 실제 시각까지 따라잡은 뒤 **실제 시각(배속 1)** 으로 흐른다. 시계·사건 버튼은 잠긴다 (403).
- **발표자 전용 조작은 하나** (`.env`의 `MOM_PRESENTER_KEY`가 있고, 요청에 머리글 `X-Presenter-Key`로 같은 값을 보낼 때만). 사건 버튼과 사건 복귀는 최종용에 없다(403).
  - `POST /api/sim/reset` — **처음으로**: 사람이 한 조작을 지우고 시각은 그대로 둔 채 지금까지 다시 따라잡는다. 회차 번호가 바뀌어 브라우저의 작업지시서 등 저장분이 새로 시작된다.
- **서버를 다시 켜도 같은 세계**: 평가자·발표자가 한 사람 조작(공구 교체, 작업기록 확정, 로트 보류·해제)은 `sim_live` 볼륨의 파일에 남고, 다시 켜면 같은 시각에 그대로 다시 한다. (보고서 확정·작업지시서 같은 화면 쪽 기록은 서버 메모리라 재시작하면 사라진다 — 공용 DB 중계가 켜진 뒤에는 DB에 남는다.)
- **발표 직전에 시험 흔적 지우기**: 팀이 서버를 시험하며 한 사람 조작(공구 교체·확정·보류 해제)은 서버에 남고 브라우저의 작업지시서 등은 **같은 회차 번호로 브라우저에 남는다**. 발표 전에 `처음으로`(발표자 키)를 한 번 부르거나(회차 번호가 바뀌어 모든 브라우저가 새로 시작) 서버를 끄고 `docker volume rm mom_sim_live` 뒤에 켠다. 시험 때 쓴 PC의 브라우저는 저장 데이터를 지우거나 새 창(시크릿)으로 연다.
- 리허설: `.env`에 `MOM_PRETEND_NOW=2026-10-26T17:00` 처럼 넣으면 그 시각부터 흐른다. 발표 전에 **반드시 지운다**.
- 시험: `./mom.sh health` 에서 `clock_mode`가 `wall`이고 `sim_at`이 지금 시각 가까이인지 본다.

## 10. 점검 도구

- `frontend/tools/smoke_server.py [포트]` — 시연 서버의 읽기 길 28개를 한 번씩 불러 500 오류가 없는지 본다 (켜 놓은 채로 어느 프로필이든, 시연 중에도 괜찮다).
