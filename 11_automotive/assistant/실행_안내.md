# 팀원별 환경에서 프로젝트 켜는 법 (2026-10-16)

> 읽는 사람: `semi-ai` 저장소를 처음 받은 팀원. 명령은 모두 **Windows PowerShell** 기준이다.
> 이 문서는 특정 PC의 절대 경로·Python 실행 파일·포트를 강제하지 않는다. 먼저 자신의 환경을 확인하고, 아래의 검증된 기준과 비교한 뒤 각자 경로·포트를 설정한다.
> 현재 외부 Claude 기능은 `anthropic` Python 패키지나 API 키 방식이 아니라 **Claude Code CLI(`claude`)와 구독 로그인**으로 실행된다.

## 결론 — 준비를 마친 사람이 바로 켜는 법 (2026-10-18)

`.venv`·설정 파일이 아직 없거나 처음 받았다면 이 절이 아니라 **0절과 4절(준비)** 부터 한다. 준비가 끝났다면 아래가 전부다. 명령의 `<자신의-semi-ai-폴더>`와 포트는 각자 값으로 바꾸고(기본 8020·8100·8765·3000), 꺾쇠괄호가 남은 명령은 실행하지 않는다.

### ① 켜기 전에 한 번 — 최신 코드와 비서 설정 한 줄

1. 저장소를 최신으로 받는다 (`git pull`).
2. 자신의 `assistant\.env`에 **`PURE_EXPAND=1`·`PURE_SAFETY=1`·`PURE_PERIOD=1`·`PURE_RULE=1` 줄**이 있는지 본다. 없으면 메모장으로 한 줄 더한다 (값 옆에 `# 설명`을 붙이지 않는다). `.env`는 사람마다 따로라서 코드를 받아도 이 줄이 저절로 생기지 않고, 줄이 없으면 비서가 안전 질문에 "작업 전 잠금 순서(6.1~6.6)·톱 차단 지점은 문서에 없다"고 틀리게 답하던 안전 결함(2026-10-18 수정, 8-2절)이 그대로 남고, `PURE_PERIOD=1`이 없으면 "한 달에 한 번 하는 정비"처럼 기간을 현장 말로 물을 때 예방 정비 기준서의 기간 표를 놓쳐 "문서에 없다"고 답하던 결함(2026-10-18 수정)이 남고, `PURE_RULE=1`이 없으면 "소모품 재고는 누가 관리해?"처럼 로트·재고 낱말이 든 규칙 질문이 문서 답 대신 운영 조회 결과를 받는 결함(2026-10-18 수정)이 남는다.

```powershell
Set-Location <자신의-semi-ai-폴더>
Select-String -Path .\11_automotive\assistant\.env -Pattern '^(PURE_EXTERNAL|PURE_EXPAND|PURE_SAFETY|PURE_PERIOD|PURE_RULE)='   # 다섯 줄이 보여야 한다 (이 줄들만 보여 주므로 비밀값은 안 나온다)
notepad .\11_automotive\assistant\.env                                                          # PURE_EXPAND=1·PURE_SAFETY=1·PURE_PERIOD=1·PURE_RULE=1 이 없을 때만 열어서 줄 추가
```

`PURE_EXTERNAL=1`이 아니면(예시 파일 기본은 `0`) 새 문서 질문 길 자체가 꺼져 있어 이 줄은 아무 일도 하지 않는다 (8-2절).

### ② 켜기 — 스크립트 (권장)

```powershell
Set-Location <자신의-semi-ai-폴더>
.\11_automotive\assistant\start_all.ps1 -DryRun     # 먼저 무엇을 할지만 본다 (설정 점검 포함, 아무것도 켜지 않는다)
.\11_automotive\assistant\start_all.ps1             # 백엔드(8020) + 비서(8100)
```

화면까지 보려면 `-Screen`을 붙인다 (시연 서버 8765 + 화면 3000). **보고서·작업지시서·지침카드 문장 기능(6-3절)** 을 켜려면 같은 창에서 스위치를 먼저 켠다 — 스크립트가 켜는 시연 서버가 현재 창의 환경변수를 그대로 물려받는다.

```powershell
$env:MOM_LLM_COMPOSE = '1'
.\11_automotive\assistant\start_all.ps1 -Screen
```

**이미 켜진 서버는 건드리지 않는다.** 코드를 받았거나 `.env`·스위치를 바꿨다면 먼저 끄고(③) 다시 켠다. 스크립트가 알아서 확인해 주지 않는다 (5-0절 "한계").

### ② 켜기 — 터미널로 하나씩 (스크립트를 쓰지 않을 때)

```powershell
# 터미널 1 — 비서 (8100)
Set-Location <자신의-semi-ai-폴더>\11_automotive\assistant
.\.venv\Scripts\python.exe -m uvicorn backend.chat_service:app --host 127.0.0.1 --port <ASSISTANT_PORT>

# 터미널 2 — 시연 서버 (8765). 문장 기능을 안 볼 거면 두 번째 줄(스위치)을 뺀다
Set-Location <자신의-semi-ai-폴더>\11_automotive\frontend
$env:MOM_LLM_COMPOSE = '1'
..\생성기\.venv\Scripts\python.exe tools\sim_server.py

# 터미널 3 — 화면 (3000). 브라우저에서 http://localhost:3000
Set-Location <자신의-semi-ai-폴더>\11_automotive\frontend
npm run dev

# 터미널 4 — 백엔드 (8020). 이브 채팅 탭을 새 비서에 이을 때만 (공용 DB에 붙는다)
Set-Location <자신의-semi-ai-폴더>\11_automotive\backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --env-file .env.supabase --port <BACKEND_PORT>
```

문장 기능만 볼 때는 터미널 4(백엔드)가 필요 없다. 자세한 설명은 5-2·5-3절(백엔드·비서), 6절(화면·시연 서버), 6-3절(문장 기능).

### 켜졌는지 확인

- **시연 서버:** `Invoke-RestMethod http://127.0.0.1:8765/api/health` → 결과의 `llm_compose` 칸에 `enabled: True`가 보이면 문장 기능이 켜진 것이다. 이 칸이 없으면 예전 코드로 떠 있는 것이니 다시 시작한다.
- **비서에 직접 물어 보기 (고친 결함 확인):** 아래를 그대로 붙여 넣는다. 백엔드를 거치지 않으므로 공용 DB에 질문 기록이 남지 않는다. 외부 Claude가 켜져 있으면 이 질문과 문서 조각이 외부로 한 번 나간다 (지금은 가상 데이터만).

```powershell
Set-Location <자신의-semi-ai-폴더>
$key = (Select-String -Path .\11_automotive\assistant\.env -Pattern '^MOM_ASSISTANT_KEY=').Line.Split('=',2)[1]
$body = @{ question = '잠금·표지·순서'; user = @{ user_id = 'U01'; role_code = 'OPR' } } | ConvertTo-Json -Depth 3
$res = Invoke-WebRequest http://127.0.0.1:<ASSISTANT_PORT>/chat -Method Post -Headers @{ 'X-Service-Key' = $key } -ContentType 'application/json; charset=utf-8' -Body ([Text.Encoding]::UTF8.GetBytes($body)) -UseBasicParsing
$r = [Text.Encoding]::UTF8.GetString($res.RawContentStream.ToArray()) | ConvertFrom-Json
"출처: " + (($r.sources | ForEach-Object { $_.section }) -join ', ')
$r.answer
```

  **정상:** 출처에 `2.1`이 있고, 답의 "작업 전 6단계"에 6.1~6.6이 나온다. **이상:** "작업 전에 잠그는 단계(6.1~6.6)는 문서에 없어요"라고 하면 위 ①의 `.env` 줄이 없거나, 줄을 넣은 뒤 비서를 다시 시작하지 않았거나, 옛 코드로 떠 있는 것이다. (`Invoke-RestMethod`가 아니라 `Invoke-WebRequest`를 쓰는 까닭: Windows PowerShell 5.1의 `Invoke-RestMethod`는 서버가 글자 인코딩을 알려 주지 않으면 한글을 깨뜨린다.)
- "시험·조정 때문에 잠깐 전원을 넣을 때"의 5단계도 이제 나온다 (2026-10-18에 DOC-05 §2.2 그 표에 "우리 라인에서 할 일 [가상]" 칸을 더했다 — 원문 칸만 있던 표라 팀 규칙 D-03 때문에 비서가 못 읽었다). 문서를 `git pull`로 받은 뒤 비서를 다시 켜야 반영된다.
- 같은 방법으로 "톱 정비 전에 어디를 차단해야 해?"를 물으면 출처에 `3.1`이 있고 차단 지점 두 곳(SAW-01-E1 주 차단기, SAW-01-E2 공급 분전반 차단기)이 나온다. "문서에서 찾지 못했어요"가 나오면 위 ①의 `PURE_SAFETY=1` 줄이 없거나 비서를 다시 켜지 않은 것이다.

### ③ 끄기

```powershell
.\11_automotive\assistant\stop_all.ps1      # start_all.ps1이 켠 것만 끈다
```

터미널로 켰다면 각 터미널에서 `Ctrl+C`. 창을 닫아 남았으면 7절대로 포트를 확인하고 끈다. **8000·8010은 다른 프로젝트의 서버라 끄지 않는다.**

### 꼭 지킬 것

- **시연 서버를 하나 더(다른 포트로) 띄우지 않는다.** 시작할 때 `생성기\out_realtime\cmm_drop`을 비워서, 쓰던 서버가 만든 파일이 사라진다.
- **코드나 `.env`를 바꾼 뒤에는 비서와 시연 서버를 다시 시작한다.** 켜진 채로는 반영되지 않는다.
- **공용 DB를 지킨다.** 시연 모드(`MOM_DEMO_MODE`)와 스케줄러(`MOM_RUN_WORKERS`)는 켜지 않는다 (`start_all.ps1`이 막는다, 9절).
- 보고서 문장은 교대가 끝난 뒤 몇 초 지나야 바뀐다 (6-3절).

**이 절에서 확인한 것 (2026-10-18):** `start_all.ps1 -DryRun`(설정 점검 OK), 비서에 직접 묻는 명령(PowerShell 7.6과 Windows PowerShell 5.1 모두에서 출처 `2.1` 포함·작업 전 6단계 정상 확인), `$env:` 값이 자식 프로세스에 물려지는 원리. **확인하지 못한 것:** `-Screen`과 `$env:MOM_LLM_COMPOSE`를 함께 써서 시연 서버를 새로 켜 보는 것 (시연 서버를 하나 더 띄우면 안 되어 해 보지 않았다 — 처음 켜는 사람이 확인해 달라). 터미널 4개 방법은 5-2·5-3·6·6-3절의 기존 명령을 한곳에 모은 것이다.

## 3. 기본 포트와 변경 방법

| 포트 | 무엇 | 비고 |
|---|---|---|
| 3000 | 화면 (`next dev`) | 팀 |
| 8765 | 시연 서버 `sim_server.py` | 팀 — 화면이 `/api/*`를 여기로 넘긴다 (`frontend/next.config.mjs`) |
| **8020** | **새 백엔드** (`app.main:app`) | 이 문서의 길. 8000이 아니라 8020인 까닭은 아래 |
| **8100** | **비서 서비스** (`backend.chat_service:app`) | 밖에 열지 않는다 (127.0.0.1) |
| 8000, 8010 | **내 원본 프로젝트의 옛 모의 서버** (`backend.app:app`) | 이 프로젝트가 아니다. 켜져 있으면 끄지 않는다 |

위 포트는 이 문서의 기본 예시다. 사용 중인 포트가 있으면 비서와 백엔드 포트를 각각 다른 번호로 정하고, 아래 세 곳의 주소를 일관되게 바꾼다.

1. 백엔드 실행 명령의 `--port`
2. `assistant/.env`의 `MOM_BACKEND_URL`
3. `backend/.env.supabase`의 `MOM_ASSISTANT_URL`
4. 선택 사항인 `assistant/.env.e2e`의 `MOM_E2E_BACKEND`

예를 들어 백엔드를 `8021`, 비서를 `8101`로 쓰면 다음처럼 맞춘다.

```text
MOM_BACKEND_URL=http://127.0.0.1:8021
MOM_ASSISTANT_URL=http://127.0.0.1:8101
MOM_E2E_BACKEND=http://127.0.0.1:8021
```

팀 문서의 `npm run dev`는 별도의 기본 개발 경로(백엔드 8000 + 화면)를 사용한다. 이 문서의 새 비서 연결을 확인할 때는 아래 5절의 백엔드(8020 예시)와 비서(8100 예시)를 사용한다.

### 4-2. 설정 파일 세 개 (모두 git에 안 올라간다)
비밀번호와 키는 **파일에만** 적는다. 채팅·메신저에 붙여 넣지 않는다.

파일이 없을 때만 예시 파일을 복사한다. 이미 개인 설정 파일이 있으면 덮어쓰지 않는다.

```powershell
Set-Location <자신의-semi-ai-폴더>
if (-not (Test-Path .\11_automotive\backend\.env.supabase)) { Copy-Item .\11_automotive\backend\.env.supabase.example .\11_automotive\backend\.env.supabase }
if (-not (Test-Path .\11_automotive\assistant\.env)) { Copy-Item .\11_automotive\assistant\.env.example .\11_automotive\assistant\.env }
```

| 파일 | 만드는 법 | 채울 것 |
|---|---|---|
| `backend/.env.supabase` | `.env.supabase.example`을 복사 | DB 비밀번호는 **DB 담당에게 개인적으로** 받는다. `MOM_JWT_SECRET`, `MOM_INGEST_KEY`, `MOM_ASSISTANT_KEY`는 각자 새로 만든다. `MOM_DEMO_MODE=false`, `MOM_RUN_WORKERS=false`, `MOM_ASSISTANT_URL`은 자신의 비서 주소로 설정 |
| `assistant/.env` | `.env.example`을 복사 | `MOM_ASSISTANT_KEY`를 백엔드 파일과 **같은 값**으로 설정하고, `MOM_BACKEND_URL`을 자신의 백엔드 주소로 설정. 외부 Claude를 쓰지 않을 때는 예시 기본값을 유지 |
| `assistant/.env.e2e` | 새로 만든다 (예시 파일 없음) | 아래 두 줄. 끝에서 끝 확인(5-5)을 할 때만 필요하다 |

```
MOM_E2E_LOGIN_PASSWORD=시연 비밀번호(DB 담당에게)
MOM_E2E_BACKEND=http://127.0.0.1:8020
```

무작위 글자 만들기 (한 줄씩 실행하고 출력값을 해당 `.env`에 붙여 넣는다):
```powershell
.\11_automotive\assistant\.venv\Scripts\python.exe -c "import secrets; print(secrets.token_urlsafe(32))"
```

`MOM_ASSISTANT_KEY`는 백엔드와 비서 설정에 같은 값을 넣고, `MOM_JWT_SECRET`·`MOM_INGEST_KEY`는 백엔드 설정에 각각 다른 값을 넣는다. DB 비밀번호·서비스 키·JWT 키를 문서, Git, 메신저에 기록하지 않는다.

설정 파일은 메모장 등으로 열어 채운다.

```powershell
notepad .\11_automotive\backend\.env.supabase
notepad .\11_automotive\assistant\.env
```

**`.env`에서 지킬 것 두 가지**
- 값 **옆에** `# 설명`을 붙이지 않는다. 설명까지 값으로 읽혀서 `EXTERNAL_LLM_APP=1   # …`는 조용히 꺼진 채로 남는다. 설명은 윗줄에 쓴다. (시험 `test_env_example.py`가 예시 파일을 지킨다.)
- 비밀번호에 `@ : / ? # %`가 있으면 주소 안에서 `%40`처럼 바꿔 쓴다. `MOM_DATABASE_URL`·`MOM_READONLY_DATABASE_URL`은 끝이 `?sslmode=require`로 **한 번만** 끝나야 한다 (`??`가 되면 접속 실패).

### 4-3. 외부 Claude를 사용할 때만 추가 준비

외부 Claude를 사용하지 않는 팀원은 이 절을 건너뛰고 5절의 연결 확인부터 진행한다. 기본 설정은 외부 전송이 꺼져 있다.

현재 구현은 `ANTHROPIC_API_KEY`를 읽어 호출하는 방식이 아니라 `claude -p`를 실행하는 방식이다. 따라서 각자 PC에서 Claude Code CLI를 공식 설치 방법으로 설치하고, 자신의 계정으로 로그인한다.

```powershell
claude --version
claude auth status
```

`claude auth status`가 로그인 상태를 보여 주고 `claude`가 어느 폴더에서나 실행되어야 한다. CLI의 정확한 최소 지원 버전은 아직 확인하지 않았으므로, 각자 확인한 버전과 로그인 결과를 기록한다.

`assistant/.env`에서 아래 값을 설정한다. 값 옆에 설명을 쓰지 않는다.

```text
ASSISTANT_PROVIDER=claude
EXTERNAL_LLM_APP=1
LLM_ENABLED=1
LLM_JOBS=write,route
```

Claude CLI가 PATH에 없으면 실행 파일의 전체 경로를 `MOM_CLAUDE_BIN`에 넣고, 저장소 밖의 빈 작업 폴더를 만들어 `MOM_CLAUDE_CWD`에 넣는다.

```powershell
New-Item -ItemType Directory -Force <자신의-저장소-밖-빈-폴더>
notepad .\11_automotive\assistant\.env
```

`MOM_CLAUDE_CWD`는 각자 PC의 실제 경로로 바꾼다. API 키만 추가하고 CLI 로그인을 생략하면 현재 구현에서는 외부 Claude가 연결되지 않는다. 외부 전송이 승인되지 않은 실제 자료는 사용하지 않는다.

## 5. 켜는 순서 (새 길)

아래 명령의 `<자신의-semi-ai-폴더>`, `<BACKEND_PORT>`, `<ASSISTANT_PORT>`는 복사 전에 각자 값으로 바꾼다. 꺾쇠괄호가 남은 명령은 실행하지 않는다.

터미널을 두 개 쓴다. **공용 DB에 붙으니 팀원이 시연이나 발표를 하지 않는 때에** 한다.

### 5-0. 한 번에 켜고 끄기 (스크립트) — 2026-10-17

아래 5-2·5-3(터미널 둘)을 스크립트 하나로 할 수 있다. **코드를 합친 것이 아니라 켜는 일만 묶은 것**이라 비서는 여전히 별도 서비스(8100)다. 5-1 이후의 수동 방법은 그대로 쓸 수 있다.

```powershell
Set-Location <자신의-semi-ai-폴더>
.\11_automotive\assistant\start_all.ps1        # 백엔드(8020) + 비서(8100)
.\11_automotive\assistant\stop_all.ps1         # 끄기 — 이 스크립트가 켠 것만 끈다
```

| 옵션 | 뜻 |
|---|---|
| `-BackendPort 8021 -AssistantPort 8101` | 포트 바꾸기. 두 서비스가 서로 찾는 주소(`MOM_BACKEND_URL`, `MOM_ASSISTANT_URL`)는 **켜는 프로세스에만** 맞춰 준다 (설정 파일은 안 고친다) |
| `-Screen` | 시연 서버(8765)와 화면(3000)도 켠다. 이미 켜져 있으면 건드리지 않는다. `-ScreenPort`로 화면 포트 변경 (3000이 아니면 백엔드 `MOM_CORS_ORIGINS`에 그 주소가 있어야 한다 — 없으면 경고) |
| `-NewChat` | `-Screen`과 같이. 이브 채팅 탭을 새 비서에 잇는다 — **새로 켜는 화면 프로세스에만** `NEXT_PUBLIC_MOM_API`를 준다. `frontend\.env.local`은 만들지 않는다 |
| `-CheckDb` | 켜기 전에 5-1(DB 접속 점검, 읽기만)을 먼저 한다 |
| `-DryRun` | 아무것도 켜지 않고 무엇을 할지만 보여 준다 (설정 점검은 한다). `stop_all.ps1 -DryRun`도 있다 |

**스크립트가 지키는 것**
- 켜기 전에 설정을 **읽기만** 해서 점검한다: 가상환경 두 개, 설정 파일 두 개, 두 파일의 `MOM_ASSISTANT_KEY`가 같은지, DB 주소의 `<…>`, 그리고 공용 DB를 지키는 **`MOM_RUN_WORKERS=false`**(줄이 없으면 기본값이 true라 스케줄러가 도니 거부)와 `MOM_DEMO_MODE`. 키·비밀번호는 화면에도 로그에도 찍지 않는다.
- **이미 켜진 포트는 끄지도 덮지도 않는다.** 명령줄에 우리 서버 이름(`app.main:app`, `backend.chat_service:app`)이 있고 `health`가 맞으면 그대로 쓰고, 다른 프로그램이면 멈춘다 (예: 옛 모의 서버 8000·8010을 백엔드로 착각하지 않는다).
- 켠 것만 `assistant\.run\pids.json`에 적고 로그도 `assistant\.run\`에 둔다 (git에 안 올라간다). `stop_all.ps1`은 그 pid가 **지금도 그때 켠 프로세스인지**(명령줄 이름과 시작 시각) 확인하고 끈다. 켜다 실패하면 이번에 켠 것을 되돌린다.
- Windows PowerShell 5.1과 PowerShell 7 모두에서 켜기·재사용·끄기를 확인했다.

**한계**
- 이미 켜진 서버는 **코드가 최신인지 확인하지 않는다.** 옛 코드로 돌고 있으면 직접 끄고 다시 켠다.
- `-NewChat`은 새로 켜는 화면에만 적용된다 (환경변수는 화면을 켤 때 읽는다). 이미 켜진 화면에는 `frontend\.env.local` 방법(6-2절)을 쓴다.
- 화면·시연 서버를 **실제로 켜는 것**은 이 PC에서 이미 돌고 있어 해 보지 않았다 (명령 조립과 재사용 판단만 확인). 다른 PC에서 처음 켤 때 `frontend`에서 `npm install`이 되어 있어야 한다.
- 5.1에서 스크립트 출력을 `|`로 넘기거나, 출력을 붙잡는 도구(일부 편집기 작업 등)로 돌리면 켜진 서버가 그 출력을 물려받아 **서버가 떠 있는 동안 명령이 안 끝날 수 있다.** 평범한 터미널에서 그대로 실행하면 문제없다.
- 컨테이너 대신 스크립트로 한 까닭: Claude Code CLI 구독 로그인과 `.venv`가 각자 PC에 있다. 컨테이너 안에서는 로그인을 다시 해야 한다.

### 5-1. 접속 확인 — 데이터는 읽기만 한다 (쓰기 막힘을 확인하는 시도가 들어 있다)

| 무엇 | 어떻게 |
|---|---|

| 보내는 것 | `{question, context:{screen:'SCR-xx', equipment_id}}` + 토큰. 역할은 토큰에서 정해지므로 화면이 `role`·`user_id`를 보내지 않는다 |
| 받는 것 | `answer`·`sources`·`status`. 상태는 화면에서 `답변`·`문서에 없음`·`권한 밖`·`거부`·`응답 없음`으로 보인다 (명세서 AST-02 표기) |
| 실패 | 연결 안 됨·시간 초과(140초)·503·로그인 실패·알 수 없는 상태 모두 **"응답 없음" + 기본 문구**. 옛 규칙 답으로 몰래 바꿔 주지 않는다 (같은 질문에 숫자가 엇갈리는 것을 막는다) |
| 안내 문구 | 켜면 채팅 위 안내가 "외부 LLM(Claude)이 …답합니다. … 질문과 문서 조각이 외부로 전송됩니다(지금은 가상 데이터)"로 바뀐다 — **문구는 팀 검토 대상** |

**한계**
- 옛 규칙 답에 있던 **센서 추세 그래프**와 **"지금 병목"**(시연 서버의 실시간 값)은 새 길에 없다 — 문서 설명으로 답한다. 시연 질문 목록에 있으면 별도 작업.

- 켜진 개발 서버는 파일을 고치면 바로 다시 컴파일한다. `.env.local`은 **브라우저 확인 직전에** 만든다.

4. 오른쪽 위에서 계정을 보전 담당자(U07)로 바꾸고 같은 MTTR 질문 → 값이 나온다.

### 6-3. 문장 기능 켜기 — 보고서·작업지시서·지침카드 (2026-10-18)

비서(외부 Claude)가 프로그램이 만든 **기본 문장을 읽기 쉽게 다듬어** 화면에 바꿔 끼운다. **기본은 꺼짐**이고, 켜지 않으면 화면은 지금과 똑같다. 켜도 실패하면 기본 문장 그대로다 (몰래 다른 길로 가지 않는다).

| 어디 | 켜면 어떻게 되나 |
|---|---|
| 교대 보고서 [7] 특이 사항 | 끝난 교대의 초안 문장을 비서가 다듬은 것으로. 사람이 저장·확정하면 그 글이 기준이고 비서가 덮어쓰지 않는다 |
| 일일 보고서 "오늘의 문제" | 항목 문장만 다듬는다 (머리의 건수·항목 수·순서는 프로그램 그대로). 확정할 때 사람이 본 문장이 굳는다 |
| 작업지시서 제목·증상 | 비서가 다듬으면 "제목 · 증상" 이름이 "AI비서 초안"으로 바뀐다. 사람이 손대기 전 초안만 |
| 알람 지침카드 | **"먼저 할 일" 원문(DOC-03)은 그대로**이고, 아래에 점선 칸 "비서 풀이 (참고)"가 더해진다. 없거나 실패하면 그 칸은 안 보인다 |

**켜는 순서** (모두 PowerShell)

1. 먼저 4-3절(Claude Code CLI 로그인)과 `assistant/.env`의 `ASSISTANT_PROVIDER=claude`, `EXTERNAL_LLM_APP=1`, `LLM_ENABLED=1`, `MOM_ASSISTANT_KEY=…`가 되어 있어야 한다.
2. 비서 서비스를 **다시 시작**한다 (5-3절). 코드를 바꾼 뒤에는 껐다 켜야 반영된다.
3. 시연 서버를 켤 때 같은 창에서 스위치를 켠다:

```powershell
Set-Location <자신의-semi-ai-폴더>\11_automotive\frontend
$env:MOM_LLM_COMPOSE = '1'
# 서비스 키: 환경변수 MOM_ASSISTANT_KEY가 있으면 그것, 없으면 assistant\.env의 같은 이름 줄을 읽는다 (값은 화면·로그에 안 나온다)
# 비서 주소 기본값은 http://127.0.0.1:8100 — 바꾸려면 $env:MOM_ASSISTANT_URL (이 PC 주소만 허용)
..\생성기\.venv\Scripts\python.exe tools\sim_server.py
```

4. 화면은 그대로 `npm run dev` (6절). `.env.local` 같은 설정은 필요 없다 — 이 기능은 시연 서버가 비서를 부른다.
5. 켜졌는지 확인: `Invoke-RestMethod http://127.0.0.1:8765/api/health` → `llm_compose` 칸에 `enabled: True`와 `ready`·`pending`·`failed` 개수가 보인다. 이 칸이 없으면 예전 코드로 떠 있는 것이니 시연 서버를 다시 시작한다.

**언제 보이나:** 비서 호출은 5~20초 걸린다. 시연 서버는 기다리지 않고 기본 문장을 먼저 내보내므로 화면이 멈추지 않는다. 교대 보고서는 **교대가 끝난 뒤**(시연 [17:00으로] 등) 목록이 10초마다 갱신되며 바뀌고, 보고서 상세는 한 번 읽어 오므로 문장이 준비된 뒤에 열거나 닫았다 다시 연다. 지침카드 풀이는 알람이 뜰 때 미리 만들기 시작한다.

**끄는 법:** `$env:MOM_LLM_COMPOSE`를 비우고 시연 서버를 다시 시작한다. (비서 쪽 스위치 셋 중 하나만 꺼도 비서가 503을 돌려주어 기본 문장으로 돌아간다.)

**주의**

- 켜면 보고서·작업지시서·지침카드 문장이 Claude로 **전송된다.** 사람 이름·사용자 ID·사원 번호·계정 정보는 가려지고, 그런 글이 든 재료는 아예 나가지 않는다 (요구사항 NFR-SEC-08). 지침카드 풀이를 켜면 점검 순서 문장이 외부로 전송된다 (채팅 안내문에 밝혀 둠).
- **시연 서버를 하나 더(다른 포트로) 띄우지 않는다.** 시작할 때 `생성기/out_realtime/cmm_drop/`을 비워서, 쓰던 서버가 만든 파일이 사라진다 (2026-10-17 실제로 있었던 일).
- 시연 PC의 구독 한도는 시험하지 않기로 했다. 한도가 차면 비서가 "응답 없음"(503)이 되고 화면은 기본 문장으로 돌아간다.
- 이 절은 진짜 Claude로 교대 보고서·일일 보고서·작업지시서·지침카드를 한 번씩 확인했고(2026-10-17), 브라우저 화면을 눌러 확인한 것은 아니다.

|---|---|---|
| health의 `failed`가 늘고, 비서 로그에 `401` | 시연 서버와 비서의 `MOM_ASSISTANT_KEY`가 다름 | 두 쪽을 같은 값으로 맞추고 다시 시작 |
| 비서 로그에 `문장 입구 실패: external switch off` / `provider is not claude` / `llm disabled` | 스위치 셋 중 하나가 꺼져 있음 | `assistant/.env`의 세 값을 확인하고 비서 다시 시작 |

## 8. 안 될 때

| 증상 | 까닭 | 고치는 법 |
|---|---|---|
| `pip install`이 `UnicodeDecodeError: 'cp949'`로 멈춤 | `requirements.txt`의 한글 주석 | `$env:PYTHONUTF8 = '1'` 하고 다시 |
| `py -3.12`를 찾을 수 없음 | Python 3.12 또는 Windows `py` 런처가 없음 | `py --list`를 확인하고 Python 3.12.x와 py launcher를 설치한 뒤 다시 진행 |
| `python --version`은 맞지만 실행 결과가 다름 | 시스템 Python으로 실행함 | 반드시 `backend\.venv\Scripts\python.exe` 또는 `assistant\.venv\Scripts\python.exe`를 직접 사용 |
| `ModuleNotFoundError` | 다른 가상환경에서 실행했거나 설치가 끝나지 않음 | 실행 명령의 `.venv\Scripts\python.exe -m pip show <패키지>`와 설치 로그를 확인 |
| `check_connection`: `MOM_DATABASE_URL 이 없거나 <...> 를 아직 안 바꿈` | `MOM_DATABASE_URL`·`MOM_READONLY_DATABASE_URL` 줄의 비밀번호 자리가 `<…>` 그대로 | DB 담당에게 받은 비밀번호로 채운다 (`<`와 `>`도 지운다) |
| `invalid URI query parameter: "?sslmode"` | 주소 끝이 `??sslmode=…` | 물음표 하나 지운다 |
| 접속 실패 / 시간 초과 | 공용 DB 연결 15개 제한, 인터넷 | `MOM_DB_POOL_SIZE=2` 확인, 잠시 뒤 다시 |
| 켤 때 `Address already in use` / 포트 사용 중 | 3절의 다른 서버가 쓰는 번호 | 안 쓰는 번호로 켜고 `MOM_BACKEND_URL`·`MOM_E2E_BACKEND`·백엔드 `MOM_ASSISTANT_URL`의 번호도 같이 바꾼다 |
| `claude`가 명령으로 인식되지 않음 | Claude Code CLI가 설치되지 않았거나 PATH에 없음 | `claude --version`을 확인하고 공식 설치 방법으로 설치한다. PATH에 없으면 `MOM_CLAUDE_BIN`에 실행 파일 전체 경로를 설정 |
| Claude가 로그인되지 않음 | 구독 로그인 상태가 없음 | `claude auth status`를 확인하고 해당 PC의 계정으로 로그인한다. `ANTHROPIC_API_KEY`만 넣는 것으로는 현재 CLI 경로가 인증되지 않음 |
| 로그인 401 | 사용자 ID나 시연 비밀번호가 틀림 | `U01`~`U12`, 비밀번호는 DB 담당 |
| 백엔드 채팅 응답 `status: NO_RESPONSE` | 비서(`<ASSISTANT_PORT>`)가 꺼짐, 두 파일의 `MOM_ASSISTANT_KEY`가 다름, 백엔드의 `MOM_ASSISTANT_URL`이 비어 있음 | 5-3 확인, 두 키를 같게, `detail.reason`을 본다 (`NOT_CONFIGURED` = URL 없음, `HTTPError` = 키 틀림·비서 오류) |
| 비서가 503 `ASSISTANT_UNAVAILABLE` | 백엔드(`<BACKEND_PORT>`)가 꺼짐, `MOM_BACKEND_URL`·키가 틀림, DB 문제 | 비서 터미널에 `비서 응답 실패: …`가 찍힌다 (백엔드를 끈 채 운영 질문을 보내 확인함: `BackendToolError`) |
| 비서가 "아직 조회할 수 없습니다"라고 답함 | **정상** — 백엔드 조회 도구가 안 주는 정보 (2절) | DB·백엔드 담당과 도구 추가를 정한다 |

**외부 Claude를 켠 채 쓸 때 (시간 제한)** — 문서 질문 한 번에 20초 넘게 걸릴 수 있다(측정: 20.5초). 아래 두 곳이 기본 **30초**라 넘으면 "응답 없음"이 된다.

(예전에 남아 있던 "시험·조정 5단계" 한계는 같은 날 DOC-05 §2.2 표에 우리 말 칸을 더해 풀었다 — 아래 문단.)

**✅ 해결 (2026-10-18) — 안전 질문의 거짓 "문서에 없다" 원천 차단 (`PURE_SAFETY=1`)**: "톱 정비 전에 어디를 차단해야 해?"에 "톱의 차단 지점은 문서에서 찾지 못했어요"(`NOT_IN_DOCS`, 출처 없음)가 나왔다. DOC-05 §3.1에 차단 지점 두 곳이 있는데 낱말 검색에서 68위라 Claude에게 가지 못했다. **근본 원인:** 낱말이 같아야 찾는 검색(현장 말 "톱" ≠ 문서 말 "SAW-01·콜드쏘")과 "못 찾음"을 "문서에 없음"으로 말하는 것. 고친 방법: ① 안전 낱말이 든 질문에는 DOC-05를 통째로 더하고(약 16,600자), ① -b 신호가 설비 이름뿐인 안전 질문은 기존 길이 아니라 순수 길로 보내며, ② 그래도 답이 없으면 "자동으로 확인하지 못했어요 — 문서에 없다는 뜻은 아니에요 + 가까운 DOC-05 절"로 답한다(상태는 기존 "확인 필요", API로는 `OK` — 새 상태 값 없음). 문서도 보강했다: DOC-05 §2.1·§2.2 제목에 "잠금·표지를 거는/푸는 순서", §3.1 제목에 "톱", §2.2 시험·조정 표에 우리 말 칸(개정 번호는 Rev.2로 올림 — 개정 기록 새 행은 2026-10-18에 승인됨, 출처 표기가 "Rev.2 (2026-10-18)"로 나온다). **측정(같은 도구 `eval/safety_recall.py`, 점검표 68개):** 정답 절이 Claude 조각에 있는 비율 85% → 100%. 진짜 Claude로 위험 질문 21개: 정답 절 없이 "없다/못 찾음"이라 답한 것 7개 → 0개, `NOT_IN_DOCS` 2개 → 0개, 평균 응답 10.4초 → 8.4초. 대신 보내는 문서 글자 수는 안전 질문에서 평균 약 7,700자 → 약 21,900자(최대 약 27,200자)로 늘었다. 끄면(`0`) 지금과 한 글자도 같다. 합친 뒤 각자 `PURE_SAFETY=1`을 `.env`에 더하고 비서를 다시 켠다. 자세한 수치와 한계는 [`변경기록.md`](변경기록.md)의 "안전 질문 거짓 단정 원천 차단" 절.

**✅ 해결 (2026-10-18) — "로트·재고" 낱말이 든 규칙 질문의 라우팅 (`PURE_RULE=1`)**: "소모품 재고는 누가 관리해?"·"홀드 걸린 로트도 내보낼 수 있어?"·"정비 기한이 지나면 알림이 가?"가 문서 답이 아니라 재고 부족 목록이나 "로트 번호를 알려 주세요"를 받던 결함. 낱말 하나(로트·재고)로 "규칙을 묻는지 데이터를 묻는지"를 가르지 못해 운영 조회로 간 것이 원인이다(검색 문제가 아니라 라우팅 문제). 고친 방법: 신호가 운영 낱말뿐이고 지금 상태를 묻는 말이 없고 규칙 낱말이 있을 때만 문서 길로 보내고, 문서에 없으면 원래 운영 조회로 되돌린다. 독립 질문 은행(처음 본 질문)에서 운영 질문 오탐 0/80, 앞서 문서 답을 못 받던 21개 중 20개가 문서 답. 문서 길의 Claude 호출이 실패하거나 문서에 없다고 하면 원래 운영 조회로 돌아간다. **한계:** 재현율이 낮다(규칙 질문 10개 중 3~4개만 구제) — "~맞지?"·긴 서술·정의 질문은 그대로 운영 조회로 간다. 기준·근거는 `변경기록.md`와 1018 수정 메모 7장을 본다.

**◐ 일부 해결 (2026-10-18) — 검사 기준서(DOC-06)의 현장 말 질문 (문서 Rev.4 + 용어집 Rev.5, 설정 변경 없음)**: "첫 물건 검사는 누가 해?"·"홀드 걸고 나서 할 일"·"봉 한 개에서 부품이 몇 개 나와?"처럼 현장 말로 묻는 질문에서 정답 절이 Claude에게 가지 않던 것을 문서 쪽으로 풀었다 — DOC-06 절 제목 8줄에 현장 말을 병기하고 용어집 "쓰지 않는 말" 칸에 현장 말(첫 물건·샘플링·빡세게 하는 검사·라인이 막혀 …)을 더했다. 합친 뒤 **비서를 다시 켜면** 반영된다(문서와 용어집은 비서가 시작할 때 읽는다, `.env` 변경 없음). 점검표 62/75 → 70/75, 진짜 Claude로 옛 놓침 11개의 거짓 "없다" 9 → 3. **알려진 별명에만 듣는다** — 처음 보는 말투로 만든 봉인 질문 16개는 11/16 그대로였다. 남은 놓침은 "그 항목"·"어떤 식으로" 같은 일반적인 질문어라 낱말 사전으로 못 잡으며, 다음 처방은 "못 찾음 ≠ 문서에 없음"을 전반에 반영하는 것(따로 기획)이다. 자세한 내용은 `변경기록.md`·`구현_중_수정사항/1018_수정간단내용.md` 8장.

**그 밖의 한계 (추가 묶음 설명서가 적은 것 그대로)**: 이 길에는 숫자·허락·지시 코드 검사가 없어 안전은 지시문과 코드에 고정된 끝 안전 문구뿐이고 실행마다 흔들릴 수 있다. 실제 Claude 시험은 표본이 적다 (허락 질문·위험한 부탁·용어 풀이·이어 묻기·안전 절차는 거의 시험되지 않았다). 문서 조각 8개가 매번 외부 Claude로 나간다 (지금은 가상 데이터만).

## 9. 주의

- **팀 공용 DB다.** 읽기 점검과 `health`는 기록을 안 남기지만, 로그인과 비서 질문은 남긴다. 시연 되돌리기(`/api/sim/reset` 등) 같은 쓰기 API는 부르지 않는다 — 그래서 `MOM_DEMO_MODE=false`로 둔다.
- 비밀번호·키·`.env*` 파일은 git에 올리지 않는다 (`.gitignore`가 막아 준다). 채팅·화면 공유에도 올리지 않는다.
- Supabase 관리 토큰(`SUPABASE_ACCESS_TOKEN`)이 환경에 있어도 쓰지 않는다. DB 접속 값은 DB 담당이 주는 것을 쓴다.
- **채팅 탭은 외부 LLM(Claude) 구성으로 사용할 수 있다** (2026-10-16). 예시 파일 `.env.example`은 안전하게 꺼진 채(`ASSISTANT_PROVIDER=local`, `EXTERNAL_LLM_APP=0`, `LLM_ENABLED=0`)다. 각자 `.env`에서 Claude를 켜면 질문, 사내 문서 조각, 운영 조회 결과가 Claude로 나간다 — **실제 자료는 반출 승인 전까지 쓰지 않는다.** 끄려면 `EXTERNAL_LLM_APP=0`.
- 줄바꿈: Windows에서 새로 받으면 CRLF가 되어 `MANIFEST.md`의 해시와 달라질 수 있다.
