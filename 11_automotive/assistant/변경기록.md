# assistant/ 변경 기록

이 폴더는 `261003_창민/claude_bundle_20261016`(외부 Claude 비서 백엔드 묶음, 2026-10-16)을 복사한 것이다.
복사 직후 `MANIFEST.md`의 318행 SHA-256과 모두 일치함을 확인했다. **`MANIFEST.md`는 원본 그대로 두고**, 그 뒤에 바꾼 파일만 아래에 적는다
(여기 없는 파일의 해시는 MANIFEST와 같다).

## 한눈에

백엔드(`11_automotive/backend`)가 `MOM_ASSISTANT_URL`로 부르는 **별도 비서 서비스**다. 실행: `assistant/`에서
`uvicorn backend.chat_service:app --host 127.0.0.1 --port 8100` (밖에 열지 않는다). 백엔드 `.env`에 `MOM_ASSISTANT_URL=http://127.0.0.1:8100`과
같은 `MOM_ASSISTANT_KEY`, 이 폴더 `.env`에 `MOM_BACKEND_URL`·`MOM_ASSISTANT_KEY`(`.env.example` 참고).

```
백엔드 POST /api/assistant/chat ──▶ 비서 서비스 POST /chat ──▶ answer() ──▶ 백엔드 POST /api/assistant/tools/{도구} (읽기 전용 14개 중)
        (로그인·chat_log 저장)        (서비스 키, 권한 게이트)      (규칙+문서 검색)       (on_behalf_of = 묻는 사용자, 그 역할 권한으로 거름)
```

## 운영 데이터 질문 — 되는 것과 아직 안 되는 것

| 질문 | 백엔드 도구 | 비고 |
|---|---|---|
| 설비 상태, 알람 횟수, 지표(OEE 등), 생산 실적, 로트(번호로), 작업지시, 작업기록, 예방 정비 기한, 공구 수명, 재고 | `equipment_status`·`alarms`·`kpi`·`production`·`lot`·`work_orders`·`work_records`·`pm_due`·`tool_life`·`inventory` | 된다 |
| MTTR·MTBF | `reliability` | MNT·MGR만 (백엔드가 허용 목록에서 뺀 역할은 값도 "—"도 안 나옴) |
| 정지 | `stop_reasons` | **손실 정지만** — 계획 정지·필수 정지(5분 이상)·순간 정지는 말하지 않는다 |
| 알람 | `alarms` | **설비·알람 번호별 횟수만** — 건별 목록·처리 여부·반복 알람 단계는 없다 |
| 로트 | `lot` | **로트 번호로만** — 작업지시 번호로 찾기는 아직 없다고 답한다 |
| 센서 추세(`sensor_trend`)·설비 사양(`equipment_spec`) | | 묶음에 이 질문 종류가 없어 아직 안 쓴다 |

**백엔드/DB 담당과 정할 일(빠진 정보 3가지):** 필수 정지·계획 정지, 알람 건별·처리 여부·반복 알람 단계, 작업지시 번호로 로트 찾기. 필요하면 백엔드에 조회 도구를 더해야 한다(이번 작업은 백엔드를 고치지 않았다).
날짜 기본값(기간 없이 물으면 "2026-09-30까지 30일")은 묶음의 시연 기준 그대로다 — 실시간 시계를 따르게 하는 것은 아직 안 했다.

## 일부러 고치지 않은 것

- `backend/eval/*.py`: 평가 도구라 앱 실행에 필요 없다. 옛 경로(`simulator/…`)를 그대로 읽어 이 폴더에서는 돌지 않는다.
- `backend/app.py`(옛 모의 API)와 그 위의 `briefing`·`guide_card`·`notifications`·`shift_reports`·`demo_state`: 비서 서비스는 쓰지 않는다.

**문서 답이 달라지지 않았는지:** 평가 질문 1,018개를 조회 도구 교체 전(`401ea08`)과 지금으로 같은 문서·같은 질문에 돌려 비교했다. 전에도 답한 687개는 **상태·결론·점검 순서·관련·주의·출처·조회 범위 모두 똑같고**, 전에 오류가 났던 운영 질문 331개는 이제 모두 답한다.
(이 비교로 기준표 변환 오류 2개 — `control`이 제어기 이름이어야 함, `doc02_section`에 문서 번호가 있어야 함 — 도 시험이 잡아내 고쳤다.)

**진짜 백엔드·공용 DB로 확인 (2026-10-16):** 시연 비밀번호로 U01·U07에 로그인해 질문 8개 — **8/8 맞음** (`e2e_check.py`). 공용 DB에 `chat_log` 8줄·`access_log` 약 20줄이 남았다.

**외부 Claude 첫 시험 (2026-10-16, 가짜 백엔드·가상 데이터 질문 4개):** 문서 질문 20.5초(호출 5회), 재고 7.3초(2회), 알람 카드 2개 0초(0회 — 규칙만). 모델 `claude-sonnet-5-5`, 노력 `medium`, 단계 실패 없음. 이 PC의 `assistant/.env`는 Claude를 켠 상태, `.env.example`은 꺼진 상태.

**외부 Claude를 켠 채 진짜 백엔드·공용 DB (2026-10-16):** 8/8 맞음, 전체 62초 (문서 20.9초, 운영 7.6~8.5초, 거절·권한 밖 0.1~0.2초). 공용 DB의 `chat_log`는 이제 chat_id 1~16.

**아직 확인하지 못한 것:** 작업자의 OEE 질문에서 MTTR이 빠지는지를 진짜 DB로는 안 봤다(가짜 백엔드 시험으로만). 동시 질문과 구독 한도는 안 봤다. 묶음을 만든 원래 환경의 시험 결과는 모른다.

## 메모

- Windows에서 `pip install -r requirements.txt`는 `PYTHONUTF8=1`이 필요하다(`requirements.txt`의 한글 주석을 pip가 cp949로 읽다 실패). 원본 파일은 해시 때문에 고치지 않았다.
- 저장소에서 새로 받으면 줄바꿈이 CRLF로 바뀔 수 있어 MANIFEST의 해시와 달라진다 (해시를 다시 대조하려면 LF로).
