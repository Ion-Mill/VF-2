**결정이 남은 결함 — "잠금 표지 순서" (안전)**: 새 길의 답이 "모든 설비에 공통인 잠금·표지 단계별 순서는 문서에 없다"고 했다(두 번 같은 답). **틀렸다**: DOC-05 §2.1(작업 전 6단계)·§2.2(작업 후 3단계)가 공통 순서다. 낱말 검색 상위 8개에 §2.1이 없고(질문 5가지 표현 모두 20위 밖), 새 길은 검색 결과를 그대로 Claude에 주므로 그 빈틈을 "문서에 없다"로 메운다. 기존 길(Claude 끈 규칙 답)도 §2.1을 못 찾지만 "없다"고 단정하지는 않고 §2의 일반 원칙을 보인다. 화면 예시 버튼 "잠금 표지 순서"가 이 질문이다. 고치는 방법 후보:
1. 새 길의 검색에 안전 낱말 보강(예: "잠금·표지·순서·LOTO" → "작업 전 6단계·작업 후 3단계")을 더한다 — 추가 묶음의 "원래 질문 그대로" 설계에서 벗어나는 작은 수정, 한 질문에 맞춘 땜질이 되지 않게 시험 필요.
2. 안전 낱말(잠금·표지·LOTO·고전압·차단)이 든 질문은 새 길에서 빼고 기존 길로 보낸다(`PURE_KEEP_SIGNALS`의 신호에 더함) — 기존 길도 §2.1을 못 찾는 점은 그대로.
3. 팀 문서 DOC-05 §2.1 본문·제목에 "잠금·표지 순서" 낱말을 넣도록 팀에 요청한다 — 문서는 팀 것.
4. 아무것도 안 하고 알려진 한계로 둔다.
→ 2026-10-16에는 어느 것도 적용하지 않았고, **2026-10-18에 고쳤다** (아래 "잠금 표지 순서 수정" 절 — 1번의 보강 아이디어와 부모 보장을 `PURE_EXPAND`로 합쳤다).

- 점검표 68개에서 정답 절이 Claude 조각에 있는 비율: **85%(58/68) → 100%(68/68)**. 실제 순수 길로 가는 질문은 44/52 → 65/65. 설비·운영 신호 때문에 기존 길로 가던 질문 16개 → 3개(작업지시 조회뿐).

"문서에는 없어요" 5건은 4건이 문서 사실과 맞거나 본문이 정확하고 끝에 덧붙인 문장이며, **1건은 부정확**하다("MIL-01 주축 헤드 받치는 방법은 문서에 없다" — 문서는 "VF-2와 같은 방법"이라고 가리킨다).
- "시험·조정 5단계": 새 칸을 더한 뒤 진짜 Claude가 5단계와 시험 예를 정확히 답한다(전에는 "문서에는 없어요").
- 시험: 1499 → **1610 통과**, 건너뜀 2·예상 실패 76 그대로. 끄면 개발용 83개+점검표 68개의 검색 결과가 한 글자도 같다.

**한계·주의:**

## 문장 입구와 보내기 전 거르기 (2026-10-18)

비서가 `/chat`(질문 답) 말고도 **프로그램이 만든 기본 문장을 읽기 쉽게 다듬어 주는** 입구를 갖는다. 보고서·작업지시서·지침카드 문장에 쓴다. 켜는 법은 `실행_안내.md` 6-3.

**1) 보내기 전 거르기 — 요구사항 NFR-SEC-08** (`backend/privacy/outbound_guard.py`)
- 외부 LLM(Claude)으로 나가는 글에서 **사용자 ID(U01 …)·사용자 이름·사원 번호 라벨·토큰/접속 주소/비밀번호 꼴·서버 환경의 비밀값**을 `[사람]`·`[사번]`·`[계정정보]`로 가린다. 사내 문서에 이미 나오는 직무명("공장 관리자")은 가리지 않는다.
- 외부 호출이 모두 지나는 `llm/claude_client._chat_json_claude`에 걸어서 **기존 `/chat`도 함께 덮는다.** 사내 문서 195조각은 하나도 바뀌지 않는다(시험이 지킨다).
- 가린 원문은 로그에도 남기지 않는다(종류와 횟수만). 사용자 목록은 `생성기/masters/app_user.csv`에서 읽고, 못 읽으면 `U00` 꼴 ID만 가린다.

**2) 문장 입구 `POST /compose/{kind}`** (`backend/compose_service.py`, 논리는 `backend/llm/compose.py`, `chat_service`의 서비스 키가 그대로 걸림)
- `kind` = `shift_report`·`daily_report`·`work_order`·`guide_card`·`briefing`. 받는 것은 `{lines:[{id,text}]}`(프로그램이 만든 기본 문장) 하나뿐이고, 정해진 칸 밖의 입력은 422다. DB·백엔드를 읽지 않는다.
- 돌려주는 것은 **같은 id·순서·개수의 다듬은 줄**이다. 줄마다 `adapter.check_text`(숫자·번호·`(추정)`/`[가상]`/`잠정` 꼬리표 양방향 대조, 허락·지시 문구·한글 수사·원문 출처 거부)와 줄 모양 검사(문장 수·끝 마침표·앞머리 `[긴급]` 꼬리표 유지, 줄바꿈·마크다운 없음, 길이)를 통과해야 한다. 틀리면 사유를 붙여 한 번 다시 요청하고, 그래도 틀리면 503이다.
- 종류별 추가 검사: 일일 보고서 항목은 화면이 쪼개는 `:`·` / ` 금지, 작업지시서 제목 60자, **지침카드는 "말고·~하지 않는다·금지·반드시" 표현 유지 + 원문에 없는 안전 용어(잠금·표지·차단·전원·해제) 금지 + 원문과 글자 절반 이상 겹침.**
- 스위치 셋(`ASSISTANT_PROVIDER=claude`, `EXTERNAL_LLM_APP=1`, `LLM_ENABLED=1`)이 모두 맞아야 한다. 하나라도 꺼져 있으면 **외부·로컬 LLM 모두 호출 0**이고 503이다. 사람·계정 글이 든 재료는 가리지 않고 아예 보내지 않는다.
- 실패는 모두 503 `ASSISTANT_UNAVAILABLE`(안쪽 사정은 응답에 없음). 부른 쪽(시연 서버)은 지금의 기본 문장을 그대로 쓴다.

**호출하는 쪽 (이 폴더 밖, 팀 파일):** `frontend/tools/llm_compose.py`(새, 기다리지 않는 백그라운드 호출·캐시·백오프), `frontend/tools/sim_server.py`(교대·일일 보고서, `assist/work-order-text`, `assist/guide-card-text`), `frontend/src/shell/assistText.ts`(새)·`App.tsx`·`CardScreen.tsx`·`WorkOrderScreen.tsx`·`workflow.ts`. 시연 서버 쪽은 `MOM_LLM_COMPOSE=1`일 때만 움직인다(기본 꺼짐).

**확인한 것 (2026-10-17, 진짜 Claude·가상 데이터, 공용 DB 안 씀):** 교대 보고서 5.9초·일일 보고서 항목·작업지시서 제목/증상 11초·지침카드 알람 992의 4줄 9.2초에 통과, 숫자·`(추정)` 등 유지. 사람 ID가 든 재료는 외부 호출 없이 0.01초에 503. 시연 서버 쪽 시험으로 "요청이 막히지 않음"·"사람이 고친 보고서는 안 덮어씀"·"처음으로에서 비움"을 확인.

**한계:** 지침카드 풀이는 검사를 엄격히 걸어서 원문에 아주 가깝게 나온다(말투 정도). 이름 거르기는 `app_user.csv` 목록과 글자 꼴 기준이라, 목록에 없는 임의의 사람 이름은 못 잡는다 — 그래서 새 입구는 정해진 칸의 프로그램 문장만 받는다. 시연 PC의 구독 한도는 시험하지 않기로 했다(사용자 결정).

**실행 안내대로 켜 보고 찾은 결함 (2026-10-18):** 작업지시서 제목의 설비 이름 `VF-2 #1`을 그대로 두면 "마크다운 금지" 검사가 `#`만 보고 거부했다. 줄 머리의 제목/목록 기호·`**`·백틱만 거부하고 원문에 있던 모양은 문제 삼지 않도록 고쳤다(시험 1개 추가). 검증 기록은 `실행_안내.md` 10절.

## 메모

- Windows에서 `pip install -r requirements.txt`는 `PYTHONUTF8=1`이 필요하다(`requirements.txt`의 한글 주석을 pip가 cp949로 읽다 실패). 원본 파일은 해시 때문에 고치지 않았다.
- 저장소에서 새로 받으면 줄바꿈이 CRLF로 바뀔 수 있어 MANIFEST의 해시와 달라진다 (해시를 다시 대조하려면 LF로).
- **올리지 않은 것 (2026-10-16):** 평가 결과물 `backend/eval/results*` 180개(5.4MB, 실행 결과·봉인 시험 답)는 git에 올리지 않는다. 시험이 읽지 않고 평가를 다시 돌리면 다시 생기는 파일이다. 평가 도구(`*.py`)와 질문 세트(`qa_*.json`, 시험이 읽는다)는 그대로 있다. 그래서 `MANIFEST.md` 해시 목록의 `results*` 줄은 이 저장소에 파일이 없다(원본 번들 쪽에는 있다). 다시 올라가지 않게 `assistant/.gitignore`에 규칙을 넣었다.
