## 일부러 고치지 않은 것

- `backend/eval/run_eval.py`·`eval/*.py`: 평가 도구라 앱 실행에는 필요 없다. 옛 경로(`simulator/…`)를 그대로 읽으므로 이 폴더에서는 돌지 않는다.
- 시험 `test_req_map.py`·`test_step_log.py`·`test_run_blind_sb.py`: 묶음 밖 파일(기획 문서·루트 `scripts/`)을 읽는 알려진 예외 (`MANIFEST.md` 4절).

## 알려진 한계 (다음 단계에서 풀 것)

- Windows에서 `pip install -r requirements.txt`는 `PYTHONUTF8=1`을 켜고 해야 한다 (`requirements.txt`의 한글 주석을 pip가 cp949로 읽다 실패). 원본 파일은 해시 때문에 고치지 않았다.
- 2026-10-16 첫 시험(`pytest backend/tests`): 738 통과 / 478 실패 / 오류 10 / 건너뜀 2. 실패의 대부분은 `KeyError`(생성기 CSV의 열 이름이 묶음이 읽는 것과 다름, 예: `alarm_master.csv`의 `alarm_code` ↔ 묶음의 `code`).

- 생성기 CSV(`생성기/out`, `생성기/masters`)는 묶음이 읽는 옛 표 이름·열과 다르다. 운영 데이터를 읽는 길(`get_state()`, 운영 조회 도구, `/api/health`)은 **조회 도구를 백엔드 API로 바꾸는 단계(5단계) 전까지 오류**가 난다.
- 사내 문서 검색·문서 답은 동작한다 (`가상사내문서/`의 8개 파일, 195조각).
- 기존 백엔드(`../backend`)의 `POST /chat` 계약에 맞추는 어댑터는 아직 없다 (4단계).
