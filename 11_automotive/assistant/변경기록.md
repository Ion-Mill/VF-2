# assistant/ 변경 기록

이 폴더는 `261003_창민/claude_bundle_20261016`(외부 Claude 비서 백엔드 묶음, 2026-10-16)을 복사한 것이다.
복사 직후 `MANIFEST.md`의 318행 SHA-256과 모두 일치함을 확인했다. **`MANIFEST.md`는 원본 그대로 두고**, 그 뒤에 바꾼 파일만 아래에 적는다
(여기 없는 파일의 해시는 MANIFEST와 같다).

## 한눈에

백엔드(`11_automotive/backend`)가 `MOM_ASSISTANT_URL`로 부르는 **별도 비서 서비스**다. 실행: `assistant/`에서
`uvicorn backend.chat_service:app --host 127.0.0.1 --port 8100` (밖에 열지 않는다). 백엔드 `.env`에 `MOM_ASSISTANT_URL=http://127.0.0.1:8100`과
같은 `MOM_ASSISTANT_KEY`, 이 폴더 `.env`에 `MOM_BACKEND_URL`·`MOM_ASSISTANT_KEY`(`.env.example` 참고).

```
백엔드 POST /api/assistant/chat ──▶ 비서 서비스 POST /chat ──▶ answer() ──▶ 백엔드 POST /api/assistant/tools/{도구} (읽기 전용 14개 중)
        (로그인·chat_log 저장)        (서비스 키, 권한 게이트)      (규칙+문서 검색)       (on_behalf_of = 묻는 사용자, 그 역할 권한으로 거름)
```

**내 쪽에서 더한 것:** `chat_mapping.py`의 `blocks_to_text` — 화면 말풍선은 블록(section·lead·text·ops·steps·line)을 그리지 못하고 디자인은 안 바꾸므로, 비서 쪽이 블록을 **글자 하나로 푼다**(소제목 "■ 제목", 목록 "1. …", 접어 두던 원문 줄 `orig`은 제외, 소제목은 바로 다음 블록과 한 덩어리, 덩어리 사이 빈 줄). 블록이 없으면 예전 방식. 알람 카드도 같은 규칙으로 소제목이 생긴다. 스위치는 `.env.example`에 기본 꺼짐으로, 이 PC `.env`는 켠 채(`PURE_EXTERNAL`·`PURE_STYLE`·`PURE_LAYOUT`·`PURE_KEEP_SIGNALS`=1, `PURE_TOPK`=8). 설명은 [`실행_안내.md`](실행_안내.md) 8-2절.

**결정이 남은 결함 — "잠금 표지 순서" (안전)**: 새 길의 답이 "모든 설비에 공통인 잠금·표지 단계별 순서는 문서에 없다"고 했다(두 번 같은 답). **틀렸다**: DOC-05 §2.1(작업 전 6단계)·§2.2(작업 후 3단계)가 공통 순서다. 낱말 검색 상위 8개에 §2.1이 없고(질문 5가지 표현 모두 20위 밖), 새 길은 검색 결과를 그대로 Claude에 주므로 그 빈틈을 "문서에 없다"로 메운다. 기존 길(Claude 끈 규칙 답)도 §2.1을 못 찾지만 "없다"고 단정하지는 않고 §2의 일반 원칙을 보인다. 화면 예시 버튼 "잠금 표지 순서"가 이 질문이다. 고치는 방법 후보:
1. 새 길의 검색에 안전 낱말 보강(예: "잠금·표지·순서·LOTO" → "작업 전 6단계·작업 후 3단계")을 더한다 — 추가 묶음의 "원래 질문 그대로" 설계에서 벗어나는 작은 수정, 한 질문에 맞춘 땜질이 되지 않게 시험 필요.
2. 안전 낱말(잠금·표지·LOTO·고전압·차단)이 든 질문은 새 길에서 빼고 기존 길로 보낸다(`PURE_KEEP_SIGNALS`의 신호에 더함) — 기존 길도 §2.1을 못 찾는 점은 그대로.
3. 팀 문서 DOC-05 §2.1 본문·제목에 "잠금·표지 순서" 낱말을 넣도록 팀에 요청한다 — 문서는 팀 것.
4. 아무것도 안 하고 알려진 한계로 둔다.
→ 2026-10-16에는 어느 것도 적용하지 않았고, **2026-10-18에 고쳤다** (아래 "잠금 표지 순서 수정" 절 — 1번의 보강 아이디어와 부모 보장을 `PURE_EXPAND`로 합쳤다).

## "잠금 표지 순서" 수정 — `PURE_EXPAND` (2026-10-18)

위 "결정이 남은 결함"을 고쳤다. 승인받은 계획서는 `261003_창민/잠금표지순서_결함_수정계획_20261017.md`(아직 git에 올리지 않은 작업 문서)다.

**원인(재확인):** 낱말 검색(BM25)에서 DOC-05 §2.1 "작업 전 6단계"가 66위(질문 변형 10개 중 8개에서 상위 8개 밖). 둘째 원인은 "작업 전에 **잠그는** 순서"처럼 동사형으로 물으면 부모 §2도 상위 8개 밖이라(동사형 변형 10개 중 6개) 아래 절 확장만으로는 못 고치는 것. 문서가 "잠금" 대신 "자물쇠·차단 지점"이라고 쓰는 것도 한 까닭이다.

**고친 것 (스위치 `PURE_EXPAND`, 코드 기본 0 = 지금 동작 그대로, `.env.example` 기본 1):**
- `backend/services/pure_external.py`: `expand()`(상위 조각의 직계 아래 절을 이미 있는 것은 빼고 짧은 것부터 최대 4개·2,500자, 부모 바로 뒤, 점수 0.0), `guarantee()`(질문에 잠금 낱말 — `LOCK_TERMS` — 이 있고 DOC-05 §2가 상위에 없으면 맨 앞에 더하고 먼저 확장), `context()`(켜면 둘을 적용, 끄면 `retrieve()`와 같음).
- `backend/services/answer.py`: `PURE.retrieve(...)` 호출을 `PURE.context(...)`로(1줄), 켜졌을 때만 `retrieval.expanded_ids`와 STEP_LOG "확장으로 더해짐" 기록. `backend/config.py`: `pure_expand` 설정·flags. `tests/conftest.py`: 시험 기본 0 고정.
- `e2e_check.py`: 잠금 표지 질문 2개(원래 질문 + 동사형)에 `never` 패턴(`LOCK_NEVER`)을 걸었다 — 예전에는 `never=None`이라 틀린 답도 통과했다. 정상 답의 "시험·조정 단계는 문서에 없다" 같은 문장은 걸리지 않게 했다. 질문이 10개에서 11개가 되어 한 번 돌릴 때 공용 DB `chat_log`가 11줄 남는다.
- **손대지 않은 것:** `eval/run_eval.py`·`eval/route_eval.py`(추가 묶음과 바이트까지 같은 복사본이라 원본과 달라지지 않게 두었다), 지시문(시스템 프롬프트), 원본 번들. 원본 번들에 같은 수정을 거꾸로 넣을지는 원본 소유자가 정한다 — 안 넣으면 다음에 묶음을 새로 받아 합칠 때 이 수정이 사라진다.

**확인한 것:**
- 시험 1410 → **1448 통과**(새 시험 38개 `tests/test_pure_expand.py`), 예상 실패 76·건너뜀 2 그대로. 먼저 실패하는 시험을 만들고 구현해 통과시켰다.
- 질문 변형 20개(원래 10 + 동사형 10) 모두 §2.1·§2.2가 Claude에게 가는 조각에 든다. 끄면 개발용 질문 83개 + 변형에서 검색 결과가 한 글자도 같다.
- 개발용 문서 질문의 정답 절 포함 38/40 → 38/40, **나빠진 질문 0**, 늘어난 부담은 평균 1.52개·931자. 봉인 세트(473개)는 마지막에 한 번만, 검색만 쟀다: 정답 절 포함 419 → 423, 나빠진 질문 0 (튜닝에 쓰지 않음).
- **진짜 Claude(켠 쪽 / 끈 쪽 사본, 가상 데이터):** 끈 쪽은 "6.1~7.3 내용은 문서에 없어요"라고 예전 결함 그대로 답했다. 켠 쪽은 질문 5개 표현 모두 작업 전 6단계를 원문대로 답했고 "없다" 단정이 없었다. 대조 질문은 영향이 없었다.

**남은 한계:**
- 보장은 **잠금 낱말 + DOC-05 §2 하나**에 박았다(`GUARANTEED`). 다른 안전 질문(고전압 대기·보호구 등)에 같은 모양의 놓침이 있는지는 따로 확인하지 않았다. 문서의 절 번호가 바뀌면 시험 `test_guarantee_anchor_exists_*`가 알려 준다.
- "시험·조정 5단계" 표는 원문에 있지만, 조각을 만들 때 "원문 뜻" 칸만 있는 표가 통째로 지워져서(`rag/sanitize`) 비서가 그 부분은 문서에 내용이 없다고 답한다(켠 쪽 답에서 확인). 원문 칸을 지우는 필터의 부작용이라 따로 정해야 한다.
- "설비 정비 전에 뭐부터 잠가?"의 답은 내용은 맞지만 절 순서를 재배열했다 — 질문이 "뭘 잠그나"라서 생긴 모양으로 보인다.
- 응답에 조각이 늘면 외부 Claude로 나가는 문서 조각도 늘어난다(최대 아래 절 4개·2,500자 + 보장 조각 1개). 지금은 가상 데이터만 쓴다.

## 운영 데이터 질문 — 되는 것과 아직 안 되는 것

| 질문 | 백엔드 도구 | 비고 |
|---|---|---|
| 설비 상태, 알람 횟수, 지표(OEE 등), 생산 실적, 로트(번호로), 작업지시, 작업기록, 예방 정비 기한, 공구 수명, 재고 | `equipment_status`·`alarms`·`kpi`·`production`·`lot`·`work_orders`·`work_records`·`pm_due`·`tool_life`·`inventory` | 된다 |

**백엔드/DB 담당과 정할 일(빠진 정보 3가지):** 필수 정지·계획 정지, 알람 건별·처리 여부·반복 알람 단계, 작업지시 번호로 로트 찾기. 필요하면 백엔드에 조회 도구를 더해야 한다(이번 작업은 백엔드를 고치지 않았다).
날짜 기본값(기간 없이 물으면 "2026-09-30까지 30일")은 묶음의 시연 기준 그대로다 — 실시간 시계를 따르게 하는 것은 아직 안 했다.

## 메모

- Windows에서 `pip install -r requirements.txt`는 `PYTHONUTF8=1`이 필요하다(`requirements.txt`의 한글 주석을 pip가 cp949로 읽다 실패). 원본 파일은 해시 때문에 고치지 않았다.
- 저장소에서 새로 받으면 줄바꿈이 CRLF로 바뀔 수 있어 MANIFEST의 해시와 달라진다 (해시를 다시 대조하려면 LF로).
- **올리지 않은 것 (2026-10-16):** 평가 결과물 `backend/eval/results*` 180개(5.4MB, 실행 결과·봉인 시험 답)는 git에 올리지 않는다. 시험이 읽지 않고 평가를 다시 돌리면 다시 생기는 파일이다. 평가 도구(`*.py`)와 질문 세트(`qa_*.json`, 시험이 읽는다)는 그대로 있다. 그래서 `MANIFEST.md` 해시 목록의 `results*` 줄은 이 저장소에 파일이 없다(원본 번들 쪽에는 있다). 다시 올라가지 않게 `assistant/.gitignore`에 규칙을 넣었다.
