**결정이 남은 결함 — "잠금 표지 순서" (안전)**: 새 길의 답이 "모든 설비에 공통인 잠금·표지 단계별 순서는 문서에 없다"고 했다(두 번 같은 답). **틀렸다**: DOC-05 §2.1(작업 전 6단계)·§2.2(작업 후 3단계)가 공통 순서다. 낱말 검색 상위 8개에 §2.1이 없고(질문 5가지 표현 모두 20위 밖), 새 길은 검색 결과를 그대로 Claude에 주므로 그 빈틈을 "문서에 없다"로 메운다. 기존 길(Claude 끈 규칙 답)도 §2.1을 못 찾지만 "없다"고 단정하지는 않고 §2의 일반 원칙을 보인다. 화면 예시 버튼 "잠금 표지 순서"가 이 질문이다. 고치는 방법 후보:
1. 새 길의 검색에 안전 낱말 보강(예: "잠금·표지·순서·LOTO" → "작업 전 6단계·작업 후 3단계")을 더한다 — 추가 묶음의 "원래 질문 그대로" 설계에서 벗어나는 작은 수정, 한 질문에 맞춘 땜질이 되지 않게 시험 필요.
2. 안전 낱말(잠금·표지·LOTO·고전압·차단)이 든 질문은 새 길에서 빼고 기존 길로 보낸다(`PURE_KEEP_SIGNALS`의 신호에 더함) — 기존 길도 §2.1을 못 찾는 점은 그대로.
3. 팀 문서 DOC-05 §2.1 본문·제목에 "잠금·표지 순서" 낱말을 넣도록 팀에 요청한다 — 문서는 팀 것.
4. 아무것도 안 하고 알려진 한계로 둔다.
→ 2026-10-16에는 어느 것도 적용하지 않았고, **2026-10-18에 고쳤다** (아래 "잠금 표지 순서 수정" 절 — 1번의 보강 아이디어와 부모 보장을 `PURE_EXPAND`로 합쳤다).

## 순수 길 본 답변을 Haiku 5.5로 — `PURE_MODEL` (2026-10-19, 코드 기본값 Haiku)

**문제:** 채팅(앱 외부 요청)의 Claude 모델은 `config.py`에 글자(`claude-sonnet-5-5`)로 박혀 있어 `.env`로 바꿀 수 없었다(`MOM_CLAUDE_MODEL`은 평가 경로 전용). 비교 실험에서 같은 30조각이면 Haiku 5.5의 정답 절 인용이 Sonnet 5.5와 같았고(73/75 대 73/75) list 가격은 약 1/17(호출당 0.011달러 대 0.193달러)이었다. 그래서 **측정한 곳 하나만** 모델을 고를 수 있게 했고, 사용자가 같은 날 **코드 기본값을 Haiku로** 하기로 정했다(아래 "기본값을 Haiku로"). 구독 한도가 이 가격에 비례하는지는 아직 모른다.

**고친 것 (스위치 `PURE_MODEL`, 코드 기본 `claude-haiku-5-5` = 줄이 없을 때, 줄을 비우면 Sonnet = 예전 동작, `.env.example`은 기본값과 같은 `PURE_MODEL=claude-haiku-5-5`):**
- `config.py`: 새 설정 `pure_model`(`flags()`에 보임), 허용 이름표 `CLAUDE_MODEL_NAMES`, 기본값 `PURE_MODEL_DEFAULT`. `get("PURE_MODEL", "claude-haiku-5-5")`로 읽으므로 **줄이 없을 때(Haiku)와 빈 줄 `PURE_MODEL=`(Sonnet)이 갈린다.** 값은 앞뒤 공백을 지우고 소문자로 바꾼 뒤 `claude-opus-5-5`·`claude-sonnet-5-5`·`claude-haiku-5-5` 중 하나일 때만 받는다. 오타(`haiku`, `claude-haiku`)나 모르는 이름은 **비움(= Sonnet)으로 되돌린다** — 가격표에 없는 모델이면 `claude_client.gate_problem`이 모든 외부 호출을 막기 때문이고, 오타는 보수적인 쪽(Sonnet)으로 간다. `config`가 `claude_client`를 import하면 순환이라 이름 집합을 `config`에 따로 두고, 시험이 `claude_client.PRICES`와 같은지 단정한다. `Settings.pure_model` 필드 자체의 기본값은 빈 문자열로 두었다(`Settings`를 직접 만드는 코드가 예전 동작을 받게). 새 속성 `Settings.pure_label`은 순수 길 `mode`의 이름표다.
- `llm/claude_client.py`: `_chat_json_claude` 맨 앞 — 작업 이름이 `pure_answer`이고 앱 외부 요청(`claude_app`)이고 `pure_model`이 있을 때만 설정 복사본의 `claude_model`을 바꾼다. 그래서 잠금 확인(`gate_problem`)·`--model` 인자·사용 기록·모델 불일치 검사가 모두 같은 값을 본다. 노력(`effort`)은 `medium` 그대로. 평가 경로(`MOM_CLAUDE_MODEL`)는 기본값이 Haiku여도 영향이 없다.
- `services/answer.py`: 순수 길 답의 `mode` 앞부분이 `s.pure_label`. Sonnet이면 예전과 한 글자도 다르지 않은 `외부 LLM(Claude Sonnet 5.5) · 순수 연결 …`, Haiku면 `외부 LLM(Claude Haiku 5.5) · 순수 연결 …`. 전역 이름표 `llm_label`(`/health`·단계 로그·옛 길)은 그 호출들이 Sonnet 그대로라 안 바꿨다.
- `.env.example`(`PURE_MODEL=claude-haiku-5-5` = 코드 기본값 + 윗줄 설명), `tests/conftest.py`(시험 기본을 빈 줄 = Sonnet 모드로 고정하는 한 줄 — 기존 시험은 그대로 통과), 새 시험 `tests/test_pure_model.py` 90개.

**기본값을 Haiku로 (사용자 결정 2026-10-19 "코드 기본값을 Haiku로 하자"):** 처음에는 기본 비움(= Sonnet)으로 만들었다가(커밋 2개) 같은 날 기본을 Haiku로 바꿨다. 달라지는 것: ① `.env`에 `PURE_MODEL` 줄이 없는 PC도 이 코드를 받고 비서를 다시 켜면 **저절로** Haiku가 된다 ② 줄이 없는 PC는 `PURE_TOPK`도 코드 기본 8이라 **Haiku k8**(재 보지 않은 조합)이 된다 — `PURE_TOPK=30`을 함께 두도록 안내한다(`PURE_TOPK`의 코드 기본은 이번 요청 밖이고 Sonnet 동작까지 바뀌어 **바꾸지 않았다**) ③ **위험:** 백엔드 대기가 기본 30초인 PC는 호출의 약 8%가 "응답 없음"이 된다 → 팀원 안내(`MOM_ASSISTANT_TIMEOUT_SECONDS=130`·`PURE_TOPK=30`·되돌리는 법 `PURE_MODEL=`)가 필수다 ④ 구독 한도 환산은 미확인. 시험이 보증하는 것: 줄 없음 → Haiku, 빈 줄·`claude-sonnet-5-5` 명시 → 예전 명령과 한 글자도 다르지 않음.

**바뀌는 호출, 안 바뀌는 호출:** 바뀌는 것은 `pure_answer`(질문 + 문서 조각 → Claude 1번) 하나이고, `PURE_RETRY`의 두 번째(넓게 다시 본) 호출도 같은 이름이라 같은 모델이다. **안 바뀌는 것(늘 Sonnet 5.5):** 카드 다시 쓰기·이어 묻기 쉽게의 `simplify`·`faith`, 이어 묻기 짧게의 `pick`, 옛 길의 `route`·`select`·`verify`·`phrase`·`write_answer`·`answer_faith`·`lead_faith`·`safe_simplify`·`safe_faith`, 문장 입구 `compose_*`. 안전 문장의 마지막 문인 뜻 판정 `faith`도 Sonnet에 남는다.

**측정 근거 (비교 실험, 진짜 Claude, 같은 75문항 점검표, `PURE_TOPK=30`·노력 `medium`):** 정답 절 인용 Haiku 73/75 = Sonnet 73/75(틀린 문항만 서로 1개씩 다름). 대신 Haiku가 느리다 — 한 번 호출 시간 중앙 17.3초(Sonnet 7.9초)·p95 34.6초(15.2초)·최대 53.5초(23.3초), 30초를 넘은 호출은 Haiku 6/75(8%)·Sonnet 0. 앱 안 읽기 제한 60초 안이지만 백엔드 기본 대기 30초에서는 그 8%가 "응답 없음"이 된다 → `MOM_ASSISTANT_TIMEOUT_SECONDS=130`이 필요하다([`실행_안내.md`](실행_안내.md) 8장 시간 제한 절).

**측정하지 않은 것:** 이어받기(`prev`)가 붙은 질문·고정 서식(`FIXED_BLOCK`)·규칙/고장 라우팅 노트가 붙은 질문에서의 Haiku, `PURE_TOPK=8`에서의 Haiku(30만 쟀다 — 줄이 없는 PC가 이 조합이 된다), 위 "안 바뀌는 것" 호출들의 Haiku(바꾸지 않았다), 구독 한도 소모, 사람이 화면에서 눌러 보는 확인. 이 변경의 시험은 모두 가짜 실행기이고 진짜 Claude는 부르지 않았다.

**켜기·끄기:** 이제 **켜는 일이 없다 — 기본이 Haiku다.** 코드를 받고 비서를 다시 켜면 된다(그 뒤 값만 바꿀 때는 요청마다 읽는다). 같이 할 것: `assistant/.env`에 `PURE_TOPK=30`(예시 파일 값) + 백엔드 `.env.supabase`의 `MOM_ASSISTANT_TIMEOUT_SECONDS=130`. **Sonnet으로 되돌리기 = `assistant/.env`에 `PURE_MODEL=` 한 줄(비움)** (줄을 지우면 기본값 Haiku로 돌아간다. 예시 파일을 복사해 만든 `.env`는 `PURE_MODEL=claude-haiku-5-5`가 들어 있어 Haiku다).

**시험:** 전체 2300 passed, 2 skipped, 81 xfailed(기준선 2210 + 새 시험 90). 기존 시험 파일은 고치지 않았다 — 시험 공통 고정물 `conftest.py`가 `PURE_MODEL`을 빈 줄(Sonnet 모드)로 고정해 두기 때문이다. 새 시험이 단정하는 것: 줄 없음(환경변수 삭제 + `.env` 없음) → `pure_answer`만 Haiku, 나머지 17종은 Sonnet / 빈 줄·`claude-sonnet-5-5` 명시 → 호출 이름 18종 모두 명령 전체가 예전과 같다(`--model claude-sonnet-5-5 --effort medium`) / `.env` 파일에 줄이 없거나 다른 줄만 있으면 Haiku, `PURE_MODEL=`이면 Sonnet / 두 번째(넓게 다시 본) 호출도 같은 모델 / 오타·모르는 이름은 Sonnet이라 호출이 막히지 않음 / 평가 경로·로컬 요청은 영향 없음 / Haiku를 요청했는데 Sonnet이 답하면(반대도) 실패 / 사용 기록의 모델 / 이름표 글자 / `.env.example`의 `PURE_MODEL=` 줄이 코드 기본값과 같음.

## 일일 보고서 "오늘의 문제" — 미리 만든 9/30 초안에도 문장 다듬기를 이었다 (2026-10-19, 시연 서버만)

## 분류(`route`) 검색어가 4개거나 40자를 넘어도 응답을 버리지 않는다 — `trim_queries` (2026-10-19)

## 알림 탭 알람 상세 본문 — 비서 문장을 이었다 (2026-10-19, 비서 + 시연 서버 + 화면)

기획서(4.3)·요구사항 FR-AST-02-14·UI설계서 SCR-07은 "알림 문장은 비서가 쓴다(알릴지·중요도는 규칙)"고 하는데, 알림 탭의 글은 전부 프로그램 문구였고 비서를 부르는 곳이 없었다(비서 문장 종류 5개에 알림이 없음). 알림 탭 **알람 알림 상세의 본문 한 문장**에 이었다. 목록 제목·"관련:" 줄·문서 알림은 그대로다.

- `assistant/backend/llm/compose.py`·`compose_service.py`: 새 종류 `alarm_notice`(`POST /compose/alarm_notice`). 설비·공정·알람 번호·로트·사건 코드·시각(식별 낱말)이 하나라도 빠지거나 바뀌면 거부하고, 심각도(정지·주의·조작 안내)·"해제"·"코드집에 없음"·"보전 담당자 호출"·"사건"·"로트"는 원문에 있으면 있어야 하고 없던 것이 생겨도 거부한다. 원문에 없던 원인·지시·안전 낱말(원인·조치·점검·교체·잠금·표지·차단·전원 …)과 글자 유사도 0.5 미만도 거부한다. **지침만 믿지 않고 코드가 대조한다**(브리핑에서 지침만으로는 못 지킨 교훈). 지침에는 "원문이 이미 읽기 쉬우면 그대로", "고쳐 쓸 때만 합니다체로, 반말('…났다')로 끝내지 않기"를 둔다.
- `frontend/tools/sim_server.py`: `POST /api/assist/alarm-text`(`alarm_text`). 알림 하나(`a-<알람 번호>`)에 한 줄. 비서를 **기다리지 않고** 부르고, 문장이 바뀌면(알람 해제) 옛 문장을 주지 않고 새로 만든다. 사용자가 연 알림만 부르므로 안 연 알림은 비서로 안 나간다.
- `frontend/src/shell/alarmText.ts`(새, 순수 함수 `alarmSentence`)·`assistText.ts`(`useAlarmText`)·`Eve.tsx`(`AlarmBody`): 상세를 열면 프로그램 문장을 보이다가 준비되면(4초마다 최대 30번 물음) 비서 정리로 바꾸고, 원문과 다르면 "비서 정리" 꼬리표와 **[원문 보기]**. 꺼짐·실패·탈락은 프로그램 문장 그대로다(예전 화면 글자와 192가지 조합이 글자까지 같음을 `tools/alarm_text_check.mjs`가 지킨다).
- `assistant/backend/services/notifications.py` 3행 주석: 옛 "지금은 로컬 LLM이 없어 기본 문구" 표현을 구현에 맞게 고쳤다(이 서비스의 알림 API는 기본 문구를 주고, 시연 화면 알람 상세 본문은 `alarm_notice`가 다듬는다).
- 켜는 법: 따로 없다 — 시연 서버의 같은 문장 스위치(`MOM_LLM_COMPOSE=1`)를 쓴다(6-3절). **합친 뒤 비서(8100) → 시연 서버(8765) 순서로 다시 켜야** 반영된다(거꾸로면 비서가 모르는 종류라 422, 시연 서버가 쉬었다 원문).
- 확인 (2026-10-19, 알람 기록 37개 조합 × 해제 전·뒤 + 코드집 보강 8 + 사건 S1·S3·S4·S6 + 코드집에 없음 2 = 96줄, 줄 하나씩 진짜 Claude): 호출 통과 **96/96**, 첫 시도 통과 94, 지연 중앙값 4.3초·p95 9.8초·최대 11.5초, 독립 점검 불일치(식별 낱말·숫자·심각도·해제·새 낱말·문장 수) **0**, 글자 유사도 중앙값 0.955·최소 0.897, 바뀐 줄 76·원문 그대로 20, 반말 끝맺음 0. 지침을 세 번 비교했다: ① 지침만(합니다체 없음) 96/96·첫 시도 93·원문 그대로 73·**반말 8/23** ② "등급입니다"까지 강제 95/96·첫 시도 **52**·중앙값 9.1초·최대 61.4초·96줄 전부 다시 씀("조작 안내 등급입니다. 로트 LOT-…입니다") — 나빠서 버림 ③ "고쳐 쓸 때만 합니다체"(지금 코드) 위 값. 시험: 비서 2318 → 2335, compose 56 → 73, 시연 서버 도구 76 → 89, `alarm_text_check.mjs` 7개(새), `tsc` 오류 0.
- **한계:** 기본 문장이 짧아서(평균 57자) 비서가 하는 일은 대부분 "— 주의." → "— 주의가 났습니다."처럼 끝 조각을 문장으로 잇는 정도다. 읽기 쉬워졌는지는 숫자로 못 재고, 알람 이름·누가 조치하나를 문장에 더하면 달라진다(후속, 원문이 바뀌므로 따로 정한다).
- **확인 못 한 것:** 브라우저에서 알림을 눌러 본 것(첫 열림에 프로그램 문장 → 5~15초 뒤 바뀌는 모양). 시연 서버(8765)를 새 코드로 띄워 `alarm-text`를 실제로 불러 본 것(하나 더 띄우면 `cmm_drop`이 지워져 못 했다 — 합친 뒤 재시작해서 확인). 해제로 문장이 바뀌는 순간의 화면 동작은 함수·시험으로만 봤다.

## 메모

- Windows에서 `pip install -r requirements.txt`는 `PYTHONUTF8=1`이 필요하다(`requirements.txt`의 한글 주석을 pip가 cp949로 읽다 실패). 원본 파일은 해시 때문에 고치지 않았다.
- 저장소에서 새로 받으면 줄바꿈이 CRLF로 바뀔 수 있어 MANIFEST의 해시와 달라진다 (해시를 다시 대조하려면 LF로).
- **올리지 않은 것 (2026-10-16):** 평가 결과물 `backend/eval/results*` 180개(5.4MB, 실행 결과·봉인 시험 답)는 git에 올리지 않는다. 시험이 읽지 않고 평가를 다시 돌리면 다시 생기는 파일이다. 평가 도구(`*.py`)와 질문 세트(`qa_*.json`, 시험이 읽는다)는 그대로 있다. 그래서 `MANIFEST.md` 해시 목록의 `results*` 줄은 이 저장소에 파일이 없다(원본 번들 쪽에는 있다). 다시 올라가지 않게 `assistant/.gitignore`에 규칙을 넣었다.
