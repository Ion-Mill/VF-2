# 생산 파트 가상 데이터 현실성 벤치마크 (외부 조사)

> 작성일: 2026-10-03 / 대상: `AUTOMOTIVE_MACHINING_SYNTHETIC_DATA_PLAN.md` v0.1의 가정값 검증
> 작성 방식: WebSearch 결과 요약 + WebFetch 직접 열람. 수치는 출처에 나온 것만 적었고, 없으면 "근거 없음"으로 표시했다.

## 읽는 법

- **확인 방식**
  - **직접 확인** = WebFetch로 페이지를 열어 본문에서 확인한 값.
  - **검색요약** = 검색 결과 요약 문장만 본 값. 원문 미열람이므로 인용 전에 원문 확인이 필요하다.
- **신뢰도**
  - 상 = 표준·논문·제조사 공식 자료.
  - 중 = 업계 매체, 논문 초록, 학술 사례 1건.
  - 하 = 솔루션 업체 블로그(마케팅 성격), 포럼 글, 단일 사례.
- **연도**: 검색 결과에 연도가 안 보이면 "미확인"으로 적었다. 확인하지 않고 채우지 않았다.
- **주의**: 검색 결과 상당수가 OEE 소프트웨어 업체 블로그(Fabrico, Tractian, Teeptrak, Harmoni, Oxmaint, iFactory 등)다. 이 값들은 "범위의 감"으로만 쓰고 근거로 단정하지 않는다.

## 부록: 확인 중 발견한 주의점

1. **월드클래스 85% 구성이 출처마다 다르다.**
   - oee.com 열람 결과는 90/90/90 으로 요약되었는데, 이 셋의 곱은 약 72.9%여서 85%와 맞지 않는다.
   - 다른 출처는 90/95/99.9 (곱 약 85.4%)로 서술한다.
   - 심사 자료에는 "85%"만 쓰고 구성은 Nakajima 원전(1984, 영문 1988)을 직접 확인한 뒤 인용하는 편이 안전하다. 원전은 이번에 열람하지 못했다.
2. **일부 URL은 검색 결과 목록에서 가져온 후보**다. "매칭 불확실", "후보", "원문 확인 필요"로 표시한 항목은 인용 전에 열어서 해당 수치가 실제로 있는지 확인해야 한다.
3. **재사용 가능한 방법**: ProdSim과 SmartManPy 모두 설계안의 자체 생성기(config.yaml + seed + 이벤트 규칙)에 붙여 쓰기보다 "방법 참고"로 쓰는 것이 현실적이다. 특히 SmartManPy의 드리프트·특성값 기반 불량 발생 방식은 설계안 5.12(평균 이동에 따른 불합격)와 개념이 같다. 라이선스는 SmartManPy가 LGPL, ProdSim은 미확인.
4. 이번 조사는 검색·열람 횟수가 제한적이다. 신뢰도 "상"으로 분류할 수 있는 표준 원문(AIAG PPAP, ISO 22400 등)과 Nakajima 원전은 직접 열람하지 못했다.
