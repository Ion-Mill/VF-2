**③ 현장 보기** (새 SCR-26, FR-PRD-01-28, NFR-USE-09)
- OPR 첫 화면이다. 3D가 화면 대부분을 차지하고, 옆 띠에 브리핑 5줄과 처리 안 된 알람을 보여 준다. 띠가 넘치면 "외 N건"으로 보이고, 누르면 전부 볼 수 있다.
- 긴급 팝업은 화면 대부분을 덮을 만큼 크게 뜬다.
- 글자 크기는 **보는 거리 식**을 따른다 [실제: NUREG-0700]: 최소 글자 높이 = 거리 × 0.00465 (3 m에서 약 14 mm).
- 터치 버튼은 **44 × 44 CSS px와 실제 10 mm 이상**을 둘 다 만족해야 한다.

**④ 출처** (FR-MNT-01-07·09, FR-MNT-02-12, FR-AST-COM-02·04)
- 출처는 **사내 문서 이름 + 번호 + §절**로 적는다. 쪽 번호와 원문 출처는 붙이지 않는다.
- 사내 문서 **본문 안**의 [실제]/[참고] 출처와 원문 대응표는 그대로 둔다. 사람이 근거를 추적하는 용도다.
- 검색용 문서 조각에도 원문 출처를 넣지 않는다.

### 2.3 AI 비서

**① 전부 보고 — 보고 순위** (새 FR-AST-COM-21, DOC-07 §10.5)

| 순위 | 들어가는 것 |
|---|---|
| 0 안전 | 잠금·표지 중인 설비 |
| 0-1 | 24시간 넘게 처리 안 된 주의 알림 |
| 1 긴급 | 처리 안 된 정지 등급 알람, 지금 멈춘 설비 |
| 2 생산 위험 | 목표 미달, 병목, 로트 납기 지연 |
| 3 주의 | 반복 알람(2단계 → 1단계), 주의 등급 알람, 품질, 공구 90%, 정비 기한 넘김, 재고 부족, 승인 대기 2시간, CMM 알림 |
| 4 참고 | 조작 안내, 정비 하루 전, 승인 대기 30분, 교대 보고서 확정 요청, 문서 수정 알림 |

- "전체 N건"과 순위별 건수를 항상 보여 준다. 순위 0·0-1·1은 접지 않는다.
- 브리핑 1분은 목표일 뿐이고, 1분에 맞추려고 항목을 빼지 않는다.
- 적용하는 곳: 브리핑 "먼저 챙길 일", 일일 보고서 "오늘의 문제", 일일 보고서 손실 칸(손실 전체, 큰 순서), 교대 보고서 인계 사항.

**② 필수 정지** (FR-PRD-02-04, DOC-07 §5.4)
- 정지 사유가 고장 그룹(F01~F06)이면서 **5분 이상**인 정지는 모든 공정에서 전부 싣는다.
- 순서: 정지 시간이 긴 순서 → 손실 수량이 큰 순서.
- 5분 미만 순간 정지는 건수와 합계만 한 줄로 적는다. 소재 대기(M01)는 넣지 않는다.

**③ 반복 알람 2단계** (FR-AST-02-03, 새 FR-AST-02-18, DOC-03 §1.4, DOC-07 §10.4)

| 단계 | 언제 | 무엇을 |
|---|---|---|
| 1단계 | 같은 설비·같은 알람이 7일 안 3번 | 주의 알림 + 지난 조치 + 관련 사내 문서 근거(DOC-03). MNT·SUP가 조치 계획 한 줄 작성 |
| 2단계 | 조치 계획을 쓴 뒤 **7일 안에 또 남** [가상] | "지난 조치 효과 없음" 알림 + **원인 점검** |

- 원인 점검 작업지시서 AI비서 초안은 **OP-30만** 만든다. 다른 공정은 작업지시서 없이 MNT에게 원인 점검을 요청하고, 결과를 간이 작업기록으로 남긴다.
- OP-30 정지 등급 알람이 2단계와 겹치면 작업지시서를 **1개만** 만들고 계기 두 개를 함께 적는다.
- 조치가 진행 중일 때 난 알람은 세지 않는다. 1분 묶기를 먼저 적용한다. 원인 점검 뒤 7일 동안 다시 나지 않으면 "효과 확인"으로 닫는다.
- 가상 데이터 사례: VF2-02 알람 108. 9/8~9/10에 1단계, 9/14에 2단계, 9/15에 원인 점검.

**④ 병목 원인별 조치** (새 FR-AST-02-19, DOC-07 §7.5)

| 원인 | 조치 제안 (사람이 실행) |
|---|---|
| ① 공구 마모로 사이클 증가 | 공구 수명 확인 → 사이클이 끝난 뒤 교체, 교체 뒤 초품 검사 |
| ② OP-30 1대만 가동 | 끝나는 시각 안내, 앞 공정 투입 조절, 예방 정비를 교대 사이로 옮길지 검토 |
| ③ 검사 강화 | 보류 로트 판정 서두르기, 강화 범위 확인 (검사 항목은 줄이지 않음) |
| ④ 묶음 대기 | 병목에서 제외 |
| 고장 | DOC-03 점검 순서. 병목 공정 수리를 먼저 |

- 근거는 TOC 5단계, Subramaniyan 2018, Roser 2003이다.
- 안전·검사 기준을 줄이는 제안은 하지 않는다.

**② CMM 측정 자동 입력** (FR-QLT-01-01, 새 FR-QLT-01-14~22, DOC-06 §3.6)
- 측정기 소프트웨어가 부품 하나를 잴 때마다 **CSV 결과 파일**을 공유 폴더에 쓰고, 플랫폼이 읽어 기록한다 [제안]. 대안은 QIF(ISO 23952)다.
- 플랫폼은 로트 번호·순번·검사 방식을 측정기에 넘기고, 결과 파일에 같은 값이 돌아와야 기록한다.
- 사람이 하는 일은 로트 바코드 확인, M6 게이지·외관 결과 버튼, 로그인(측정자)뿐이다. 나머지는 자동이다.
- 플랫폼이 판정을 다시 계산해 측정기 판정과 다르면 반장이 확인한다. 파일을 못 읽거나 결과가 안 오면 알림이 간다(주의, 처리 SUP). 수동 입력에는 "수동" 표시를 남긴다. 다시 잰 값은 덮어쓰지 않고 보관한다.
- 부품 온도 칸을 새로 둔다. 16~26 ℃ 밖이면 "온도 확인" 표시를 붙인다.
- CMM-01 모델은 [참고] Hexagon TIGO SF로 두었다. 기존 알람 MP-170·TempComp-202는 PC-DMIS 계열 모양을 빌린 [가상] 코드라고 밝혔다.
