# 생성기 기준 정보 목록

> 가상 데이터 생성기를 만들기 전에 **사람이 직접 써야 하는 입력**(`config.json` + 기준 정보 CSV)을 정리한 목록이다.
> 작성: 데이터·ML 담당 / 2026-10-08
> 근거: [가상데이터설계서_최종본.md](../가상데이터설계서_최종본.md) 4·5·10·12장, [논리ERD_최종본.md](../논리ERD_최종본.md) 5장(속성)·6장(코드 목록)
> 이 폴더(`생성기/`)는 설계서 10장의 `simulator/` 자리다. 생성기 코드와 입력·출력을 여기에 둔다.

---

## 1. 규칙

| 규칙 | 내용 |
|---|---|
| CSV 칸 이름 | **논리 ERD 속성 이름 그대로** (API 명세서 1장 "응답 칸 이름 = ERD 속성 이름"과 같음). 파일 이름 = 엔터티 이름 |
| 계산 칸 | ERD에 "**계산**"으로 적힌 칸은 CSV에 넣지 않는다 (생성기·플랫폼이 계산) |
| 근거 표시 | [가상]·[참고]·[실제]가 필요한 값은 ERD의 `source_tag` 칸 등에 넣는다. 근거 없는 기준 숫자는 만들지 않는다 |
| 코드 값 | ERD 6장 코드 목록의 코드를 그대로 쓴다 |
| 형식 | 설정은 JSON, 기준 정보는 CSV(UTF-8). 생성 결과도 CSV → DB 적재 (설계서 10장) |

## 2. 폴더 구조 (설계서 10장)

```
생성기/
  기준정보_목록.md       이 문서
  기준정보_CSV_설명.md   masters/ CSV 설명
  config.json            기간, 교대, 목표, 확률 값, seed, 실시간 설정 (3장)
  requirements.txt       라이브러리 버전 고정 (numpy, pandas, pytest)
  .venv/                 Python 3.12 가상환경 (각자 PC에서 만듦, 저장소에 안 올림)
  masters/               기준 정보 CSV 22개 (4·5장, 2026-10-14 알림 규칙·사내 문서 추가)
  generate.py            과거 기록 모드 (9/1~9/30)
  realtime.py            실시간 모드 (10/1) + 사건 버튼
  scenarios/             사건 버튼 S1·S3·S4·S6 정의 (JSON) + 리허설 대본
  validate.py            9장 점검
  gen/                   생성기 부품: common(공통) · calendar(달력·교대) · plan(원자재·알람·정비 계획) ·
                         flow(1분 단위 시간 흐름) · records(결과 칸 모양) · pm(예방 정비 기록) ·
                         mnt_docs(작업지시서·작업기록서) · doc03(DOC-03 읽기) · stage4(검사·보류·재고·출하·병목·센서) ·
                         quality(측정값) · past · realtime(10/1) · reports(보고서·문서 버전) · notify(알림)
  tests/                 pytest 시험 (pytest.ini)
  out/                   생성 결과 CSV + manifest.json → DB 적재
```

### 2.1 개발 환경 (2026-10-13 정함)

| 항목 | 정한 것 | 이유 |
|---|---|---|
| Python | **3.12** (3.12.10에서 확인) | 라이브러리 지원이 가장 넓다. PC에 3.12·3.13·3.14가 함께 있으면 터미널과 VS Code가 서로 다른 버전을 잡을 수 있어 버전을 못 박는다 |
| 가상환경 | `생성기/.venv` | 팀원마다 같은 라이브러리 버전 → 같은 seed면 같은 결과 |
| 라이브러리 | numpy 2.4.3 (seed 고정 난수), pandas 3.0.1 (CSV 읽기·쓰기, 점검 집계), pytest 9.1.1 (점검 시험) — `requirements.txt`에 고정 | 꼭 필요한 것만. 버전이 바뀌면 같은 seed라도 결과가 달라질 수 있다 |
| VS Code | 폴더의 `.vscode/settings.json`이 `생성기/.venv`의 Python을 쓰게 한다 (pytest도 여기서 실행) | VS Code 기본 인터프리터와 상관없이 같은 환경 |

**팀원 PC에서 처음 한 번** (Windows, `생성기/` 폴더에서 — 팀원용 안내는 [실행_안내.md](실행_안내.md))

```
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\python generate.py
```

### 2.2 결과 형식 (`out/`, 2026-10-13 정함)

| 항목 | 규칙 |
|---|---|
| 파일 | 엔터티마다 CSV 1개, 이름 = 논리 ERD 엔터티 이름 (예: `out/alarm_event.csv`). 칸 = ERD 속성 이름, **계산 칸은 넣지 않는다** (1장) |
| 글자 | `masters/`와 같다: UTF-8 (BOM 없음), 쉼표 구분, 첫 줄 = 칸 이름, 참·거짓 `true`/`false`, 빈칸 = 값 없음 |
| 날짜시각 | **`2026-09-01T08:00:00+09:00`** (초까지, 한국 시각 +09:00 — API 명세서 1장과 같은 모양). 날짜만인 칸은 `2026-09-01` |
| 코드 | ERD 6장 코드 그대로 |
| 줄 순서 | 기본 키 순서 (같은 seed면 파일이 글자 하나까지 같게) |
| 덮어쓰기 | 실행할 때마다 `out/`의 CSV를 지우고 다시 쓴다. 같은 seed·설정이면 같은 결과라 이전 결과는 다시 만들 수 있다 |
| `out/manifest.json` | 만든 시각, seed, `config.json`·`masters/` 해시(SHA-256), Python·numpy·pandas 버전, 파일별 행 수, `validate.py` 결과 요약(통과·실패 줄) |
| 원문 칸 | `alarm_master.original_desc`처럼 원문(저작권 자료)이 들어갈 칸은 비운다 |
| DB 적재 | 백엔드·DB 담당이 `out/` CSV를 그대로 적재. 시간대·자료형은 [선택 필요: 기술 회의] |
