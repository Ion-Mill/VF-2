## 2. 데이터만 쓰는 경우 (설치 없이)

`생성기/out/`과 `생성기/out_realtime/`의 CSV를 바로 쓴다. 파일 목록과 행 수는 **8장**.

| 항목 | 규칙 (ERD 11.1) |
|---|---|
| 파일 | 엔터티 1개 = CSV 1개. 파일 이름 = 엔터티 이름 (예: `production_lot.csv`) |
| 칸 | 첫 줄 = 논리 ERD 5장 속성 이름, 같은 순서. "계산" 속성은 없음 |
| 글자 | UTF-8 (BOM 없음), 줄 끝 CRLF |
| 값 | 빈칸 = NULL, 참·거짓 = `true`/`false`, 날짜 = `2026-09-01`, 날짜시각 = `2026-09-01T08:00:00+09:00` |
| 넣는 순서 | `masters/`(기준 정보) → `work_day`·`shift` → `raw_material_lot`·`production_order`·`production_lot` → 나머지 |

- `out_realtime/`은 **권장 시연 순서 대본**(`리허설_권장순서.json`)으로 돌린 결과다. 4장 ④를 돌리면 내 PC에서 덮어써진다.

## 3. 처음 한 번 설치 (Python 3.12)

**필요한 것:** Windows, **Python 3.12** ([python.org](https://www.python.org/downloads/)에서 3.12 설치. 설치 화면에서 "py launcher"를 체크. 다른 버전이 있어도 같이 깔면 된다)

`11_automotive\생성기` 폴더에서 PowerShell을 열고 두 줄을 실행한다.

```
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
```

| 줄 | 하는 일 |
|---|---|
| 1 | 이 폴더 안에 Python 3.12 전용 환경(`.venv`)을 만든다 (저장소에는 없음, 각자 만듦) |
| 2 | 정해진 버전의 라이브러리(numpy 2.4.3, pandas 3.0.1, pytest 9.1.1)를 그 환경에 설치한다 |

- 모두 같은 버전을 써야 **같은 seed로 같은 데이터**가 나온다. 그래서 PC에 원래 있던 Python을 쓰지 않는다.
- **VS Code**: `11_automotive` 폴더를 열면 `.vscode/settings.json` 때문에 자동으로 `생성기/.venv`의 Python을 쓴다. 안 되면 오른쪽 아래 Python 버전 글자를 눌러 `생성기\.venv\Scripts\python.exe`를 고른다.
- VS Code 터미널: 메뉴 **터미널 → 새 터미널**, 오른쪽 위 **＋ 옆 ∨** 에서 **PowerShell**. 그다음 `cd 생성기`.

## 4. 실행 순서

`생성기` 폴더에서 **이 순서대로** 실행한다. ①을 먼저 해야 ②·③이 된다 (②·③은 `out/sensor_sample.csv`를 읽는데, 이 파일은 ①이 만든다).

| 순서 | 명령 | 하는 일 | 걸리는 시간 | 잘 됐으면 마지막에 |
|---|---|---|---|---|
| ① | `.venv\Scripts\python generate.py` | 9/1~9/30 과거 기록 만들기 → `out/` (덮어씀) + 점검 | 약 1분 반 | `out/ 34개 파일, VF2-01 T05 9/30 끝 90%` / `점검: 통과 87 / 실패 0 / 참고 2` |
| ② | `.venv\Scripts\python validate.py` | `out/` 점검만 다시 (89줄을 모두 보여 줌) | 약 30초 | `통과 87 / 실패 0 / 참고 2` |
| ③ | `.venv\Scripts\python -m pytest` | 시험 9개 | 약 15초 | `9 passed` |
| ④ | `.venv\Scripts\python realtime.py --script 리허설_권장순서.json` | 10/1 실시간 모드를 권장 시연 순서 대본대로 (기다리지 않고) → `out_realtime/` (덮어씀) + 점검 | 수 초 | `점검: 통과 18 / 실패 0` + `[WARN] 10/1 주간 실적 … 62개` |
| ⑤ | `.venv\Scripts\python realtime.py --live` | 실제 시간으로 돌리며 키보드로 조작 (5장) | 원하는 만큼 | q를 누르면 저장·점검 |

- `realtime.py`만 쓰면(대본 없이) 사건 버튼을 누르지 않는 대본(`리허설_버튼없음.json`)으로 돈다 → `점검: 통과 19 / 실패 0`.
- ①은 실패가 있으면 끝 코드 1로 끝난다. 참고(WARN) 2개는 알고 있는 것이다 (7장).
- 설정은 `config.json`, 기준 정보는 `masters/` (설명: [기준정보_CSV_설명.md](기준정보_CSV_설명.md)), 대본·사건 정의는 `scenarios/`.

## 5. 10/1 실시간 모드 직접 보기 (`--live`)

```
cd 생성기
.venv\Scripts\python realtime.py --live
```

10/1 08:00부터 9/30 끝 상태를 이어받아 1분씩 돈다. 무작위 알람은 없고, 고장·주의 사건은 **사건 버튼**으로만 생긴다.

화면: 맨 아래 줄 = 지금 상태, 그 위로 쌓이는 줄 = 사건 기록.

```
08:00 VF2-01 → 셋업 — 교대 시작·끝 점검 (S04)
08:01 SAW-01 → 대기 — 계획 없음 (P03)
[08:03:24] ×60  진행  완료 1  재공 15/28/1/0  병목 OP-30(BASE)
```

| 칸 | 뜻 |
|---|---|
| `[08:03:24]` | 공장 시각 (10/1) |
| `×60` | 배속. 60배 = 실제 1초에 공장 1분 |
| 완료 | 10/1에 OP-50까지 끝난 부품 수 |
| 재공 | 재공 자리 4곳: OP-10→20 / 20→30 / 30→40 / 40→50. OP-20→30은 병목 앞이라 평소 20~30개 |
| 병목 | 지금 병목 공정(원인). BASE = 기준 병목 |
| `→ 가공/대기/막힘/셋업/고장/정비` | 설비 상태가 바뀜 (RUN/IDLE/BLOCKED/SETUP/DOWN/MAINT). 뒤는 정지 사유 이름(코드) |

| 키 | 동작 |
|---|---|
| 1 / 2 / 3 / 4 | 배속 180 / 60 / 10 / 1배 |
| 스페이스 | 일시정지 / 다시 시작 |
| s | 17:00으로 넘기기 |
| r | 10/1 08:00으로 처음부터 |
| q | 끝내기 — 그때까지 기록을 `out_realtime/`에 저장하고 점검 |
| **5 / 6 / 7 / 8** | **사건 버튼** S1 충돌 / S3 공구(T05) / S4 공기 압력 / S6 VF2-02 정비 (대상 설비가 가공 중일 때만, 진행 중인 사건이 있으면 잠김) |
| h | 의심 로트 보류 (S1 충돌 뒤) |
| t | T05 공구 교체 기록 |
| w | 작업기록서 확정 → VF2-01 복귀 (S1 뒤) |
| u | 보류 로트 해제 (전수 판정이 끝난 뒤) |

- 10배·1배는 공장 시계가 느려서 멈춘 것처럼 보일 수 있다. 시각의 **초**가 움직이면 정상이다.
- 한글 입력 상태여도 키가 먹는다 (ㄴ·ㄱ·ㅂ 등도 같은 키로 받음).
- T05는 08:00에 90%라, 약 1시간 안에 `t`(교체 기록)나 `6`(S3)을 누르지 않으면 한도 → 362 알람이 난다.
- 측정기가 부품을 잴 때마다 `out_realtime/cmm_drop/`에 결과 파일(CSV)이 하나씩 생긴다 (백엔드 결과 파일 읽기 시험용).

## 6. 자주 생기는 문제

| 증상 | 해결 |
|---|---|
| `validate.py`나 `pytest`에서 `sensor_sample.csv` 파일이 없다는 오류 | 저장소에는 이 파일이 없다. **4장 ① `generate.py`를 먼저** 돌린다 |
| `realtime.py`에서 "먼저 generate.py로 과거 기록(out/)을 만든다" | `out/manifest.json`이 없는 것. `git pull`이 끝났는지 보거나 ①을 돌린다 |
| Git Bash에서 `.venvScriptspython: command not found` | Git Bash는 `\`를 지운다. PowerShell을 쓰거나, Git Bash에서는 `.venv/Scripts/python`처럼 `/`로 쓴다 (`--live` 키 입력은 PowerShell에서만) |
| `py`가 없다고 나옴 | Python 설치 때 "py launcher"를 체크하지 않은 것. 다시 설치하거나 `C:\...\Python312\python.exe -m venv .venv`처럼 전체 경로로 실행 |
| `ModuleNotFoundError: numpy` 등 | `.venv\Scripts\python`이 아닌 다른 Python으로 실행한 것. 위 명령처럼 `.venv\Scripts\python`으로 실행 |
| 엑셀에서 CSV 한글이 깨짐 | CSV는 BOM 없는 UTF-8. 엑셀 **데이터 → 텍스트/CSV에서** → 파일 원본 "65001: 유니코드(UTF-8)"로 연다. VS Code로 열면 그대로 보인다 |
| ① 뒤 `git status`에 `out/manifest.json`만 바뀌었다고 나옴 | 정상. 만든 시각(`created_at`)만 바뀐 것이다 (7장 ④) |
| 팀원과 결과가 다름 | `out/manifest.json`의 `seed`·`config_sha256`·`masters_sha256`·`python`·`numpy`·`pandas`를 비교한다. 다르면 데이터·ML 담당에게 |
