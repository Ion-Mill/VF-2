# 비서·시뮬레이터·DB 연결 — 팀과 논의할 것 (2026-10-17)

- 읽는 사람: 시뮬레이터(생성기), 백엔드, DB, 화면 담당
- 쓴 이유: 비서(LLM) 담당이 교대 보고서·작업지시서·지침카드·브리핑에 LLM 글을 붙이려고 현황을 확인하다가, **혼자 정할 수 없는 것**을 찾았다. 그것을 한곳에 모았다.
- 상태: **논의용 초안.** 팀이 정한 것은 없다 (비서 담당이 정한 방향은 3-1장과 4장). **4장(비서 LLM = 외부 Claude 하나)은 2026-10-17 확정되어 팀 안건에서 뺐다.** **[제안]**은 비서 담당의 제안이고 **[선택 필요]**는 팀이 정해야 하는 것이다.
- 비서 담당의 방침: **비서 관련 기능은 계속 DB를 쓴다.** (지금처럼 비서 서비스가 백엔드 조회 도구를 거쳐 DB를 읽고, 채팅 기록은 DB에 남긴다)
- 확인한 날짜와 방법: 2026-10-17. 코드와 문서를 읽었고, 공용 DB는 읽기 전용(SELECT)으로 개수·시계만 조회했다. 쓰기와 비밀번호 출력은 없다.
- 이 문서는 아무것도 고치지 않았다. 코드 작업은 논의 결과를 보고 한다.

## 0. 10줄 요약 (쉬운 말)

1. 비서는 DB를 쓴다. 그런데 **시연 화면의 데이터는 DB가 아니라 시연 서버(`tools/sim_server.py`)에서 온다.**
2. 시연이 시작된 뒤(10/1 08:00~) 시뮬레이터가 만드는 알람·교대·실적은 **DB에 들어가지 않는다.** DB에는 9월~10/1 04:23 기록만 있다.
3. 백엔드에는 사건을 받는 입구(`/api/ingest/*` 11개)가 이미 있다. 그런데 **그것을 부르는 코드가 시뮬레이터 쪽에 없다.**
4. 그래서 비서(채팅·지침카드·브리핑·보고서)는 시연 중 새로 생긴 일을 DB에서 볼 수 없다.
5. 이 연결은 시뮬레이터 머리 주석에 `[선택 필요: 기술 회의]`로 적혀 있고, 아직 정해지지 않았다.
6. API 명세서 4장은 서버가 교대·일일 보고서와 작업지시서 초안을 **스스로** 만든다고 적었다. 즉 DB 중심이 설계 의도다.
7. DB 시계(`sim_clock`)는 지금 **10/1 08:00에 멈춰 있고**, 시연 기준점(`demo_snapshot`)은 비어 있다.
8. 비서 LLM은 **외부 Claude 하나**로 **확정**했다 (2026-10-17, 비서 담당). 요구사항 **NFR-SEC-08**("외부 LLM으로 보내지 않는다")과 달라서 문서를 고쳐야 하며, 팀에는 알린다. 안건에서는 뺐다. 상세: `외부LLM_단일_전환_제안_20261017.md`.
9. 화면 담당과 정할 것도 있다: 채팅 답 형식, 브리핑이 문장을 쪼개 쓰는 방식, 일일 보고서 모양, 작업지시서 서버 저장.
10. 비서 담당은 임시로 시연 서버를 통해 비서 글을 붙이고, 팀이 DB 연결을 정하면 호출하는 쪽만 백엔드로 바꾼다. **비서 쪽 작업은 버려지지 않게 만든다.**

## 3. 논의 1 — 시뮬레이터와 DB를 어떻게 이을까 (가장 큼)

| 안 | 내용 | 비서가 얻는 것 | 위험·비용 | 크기 | 필요한 담당 |
|---|---|---|---|---|---|
| **C1** | 시뮬레이터(생성기 `Realtime`)가 사건을 `/api/ingest/*`로 **DB에도** 보내고, DB 시계를 시뮬레이터 시계에 맞춘다. 화면은 지금처럼 시연 서버를 쓴다 | 채팅·지침카드·브리핑·보고서가 시연 중 새 사건을 DB에서 읽는다 | 두 세계를 맞춰야 한다: 알람 번호(시뮬레이터는 1부터, DB는 자기 번호), 시각, 로트 번호. 배속이 높으면 호출이 많다. 공용 DB 쓰기 충돌 | 중간~큼 | 시뮬레이터, 백엔드, DB |

**C1을 하기로 하면 정할 것 [선택 필요]:**

| 번호 | 정할 것 | 비서 담당의 의견 [제안] |
|---|---|---|
| 1 | **보낼 범위.** 알람·상태·실적·재공·병목·작업지시·로트·센서·CMM 중 어디까지 | 알람(발생·해제)·상태·실적·병목·로트는 비서 기능에 필요하다. 센서와 CMM은 "센서 추세" 질문이 아니면 뒤로 미뤄도 된다 (추정) |
| 2 | **누가 보내나.** 생성기가 직접 POST / 시연 서버가 중계 / 별도 프로그램 | 시연 서버가 이미 사건을 받아 화면에 밀어 주므로(`_push`) 중계가 가장 작을 것으로 보인다 (확인 안 함) |

| 6 | **호출 빈도.** 배속 180에서 DB 쓰기가 밀리지 않게 묶어 보내나 | 사건은 그때그때, 센서는 묶음(최대 5000줄)으로 |

### 3-1. 정한 방향 (2026-10-17, 비서 담당 — 팀 동의 전)

| 정한 것 | 내용 |
|---|---|
| **쓰기 대상 DB** | 시뮬레이터가 사건을 쓰는 곳은 **사람마다 로컬 DB(Docker)** 다. 공용 `mom-db`는 팀이 함께 보는 9월 기록과 읽기 확인용으로 둔다 |
| **연결 목표** | **C1 단계적** — 시뮬레이터가 DB에도 보낸다. 화면은 지금처럼 시연 서버를 쓴다 |
| **보내는 주체** | **시연 서버가 중계** — 사건을 화면으로 밀어 주는 `_push()` 한 곳(`frontend/tools/sim_server.py` 75행)에 "DB로도 보내기"를 걸고, 별도 스레드 큐로 화면이 느려지지 않게 한다. 생성기 코드는 거의 안 건드린다 [추정: 구현해 봐야 안다] |

**이유 (새로 확인한 사실):** 공용 DB의 `fn_demo_reset()`은 기준점에 들어 있는 모든 운영 표를 `TRUNCATE`한 뒤 기준점 값으로 다시 채운다(마이그레이션 3546행~). 지금은 기준점(`demo_snapshot`)이 비어 있어 "시연 기준점이 없음" 오류로 막혀 있을 뿐이다. 누군가 시연 모드에서 기준점을 만들고 "처음으로"를 누르면 **공용 DB의 모두의 운영 데이터가 사라진다.** 그래서 시뮬레이터가 쓰는 DB는 공용과 분리한다. **공용 DB에서는 시연 모드(`MOM_DEMO_MODE`)를 켜지 않는다 [제안].** 로컬 DB는 `backend/README.md`의 Docker 절차(`docker compose up --build`, 약 20초에 스키마·계정·9월 데이터·문서까지)가 이미 있고, 처음부터 다시는 `docker compose down -v`다.

**공용 DB용 예시 파일이 시연 모드를 켠 채로 있다 (2026-10-17 확인):** `backend/.env.supabase.example` 24행이 `MOM_DEMO_MODE=true`다(비서 담당 PC는 `false`로 꺼 둠). 이 예시를 그대로 복사해 공용 DB에 붙이면 `POST /api/sim/snapshot`(MGR)과 `POST /api/sim/reset`(시연 모드이고 기준점이 있으면 로그인한 누구나)이 열린다(`backend/app/routers/master.py` 135~150행). 지금은 기준점이 비어 있어 막혀 있을 뿐이다. 같은 예시의 `MOM_RUN_WORKERS`는 `false`이고, 로컬 Docker용 `.env.example`은 `MOM_DEMO_MODE=true`·`MOM_RUN_WORKERS=true`다(자기 PC의 DB라 괜찮다). **[제안] DB 담당이 공용 DB용 예시를 `MOM_DEMO_MODE=false`로 바꾸고, 시연 모드는 로컬 Docker용 `.env.example`에만 둔다.** `assistant/start_all.ps1`은 이미 `true`를 거부하지만 스크립트를 쓰지 않는 팀원은 이 보호를 받지 못한다.

**나머지는 기본값 [제안] — 이의가 있으면 고친다**

| 항목 | 기본값 |
|---|---|
| 알람 번호 | 번호를 맞추려 하지 않는다. 시연 서버가 "시뮬레이터 번호 → DB가 돌려준 번호" 대응표를 들고, `prev_alarm_event_id`와 상태(DOWN)에 DB 번호를 쓴다 |
| DB 시계 | **서비스 키로 부르는 시계 입구**를 백엔드에 새로 만든다(이름은 예: `/api/ingest/clock`, 팀 파일 작은 변경). 시연 서버가 배속·일시정지·넘기기가 바뀔 때마다 알린다. 지금 `/api/sim/clock`은 로그인 사용자용이고 `sim_at`는 MGR만 쓴다 |
| 되돌리기 | 로컬 DB는 `docker compose down -v` 뒤 다시 `up`. 시뮬레이터 "처음으로"와 같이 하는 안내 스크립트가 필요하면, **접속 주소가 localhost일 때만** 지우게 한다 |
| 호출 빈도 | 알람·상태·병목은 그때그때, 생산·재공은 모아서, 센서는 묶음(입구 한도 5,000줄). 밀리면 건너뛰지 않고 큐에 쌓으며 화면은 막지 않는다 |
| 안전 장치 | "DB로 보내기" 스위치는 **기본 꺼짐.** 목적지 주소가 localhost(또는 허용 목록)가 아니면 켜지지 않는다 — 공용 DB에 실수로 쓰지 않게 |
| 단계 | **1단계** 알람(발생·해제)·설비 상태 → 채팅·지침카드·브리핑이 시연 중 새 알람을 읽는다. **2단계** 생산·병목·재공·로트(시뮬레이터에 작업지시·로트 시작에 대응하는 사건이 없어 따로 만들어 보내야 한다 [추정]). **3단계** 센서·CMM |

**알아 둘 것:** 사람마다 Docker가 필요하고, 비서·백엔드의 DB 주소(`.env`)를 로컬로 맞춰야 한다. 로컬 Docker 적재 설명의 문서 조각(209개)과 공용 DB의 `doc_chunk`(232개)가 다르다 [미확인: 개정 차이로 보이나 확인하지 않음].

**스크립트와 로컬 DB (2026-10-17):** `assistant/start_all.ps1`·`stop_all.ps1`은 **공용 DB 전용**이다. 항상 `backend\.env.supabase`를 읽고(51행), 시연 모드나 스케줄러가 `true`이면 켜기를 거부한다(160~164행). 로컬 DB는 시연 모드·스케줄러를 켜야 하므로 이 스크립트를 쓰지 않고 `backend/README.md`의 Docker 절차로 켠다. 스크립트 없이 켜면 보호 점검이 없으므로 **켜기 전에 설정의 DB 주소가 `localhost`인지 직접 확인한다.** 로컬을 자주 켜게 되면 그때 `-LocalDb` 옵션(다른 설정 파일을 읽고, 주소가 `localhost`일 때만 허용)을 더할지 정한다 [제안]. 다른 팀원이 공용 DB에서 시연 모드를 켜는 위험은 스크립트와 무관하며 DB 담당 요청(6장)으로만 막는다.

## 4. 비서 LLM = 외부 Claude 하나 — 확정 (2026-10-17, 팀 안건에서 뺌)

| 항목 | 내용 |
|---|---|
| 요구사항 | **NFR-SEC-08**: 비서는 로컬 LLM으로 돌고, 운영 데이터·사내 문서·질문을 외부 LLM으로 보내지 않는다 (확인 기준에 문서 초안·알림 문장 포함). `CLAUDE.md`도 "AI 비서는 로컬 LLM으로 확정" |
| 지금 | 채팅 탭은 비서 담당이 **외부 Claude**로 정해 붙였다 (서버 설정으로 켜고 끈다, 기본은 꺼짐). 질문과 문서 조각 8개가 나간다. 운영 질문에서는 조회 결과(설비·알람·수량)도 함께 나갈 수 있다 |
| 새 기능을 붙이면 | 보고서·카드·브리핑 **재료**(설비·알람·로트·수량)가 나간다 |
| 비서 담당의 결정 (2026-10-17) | 로컬 LLM은 돌릴 수 있지만 **이 프로젝트에서는 쓰지 않고 외부 LLM(Claude) 하나만 쓴다.** 보내도 되는 것은 질문·사내 문서 조각·가상 운영 값이고, **사람 이름·사원 번호·계정 정보는 보내지 않는다.** 처음에는 "시연 한정 예외"로 제안했으나 이 방향으로 바꿨다 |

**확정:** 요구사항(NFR-SEC-08)을 "외부 LLM(Claude) 하나, 보내도 되는 범위를 정함"으로 바꾼다. 바꿀 문장 초안, 고칠 줄 목록(약 59줄), 위험, 정한 6가지는 **`외부LLM_단일_전환_제안_20261017.md`** 에 있다.
**[제안]:** 문서를 고치기 전에도 외부 LLM 기능은 기본 꺼짐으로 둔다. 문서 정정은 팀에 알리면서 한다.

## 5. 논의 3 — 보고서 문장 채우기와 스케줄러

| 항목 | 사실 | 제안 |
|---|---|---|
| 자리표시 | 교대 보고서 초안의 특이사항 칸에 DB 함수가 `(비서 문장 대기)`를 넣는다 | 비서 문장을 이 칸에 넣는다 |

## 7. 비서 담당이 정했고 팀이 알아 둘 것

| 번호 | 내용 |
|---|---|
| 1 | 비서 입구는 **"재료를 받아 문장만 쓰는"** 구조다. 호출하는 쪽(시연 서버 / 백엔드)과 무관하게 같은 입구를 쓴다 |
| 2 | 첫 호출자는 **시연 서버**(임시, C3). 팀이 DB 연결(C1)을 정하면 호출자를 백엔드로 바꾼다. 비서 쪽 작업은 버려지지 않는다 |
| 3 | 숫자·순서·안전 고정 서식은 **프로그램이 지키고**, LLM은 문장만 쓴다. 문장 속 숫자는 프로그램 값과 대조한다 (NFR-AIQ-04) |
| 4 | 비서가 실패하면 **지금의 규칙 모양을 그대로** 보인다 |
| 5 | 구현 순서: 교대 보고서 문장 → 작업지시서 제목·증상 → 지침카드 "먼저 할 일" → 브리핑 (일일 보고서는 후순위) |
| 6 | 비서 서비스는 DB에 직접 쓰지 않는다. 읽을 때는 백엔드 조회 도구를 거친다 |
