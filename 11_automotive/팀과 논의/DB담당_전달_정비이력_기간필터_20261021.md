# DB 담당 전달 — 정비 이력 날짜 조회 (작업기록 도구 기간 필터) (2026-10-21)

> 보낸 사람: AI 비서(`assistant/`) 담당 · 받는 사람: 백엔드·DB 담당
> 시연 채팅에서 `지난주 정비 이력 보여줘`를 날짜로 지켜 답할 수 없다. 원인은 비서가 아니라 작업기록 조회 도구에 **기간 인자가 없는 것**이다.
> 백엔드·DB 코드는 아무것도 고치지 않았다. 아래 부탁이 들어가면 비서는 작은 연결(질문의 날짜를 인자로 넘기기)만 더하면 된다.

## 요약

| 항목 | 내용 |
|---|---|
| 지금 | 도구 `work_records`(`backend/app/assistant/tools.py`, SQL `backend/app/sql/assistant.sql`의 `-- name: work_records`)는 인자가 `equipment_id`, `alarm_code` 둘뿐이고 `ORDER BY w.confirmed_at DESC LIMIT 20`으로 **확정된 최근 20건**만 준다 |
| 문제 | 날짜 범위가 없어 "지난주"·"9/29 정비 이력"을 지켜 답할 수 없다. 비서는 거짓 "최근 20건"을 내지 않으려고 지금은 "날짜별로는 아직 못 읽어요, 작업기록서(SCR-12)나 예방 정비 일정(SCR-23)에서 확인해 주세요"로 안내한다 (규칙 안내, 2026-10-21 PR #112) |
| 부탁 | 선택 인자 `from_date`, `to_date`를 더한다 (아래 1장). 인자를 안 주면 지금과 같게 동작 |
| 급한 정도 | 낮음 — 시연 대본의 필수 질문이 아니다. 질문 은행에도 정비 이력 날짜 질문은 적다 |
| 영향 | 비서의 `정비 이력`·`작업기록` 날짜 질문. 다른 도구·화면은 영향 없음 (인자를 안 주면 결과가 같다) |

## 1. 부탁 (SQL과 도구 정의)

`backend/app/sql/assistant.sql`의 `-- name: work_records`에 두 줄을 더한다. 날짜는 `confirmed_at`의 한국 날짜 기준 (`kpi`·`production`이 쓰는 `from_date`·`to_date`와 같은 이름).

```sql
   AND (CAST(:from_date AS date) IS NULL OR CAST(w.confirmed_at AT TIME ZONE 'Asia/Seoul' AS date) >= CAST(:from_date AS date))
   AND (CAST(:to_date   AS date) IS NULL OR CAST(w.confirmed_at AT TIME ZONE 'Asia/Seoul' AS date) <= CAST(:to_date   AS date))
```

`backend/app/assistant/tools.py`의 `Tool("work_records", …)` 인자 정의에 `"from_date": DATE, "to_date": DATE`를 더한다 (필수 아님 — 마지막 필수 목록은 비워 둠). `LIMIT 20`은 그대로 둬도 된다.

## 2. 확인 질문 (고쳐 달라는 것이 아님)

비서 답의 조회 기준 시각(`as_of`)이 **10/1 08:00**으로 고정돼 보인다. 채팅 화면의 시각(16~20시)과 다르다. 공용 DB는 시연 모드를 꺼 두므로 `app_now()`가 멈춘 것으로 이해하는데, **의도된 동작이 맞는지** 한 줄로 알려 주면 된다. (맞다면 비서 쪽은 그대로 둔다.)

## 3. 비서 쪽에서 할 일 (부탁이 들어간 뒤)

- `assistant/backend/tools/query_tools.py`의 `work_records`에 질문의 시작·끝 날짜를 `from_date`·`to_date`로 넘기고, "정비 이력" 질문을 이 도구로 보낸다. 규칙 안내(`history_unread_v25`)는 그때 지운다.
- 이 변경 전에는 안내 문구가 유지된다. 백엔드가 늦어져도 비서 동작에는 문제가 없다.
