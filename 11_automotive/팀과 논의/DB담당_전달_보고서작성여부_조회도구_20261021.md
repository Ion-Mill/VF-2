# DB 담당 전달 — 보고서 작성·확정 여부를 채팅이 읽을 조회 도구 (2026-10-21)

> 보낸 사람: AI 비서(`assistant/`) 담당 · 받는 사람: 백엔드·DB 담당
> 시연 채팅에서 `어제 주간 교대 보고서 작성됐어?`·`9월 30일 교대보고서 작성됐어?`를 물으면 비서가 답할 수 있는 값이 없다. 작성·확정 여부는 문서가 아니라 DB(`shift_report`·`daily_report`)에 있는데, 비서가 읽는 조회 도구 14개(`backend/app/assistant/tools.py`) 중에 보고서 상태를 읽는 것이 없다.
> 백엔드·DB 코드는 아무것도 고치지 않았다. 비서는 이번에 "아직 읽지 못해요 + 볼 화면"을 규칙으로 알리게만 고쳤다. 아래 도구가 생기면 같은 질문에 실제 상태로 답하도록 비서를 맞춘다.

## 요약

| 항목 | 내용 |
|---|---|
| 증상 | 문서 길이 "받은 조각에서는 찾지 못했어요 + 보고서가 만들어지는 흐름"을 답했고, `어제`를 실제 달력(10월 20일)으로 잘못 말했다. 시연 시계는 10/1이라 어제는 9/30이다 |
| 비서가 한 것 | 이 질문 꼴(보고서 이름 + 작성·확정됐나 말, "언제·누가·어떻게" 같은 문서 질문은 제외)을 규칙이 받아 "채팅이 아직 못 읽어요, 교대 보고서(SCR-15)/일일 보고서(SCR-16)에서 확인해 주세요"로 답한다. Claude를 부르지 않고 날짜는 규칙이 읽은 값만 말한다 |
| 필요한 것 | 읽기 전용 조회 도구 하나: 날짜(+교대)별 보고서 상태 |
| 급한 정도 | 낮음~중간 — 도구가 없어도 비서는 거짓 없이 안내한다. 시연에서 이 질문을 실제 값으로 답하고 싶을 때만 필요하다 |

## 1. 제안 (도구 이름·모양은 백엔드 담당이 정한다)

| 항목 | 제안 |
|---|---|
| 도구 이름 | `report_status` (`backend/app/assistant/tools.py`의 `TOOLS`, SQL은 `backend/app/sql/assistant.sql`) |
| 입력 | `work_date`(필수, 날짜), `shift_type`(선택, 주간/야간 — 없으면 그날 교대 둘 + 일일 보고서) |
| 읽는 곳 | `shift_report`(`status`, `confirmed_by`, `confirmed_at`, `current_version`)에 `shift`(`work_date`, `shift_type`)를 붙여서, 그리고 `daily_report`(`status`, `confirmed_by`, `confirmed_at`) |
| 돌려줄 것 | 보고서별 `status`(`AI_DRAFT`·`EDITING`·`CONFIRMED`·`REVISED` 중 하나, 보고서 행이 아직 없으면 "없음"), 확정한 사람의 **역할**(이름 아님)과 `confirmed_at`, 잠정 값이 남아 있는지(`carry_over_is_provisional`) |
| 권한 | 기존 문서 권한 `("SHIFT_REPORT", "VIEW")`·`("DAILY_REPORT", "VIEW")`를 그대로 따른다. 작업자도 보고서는 조회할 수 있다는 기존 SCR-15 정의와 같게 |
| 쓰기 | 없음 (읽기 전용 14개 도구와 같은 규칙) |

## 2. 확인 질문

1. 보고서 행은 교대가 끝날 때(17:00·05:00) AI 초안으로 **자동 생성**되나, 아니면 처음 열 때 생기나? ("없음"과 "초안"을 비서가 어떻게 말해야 하는지가 여기서 갈린다)
2. 공용 DB의 `sim_clock`이 10/1 08:00에 멈춘 것은 의도된 동작이 맞나? (앞선 전달 문서 `DB담당_전달_정비이력_기간필터_20261021.md` 2장과 같은 질문. 시연 날짜 `어제=9/30`을 DB가 같은 날로 알아야 상태 조회가 맞는다)

## 3. 비서 쪽에서 한 것과 할 것

- 한 것 (이 문서와 같은 PR): `services/answer.py`의 `report_status_unread_v32` 규칙 — 위 "비서가 한 것". 시험 `tests/test_report_status.py`(13개).
- 할 것: 도구가 생기면 이 규칙의 고정 문구를 도구 호출 결과(`CONFIRMED` → "확정됐어요, 확정한 역할은 …")로 바꾼다. 도구가 늦어져도 비서 동작에는 문제가 없다.
- 따로 알아 둘 것 (비서 쪽 과제, DB 담당 몫 아님): 문서 길에서 Claude가 `어제` 같은 상대 날짜를 실제 달력으로 말하는 문제는 이 질문 말고도 날 수 있다. 시연 시계를 문서 길 지시문에 알려 주는 일은 비서 쪽에서 따로 다룬다.

## 4. 작업기록 데이터 속 제조사 매뉴얼 번호 (2026-10-21 추가)

시연 채팅에서 `992 지난 조치`가 "원문 출처 표기가 섞여 내보내지 않았습니다"로 막혔다. 출처 차단 필터(D-03)가 맞게 막은 것이고, 원인은 작업기록 글에 제조사 매뉴얼 번호가 들어 있는 것이다.

| 기록 | 들어 있는 번호 | 위치 |
|---|---|---|
| `MR-0903` (VF2-01, 알람 992) | `ID0003` ("체크리스트(ID0003)") | `생성기/out/work_record.csv` 조치 글 |
| `MR-0905` (VF2-02) | `SA0018`("서비스 알림 SA0018"), `ID0003`, `ID0009` | 같은 파일 조치 글 |

- 비서가 한 것: 조회 결과를 만들 때 그 번호만 가려서 보인다(`query_tools.mask_manual_ids`). DB와 생성기 원본은 안 고쳤다.
- 부탁(선택): 데이터에서도 번호를 지우면 가림 없이 같은 결과가 나온다. 다른 작업기록에 같은 모양이 더 있는지는 `[A-Z]{2}\d{4}` 꼴로 한 번 훑어 봐 주면 좋다.
