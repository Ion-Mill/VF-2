# DB 담당 전달 — 시연 공구 사용률(362)과 DB 값 (2026-10-21)

> 보낸 사람: AI 비서(`assistant/`) 담당 · 받는 사람: 백엔드·DB 담당
> 시연 3D 라인 뷰의 `VF2-01 공구 수명 한계 도달(362)` 말풍선 장면에서 채팅에 `362가 난 공구가 뭐야? 사용률은?`을 물으면, 비서는 DB의 공구 사용률(`v_tool_life`)을 읽어 답한다. 그 값이 시연 화면의 공구 수치와 **같을지 확인이 필요**하다.
> 백엔드·DB 코드는 아무것도 고치지 않았다. 비서는 이번에 질문 꼴만 고쳤다(공구 수명 조회로 연결). 필요한 요청이 있으면 아래 2장이 전부다.

## 요약

| 항목 | 내용 |
|---|---|
| 지금 | 비서의 공구 수명 조회는 도구 `tool_life`(SQL `backend/app/sql/assistant.sql`의 `-- name: tool_life`) → 뷰 `v_tool_life`(`backend/db/views/10_views.sql` 78행)다. 사용률은 `100 × tool.cum_usage ÷ tool_type.life_limit` |
| 값이 늘어나는 길 | `tool.cum_usage`는 **OP-30 생산 실적을 넣을 때** `fn_report_production → fn_add_tool_usage`(`backend/db/functions/70_realtime.sql` 100행, `30_workflows.sql` 483행)만 부품 수 × 부품당 사용량만큼 늘어난다. 공구 교체 기록은 0으로 리셋한다. 사건 입구(`/api/ingest/*`) 중 공구 상태를 직접 넣는 것은 목록에 없다 |
| 걱정 | 시연의 `T05 90% → 한도 도달`은 시연 서버가 장면 시간에 맞춰 보여 주는 값이다. 그 값이 DB에 같은 크기로 쌓일지(생산 사건이 DB로 가는지, 장면용 수치가 따로 있는지) **이 문서 작성자는 확인하지 못했다** |
| 영향 | 시연 362 장면의 채팅 필수 질문 하나(U02 `362가 난 공구가 뭐야? 사용률은?`)가 화면 수치와 같은지. 나머지 11개 질문은 공구 사용률 값에 의존하지 않는다 |
| 급한 정도 | 중간 — 시연 전에 방향만 정하면 된다 |

## 1. 확인 질문 (고쳐 달라는 것이 아님)

1. 시연에서 채팅의 공구 사용률이 화면의 공구 수치와 **같아야 하나?** (같아야 하면 아래 2장, 아니어도 되면 비서는 질문 기대를 `공구 번호·이름` 중심으로 낮춘다)
2. 시연 서버가 만드는 `T05` 사용량은 어떻게 만들어지나? 생산 사건을 보내 `fn_report_production`으로 쌓이는 값인가, 장면용 고정 수치인가?
3. 공용 DB의 `sim_clock`이 10/1 08:00에 멈춘 것은 의도된 동작이 맞나? (앞선 전달 문서 `DB담당_전달_정비이력_기간필터_20261021.md` 2장과 같은 질문이다. 맞다면 비서는 답에 기준 시각을 밝히는 것으로 충분하다.)

## 2. 같아야 할 때의 선택지 (제안)

| 선택지 | 내용 | 비고 |
|---|---|---|
| A | 시연 서버가 OP-30 생산 사건을 DB로도 보낸다(`/api/ingest/production`) | 사용량이 부품 수로 쌓이지만, 장면의 `90% → 한도` 같은 **가속 값은 일치하지 않을 수 있다**. 로컬 DB 연결(C1) 2단계와 함께 한다 |
| B | 공구 사용량을 직접 설정하는 입구를 둔다(예: `/api/ingest/tool` 또는 시연용 `fn_set_tool_usage`) | 장면 값을 그대로 맞출 수 있다. 백엔드·DB 변경이 필요하다. 공용 DB에는 쓰지 않고 로컬 DB에만 연다 |
| C | 맞추지 않는다 | 시연에서는 채팅의 사용률을 보이지 않고, 362 질문 중 공구 번호·이름·점검 순서만 본다 |

권장: **C를 기본으로 하고**, 로컬 스택(C1)을 만들 때 A·B를 같이 정한다. 공용 DB에는 어느 쪽도 쓰지 않는다 (공용 DB 보호).

## 3. 비서 쪽에서 한 것과 할 것

- 한 것 (이 문서와 같은 PR): `공구 … 사용률` 꼴 질문을 공구 수명 조회(`tool_life`)로 연결했다. VF2-01을 말하면 그 설비의 공구 전부를 사용률 순서로 보여 준다 (맨 위가 한도에 가까운 공구).
- 할 것: DB 담당 답이 오면 질문 기대(시연 362 기획 문서 4.1)를 맞춘다. 백엔드가 늦어져도 비서 동작에는 문제가 없다.

## 4. 실제 채팅 결과 (2026-10-21 시연 시험, 사용자가 화면에서 확인)

`VF2-01에서 362가 난 공구가 뭐야? 사용률은?`에 비서가 공용 DB의 공구 수명 조회로 돌려준 값:

| 공구 | 사용률 |
|---|---|
| VF2-01 T05 M6 탭 | **90.0% (360/400)** |
| VF2-01 T02 엔드밀 Ø10 | 85.0% (170/200) |
| VF2-01 T03 보링바 인서트 | 69.5% (278/400) |
| VF2-01 T04 드릴 Ø5.0 | 52.0% (520/1000) |
| VF2-01 T01 페이스밀 인서트 | 46.8% (187/400) |

같은 시험에서 시연 화면에는 알람 **362 공구 수명 한계 도달**(= 한도 100%)이 떠 있었다. 즉 **DB의 T05 사용률(90.0%)과 시연 화면 장면(한도 도달)이 어긋난다.** 1장 "걱정"이 실제로 확인된 것이다. 비서는 DB 값을 그대로 보여 줄 뿐이라 비서 쪽 문제가 아니다. 이 문서 2장의 선택지(A·B·C) 판단에 이 증거를 쓰면 된다. 새 요청은 없다.
