# 문서와 구현을 맞추는 제안 — 논리ERD↔SQL, API 명세 (2026-10-17)

- 읽는 사람: 문서 담당, 백엔드, DB, 화면, 시뮬레이터 담당
- 상태: **제안 — 팀 동의 전.** 이 문서는 어떤 문서도 고치지 않았다. 동의가 나오면 5장 순서로 고친다.
- 정한 사람: 비서(LLM) 담당 (2026-10-17). 아래 1장의 방향은 비서 담당이 정했고 팀 확인이 필요하다.
- 바탕: 백엔드 담당이 먼저 정리한 `backend/docs/08_팀문서_수정제안.md`(2026-10-14)를 직접 읽었고, 이번에 새로 찾은 것을 더했다.
- 표시: **[제안]** 비서 담당의 제안 / **[선택 필요]** 팀이 정할 것 / **[미확인]** 확인하지 못함 / **(직접 확인)** 이번에 파일을 읽어 확인 / **(에이전트 보고)** 조사 보고만 근거

## 0. 10줄 요약 (쉬운 말)

1. 백엔드는 생성기 데이터를 따라 DB를 만들었고, 그 결과 **논리ERD와 SQL이 여러 곳 다르다.**
2. 백엔드 담당이 이미 "문서를 고칠지 생성기를 고칠지 팀이 정하라"며 목록을 만들어 두었다(08 문서).
3. 제안: **문서를 SQL·데이터에 맞춘다.** 생성기를 고치면 9월 기록 전체가 다시 만들어진다.
4. 백엔드가 만든 `alarm_related_item` 표("같은 원인 한 줄"의 기준)는 **문서에 받아들인다.**
5. 이번에 새로 찾은 어긋남: `chat_log` 상태 5값, 알림 문장 출처 코드(`ASSISTANT`), `usual_state`, SQL에만 있는 표 9개.
6. API는 명세 밖 라우터가 **60개**다(서버끼리 17 + 화면용 43). 백엔드 문서 `03_API_명세.md`가 코드에서 자동으로 만들어지므로 그것을 **구현 정본**으로 한다.
7. 팀 `API명세서_v1`은 화면↔서버 약속 63개 그대로 두고, 맨 위에 "구현 현황과 명세 밖 API는 백엔드 문서"라는 한 줄과 요약표만 더한다.
8. QR 기능 5개는 기획서·요구사항·UI에 없는 **가정 기능**이다. 백엔드에만 두고 팀 회의에서 받을지 정한다.
9. 명세와 구현이 다른 4개 중 시뮬레이터 관련 3개는 "시연 서버 책임"으로 명시하고, 로그인 응답(`AUTH-01`)에만 담당 공정 칸을 더한다.
10. 팀이 확인할 것은 6장이다.

### 3-2. QR 기능 5개 — 가정 기능

| 항목 | 내용 |
|---|---|
| 사실 | `qr.py` 머리말: "2026-10-13 가정 [제안] — 기획서·요구사항·UI설계서에는 아직 없음". 조회, 입고·실사, 출하 전 로트 확인, 측정 시작 로트 확인(`inspection/instructions/{id}/start`의 `scanned_code`). 기록 표 `qr_scan`. 출하 전 확인 강제는 설정 `MOM_QR_SHIP_CHECK_REQUIRED`(**기본 꺼짐**). 백엔드 결정 기록 P-55~57 (직접 확인) |
| 제안 | 지금은 **백엔드에만 두고** 백엔드 문서에 "기획·요구사항·UI에 없는 **가정 기능**"이라고 분명히 표시한다. 팀이 기능으로 받겠다고 하면 그때 요구사항·UI·테스트에 도입하고, 아니면 코드와 `qr_scan` 표를 뗀다 |
| 팀이 정할 것 | QR 기능을 이 프로젝트의 기능으로 받을지(남은 시간 대비) |

### 3-3. 명세와 구현이 다른 4개 (에이전트 보고)

| API | 차이 | 제안 |
|---|---|---|
| `API-AUTH-01` | 로그인 응답(`TokenOut`)에 담당 공정 칸이 없고 `/api/me`에만 있음 | **구현을 고친다**: 로그인 응답에 담당 공정 칸 추가 (백엔드 작은 변경) |
| `API-STR-01` | 실시간 사건 9개에 `sim_clock`이 없음 | 명세에 "`sim_clock` 사건은 시연 서버가 제공, 백엔드는 없음"으로 명시 |
| `API-SIM-01` | 잠금 검사(`INVALID_STATE`)가 백엔드에 없고, 잠금은 생성기 `button_state()`에만 있음. 백엔드는 `equipment_id`·`alarm_code`도 받고 `alarm_event_id`만 돌려줌 | 명세에 "사건 버튼 잠금은 시뮬레이터(시연 서버)가 맡음, 백엔드 `/api/sim/inject`는 DB에 알람을 넣는 단순 버전"으로 명시 |
| `API-SIM-02` | GET·POST는 있으나 응답이 시각만 돌려주고 진행 중 사건·버튼 잠금이 없음 | SIM-01과 같게 "시연 서버가 제공하는 응답"으로 명시 |

이유: 2026-10-17에 정한 방향(C1)에서 시연 서버가 시뮬레이터를 계속 감싸므로, 잠금·버튼 상태·`sim_clock`은 시연 서버의 일이다. 백엔드가 같은 일을 또 구현하면 두 곳이 어긋난다.
