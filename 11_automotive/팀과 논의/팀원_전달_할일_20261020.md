## 1. 화면 담당 — 일일 보고서 [안전] 항목

**무엇이 문제인가:** 백엔드와 생성기는 오늘의 문제 글을 `전체 N건 (안전 a · 긴급 b · 생산 c · 주의 d · 참고 e): 1) [안전] … / 2) [긴급] …` 모양으로 만든다. 순위 0 "안전"(잠금·표지 중인 설비)이 맨 앞이다 (요구사항 FR-AST-COM-21: 순위 0·0-1·1은 접지 않고 늘 보인다). 그런데 `Reports.tsx`는 긴급·생산·주의·참고만 골라 그려서 **[안전] 줄이 화면에서 사라진다.**

```text
11_automotive/frontend/src/shell/Reports.tsx 의 일일 보고서 화면(DailyReportScreen)을 고쳐 줘.

[지금]
- splitIssues(r.issues_summary)가 "1) [긴급] …" 같은 줄을 {rank, text}로 나눈다.
- 215~217행 근처에서 prodItems(생산)·urgItems(긴급)·warnItems(주의)·refItems(참고)만 골라 "오늘의 문제" 칸(Sec title="오늘의 문제")에 그린다.
- rank가 '안전'인 줄은 어느 목록에도 안 들어가서 화면에 안 보인다.

[바라는 것]
- rank === '안전' 줄을 "오늘의 문제" 칸의 맨 위(정지 목록 stops보다 위)에 그린다. 접지 않는다(Fold 안에 넣지 않음).
- 칩은 기존 Chip 컴포넌트로, 긴급보다 눈에 띄거나 같은 수준(예: tone="solid-crit", 글자 "🔒 안전" 또는 "⚠ 안전")으로. 본문은 기존 ReportLine으로.
- "긴급 · 생산 문제 없음" 문구 조건에 안전 줄 수도 더한다 (안전 줄이 있으면 그 문구를 보이지 않게).
- 다른 칸·모양·동작은 바꾸지 않는다.

[확인]
- issues_summary = "전체 2건 (안전 1 · 긴급 0 · 생산 0 · 주의 1 · 참고 0): 1) [안전] 잠금·표지 중: VF2-01 / 2) [주의] 보류 로트 LOT-2609-041-1" 일 때
  안전 줄이 맨 위에 접히지 않고 보이고, 주의 줄은 지금처럼 접힌 칸 안에 보인다.
- npx tsc --noEmit 오류 0. frontend/tools/*_check.mjs 가 모두 통과 (node tools/chat_bubble_check.mjs 등).

[규칙] 11_automotive/CLAUDE.md를 따른다: 파일설명.md의 변경 기록 표에 한 줄 더하고,
구현_중_수정사항/1020_수정간단내용.md(날짜가 바뀌었으면 그 날짜 MMDD 파일)에 짧게 적는다. 커밋 제목은 "화면: …" 한국어.
```

## 2. 비서 담당 — 작업기록서 [메모 정리] 입구 `POST /work-record-assist`

**무엇이 문제인가:** 화면의 작업기록서 [메모 정리](API-MNT-10, FR-MNT-05-02)는 백엔드 `POST /api/maint/work-records/{번호}/assist`를 부르고, 백엔드는 비서 서비스의 **`POST /work-record-assist`** 로 넘긴다. 비서 서비스(`assistant/backend/chat_service.py`)에는 `/chat`·`/health`만 있어서 **늘 503 ASSISTANT_UNAVAILABLE**(화면은 기본 문구)이다.

```text
11_automotive/assistant/backend/chat_service.py 에 작업기록서 메모 정리 입구 POST /work-record-assist 를 더해 줘.

[부르는 쪽 — 바꾸지 않는다]
- 백엔드 11_automotive/backend/app/routers/maintenance.py 의 wr_assist 가
  client.call("/work-record-assist", {"record_no": "MR-0901", "equipment_id": "VF2-01", "memo": "<보전 담당자 메모>", "user_id": "U07"})
  로 부른다 (헤더 X-Service-Key, /chat과 같은 서비스 키, 기다리는 시간 130초 — backend/app/config.py assistant_timeout_seconds).
- 백엔드가 기대하는 응답 (backend/app/assistant/client.py 참고):
  {"cause": "원인 문장", "action": "조치 문장",
   "sources": [{"doc_name": "고장대응매뉴얼", "doc_no": "DOC-03", "rev": "Rev.1", "section": "§2.1"}],
   "parts": [{"item_no": "CS-SLUB", "qty": 0.5}]}
  dict가 아니거나 연결이 안 되면 백엔드가 503으로 바꾼다. 출처는 사내 문서 칸(doc_name·doc_no·rev·section)만 (원문 매뉴얼 출처 금지, D-03·R-85).

[바라는 것]
- /chat 과 같은 방식(서비스 키 확인, 외부 Claude 호출은 llm/claude_client 한 곳 — privacy/outbound_guard가 사람 이름·사용자 ID·계정 정보를 가림)으로 만든다.
- 입력 memo(자유 글)를 원인(cause)·조치(action) 두 문장으로 정리한다. 메모에 없는 사실·숫자를 지어내지 않는다 (FR-AST-COM-05).
- 근거가 되는 사내 문서 조각(DOC-03 해당 알람 절 등)을 sources 로 돌려준다. equipment_id·record_no 로 백엔드 조회 도구를 써도 된다 (repositories/backend_tools.py).
- parts 는 메모에 나온 부품·소모품만, 재고 품목 번호(item_no)로 바꿀 수 있을 때만 넣는다. 모르면 빈 목록.
- 사용자 ID(user_id)는 외부로 보내지 않는다 (NFR-SEC-08 — outbound_guard가 막는지 시험으로 확인).

[확인]
- 가짜 실행기(llm/claude_client.use_runner)로 시험을 더한다: ① 정상 응답 모양 ② 서비스 키 틀리면 401 ③ 외부로 나간 글에 user_id·이름이 없음 ④ 메모가 비면 400 또는 빈 cause/action.
- 기존 assistant/backend/tests 가 그대로 통과.
- 백엔드에서 확인: 비서 서비스를 켠 상태에서 백엔드 시험의 wr_assist 가 503이 아닌 응답을 받는지 (backend/tests/test_routers_db.py test_03은 지금 503을 기대하므로, 비서 서비스가 없을 때만 503이라는 뜻 — 백엔드 시험은 고치지 않아도 된다).

[규칙] 11_automotive/CLAUDE.md: 파일설명.md 변경 기록 한 줄, 구현_중_수정사항 MMDD 파일에 짧게. 커밋 제목 "비서 서비스: …".
```

## 3. 생성기 담당 — 정지 손실을 보고서 구간 안으로만

**무엇이 문제인가:** `생성기/gen/reports.py`의 `Timeline.stops`가 정지 **분**은 보고서 구간 안만 세는데(`ov`), **손실 수량**은 정지 전체 길이(`e - s`)로 센다. 9/15 04:20~05:41 VF2-02 정지(81분)는 9/14 일일 보고서 구간(05:00까지) 안이 40분인데 손실은 81분치(11.6개)로 적힌다. 백엔드·시연 서버는 구간 안 기준(5.7개)이라 숫자가 다르다 (`구현_중_수정사항/1020_수정간단내용.md` 33장 4번).

```text
11_automotive/생성기/gen/reports.py 의 Timeline.stops 에서 정지 손실 수량을 보고서 구간 안의 분으로만 세게 고쳐 줘.

[지금] (68~80행 근처)
  ov = min(e, b) - max(s, a)                       # 구간 안 분 → "minutes"
  "loss": round((e - s) / self.per_part[eq], 1)    # ← 정지 전체 길이로 셈 (틀림)
[바라는 것]
  "loss": round(ov / self.per_part[eq], 1)         # 구간 안 분 ÷ 부품당 시간
- "5분 이상 정지" 조건(e - s >= 5)은 정지 전체 길이 그대로 둔다 (DOC-07 §5.4 필수 정지 정의).
- 이 값을 쓰는 곳(일일 보고서 failure_loss_qty, 오늘의 문제 글 "고장 손실 약 N개", 교대 보고서 필수 정지 줄)이 함께 바뀐다.

[확인]
- 9/14 일일 보고서: VF2-02 40분 정지의 손실이 약 5.7개, issues_summary 문장도 "고장 손실 약 5.7개".
- 생성기 시험(생성기/tests) 통과. 기대값이 바뀌는 시험은 이유를 적어 고친다.
- 생성기를 다시 돌려 생성기/out/ CSV를 새로 만든다.

[다음 사람에게]
- out/ CSV가 바뀌면 백엔드·DB 담당에게 알린다: 공용 mom-db의 9월 데이터를 다시 적재해야 숫자가 맞는다 (백엔드 tools/load_generated.py).
[규칙] 11_automotive/CLAUDE.md: 파일설명.md 변경 기록, 구현_중_수정사항 MMDD 파일. 커밋 제목 "생성기: …".
```
