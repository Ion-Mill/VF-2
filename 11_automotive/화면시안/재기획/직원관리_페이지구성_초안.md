# 직원 관리 페이지 구성 초안 (2026-10-23)

> 상태: **질문 답 받음 · 문서 반영 끝 (2026-10-23)** — P1~P7 답은 7장. 6장 문서 6개에 반영함(요구사항 USR-01, UI SCR-27, 기획서 13.2, API-USR-01~03, 논리 ERD APP_USER, 페이지구조 v3). 남은 것: 테스트 계획서, 화면 제작.
> 범위: **1단계 명단·배치표 + 2단계 직원별 업무 기록**. 3단계 자격·교육은 근거 데이터가 없어 뺐다 (5장).
> 표시: **[확정]** 사용자 답 · **[제안]** 이 초안이 고른 것 · **[가상]** 팀이 정한 값

---

## 1. 한 줄 요약

공장 관리자가 **누가 어느 교대·공정을 맡았는지**(명단·배치표)를 보고 **바꾸며**, **각자 무엇을 처리했는지**(업무 기록)를 한 페이지에서 본다. 업무 기록은 새로 쌓지 않고 기록 표의 "누가" 칸을 사람별로 모으고, 배치를 바꾸면 직원 명단(`app_user`)을 고치고 수정 이력에 남긴다.

| 항목 | 내용 |
|---|---|
| 화면 번호 | SCR-27 [제안] (지금 마지막 번호 SCR-26 현장 보기 다음) |
| 메뉴 자리 | 위 가로 메뉴 **설정 바로 앞** [확정 P7] — 권한 없는 계정은 지금 규칙대로 흐리게 + 눌러도 안 열림 (페이지구조 v3 N3) |
| 쓰는 사람 | **공장 관리자(MGR)만** [확정 P1]. 서버도 MGR이 아니면 거부 (NFR-SEC-04와 같은 방식) |
| 형태 | 메뉴 페이지 (가로 탭 2개: 명단 · 배치표) + 사람을 누르면 직원 상세 |

## 2. 쓰는 데이터 (새 표 없음)

### 2.1 명단·배치표

| 화면 칸 | 표 · 칸 (논리 ERD) |
|---|---|
| 이름 · 역할 · 담당 교대 · 담당 공정(최대 2개) · 사용 중 | `app_user` (`user_name`, `role_code`, `home_shift_type`, `home_process_code`, `home_process_code_2`, `is_active`) — 가상 직원 12명 [가상] |
| 그 교대의 반장 | `shift.supervisor_user_id` |
| 지금 근무 중 | 시연 시계의 지금 교대(`shift`)와 `home_shift_type`이 같으면 근무 중 [제안] |
| 배치 바꾼 기록 | `document_revision`(문서 종류 `APP_USER`, 문서 키 = 사용자 ID) + `document_revision_change`(바뀐 칸 전·후) — 문서 수정 이력과 같은 표를 쓴다 [제안] (3.3) |

### 2.2 직원별 업무 기록 — "누가" 칸을 사람별로 모음

| 무엇을 했나 | 표 · 칸 | 주로 누가 |
|---|---|---|
| 공정 실적(생산 수량·양품·불량) | `operation_report.worker_user_id` | 작업자 |
| 정지 사유 입력 / 확정 | `equipment_state_log.reason_entered_by` / `reason_confirmed_by` | 작업자·보전 / 반장 |
| 공구 교체 | `tool_change.changed_by` | 작업자·보전 |
| 작업지시서 담당 / 승인 | `maintenance_work_order.assignee_user_id` / `approved_by` | 보전 / 반장 |
| 작업기록서·간이 작업기록 확정 / 확인 | `work_record.confirmed_by` / `checked_by` | 보전·작업자 / 반장 |
| 예방 정비 실시 / 기록 | `pm_record.done_by` / `recorded_by` | 작업자·보전 / 보전 |
| 검사 확인 · 수동 입력 | `inspection_result.checked_by` · `entered_by` | 반장 · 작업자 |
| 불량 기록 | `defect_record.recorded_by` | 작업자·반장 |
| 로트 보류 · 해제 · 폐기 승인 | `lot_hold.held_by` · `released_by` · `scrap_approved_by` | 반장 · 관리자 |
| 재고 입출고 기록 | `inventory_txn.txn_by` | 반장 |
| 출하 확인 | `shipment.confirmed_by` | 반장 |
| 교대 보고서 확정 / 일일 보고서 확정 | `shift_report.confirmed_by` / `daily_report.confirmed_by` | 반장 / 관리자 |
| 문서 수정 | `document_revision.author_user_id` | 모두 |

- 채팅 기록(`chat_log.user_id`)은 **넣지 않는다** [제안] — 질문 내용은 업무 기록이 아니고, 사람을 살피는 화면에 나오면 이브에게 묻기를 꺼리게 된다.
- 9월 기록(생성기 CSV)과 10/1 화면에서 만든 기록을 같이 센다 (문서함과 같은 규칙).

## 3. 화면 구성

### 3.1 공통 머리

```text
직원 관리                                            [명단] [배치표]
╭ 결론 띠 ─────────────────────────────────────────────────────╮
│ ✓ 지금 주간 근무 6명 · 비어 있는 공정 없음                        │
│   (주의 예: ▲ 야간 OP-30 담당이 없어요)                           │
╰──────────────────────────────────────────────────────────────╯
```

- 결론 띠는 디자인 통일 C안의 띠 함수(`bands.ts`)에 `staffBand`를 더해 만든다 [제안].
- 주의 기준: **공정에 담당이 0명일 때만** 주의 [확정 P4]. "1명뿐" 같은 기준은 근거 숫자가 없어 쓰지 않는다 (위 그림의 주의 예는 "▲ 야간 OP-30 담당 없음" 모양).

### 3.2 명단 탭

```text
[전체] [작업자] [보전 담당] [반장] [관리자]        [주간] [야간]      기간 [7일 ▾]
╭──────────────┬──────┬──────┬───────────┬────────┬──────────────┬──────╮
│ 이름          │ 역할  │ 교대  │ 담당 공정  │ 지금    │ 기간 안 처리   │      │
├──────────────┼──────┼──────┼───────────┼────────┼──────────────┼──────┤
│ 작업자 주간 1  │ 작업자 │ 주간  │ OP-10·20  │ ● 근무  │ 실적 14 · 정지 2 │ [보기] │
│ 보전 담당 1   │ 보전   │ 주간  │ —         │ ● 근무  │ 작업지시 3      │ [보기] │
│ 반장 야간     │ 반장   │ 야간  │ —         │ 휴무    │ 확정 5         │ [보기] │
╰──────────────┴──────┴──────┴───────────┴────────┴──────────────┴──────╯
```

- "기간 안 처리"는 역할마다 대표 숫자 1~2개만 (3.4 표의 첫 칸들). 순위·점수는 매기지 않는다 [제안].
- 줄을 누르면 3.4 직원 상세.

### 3.3 배치표 탭

```text
              주간                        야간
OP-10 절단    작업자 주간 1                 작업자 야간 1
OP-20 황삭    작업자 주간 1                 작업자 야간 1
OP-30 정밀 가공  작업자 주간 2               작업자 야간 2
OP-40 세척·디버링 작업자 주간 3              작업자 야간 3
OP-50 측정    작업자 주간 3                 작업자 야간 3
보전          보전 담당 1 · 보전 담당 2       보전 담당 3
반장          반장 주간                     반장 야간
```

- 사람 이름을 누르면 3.4 직원 상세. 빈 칸은 주의(▲ 담당 없음)로 표시.
- 한 사람이 두 공정을 맡은 칸(예: 작업자 주간 1 = OP-10·20)은 두 줄 모두에 이름이 나온다.
- **배치 바꾸기** [확정 P2: 바꿀 수 있게]

```text
배치표                                                   [배치 바꾸기]
  → 바꾸기 모드: 칸을 누르면 그 자리에 넣을 사람 목록
     OP-30 · 야간  [작업자 야간 2 ✓] [작업자 야간 1] [작업자 야간 3]   [비우기]
╭ 바꾸기 확인 ────────────────────────────────────────────╮
│ 작업자 야간 1   담당 공정 OP-10·20 → OP-10·30             │
│ 작업자 야간 2   담당 공정 OP-30 → (없음)                   │
│ ▲ 바꾸면 야간 OP-20 담당이 없어요                            │
│ 사유 [                                   ] (선택)          │
│                                   [취소]  [바꾸기]          │
╰────────────────────────────────────────────────────────╯
```

| 규칙 | 내용 |
|---|---|
| 누가 | 관리자만 (P1). 서버도 MGR이 아니면 거부 |
| 넣을 수 있는 사람 | 공정 줄 = 작업자, 보전 줄 = 보전 담당, 반장 줄 = 반장. 그 칸의 교대로 옮기면 담당 교대도 같이 바뀜 [제안] |
| 담당 공정 수 | 한 사람 최대 2개 (`home_process_code`, `home_process_code_2` 두 칸). 3개째를 넣으려 하면 하나를 빼라고 알림 |
| 확인 | [바꾸기] 전에 바뀌는 사람·칸 전→후와 그 결과 빈 공정이 생기는지 보여 줌. 사유는 선택 [제안] |
| 기록 | 사람마다 `document_revision` 한 줄(`APP_USER`, 고친 사람·때·사유) + 바뀐 칸 전·후. **문서함 › 수정 이력**에 "직원 배치" 종류로 보임 [제안] |
| 적용 때 | 저장하면 바로 적용 [제안] — 담당 공정이 바뀌면 그 작업자의 브리핑 요약·담당 공정 알림(FR-AST-01-07 등)도 바로 바뀜. 확인 창에 이 말을 한 줄 넣음 |
| 하지 않는 것 | 역할 바꾸기(작업자 → 반장 등)·계정 켜고 끄기는 이번 범위 밖 (5장) |


### 3.4 직원 상세 (사람을 누르면)

```text
← 직원 관리   작업자 주간 1   작업자 · 주간 · OP-10·20 · 사용 중      기간 [오늘] [7일] [30일] [9월 전체]
╭ 숫자 칸 4개 (역할마다 다름, 아래 표) ─────────────────────────────────╮
│ 생산 수량 112개 │ 양품률 98.2% │ 공구 교체 3번 │ 정지 사유 입력 4건    │
╰──────────────────────────────────────────────────────────────────╯
╭ 최근 업무 (시간순, 누르면 그 문서·화면으로) ─────────────────────────────╮
│ 10/1 09:12  정지 사유 입력   VF2-01 · 칩 막힘              [정지 사유 ›] │
│ 10/1 08:40  공구 교체        VF2-01-T05                    [공구 수명 ›] │
│ 9/30 21:05  간이 작업기록 확정 SR-0930-02                   [문서 ›]     │
╰──────────────────────────────────────────────────────────────────╯
```

| 역할 | 숫자 칸 4개 [확정 P5] | 최근 업무에 나오는 것 |
|---|---|---|
| 작업자 | 생산 수량 · 양품률 · 공구 교체 · 정지 사유 입력 | 공정 실적, 정지 사유 입력, 공구 교체, 간이 작업기록, 예방 정비 실시(작업자 항목), 불량 기록 |
| 보전 담당 | 맡은 작업지시 · 작업기록 확정 · 수리 시간 합계 · 예방 정비 실시 | 작업지시서, 작업기록서·간이 작업기록, 예방 정비, 공구 교체 |
| 반장 | 작업지시 승인 · 정지 사유 확정 · 교대 보고서 확정 · 로트 보류 | 승인·확정·확인한 문서, 로트 보류·해제, 재고 입출고, 출하 확인 |
| 관리자 | 일일 보고서 확정 · 폐기 승인 · 설정 변경 · 문서 수정 | 확정·승인한 문서, 설정 변경 |

- 숫자는 기간 칩에 맞춰 센다. 기간 칩 처음 값은 **7일** [확정 P6] (명단 탭 "기간 안 처리"도 같음). 위 그림의 숫자·문서 번호(SR-0930-02 등)는 모양을 보이려고 적은 것이고 실제 값이 아니다.
- 평균값(평균 수리 시간 등)은 건수가 적으면 흔들려서 **합계만** 보인다 [제안].
- 인쇄: 직원 상세도 문서 틀(`DocPage`)을 쓰면 [인쇄] 한 장 맞춤이 그대로 된다 [제안].

## 4. 설정 › 사용자 탭과의 관계

지금 설정(SCR-25)에 **사용자 탭**(ID·이름·역할·교대·담당 공정, 보기만)이 있다. 이 페이지 명단과 겹친다.

| 안 | 내용 |
|---|---|
| **A [확정 P3]** | 설정의 사용자 탭을 빼고 이 페이지로 옮긴다. 설정에는 "직원 관리에서 봅니다 ›" 줄만 남김 |
| B | 둘 다 둔다 (설정 = 계정 정보, 직원 관리 = 배치·업무) |

→ A로 정함.

## 5. 이번 범위에서 하지 않는 것

| 하지 않는 것 | 이유 |
|---|---|
| 자격·교육(잠금·표지 자격, 설비 조작 자격, 안전 교육 만료) | 3단계. 데이터 설계서·가상 사내 문서(DOC-05 등)에 근거부터 만들어야 함 |
| 근태·출퇴근·휴가·급여 | 이 플랫폼(MOM) 범위 밖. 근무 여부는 담당 교대로만 본다 |
| 순위표·점수·평가 등급 | 기록을 모아 보는 화면이지 평가 화면이 아님. 숫자도 역할 안에서만 보임 |
| 이브 채팅 내용 | 2.2 참고 |
| 계정 만들기·지우기·비밀번호, 역할 바꾸기, 계정 켜고 끄기 | 시연은 가상 12명 고정, 비밀번호 0000 (로그인 화면 규칙). 배치(교대·담당 공정)만 바꾼다 |
