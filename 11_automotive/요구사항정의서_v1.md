## 1. 목적과 범위

### 1.1 목적

| 항목 | 내용 |
|---|---|
| 왜 만드나 | 기획서의 기능 설명을 **개발·시험할 수 있는 단위**로 나눈다. UI 설계서·논리 ERD·API 명세·테스트 계획이 이 문서의 요구사항 ID를 기준으로 연결된다 (기획서 18장 1·10번) |
| 누가 보나 | 팀 5명 (AI 비서 2, 데이터·ML 1, 백엔드·DB 1, 프론트엔드 1), 심사위원 |
| 무엇을 담나 | 기능 요구사항(5장), AI 비서 공통 요구사항(6장), 비기능 요구사항(7장), 시연 연결(11장) |

| 코드 | 분류 |
|---|---|
| PERF | 성능 |
| USE | 사용성 |
| SEC | 보안·권한 |
| DATA | 데이터 |

## 5. 기능 요구사항

### 5.1 PRD-01 모니터링형 디지털 트윈(3D 라인 뷰)·가동 현황 (필수)

주 사용자 SUP, 조회 전원. AI는 쓰지 않는다 (비서 창 설명만).

| 요구사항 ID | 요구사항 | 설명 | 사용자 | 우선순위 | 수용 기준 | 출처 |
|---|---|---|---|---|---|---|
| FR-PRD-01-01 | 3D 라인 전경 표시 | 5개 공정 6대 설비(SAW-01, MIL-01, VF2-01, VF2-02, WSH-01, CMM-01)를 단순한 도형(상자·원기둥)으로 공정 순서대로 그린다. 메뉴 이름은 "3D 라인 뷰" | 전원 | 필수 | 6대가 OP-10→50 순서로 모두 보인다. 사실적인 3D 모델을 쓰지 않는다 | 기획서 6.2, 9장 PRD-01 |
| FR-PRD-01-02 | 화면 각도 | 화면 각도는 고정이 기본이다. **자유 돌리기(끌기)는 하지 않고**, 정해진 시점 버튼 3개(전체 / OP-30 가까이 / 위에서) + 확대·축소 [+][−] + [처음]만 둔다 (UI설계서 9장 #1) | 전원 | 필수 | 처음 열면 고정 각도로 6대가 한 화면에 보인다. 끌어서 돌아가지 않는다. [처음]을 누르면 처음 각도로 돌아온다 | 기획서 6.2, 17.2, UI설계서 9장 #1 |
| FR-PRD-01-03 | 설비 상태 판정 | 설비는 한 시점에 RUN·IDLE·BLOCKED·SETUP·DOWN·MAINT 중 하나다. 실제 데이터 값과 대응: RUN = MTConnect ACTIVE(Q500 BUSY), IDLE = READY(Q500 IDLE), BLOCKED = READY + 뒤 재공 한도 도달, SETUP = 작업자 입력, DOWN = STOPPED + 정지 등급 알람, MAINT = 예방 정비 진행 | 전원 | 필수 | 한 설비의 상태 구간이 서로 겹치지 않는다.
