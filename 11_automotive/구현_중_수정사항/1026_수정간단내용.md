## 7. 직원 관리 저장 동작 확인 (사용자 "확인이 완료되면 커밋, pr까지")

PR #190에서 "못 한 것"으로 남은 저장 동작(직원 추가·정보 고치기·비밀번호·사용 중지·배치 저장)을 이 PC 로컬에서 실제로 눌러 봤다. 공용 DB에는 쓰지 않았다 — 공용 DB에 만든 직원은 지울 수 없고(사용 중지만) [처음으로]로도 지워지지 않는다.

| 항목 | 내용 |
|---|---|
| 환경 | main(`11170b9`, #184·#190 포함) 백엔드 :8000 + 이 PC Docker DB(`backend-db-1`, 10/23에 만든 9월 데이터) + 화면 :3000(같은 주소 `/api`). DB에 빠져 있던 마이그레이션 3개(`20261024000000`·`20261025000000`·`20261025010000_staff_1025`)를 `mom_owner`로 올리고 이름도 6장처럼 맞춤 |
| 백엔드 (24개 통과) | 직원 추가(아이디 비우면 다음 번호) · 새 직원 로그인 · 같은 아이디 409 · 비밀번호 8자 미만 422 · 이름 고치기 → `/api/users`에 바로 · 바뀐 칸 없음 422 · 배치 저장(화면 모양 `procs`) · 담당 공정 3개 422 · 역할 OPR→MNT(담당 공정 비움) · 비밀번호 다시 정하기(옛 비밀번호 401, 새 비밀번호 200) · 사용 중지(로그인 401, 옛 토큰 401, 기본 명단에서 빠짐) · 다시 사용 · 자기 사용 중지·역할 바꾸기 422 · 작업자가 고치기 403 |
| 화면 (19개 통과, 브라우저 자동) | U12 로그인 → "장현우" · 명단 새 이름 · [+ 직원 추가]: 같은 아이디는 창 안에 서버 문장 "이미 있는 아이디: U12", 짧은 비밀번호는 화면에서 막음, 추가 → 새 직원 상세 + 알림 · [정보 고치기]: 작업자 → 보전이면 "담당 공정이 비워져요" 안내, 저장 뒤 상세 이름·역할 바뀜 · [비밀번호 다시 정하기] · 새 직원이 다른 창에서 소문자 아이디·새 비밀번호로 로그인 → 이름 보임 · [사용 중지] → "사용 중지" 표, 그 직원 창은 다음 요청에서 로그인 화면(401), 다시 로그인 거절 · [다시 사용] · 배치표 [배치 바꾸기] → 확인 창 "교대 주간 → 야간" → 저장 → 야간 보전 칸에 들어감 · 자기 상세에서 [사용 중지] 막힘, 역할 칸 막힘. 화면 오류 0 |
| 수정 이력 | 사람마다 `APP_USER` v0(직원 추가, 사유) → v1(이름·역할·담당 공정) → v2 비밀번호 → v3·v4 사용 여부 → v5 교대. 비밀번호 칸은 "비밀번호 정함"/"비밀번호 바꿈"만, 비밀번호·해시가 이력에 남은 곳 0건 |
| 정리 | 시험으로 만든 직원 U13~U19와 그 수정 이력·접속 기록은 로컬 DB에서 지움 (직원 12명, `APP_USER` 이력 0건으로 돌아감) |
| 참고 | 이 PC의 `frontend/.env.local`(git에 없음)에 옛 `NEXT_PUBLIC_MOM_API=http://127.0.0.1:8020`이 있으면 브라우저가 그 주소로 바로 가서 로그인에 "서버에 연결할 수 없습니다"가 뜬다. 로컬에서 그렇게 나오면 그 줄을 지우거나 비운다(이번 확인은 `NEXT_PUBLIC_MOM_API=`로 켬) |
| 남은 일 | 시연 서버(AWS)에 반영: 서버에서 `git pull` 뒤 `docker compose up -d --build backend web` — `sim`은 다시 켜지 않는다(공용 DB가 기준점으로 되돌아감) |
| 고친 파일 | 이 파일, `파일설명.md` (코드 수정 없음) |
