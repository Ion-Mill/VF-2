## 1. 비서가 알람 건수·로트 상태·설비 상태를 더 알아듣고 맞게 답함 (AWS 서버 점검 보고 후속, 사용자 "진행해")

| 항목 | 내용 |
|---|---|
| 왜 | 팀원 점검 보고에서 "어제 알람 몇 건이야?"가 설비·번호를 되묻고(PR #187 뒤에도 운영 경로에서는 그대로), "몇 개·건수·횟수"는 "찾지 못했어요", 로트 답에 DB 코드(`IN_PROCESS`)가 그대로 나오고, 설비 상태 답에 "몇 분째"가 없고 묻지 않은 설비까지 나열됐다. 외부 Claude 채팅은 조회 도구 길(`lookup_turn`)을 타는데 거기서 번호 없는 알람 건수를 막고 있었다 |
| 한 일 | ① 번호 없는 알람 건수를 막지 않고 기간 안 전체 건수와 설비별 건수로 답함("모든 설비"는 한 번 조회해 합계 줄) ② 알람 건수 낱말(몇 개·건수·횟수·얼마나 떴), "이번 달"·"N월" ③ 기록 밖 달("9월")은 다른 달 값을 대신 쓰지 않고 "기록 밖" 안내 ④ 로트 상태를 DB 시드와 같은 공식 한글 이름으로 ⑤ 설비 상태 값 표에 시작 시각·"N분째"·프로그램이 센 상태별 대수, 지시문에 범위 규칙 |
| 안 바꾼 것 | 백엔드·DB·화면·`.env`(새 스위치 없음), 번호가 있는 알람 건수, 병목 답(값 표 줄만 같이 바뀜), 지난 병목 고정 안내, 214개 실패 시험 |
| 알아 둘 것 | **백엔드 쿼리가 알람을 두 번 세는 경우가 있어** 비서 합계가 DB 직접 셈보다 크다(어제 19건↔18건, 10월 299건↔293건). `count(DISTINCT a.alarm_event_id)`로 고치면 풀린다(DB 담당). 달력 날짜가 든 조회("10월 24일 주간 생산 실적")·설비 없는 예방 정비 기한 질문은 이번에 안 풀었다 |
| 확인 | 새 시험 56개, 비서 전체 3,606 → 3,662 통과(실패 214개는 바꾸기 전과 같은 목록). 진짜 Claude로 건수 11/11(비서 숫자 = 알람 도구 합계)·로트 6/6(코드 노출 0)·상태 8/8(다른 설비 언급 없음·N분째 있음·대수 맞음). **화면에서 눌러 본 확인은 안 함** |
| 고친 파일 | `assistant/backend/services/answer.py`·`services/lookup_turn.py`·`tools/query_tools.py`, `assistant/backend/tests/test_count_lot_status.py`(새)·`test_anchor_clock.py`·`test_bottleneck_note.py`·`test_equipment_state_note.py`·`test_routing.py`, `assistant/변경기록.md`, `파일설명.md`, 이 파일 |
| 문서 담당(= 사용자)이 판단할 것 | 백엔드 알람 쿼리의 중복 집계를 DB 담당에게 넘길지 |
