## 1. 비서가 "작업 전 잠금 순서는 문서에 없다"고 틀리게 답하던 안전 결함을 고쳤다

| 항목 | 내용 |
|---|---|
| 증상 | "잠금 표지 순서가 어떻게 돼?"에 비서가 "모든 설비에 공통인 순서는 문서에 없다"고 답했다. **틀렸다** — DOC-05 §2.1 "작업 전 6단계"와 §2.2 "작업 후 3단계"가 공통 순서다. 화면 예시 버튼이 바로 이 질문이라 시연에서 보일 수 있었다 |
| 원인 | Claude가 아니라 **문서 검색**이다. 낱말 검색에서 §2.1이 66위라 Claude에게 가지 않았고, 문서는 "잠금" 대신 "자물쇠·차단 지점"이라고 쓴다. "잠그는/잠가"처럼 동사형으로 물으면 부모 §2도 상위 8개 밖이었다 |
| 고침 | 스위치 `PURE_EXPAND` (비서 `.env`). 켜면 ① 검색 상위 조각의 아래 절을 짧은 것부터 최대 4개·2,500자 더 주고 ② 질문에 잠금 낱말이 있으면 DOC-05 §2를 빠뜨리지 않는다. 코드 기본은 꺼짐(= 이전과 한 글자도 같음), 예시 파일(`.env.example`)은 켬 |
| 확인 | 시험 1410 → 1448 통과. 질문 변형 20개 모두 §2.1·§2.2가 Claude에게 간다. 개발용 문서 질문 정답 포함 38/40 → 38/40(나빠진 질문 0), 봉인 세트 473개 419 → 423(나빠진 질문 0). 진짜 Claude로 질문 표현 6개 모두 "없다" 단정이 없었고 5개는 작업 전 6단계를 원문대로 답했다(끈 쪽은 예전 결함 그대로) |
| 안전망 | `e2e_check.py`가 잠금 표지 질문 2개에서 "순서가 문서에 없다"는 단정을 틀린 답으로 본다. 질문이 10개 → 11개 (한 번 돌릴 때 공용 DB `chat_log` 11줄) |

**각자 해야 할 일:** 이미 쓰는 `assistant/.env`에는 새 줄이 자동으로 생기지 않는다. `PURE_EXPAND=1`을 더하고 비서(8100)를 껐다 켠다. 줄이 없으면 결함이 그대로다.

**남은 것:**
- 문서 담당에게: DOC-05 §2.1 제목·본문에 "잠금·표지 순서" 낱말을 넣으면 검색이 더 쉽게 찾는다 (문서는 팀 것이라 고치지 않았다).
- "시험·조정 5단계" 표(DOC-05 §2.2)는 비서가 못 본다 (원문에는 있음). 팀 규칙 D-03(원문은 검색하지도 보이지도 않는다)에 따라 필터가 "원문…" 칸을 일부러 지우는데 이 표는 "원문 뜻" 칸만 있기 때문이다. 필터를 풀기보다 문서 쪽(그 표에 "우리 라인에서 할 일 [가상]" 같은 사내 문구 칸을 더함)을 고치는 게 맞아 문서 담당·팀이 정할 일이다.
- DB 담당에게: `e2e_check.py`가 질문 11개로 늘었다.
- 보장은 잠금 낱말 + DOC-05 §2 하나다. 다른 안전 질문에 같은 모양의 놓침이 있는지는 따로 확인하지 않았다.

자세한 내용: `assistant/변경기록.md`의 "잠금 표지 순서 수정", `assistant/실행_안내.md` 8-2절.

## 3. 안전 질문의 거짓 "문서에 없다"를 구조적으로 막았다

| 항목 | 내용 |
|---|---|
| 증상 | "톱 정비 전에 어디를 차단해야 해?"에 "톱의 차단 지점은 문서에서 찾지 못했어요"(출처 없음). DOC-05 §3.1에 차단 지점 2곳이 있는데도 그렇다 — 1장과 같은 모양이 또 나왔다 |
| 근본 원인 | 비서는 낱말이 같아야 문서를 찾는다(현장 말 "톱" ≠ 문서 말 "SAW-01·콜드쏘"). 그리고 **"못 찾음"을 "문서에 없음"이라고 말한다** — 이 둘을 모두 막아야 같은 문제가 안 생긴다 |
| 고침 | 스위치 `PURE_SAFETY` (코드 기본 꺼짐, 예시 파일 기본 켬). ① 안전 질문에는 DOC-05를 통째로 더함 ①-b 설비 이름만 든 안전 질문도 순수 길로 ② 그래도 답이 없으면 "자동으로 확인하지 못했어요(문서에 없다는 뜻 아님) + 가까운 절". 상태는 기존 "확인 필요"(API `OK`)라 백엔드·화면은 안 바뀐다. D-03(원문 칸 지우기)은 건드리지 않았다 |
| 문서 | DOC-05 §2.1·§2.2·§3.1 제목에 현장 말 병기, §2.2 "시험·조정" 표에 "우리 라인에서 할 일 [가상]" 칸(그 표는 원문 칸뿐이라 비서가 못 읽었다). **개정 번호는 안 올림** — §7 블록·코드·UI설계서가 "Rev.1" 글자를 써서 번호 정책은 문서 담당이 정한다. 개정 기록에 "Rev.1 보정(검토 대기)" 행 |
| 측정 | 점검표 68개 정답 절 포함 85% → 100%. 진짜 Claude 위험 질문 21개: 정답 절 없이 "없다"고 답한 것 7 → 0, 평균 10.4초 → 8.4초. 보류 질문 30개 검색 26 → 30(문서 보강 전 코드만). 시험 1499 → 1610. 대가: 안전 질문에서 보내는 문서 글자가 평균 약 7,700자 → 약 21,900자 |
| 한계 | 보장은 DOC-05 한 문서. 보류 질문 중 부정확한 "없다" 1건("MIL-01 주축 헤드 받치는 방법은 없다" — 문서는 "VF-2와 같은 방법"). 발동은 낱말 기반이라 새 현장 말은 `SAFETY_TERMS`와 점검표에 더해야 한다 |

**문서 담당이 할 일:** DOC-05 "Rev.1 보정" 행(검토 대기)을 검토·승인하고, 개정 번호를 올릴지(올리면 §7 블록·`safety/templates.py`·UI설계서의 "Rev.1"도 같이) 정한다. 새 "우리 라인에서 할 일" 문장(§2.2 시험·조정)이 의도와 맞는지 본다.
