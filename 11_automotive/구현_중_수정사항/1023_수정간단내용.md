| 항목 | 내용 |

## 9. DB 중계를 공용 Supabase에도: "DB 1개 = 공장 1개" (백엔드·화면·생성기, 사용자 결정)

| 항목 | 내용 |
|---|---|
| 왜 | 팀은 Supabase(`mom-db`) 하나만 쓴다. 8장의 중계는 시연 모드(로컬 Docker DB)에서만 받아 Supabase에는 들어가지 않았다. 사용자 결정: **DB 1개 = 공장 1개** — 모두가 같은 DB·같은 데이터를 보고, 여러 명이 겹쳐 쓰는 것과 누가 [처음으로]를 눌러 모두의 10/1 기록이 지워지는 것은 받아들인다. 시계는 나중에 실제 시간으로 바꾼다 |

## 30. 새로고침해도 로그인 화면으로 가지 않고 보던 화면 그대로 (화면, 사용자 요청 "새로고침 누르면 로그인 페이지 말고 그 페이지 새로고침으로")

| 항목 | 내용 |
|---|---|
| 원인 | 로그인한 사람이 화면 메모리(`App`의 state)에만 있어서 새로고침하면 사라짐 → 로그인 화면. 보던 화면은 이미 주소(`/tools`, `/card?k=…`)로 다시 열 수 있었음(`screenFromUrl`) |
| 고침 | 로그인 · 계정 바꾸기 때 사용자 ID를 **브라우저 탭 저장소(sessionStorage)** 에 두고, 새로 열 때 그 ID로 다시 들어감 → 같은 사람 · 같은 화면. 로그아웃하면 지움, 탭을 닫으면 브라우저가 지움. 저장소를 읽기 전에는 아무것도 그리지 않아 로그인 화면이 잠깐 비치지 않음 |
| 그대로 | 비서(백엔드) 토큰은 지금처럼 메모리에만 — 새로고침 뒤 첫 질문 때 다시 받음(`assistantApi.ts` 설명 그대로) |
| 파일 | `frontend/src/shell/App.tsx` (`App` 함수) |
| 확인한 것 | `tsc --noEmit` 오류 0, 브라우저: 보전 담당 1 → 공구 수명에서 새로고침 → 같은 계정 · `/tools` 그대로, 로그아웃 뒤 새로고침 → 로그인 화면 |
