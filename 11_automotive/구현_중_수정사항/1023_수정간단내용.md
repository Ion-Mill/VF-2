# 2026-10-23 수정 간단 내용

> 팀 전달 뒤 바뀐 내용을 핵심만 정리한다 (`CLAUDE.md` 규칙). 같은 날 수정은 이 파일에 더한다.

## 1. 채팅 Claude 호출을 API로, 비교 갈래 둘 (비서, 사용자 "이 기획 진행해")

| 항목 | 내용 |
|---|---|
| 왜 | 같은 호출 방식으로 두 갈래를 비교하려고 한다. 채팅은 구독(`claude -p`)으로 고정돼 있어, 갈래를 나누기 전에 API로 바꿨다. 1번은 문서만 순수 LLM이고 수량·설비 상태·안전 순서는 프로그램이 답한다. 2번은 그 셋도 순수 LLM이 답한다 |
| 한 일 | `config.py`: 채팅 앱이면 `claude_via`를 `api`로, 모델은 Haiku 5.5, 노력은 medium. 평가 경로는 `MOM_CLAUDE_VIA` 기본 `cli` 그대로. 스위치 `PURE_COMPARE`(기본 0). `answer.py`: 0이면 수량·설비 상태를 프로그램 조회에 남기고, 안전 순서(고정 서식이 붙는 질문)는 LLM 없이 고정 서식만 낸다. 1이면 그 셋을 순수 길로 한 번 보내고, 없어도 되돌리거나 서식으로 바꾸지 않는다. 열쇠는 환경 변수 `ANTHROPIC_API_KEY`가 있으면 그것, 없으면 비서 폴더 `.env`. 시험이 가짜 실행기를 끼우면 그 실행기를 쓴다 |
| 안 바꾼 것 | 지시문 세 줄 추가는 하지 않았다. `prompts.py`, 화면, 팀 백엔드, 사내 문서, 공용 DB, 켜진 서버의 `.env`, `실행_안내.md`의 스위치 표. 센서 값 질문과 "재고는 누가 관리해?" 같은 규칙 질문, "어디를 차단" 같은 문서 질문은 지금 길 |
| 고친 파일 | `assistant/backend/config.py`·`llm/claude_client.py`·`services/answer.py`·`.env.example`·`tests/conftest.py`·`tests/test_external_switch.py`·`tests/test_pure_external.py`, `assistant/변경기록.md`, `파일설명.md`, 이 파일 |
| 확인 | 갈래 판정은 스크립트로 1번·2번을 나눠 봤다. 시험 5개 통과(설정 1, 알람은 순수 길 2, 수량은 프로그램 길 1, 신호 켜면 예전 길 1). 전체 시험은 안 돌렸다. 이 세션 환경에 `ANTHROPIC_API_KEY`가 없어 API 답은 못 봤다. 채팅 질문은 보내지 않는다 |
| 문서 담당(= 사용자)이 판단할 것 | 비교 뒤 2번을 남길지. 남기지 않으면 작업 폴더를 지운 뒤 로컬 가지 `feat/two-llm-ver-20261023`를 지우면 된다. 그 폴더의 `.env`에 적은 열쇠는 폴더를 지우면 함께 없어진다. `실행_안내.md` 스위치 표에 `PURE_COMPARE`를 넣을지는 사용자가 정한다 |

`PURE_COMPARE=0`이 기본이라, "잠금 표지 순서"를 순수 길로 기대하는 기존 시험(`test_pure_expand`의 끝에서 끝, `test_fixed_block`)은 그대로 돌리면 어긋난다. 그 시험이 보던 일은 2번(`PURE_COMPARE=1`)에서 LLM이 순서를 쓰는 쪽으로 바뀌었고, 1번에서는 프로그램 고정 서식만 낸다.

## 2. 조회 도구와 이어 묻기 (비서·채팅 말풍선)

| 항목 | 내용 |
|---|---|
| 왜 | 1번은 프로그램이 이번 문장만 보고 조회하고, 2번은 문서만 보고 "없음"이 됐다. `VF2-01 지금 상태 어때?`는 프로그램이 먼저 "확인 필요"를 말했다. 같은 날 오후 기획은 둘을 한 길로 합친다 |
| 한 일 | 외부 Claude 채팅에서 수량·설비 상태·안전 순서는 `PURE_COMPARE`와 상관없이 같다. 뜻이 안 정해지면 LLM 질문만, 정해지면 이미 있는 조회만 실행한다. 위는 LLM 문장, 아래는 `원문 보기`(말풍선에서 처음에 접힘). `어제`는 기준일 2026-10-01로 2026-09-30. `모든 설비`는 여섯 대. 가동 상태·정비 기한·정지·MTTR은 설비가 없으면 실행하지 않는다. 재고는 설비 없이 실행한다. 최근 5턴은 이미 받는 `history`의 질문과 위 문장만. 안전 순서는 위 LLM, 아래 DOC-05. 실패 로그에 예외 메시지를 남기고 열쇠·요청 본문은 남기지 않는다 |
| 안 바꾼 것 | 팀 백엔드, 알람 카드·브리핑·지침카드, 화면 설명·센서 추세·권한 거절의 순서, 채팅 모델(Haiku 5.5)·노력 medium·열쇠 위치, 사내 문서, 공용 DB, 새 시험 파일, 새 조회 |
| 고친 파일 | `assistant/backend/services/lookup_turn.py`(새), `answer.py`, `pure_external.py`, `chat_service.py`, `llm/external.py`, `llm/claude_client.py`, `tests/test_status_askback.py`, `frontend/src/shell/ChatBubble.tsx`, `assistant/변경기록.md`, `파일설명.md`, 이 파일 |
| 확인 | `test_status_askback.py` 46 통과. 전체 시험·`e2e_check.py`·채팅 질문은 돌리지 않았다. 화면 접힘은 사용자가 본다 |
| 문서 담당(= 사용자)이 판단할 것 | 이 길을 채택하지 않으면 작업 폴더를 지운 뒤 로컬 가지 `feat/two-llm-ver-20261023`를 지우면 된다. 3000 화면은 주 폴더라, 접힌 `원문 보기`는 작업 폴더 프론트를 봐야 한다 |
