> 팀 전달 뒤 바뀐 내용을 핵심만 정리한다 (`CLAUDE.md` 규칙). 같은 날 수정은 이 파일에 더한다.

## 1. 시연 시계 [20:00으로] 넘기기가 거절되던 것을 고쳤다 (시연 서버가 읽는 생성기, 사용자 요청)

| 항목 | 내용 |
|---|---|
| 증상 | 17:00이 지난 휴무에 조작판 [20:00으로]를 누르면 `넘기기는 ['TODAY_17:00']만` 이 떴다. 화면(`SimPanel.tsx`)은 `TODAY_20:00`을 보내는데, `config.json`의 `skip_targets`와 `Realtime.skip`이 17:00만 알고 시각도 항상 17시로 잡았다 |
| 고침 | `skip_targets`에 `TODAY_20:00`을 넣고, `skip`이 그 이름이면 오늘 20:00(야간 교대 시작)까지 분을 만든다. 그 시각이 이미 지났으면 시계는 그대로. 17:00 넘기기와 다음 날 06:00 넘기기 금지는 그대로 |
| 확인 | 임시 측정 폴더로 시뮬레이터를 만들어 확인: `TODAY_17:00` → 2026-10-01 17:00, 이어서 `TODAY_20:00` → 20:00, 한 번 더 눌러도 20:00 그대로, `TODAY_06:00`은 거절. 시연 서버(8765)만 다시 켬. `생성기/out_realtime/cmm_drop` git 목록은 같음(시연 서버 측정 폴더는 `out_live`). 시계는 10/1 08:00부터 다시 흐름 |
| 문서 담당(= 사용자)이 판단할 것 | 없음. 화면이 이미 약속한 버튼이 서버에서 거절되던 것을 맞춘 것이다 |

## 2. 시연 화면: 재고 "할 일" 버튼은 누른 것만 파란색 (시연 화면, 사용자 요청)

| 항목 | 내용 |
|---|---|
| 전 | 할 일의 [출하 등록]만 늘 파란색이라, 아무것도 안 눌렀는데 출하 등록을 누른 것처럼 보였다 |
| 후 | [입고 등록]·[실사·조정]·[출하 등록] 모두 흰 버튼이 기본. 누른 버튼(입력 칸이 열린 입고 등록·실사·조정)만 파란색이고, [취소]·[저장]으로 칸이 닫히면 다시 흰색. [출하 등록]은 출하 탭으로 넘어가므로 이 자리에서는 흰색 그대로 |
| 파일 | `frontend/src/shell/InventoryScreen.tsx` (`todo` 버튼 모양 한 곳) |
| 확인 | `tsc --noEmit` 오류 0. 브라우저(3000)에서 반장 주간으로 입고 등록을 누르면 그것만 파래지는 것 확인 |

## 6. 시연 화면: 채팅 기록을 서버(`chat_log`)에서 읽고, 이어서 물을 때 앞 질문 번호를 보낸다 (시연 화면, 사용자 요청 "기획서에 맞게")

| 항목 | 내용 |
|---|---|
| 기획서 | 질문·답은 사용자마다 **서버에** 30일 저장하고, 채팅 기록 탭에서 본인 것을 다시 보고 이어서 묻는다 (기획서 9장 MNT-01 "채팅 기록", FR-MNT-01-01, NFR-DATA-13, API-AST-02 GET·`prev_chat_id`) |
| 전 | 백엔드는 이미 `chat_log`에 저장하고 GET도 있었지만, 화면의 채팅 기록 탭은 **이 브라우저 저장소(`chat:<사용자>`)만** 읽었다 → 다른 PC·브라우저·시크릿 창에서는 기록이 비어 보였다. 이어서 물을 때 앞 `chat_id`도 보내지 않았다 |
| 후 | 백엔드 비서를 켰을 때(`NEXT_PUBLIC_MOM_API`) 채팅 기록 탭을 열 때마다 `GET /api/assistant/chat`(본인 것·30일)을 받아 이 브라우저 기록과 합쳐 보인다. 같은 질문은 `chat_id`로 한 번만(이 기능 전 브라우저 줄은 질문·답 글자가 같으면 같은 것으로). 기록을 눌러 연 대화가 서버에만 있어도 채팅 탭에서 보인다. 질문할 때 보고 있는 대화의 마지막 `chat_id`를 `prev_chat_id`로 보낸다(새 대화 첫 질문은 없음). 서버에 그 번호가 없으면(30일 지남·DB 초기화) 앞 질문 없이 한 번 다시 묻는다. 백엔드 비서를 끄면 전처럼 브라우저 기록만 |
| 파일 | `frontend/src/shell/assistantApi.ts` (`askAssistant`에 `prevChatId`·답에 `chatId`, `fetchChatLog` 새), `chatLog.ts` (`mergeServerLog`·`lastChatId` 새), `Eve.tsx` (`useServerChat`, 채팅·채팅 기록 탭), `ChatBubble.tsx` (`ChatRow.chatId`), `frontend/tools/chat_log_check.mjs` (시험 16 → 22개) |
| 확인 | `tsc --noEmit` 오류 0, `chat_log_check.mjs` 22개·`chat_bubble_check.mjs` 통과. 브라우저(3000)에서 반장 주간으로 열자 이 브라우저에 없던 서버 기록 6줄이 채팅 기록 탭에 보임. 질문 두 개를 이어 물으니 두 번째 줄의 `prev_chat_id`가 첫 질문 `chat_id`로 저장됨 |
| 남은 것 | ① 비서 서비스(`assistant/backend/chat_service.py`)는 지금 앞 대화(`history`)를 답에 쓰지 않는다(`FOLLOWUP=0`) — 백엔드는 넘기지만 답은 여전히 질문마다 독립이다. 쓸지는 [선택 필요: LLM 담당]. UI설계서 SCR-10 [9]의 "비서에게는 이전 대화를 보내지 않으므로(질문마다 독립)" 문장도 그때 같이 고친다 ② DB 시연 시계(`sim_clock`)와 시연 서버 시계가 따로 가서, 다른 PC에서 물은 줄은 DB 시각(지금 10/1 08:00 멈춤)으로 보인다 |
