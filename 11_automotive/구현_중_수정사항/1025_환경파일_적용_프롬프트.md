# 환경 파일 적용 프롬프트 — 받은 `.env` 두 개를 내 PC에 적용하기 (2026-10-25)

> **이 문서에는 비밀값이 없다.** 적용할 `backend/.env`·`assistant/.env`(비밀 포함)는 저장소에 없고, 배포자가 **개인 메시지로만** 따로 보낸다.
> - 쓰는 법: 개인 메시지로 받은 `.env` 두 파일을 한 폴더에 둔 뒤, 아래 `========` 줄 **아래 전체**를 자기 Claude Code에 붙여 넣는다.
> - `.env.supabase`(공용 DB)는 들어 있지 않다. 필요하면 DB 담당에게 받는다.
> - 받은 파일 안의 Anthropic·Gemini 키는 배포자 계정이라, 쓰면 요금과 한도가 배포자에게 잡힌다. 다른 곳에 쓰지 않는다.
> - 로컬 DB(Docker)용 설정이다. 공용 DB 설정과 섞지 않는다.
========================== 아래부터 붙여 넣기 ==========================

너는 이 저장소(`semi-ai`, `Ion-Mill/VF-2`)에서 내 PC의 **환경 설정 파일 2개를 적용**하는 일을 돕는다. 아래를 **순서대로** 하고, 모르는 것은 추측하지 말고 나에게 먼저 묻는다. 한국어로 쉽게 답한다.

## 0. 먼저 지킬 것 (전부 지킨다)

- 받은 `.env` 두 파일의 **값(비밀번호·키·접속 주소)을 화면·채팅·문서·커밋·로그에 출력하지 않는다.** 키 **이름**과 "있음/없음"만 말한다.
- `.env` 파일은 **git에 올리지 않는다.** 커밋·푸시·PR에 넣지 않고, `.env.example`에 값을 옮겨 적지 않는다.
- 공용 DB(Supabase `mom-db`)에는 **아무 쓰기도 하지 않는다.** `backend/.env.supabase`를 만들거나 고치지 않는다. 시연 모드·스케줄러를 공용 DB에 대해 켜지 않는다.
- 8000·8010 포트는 다른 프로젝트 것이니 건드리지 않는다. 시연 서버(8765)를 **하나 더 띄우지 않는다.** `taskkill /IM`처럼 **이름으로 프로세스를 끄지 않는다**(PID로만).
- 손으로 `uvicorn`/`npm run dev`를 켜지 않는다. 서버는 `start_all.ps1`로만 켜고 `stop_all.ps1`로만 끈다.
- `npm install`·`pip install`·`docker compose down -v`처럼 **내 PC의 데이터나 패키지를 바꾸는 일은 먼저 나에게 묻는다.**

## 1. 준비 확인 (읽기만)

1. `git status`, 현재 가지, 최신 `main`을 받았는지 확인한다. `11_automotive/assistant/start_all.ps1`에 아래 세 가지가 **모두** 있는지 확인한다: ① `-LocalDb` 옵션 ② 시연 서버에 `MOM_ENV_FILE`을 넘기는 줄 ③ 서버를 켠 뒤 원래 없던 환경변수를 `Remove-Item "Env:..."`로 지우는 부분(없으면 서버를 한꺼번에 켤 때 시연 서버가 빈 `MOM_ASSISTANT_URL`을 받아 지침카드의 비서 정리 글이 전부 실패한다). 하나라도 없으면 `main`이 오래된 것이니 나에게 `git pull origin main`을 할지 묻는다.
2. 가상환경이 있는지만 본다: `11_automotive/backend/.venv`, `11_automotive/assistant/.venv`, `11_automotive/생성기/.venv`, `11_automotive/frontend/node_modules`. 없으면 나에게 알린다(설치는 묻고 한다).
3. Docker Desktop이 켜져 있는지, 포트 5432·5433·8020·8100·8765·3000이 쓰이는지 본다.
4. 내 PC에 이미 `11_automotive/backend/.env`, `11_automotive/assistant/.env`가 있는지 본다.

## 2. 덮어쓰기 전에 내 기존 설정 기록 (있을 때만)

내 기존 `assistant/.env`가 있으면, 덮어쓰기 **전에** 아래 **이름과 값만**(키·비밀번호는 말고) 나에게 보고한다. 비서 쪽 문제를 찾는 데 쓴다.

- `ASSISTANT_PROVIDER`, `CLAUDE_VIA`(있으면), `PURE_MODEL`, `EXTERNAL_LLM_APP`, `LLM_ENABLED`
- `GEMINI_API_KEY`·`ANTHROPIC_API_KEY`가 **채워져 있는지 아닌지**(있음/없음만)

그리고 기존 `assistant/.env`와 `backend/.env`를 같은 폴더에 `.env.bak-20261025`로 **이름만 바꿔 보관**한다(내용을 읽어 출력하지 않는다). 그 파일들도 git에 올라가지 않는지 `git check-ignore`로 확인한다.

## 3. 파일 놓기

내가 알려 주는 폴더(받은 폴더)에서 아래 둘을 복사한다.

| 받은 폴더 안 | 놓을 곳 |
|---|---|
| `backend/.env` | `11_automotive/backend/.env` |
| `assistant/.env` | `11_automotive/assistant/.env` |

그다음 확인한다(값은 출력하지 않는다):

1. 두 파일이 `git check-ignore`로 **무시되는지**(안 되면 중단하고 알린다).
2. `.env`와 `.env.example`의 **키 이름**을 비교한다(백엔드 29개, 비서 68개). 차이가 있으면 이름만 보고한다.
3. 백엔드와 비서의 `MOM_ASSISTANT_KEY`가 **같은 값인지**를 해시로만 비교한다(값을 찍지 않는다).

## 4. 내 PC에 맞출 값 (이 세 가지만 고친다)

1. **DB 포트.** 받은 백엔드 `.env`의 `MOM_DATABASE_URL`·`MOM_READONLY_DATABASE_URL`은 `127.0.0.1:5433`이다(보낸 사람 PC는 5432를 다른 Postgres가 써서 5433을 쓴다). 내가 `backend/docker-compose.yml`을 **그대로** 쓰면 DB가 5432로 열리므로, 두 줄의 **포트 숫자만** 내 DB 포트에 맞춘다. 비밀번호 부분은 그대로 둔다. 5432를 이미 다른 프로그램이 쓰면 나에게 묻는다.
2. **영상용 데이터 폴더.** `.env`에 `GEN_OUT_DIR=out_video`, `GEN_RT_DIR=out_realtime_video`가 있다. `11_automotive/생성기/out_video`가 없으면 `cd 11_automotive/생성기` 뒤 `.venv\Scripts\python generate.py --profile video`로 만든다(약 15초, 깃에 올라가지 않음). 만들기 전에 나에게 알린다.
3. **마이크.** 비서 `.env`는 `ASSISTANT_VOICE=1`이다. 처음 마이크를 쓸 때 음성 모델(`large-v3-turbo`, 약 1.5GB)을 내려받는다. 내 PC가 느리거나 마이크를 안 쓸 거면 `0`으로 바꿀지 나에게 묻는다.

## 5. 로컬 DB 띄우기

- `11_automotive/backend`에서 `docker compose up -d --build`로 DB와 처음 적재를 한다(약 20초~수 분). 로그에서 "적재 점검"이 모두 OK이고 `완료`가 나오는지 본다.
- **이미 내 PC에 예전 로컬 DB 볼륨(`pgdata`)이 있으면** 비밀번호가 달라 접속이 안 될 수 있다. 이때 `docker compose down -v`는 **내 로컬 DB 데이터를 지우므로 반드시 나에게 먼저 묻는다.** 묻기 전에는 하지 않는다.
- 적재가 끝나면 필요 없는 `api` 컨테이너는 멈춘다(서버는 아래 6번 `start_all.ps1`이 내 PC에서 켠다). DB 컨테이너는 둔다.
- 점검: `cd 11_automotive/backend` 뒤 `.venv\Scripts\python tools\check_connection.py --env-file .env` → **4개 모두 OK**여야 한다. 비밀번호가 섞인 접속 주소가 출력에 나오면 `://사용자:***@`로 가려서 보여 준다.

## 6. 서버 켜기

저장소 루트에서 **먼저 계획만** 본다(아무것도 켜지 않는다).

```powershell
.\11_automotive\assistant\start_all.ps1 -LocalDb -Screen -Profile video -LlmCompose -DryRun
```

문제가 없으면 `-DryRun`만 빼고 같은 명령으로 켠다. 거부되면 **우회하지 말고** 이유를 그대로 알려 준다. 끄기는 `.\11_automotive\assistant\stop_all.ps1`(끄기 → 켜기 순서). 이 설정은 **로컬 DB용**이라, 나중에 공용 DB로 돌아가려면 `stop_all.ps1`로 끈 뒤 `-LocalDb` **없이** `start_all.ps1 -Screen -Profile video`로 켠다(그때는 `backend/.env.supabase`가 필요하고, 없으면 나에게 알린다).

## 7. 켠 뒤 확인 (읽기 위주)

- `11_automotive/assistant/.run/pids.json`에 서버 4개(backend·assistant·sim_server·screen)가 있고 살아 있는지.
- `http://127.0.0.1:8020/api/health` → 200, 비서 `http://127.0.0.1:8100/health`를 **키 없이** 부르면 401, `http://localhost:3000/` → 200.
- 브라우저 `http://localhost:3000`: 아이디를 고르면 비밀번호 `0000`이 채워진다. **U12**로 들어가 시연 조작판의 사건 버튼과 [처음으로]가 되는지 나에게 눌러 보게 한다(너는 누르지 않는다).
- **채팅 질문은 꼭 필요할 때만** 한다. 질문이 외부 Claude로 나가고 요금이 키 주인(배포자)에게 잡힌다.

## 8. 추가 요청 (비서 답이 "응답 없음"이 되는 문제 확인, 선택)

비서가 답에 쓸 문서 줄을 **6개 넘게 고르면** 질문 전체가 "응답 없음"이 될 수 있다는 가설이 있다. 아래를 **읽기만** 해서 알려 준다.

1. `11_automotive/assistant/.run/*.log`와, `STEP_LOG` 폴더(비서 `.env`의 `STEP_LOG_DIR`, 없으면 기본 위치)에서 `스키마 제약 위반` 또는 `항목 N개 > 6`(N은 숫자)을 검색한다.
2. 나온 **횟수**와, 나온 줄 **한 줄씩**(질문 글·키·비밀번호는 빼고, 시각과 오류 문구만)을 보고한다. 하나도 없으면 "없음"이라고 쓴다.
3. 2번에서 기록해 둔 내 **기존** 비서 설정(이름과 값, 키는 있음/없음)도 같이 보고한다.
