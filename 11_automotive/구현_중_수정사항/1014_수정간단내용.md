## 1. 공구 수명 예측 모델(ML) 빼기 (데이터·ML 담당 결정)

ML-01 **공구 수명 관리·교체 알림** 기능은 그대로 두고, 그 안의 **예측 모델만** 뺐다.

| | 전 | 지금 |
|---|---|---|
| 교체 알림 | 사용량 기준 (90% 교체 알림, 한도 → 알람 362, 부하 급증 → 174) | **그대로** |
| 공구 화면 (SCR-22) | 사용률 + "참고값 ○○% (실제 데이터로 한 예측 실험)" | 사용률 + **남은 수명** (100 − 사용률, 남은 부품 수 — 계산식) |
| 예측 모델 | 실제 Haas VF-1 실험 데이터(엔드밀 14개)로 학습한 LightGBM | **없음** |

**왜 뺐나**

| 이유 | 내용 |
|---|---|
| 계산식으로 충분 | 공구 교체 판단은 사용량 계산식과 Haas 알람으로 이미 됨. 실험 데이터에서도 "몇 번 썼나"만으로 남은 수명이 대부분 맞음 (R² 0.597, ML 최고 0.652) |
| 우리 데이터와 맞지 않음 | 실험은 강철·진동·전류 센서, 우리 공장은 알루미늄·진동 센서 없음. 10/1 시연과 연결하려면 센서 값을 만들어 넣어야 해서 근거 규칙과 부딪힘 |
| 프로젝트 성격 | 데이터는 실제 공개 기록·실제 문서를 바탕으로 만든 가상 데이터이고, 이 프로젝트의 AI는 **AI 비서(이브)**. ML을 억지로 넣을 필요가 없음 |

**검토한 다른 ML 후보** (결과: 넣지 않음): 센서 기반 공구 파손 조기 경보(실험 데이터에서는 센서가 도움이 됐지만 우리 설비 데이터와 연결 불가), 문서 검색 임베딩 시험(AI 담당 영역 — NFR-AIQ-05 그대로), 정비 메모 구조화 정확도, 불량 위험 점수, 정지 시간 예측 — 데이터가 작거나 정답이 없어 약함.

## 2. 생성기 5단계 ①: 측정값으로 판정 (데이터·ML)

측정한 부품마다 항목별 측정값(`inspection_result`)과 측정 결과 파일 가져오기 기록(`cmm_import`)을 만들고, **로트 판정을 측정값으로** 한다. `out/` CSV **28개**, 점검 **66줄 실패 0·참고 1**, pytest 7개 통과, 같은 seed면 같은 결과.

| 규칙 | 근거 |
|---|---|
| 측정값 = 규격 가운데 근처 정규분포. Cpk 항목마다 1.5~2.0, **1번 부싱 구멍 1.8~2.0** | 설계서 5.15, DOC-06 §2 (1번 최소 1.67) |
| 치수 불량(DIM)은 **평균이 움직인 부품**(공구 사용률 90% 넘음, 108·충돌 직후)에서만. 그 부품의 평균을 0.5 표준편차 옮김 [가상] | 설계서 5.15 "공구 수명 끝, 충돌 직후 평균이 움직여 불합격" |
| 치수 불량은 **측정한 부품에서만** 찾음 (게이지·육안으로는 못 찾음) | DOC-06 §3 (발췌 검사) |
| 측정 불합격 → 로트 **보류 검토** → 남은 부품 전수 → 반장 **보류(계기 = 측정 불합격)** → 판정 → 해제 | DOC-06 §4.1·§4.2 |
| 부품 온도 = 냉각식 (세척 뒤 47~53 ℃, 시간 상수 48분), 측정실 20 ℃ | DOC-06 §6.1 |
