| 누가 쓰는지 | 공용 DB에 쓰는 PC는 **한 번에 하나**: DB에 `live_owner` 표지(쓰는 사람·마지막 기록 시각)를 두고, 최근 2분 안에 다른 PC가 쓰고 있으면 거부. 인계는 `-TakeOver` |
| 확인 옵션 | `final`을 켤 때 `-ConfirmSharedWrite`가 있어야 통과 (모르고 켜는 사고 방지) |
| 프로필과 DB 일치 | DB의 `demo_meta` 표지(프로필·기록 기간·시드)와 인자가 다르면 거부 |
| `stop_all.ps1` | 그대로 (켠 프로세스를 기록해 두고 끔). 포트도 그대로 — 시연 서버 포트(8765)가 코드에 박혀 있어 두 프로필을 **동시에 켤 수는 없음** |
| 먼저 시험 | `-DryRun`을 붙이면 아무것도 켜지 않고 프로필 값과 요약만 확인 |

### 6-5. "잠금"을 어떻게 바꾸나 (풀지 않고 허용 조건을 좁게)

| 잠금 | 지금 | 바꿀 내용 |
|---|---|---|
| DB 중계 ① | 중계 대상 주소가 localhost가 아니면 안 켜짐 | 서버에서 시연 서버와 백엔드가 같은 기계면 그대로 통과. 다른 기계면 "허용 주소 목록"에 그 주소만 추가 |
| DB 중계 ② | 백엔드가 시연 모드(`MOM_DEMO_MODE`)가 아니면 거부(409) | **서버의 백엔드를 시연 모드로 켬** (핵심 변경) |
| `start_all.ps1` 공용 DB 보호 | 공용 DB에서 `MOM_DEMO_MODE=true`면 시작 거부 | `final`에서만 허용, `-ConfirmSharedWrite`가 있을 때만 통과. `MOM_RUN_WORKERS=false`는 유지 |

시연 모드를 켜면 되돌리기·재동기화 같은 API도 열리므로, 서버에서는 **접속 키가 있어야 부를 수 있게** 해야 한다.

| 항목 | 동작 |

팀원이 화면을 시험해 볼 때는 **영상용(`video`)** 을 로컬 DB로 쓰면 된다(공용 DB에는 10/24 09:00 이후 기록도 들어 있어 미래 기록이 보임).

## 11. 위험과 되돌릴 곳

- 발표(월요일)까지 이틀이라 **프로필·교대·데이터·문서를 한꺼번에 바꾸는 것은 위험**하다. 진행하기 전에 현재 상태에 `git tag`를 달아 두고, 개조가 안 되면 지금 설계(9/30 → 10/1)로 발표할 수 있게 한다.
- 권장 순서: ① 날짜·교대 시각 하드코딩 목록 만들기 → ② 설정화와 `profiles/` → ③ 데이터 한 번 생성(공용 DB 교체) → ④ 문서·시험 정리 → ⑤ 영상 재촬영 → ⑥ 서버 올리기.
- 공용 DB에 쓰는 것은 팀원 테스트와 충돌할 수 있으므로 `live_owner` 잠금과 `-ConfirmSharedWrite`를 반드시 같이 한다.

**오전 충돌의 작업지시서·작업기록 (A안, 고침)**: 화면의 작업지시서·작업기록은 원래 브라우저마다 따로 저장(`localStorage`)된다. 그래서 오전 충돌 문서가 평가자 모두에게 같게 보이도록, 생성기가 **실시간 구간에 끝난 OP-30 정지 알람마다 작업지시서(승인 → 완료)·작업기록서(확정)·문서 버전(v0~)·사용 부품·재고 거래(`WORK_RECORD`)** 를 과거 기록과 같은 방식으로 만들고(`gen/realtime.py _maint_docs`, `mnt_docs.build_mnt` 재사용, 번호는 과거 뒤: `MW-1009`·`MR-1009`), 시연 서버가 이것을 **지난 정비 기록**(`maint/history`)과 정지↔작업지시서 연결(`wo_link`)로 내려준다. 같은 문서가 DB 적재 CSV(`out_realtime_final/`)에도 들어 있다. 남은 선택: DB에서 읽게 할지(PR #142 C2).
