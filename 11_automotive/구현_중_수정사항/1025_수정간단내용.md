## 1. 지침카드 두 칸이 동시에 다듬기를 시작

| 항목 | 내용 |
|---|---|
| 왜 | 시연 서버의 비서 호출 자리가 2개뿐이고 보고서·작업지시서와 같이 쓴다. 한 칸이 자리를 잡으면 다른 칸은 그 답이 끝날 때까지 기다린다. 로그에서 992 보전 칸은 13702ms로, 먼저 할 일 5077ms보다 늦게 끝났다 |
| 한 일 | 지침카드만 자리 2개를 따로 둔다. 먼저 할 일과 보전 담당자 단계는 보고서가 자리를 잡고 있어도 같이 비서를 부른다. 한 호출로 합치지 않는다 |
| 안 바꾼 것 | 지시문, 화면, 검사, 비서 동시 호출 한도(8), 보고서·작업지시서의 자리 2개 |
| 고친 파일 | `frontend/tools/llm_compose.py`, `frontend/tools/tests/test_llm_compose.py`, `assistant/변경기록.md`, `파일설명.md`, 이 파일 |
| 확인 | `test_llm_compose.py` 중 지침카드 입구와 동시 시작 시험 13 통과. 전체 시험·화면·서버 다시 켜기는 사용자가 한다 |
| 문서 담당(= 사용자)이 판단할 것 | 없음. UI설계서 문장은 그대로다 |

## 2. 지침카드 지시문에 절·점검 번호를 그대로 두라고 더함

| 항목 | 내용 |
|---|---|
| 왜 | 보전 2번 줄 `(§2.5 점검 8)`에서 `2.5`와 `8`이 빠져 검사가 거절했다. 시연 서버는 30초 뒤에 다시 불러 보전 칸이 약 54초 뒤에 보였다. 공통 지시문은 숫자를 빼지 말라고 이미 적혀 있고, 모델은 괄호 안 번호를 설명으로 보고 뺐다 |
| 한 일 | 지침카드 지시문에 괄호 안의 절 번호·점검 번호(§2.5 점검 8)를 빼거나 풀어 쓰지 말고 원문 그대로 두라고 더했다. 검사는 그대로다 |
| 안 바꾼 것 | 자리 분리, 화면, 30초 재시도, 안전 칸 고정 서식 |
| 고친 파일 | `assistant/backend/llm/compose.py`, `assistant/backend/tests/test_compose_service.py`, `assistant/변경기록.md`, `파일설명.md`, 이 파일 |
| 확인 | 해당 시험 5개 통과. 비서를 다시 켠 뒤 같은 보전 네 줄은 첫 답이 10.3초에 준비되고 `2.5`·`8`이 남았다. 전체 시험과 채팅 질문은 돌리지 않았다 |
| 문서 담당(= 사용자)이 판단할 것 | 없음 |

## 3. 백엔드 예시 파일에 비서 주소와 대기 시간을 채움

| 항목 | 내용 |
|---|---|
| 왜 | 이 PC의 공용 DB 설정에는 비서 주소와 대기 130초가 있는데, 팀원에게 주는 예시에는 주소가 비어 있고 대기 줄이 없었다. 로컬 예시는 대기가 30초였다 |
| 한 일 | `.env.supabase.example`에 비서 주소 `http://127.0.0.1:8100`과 `MOM_ASSISTANT_TIMEOUT_SECONDS=130`을 넣었다. `.env.example`의 대기를 130초로 바꿨다 |
| 안 바꾼 것 | `.env.supabase` 실제 파일. DB 호스트·5432와 비서 `127.0.0.1:8100`은 예시에 둠. 비밀번호·서명 키·ingest 키·비서 키는 자리표시. 시연 모드·스케줄러는 공용 DB 예시에서 `false` |
| 고친 파일 | `backend/.env.example`, `backend/.env.supabase.example`, `파일설명.md`, 이 파일 |
| 확인 | 키 이름만 대조. 서버는 다시 켜지 않음 |
| 문서 담당(= 사용자)이 판단할 것 | 팀원에게 예시 파일을 전달할 때, 비밀번호와 키는 예시가 아니라 각자 채운다 |
