## 1. 생성기 개발 환경과 결과 형식 (3단계 준비)

PC를 확인해 보니 Python 3.12·3.13·3.14가 함께 깔려 있고, 터미널 기본은 3.12, VS Code 기본은 3.14로 서로 달랐다. 그래서 버전과 환경을 못 박았다. 자세한 것은 [생성기/기준정보_목록.md](../생성기/기준정보_목록.md) 2.1·2.2.

| 항목 | 정한 것 |
|---|---|
| Python | **3.12** + 프로젝트 가상환경 `생성기/.venv` (저장소에 안 올림) |
| 라이브러리 | numpy 2.4.3, pandas 3.0.1, pytest 9.1.1 — `생성기/requirements.txt`에 고정 |
| VS Code | `.vscode/settings.json`이 `생성기/.venv`의 Python을 쓰게 함 |

## 3. MNT 첫 화면과 작업지시서 배정 알림 (같은 날 2차 팀 결정)

2장 뒤 의논에서 정했다. 요구사항 수(298개)와 API·화면·엔터티 수는 그대로다.

| # | 정한 것 | 바뀌기 전 |
|---|---|---|
| 1 | **MNT 첫 화면 = SCR-04 3D 라인 뷰.** 로그인 팝업은 없다. "내 할 일"은 메뉴 "문서함"(SCR-18)에서 연다 | SCR-18 문서함 "내 할 일" |
| 2 | 작업지시서가 승인되면 **담당 MNT에게 "작업지시서 배정" 참고 알림**(보고 순위 4). 담당 MNT가 그 작업지시서를 열거나 [작업 시작]을 누르면 자동 처리 | 승인 알림 없음 |

- **이유:** MNT "내 할 일"(오늘 예방 정비·배정된 작업지시서·작성 중 작업기록서) 가운데 예방 정비는 교대 시작 브리핑과 겹친다. 남는 빈틈(급하지 않은 작업지시서가 승인돼도 담당 MNT가 모름)은 배정 알림으로 메운다. 고장 작업지시서는 긴급 팝업이 이미 MNT에게 간다.
- **결과:** 모든 역할의 첫 화면에 3D가 있다 (OPR = SCR-26 현장 보기, SUP·MNT·MGR = SCR-04). 로그인 팝업은 MGR의 일일 보고서 팝업 하나뿐이다.

**반영한 문서:** [기획서](../기획서_최종본.md) 4.3 중요도·보고 순위 표, 9장 AST-02 알림 표, PRD-04 MGR 줄, 18장 6번, 20장 끝 표 / [요구사항](../요구사항정의서_최종본.md) FR-MNT-03-14, FR-AST-01-02, 보고 순위 4, NFR-USE-08, 12.4 / [UI설계서](../UI설계서_최종본.md) 2.2 메뉴 표, 2.3·2.5, 3장 SCR-18 줄, 4.1 그림·글, SCR-07 표, SCR-11 [10], SCR-18 머리, 9.1 #9, 9.8 #6·#7, 추적표 / [논리ERD](../논리ERD_최종본.md) 6.36 `WO_ASSIGNED`·처리 표, R4, `notification_rule` 23행, 6.37 MNT / [API](../API명세서_v1.md) API-MNT-06 / [테스트](../테스트계획서_v1.md) T-FR-MNT-03-14-2 (경계·예외 39개) / [DOC-07](../가상사내문서/DOC-07_설비데이터지표정의서.md) **Rev.4** §10.2·§10.5

## 10. 세척(OP-40) 묶음 = 한 로트만, 최대 30개 (같은 날, 데이터·ML 결정)

### 10.1 바뀐 규칙

| | 전 | 뒤 |
|---|---|---|
| 한 번 세척 | 30개가 모이면 로트와 관계없이 30개 | **한 로트만, 최대 30개**. 48개 로트 → 30개 + 18개 두 번 |
| 30개가 안 될 때 | 앞 공정이 비었거나 교대 끝 40분 안이면 모인 만큼 | **그 로트의 마지막 부품이 OP-30을 마치면** 세척. 앞 공정이 비었거나 **교대 끝 90분** 안이면 먼저 온 로트부터 모인 만큼 [가상] |
| 세척 시간 | 25분 | 25분 그대로 (개수와 관계없이, 초음파·진동 바렐은 한 번 돌리는 시간이 정해져 있음) [가상] |
| 이유 | — | **로트 추적.** 전에는 9월 세척 묶음의 62%(217번 중 134번)에 로트 2~4개가 섞여, 세척 문제(WSH-02 세정력 저하 등)가 나면 여러 로트를 의심해야 했음 |

- 교대 끝 기준을 40 → 90분으로 늘린 이유: 상자에 로트가 2~3개 있으면 25분씩 차례로 씻어야 해서, 40분이면 남은 로트가 다음 교대로 넘어가 교대 실적이 59~133개로 흔들림. 90분이면 55~102개 (전 65~106개와 비슷).
- 세척 횟수는 217번 → **398번**(평균 22개 → 12개), 세척기 가동 약 22% → 40%. 라인(3.5분/개)보다 훨씬 빨라 병목이 되지는 않음. 처음 예상(약 254번)보다 많은 까닭은 로트가 작고(평균 25개) 두 VF-2에서 로트가 번갈아 나와 "로트 마지막 부품" 조건이 자주 걸려서.
- 시험 추가: 세척 한 번에 로트 1개·30개 이하 (pytest 7개).
- 함께 고친 버그: 과거 기록의 병목 원인 ③(검사 강화) 시작을 그 로트 부품이 OP-50에 처음 온 때로 잡아, 9/3에 보류(21:16)보다 먼저(16:48) ③이 기록됨 → **보류한 때부터** 세도록 고침 (실시간 쪽은 원래 맞음). 점검 1줄 추가: "③은 로트 보류 뒤에만".
