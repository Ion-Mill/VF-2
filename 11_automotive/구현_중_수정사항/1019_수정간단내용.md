## 8. 작업지시서에서 비서(LLM)가 쓰는 칸은 "제목·증상" 한 곳 — 기획 문서의 "비서가 쓴다" 표현을 구현에 맞췄다 (기획·설계 문서, 사용자 결정)

| 항목 | 내용 |
|---|---|
| 바꾼 것 | 문서 글만 고침. **기획서** 9장 MNT-03 칸 표(제목·증상 / 작업 순서 / 예상 부품·공구), **요구사항정의서** FR-MNT-03-04·05·12, **UI설계서** SCR-11 3·4·8번 줄, **논리 ERD** 5.D.2 `work_order_step`·5.D.3 `work_order_part` 설명. 네 문서의 개정 기록에 한 줄씩(기획서는 "최종본 수정" 단락). 요구사항 수·화면 수·엔터티 수는 그대로 |
| 왜 | 문서는 제목·증상, 작업 순서, 예상 부품 세 칸을 모두 "비서가 쓴다"고 했다. 구현(`App.tsx` `createWo`)은 **제목·증상만** 비서(LLM)가 다듬고(스위치가 켜져 있을 때, 못 쓰면 기본 문장 그대로), **작업 순서**는 알람의 보전 줄(없으면 점검 순서)을 프로그램이 옮기고, **예상 부품**은 9월 같은 알람 작업기록서에 쓴 부품을 프로그램이 가져온다 |

## 9. `start_all.ps1`에 `-LlmCompose` 옵션을 더했다 (비서 폴더 스크립트, 사용자 요청)

| 항목 | 내용 |
|---|---|
| 왜 | 시연 서버의 문장 다듬기 스위치(`MOM_LLM_COMPOSE`)는 기본 꺼짐인데 `start_all.ps1`이 이 값을 주지 못해, 스크립트로 시연 서버를 켜면 보고서 둘·작업지시서·지침카드의 비서 문장이 늘 안 나왔다 (이 PC 시연 서버 `health`의 `llm_compose.enabled: false`로 확인) |
| 고침 | `assistant/start_all.ps1`: `-Screen -LlmCompose`면 새로 켜는 시연 서버 프로세스에만 `MOM_LLM_COMPOSE=1`을 줌. 이미 켜진 시연 서버는 건드리지 않고 `health`를 읽어 "적용 안 됨"을 알림. `assistant/실행_안내.md` 결론 ②·5-0절·6-3절에 옵션을 적고 낡은 시험 수(1499→2210)를 고침 |
| 확인 | PowerShell 7·5.1 `-DryRun` 5가지. 비서 시험 2210 passed·2 skipped·81 xfailed, 시연 서버 도구 시험 39 passed. 실제로 새로 켜 보는 것은 아직 못 함 |
| 팀 코드·DB | **안 고침** (`frontend/`·`backend/`·공용 DB). 켜면 보고서 둘·작업지시서·지침카드 문장이 외부 Claude로 전송된다(가상 데이터 문장만, 요구사항 NFR-SEC-08) |
| 문서 담당(= 사용자)이 판단할 것 | 팀원에게 "시연 서버를 껐다 켤 때 `-LlmCompose`를 붙인다"고 알릴지 |
