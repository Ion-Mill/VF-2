## 2. 시연 화면: 출하 줄·출하 등록의 [합격] 시각을 "완제품으로 들어온 시각"으로 맞췄다 (시연 서버·화면, 사용자 요청)

| 항목 | 내용 |
|---|---|
| 증상 | ① 출하를 확정한 직후 지난 출하 상세의 [합격] 칸이 `—`로 나왔다 — 시연 서버가 10/1에 만든 출하 줄에 `lot_passed_at`을 안 넣었다 ② 그걸 고친 첫 수정은 언제나 **판정 시각**(`judged_m`)을 넣어, 보류 뒤 **해제한 로트**는 9월 기록·실제 백엔드와 다른 시각이 찍혔다 ③ 출하 등록의 로트 카드 "합격 …"과 선입선출 순서도 판정 시각(`judged_at`)을 써서 해제 로트만 어긋났다 |
| 맞는 기준 | 합격 = 판정 시각, 해제 = **해제 시각**. 생성기 `생성기/gen/stage4.py`의 `passed_m`(9월 `shipment_line.lot_passed_at`이 이 값), 백엔드 `v_production_lot.passed_at`·`fn_confirm_shipment`(`LOT_PASS` 입고 시각)이 모두 이렇다 |
| 고침 | ① `frontend/tools/sim_server.py` 출하 등록(POST `shipments`): 줄마다 `lot_passed_at = passed_m(로트)` ② `frontend/tools/server_live.py` 로트 목록(`lots`)에 `passed_at`을 더함(백엔드와 같은 이름, 합격·해제 로트만 값이 있음). `judged_at`은 그대로(로트 화면·보고서는 "판정 끝났나"로 씀) ③ `frontend/src/shell/InventoryScreen.tsx` 출하 등록 카드의 "합격" 표시와 선입선출 정렬을 `judged_at` → `passed_at` |
| 확인 | 시연 서버를 프로그램 안에서 띄워 점검: 해제 로트 `LOT-2609-012-1`이 판정 09-04 03:30 / `passed_at` 09-04 04:49(9월 출하 줄 값과 같음), 합격 로트는 모두 `passed_at = judged_at`, 합격·해제가 아닌 로트는 비어 있음, 새 출하 줄의 `lot_passed_at`이 로트 `passed_at`과 같음. `npx tsc --noEmit` 통과. 브라우저로 화면을 직접 보지는 않음. 시연 시작(10/1 08:00)에는 출하할 수 있는 해제 로트가 없어 해제 로트는 남은 수량을 메모리에서만 늘려 시험함 |
| 팀 코드·DB | **안 고침**(실제 백엔드는 이미 해제 시각을 씀) |
| 남은 차이 | 백엔드 선입선출은 합격 **날짜** 단위로 순서를 매기고(`inventory.sql` `fifo_rank`), 시연 화면은 시각 단위로 매긴다. 이번에 바꾸지 않음 |
