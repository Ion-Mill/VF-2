# 06. 역할별 권한 — OPR·MNT·SUP·MGR

기획서 13.1·13.2, API명세서_v1 2장 "역할" 칸, UI설계서 9장을 서버에서 어떻게 지키는지 한곳에 모은 문서다.
버튼 숨기기는 화면 편의일 뿐이고, **막는 것은 서버다** (NFR-SEC-05).

## 1. 세 겹으로 막는다

| 겹 | 어디서 | 무엇을 | 걸리면 |
|---|---|---|---|
| ① 관문 | 처리기 `Depends(require(target, action))` / `require_any(...)` — 표는 `role_permission` (`db/seed/20_roles_permissions.sql`) | 이 역할이 이 동작을 할 수 있나 | 403 `FORBIDDEN` |
| ② 범위·대상 | 처리기 안 — 관문이 돌려준 `scope`, 그리고 행(누가 반장인지, 누가 담당인지, 누가 고쳤는지) | 이 역할이 **이 행**에 할 수 있나 | 403 `FORBIDDEN` + `detail.reason`, 또는 목록을 좁힘 |
| ③ DB | 트리거 `fn_require_role` 등 (`20_integrity`, `30_workflows`, `85_access`) | 확정자·승인자·입고자 역할, 원자재 로트 품목 | 409 / 422 (서버를 거치지 않은 쓰기도 막힘) |

## 3. 범위(scope)와 "그 사람만" 규칙

| scope / 규칙 | 뜻 | 어디서 | 걸리면 |
|---|---|---|---|
| `OWN` | OPR은 자기가 고친 버전만 — 목록도, **1건 보기도** | `documents.revisions`, `documents.revision` | 목록은 빈 목록, 1건은 403 `NOT_OWN_REVISION` |
| `SUMMARY` | OPR 브리핑은 요약형 | `/api/assistant/briefing` | — |
| `PROXY` | (쓰지 않음) 예전 MGR 대리 승인 범위. 시드 권한에 없고, `wo_approve`는 SUP가 아니면 403 `FORBIDDEN`. 응답의 `proxy`는 항상 거짓 | `maintenance.wo_approve` | 403 `FORBIDDEN` |
| `OWNED_ITEMS` | 입고는 자기 역할이 관리하는 품목만 (`inventory_item.owner_role`) | `inventory.txn`, `inventory.material_receipt` (+ DB R-77) | 403 `NOT_ITEM_OWNER` (`owner_role` 같이 줌) |
| 원자재 로트 | 원자재(`MATERIAL`) 품목만 | `material_receipt` 422 + DB 트리거 `raw_material_lot_item` | 422 `VALIDATION` / 23514 |
| 그 교대 반장 | 교대 보고서 저장·확정·확정 후 수정 | `production` (+ DB R-36) | 403 `NOT_SHIFT_SUPERVISOR` |
| 담당 보전 | 작업 시작 | `maintenance` | 403 `NOT_ASSIGNEE` |
| 받은 사람 | 알림 1건 보기·읽음·긴급 확인 (보기는 MGR 전부) | `notifications` | 403 `NOT_RECIPIENT` |
| 측정 담당 | 검사 입력·결과 파일·측정 지시·시작 (OP-50 작업자, 반장) | `quality` | 403 `NOT_MEASURER` |
| 작업기록 종류 | 정식 = `WORK_RECORD`, 간이 = `WORK_RECORD_SIMPLE` — 고치기·확정 관문이 둘 중 하나만 있으면 통과, 처리기가 기록 종류를 보고 다시 가름 | `maintenance` (`WR_EDIT`, `WR_CONFIRM`) | 403 |
| 실시간(SSE) | 알림·긴급 팝업은 받은 사람만(긴급은 전원이 받음), 문서 사건은 볼 수 있는 역할만 | `realtime` | 사건을 안 보냄 |
| 채팅 권한 (`chat_roles`) | 비서 도구 중 MTTR(`reliability`)·센서(`sensor_trend`)는 MNT·MGR만 — 다른 역할은 도구 목록에서 빠지고 서비스에 `out_of_role`(볼 수 있는 역할)을 넘김 [가상: 2026-10-13 팀 결정] | `assistant` (`_allowed`) | 403 (도구 직접 호출), 채팅 답은 `OUT_OF_ROLE` |
| 채팅 기록 본인만 | 목록·1건 모두 본인 것, 다른 사람 것은 404 (있는지도 안 알림). DB 읽기 계정 `mom_ai_ro`는 `chat_log`를 못 읽음 | `assistant` (`chat_*`), `db/roles.sql` | 404 |
| 담당 공정 두 칸 | OPR "담당 공정"은 `home_process_code`·`home_process_code_2` 둘 다 (측정 담당 = OP-50이 둘 중 하나) | `security.User.processes` | — |
| 직원 고치기 (2026-10-25) | 관리자는 자기 자신을 사용 중지하거나 MGR이 아닌 역할로 바꾸지 못함, 사용 중인 MGR 0명 금지, 담당 공정은 OPR만·2개까지. 직원 관리(USR-03~05)와 설정 SET-03 고치기가 같은 길 (`services/staff.py`) | `staff`, `master.user_update` | 422 `SELF`·`LAST_MGR`·`PROCESS_ROLE`·`PROCESS` |
| 사용 중지·역할 변경 뒤 토큰 (2026-10-25) | 바꾸는 주소는 요청마다 DB의 `is_active`를 봄(`current_user`). 1초마다 부르는 3D 라인 뷰(`token_user`)는 60초 기억한 사용자 상태로 — 사용 중지됐거나 역할이 토큰과 다르면 다시 로그인. 같은 서버 프로세스는 바로, 다른 프로세스는 60초 안 | `security.token_user`·`user_states_side` | 401 `UNAUTHORIZED` |

## 5. 정하지 않은 것

- 측정 담당 = 담당 공정 OP-50 (P-45 [제안]) — 문서에 정의가 없음.
- 원자재 로트를 SUP만 입고하는 것은 품목 관리 역할(`owner_role`)에서 나옴. 원자재를 다른 역할이 관리하게 바꾸면 그 역할이 입고하게 됨.
- 확인 못 함: 이번 보강(P-49~P-53)은 PostgreSQL 16 + 가짜 FastAPI(tests/stubs)로 처리기를 직접 불러 확인했다. uvicorn으로 띄운 HTTP 확인은 하지 않았다.
