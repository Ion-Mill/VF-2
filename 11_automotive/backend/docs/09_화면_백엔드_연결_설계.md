# 09. 화면 → 백엔드 → DB 연결 설계 (2026-10-24)

> 사용자 요청 "백엔드가 모두 잇게 설계해줘" — 설계 + 구현, **화면 기본값을 백엔드로** (사용자 결정 2026-10-24).
> 앞 단계: `팀과 논의/C2_다음단계_계획_20261023.md` (1·2·3·5·6묶음을 이번에 끝냄), `구현_중_수정사항/1023_수정간단내용.md` 10장.
> 이 문서는 "지금 무엇이 어디로 가는지"와 "여러 명이 같이 볼 때 무엇을 지키는지"를 한곳에 둔다.

## 1. 한 장 그림

```
 브라우저(화면, Next)                     백엔드(FastAPI)                         DB(Supabase mom-db)
 ─────────────────────                    ─────────────────                       ───────────────────
 live.ts api()  ── /api/... ──▶ 화면 서버 ──▶ 로그인·권한 확인 ──▶ 이름 붙은 쿼리 ──▶  9월 기록 + 10/1 기록
 (backendApi.ts·backendDocs.ts)  (rewrites)    │                                       ▲
                                               │ 시뮬레이터가 주인인 일                 │ 3초마다 바뀐 줄만
                                               ▼ (sim_link, MOM_SIM_URL)               │ (/api/ingest/sync)
                                         시연 서버(가짜 공장, :8765) ── DB 중계(db_relay) ┘
```

| 원칙 | 내용 |
|---|---|
| 화면은 백엔드만 | 기본값 (`NEXT_PUBLIC_MOM_BACKEND`가 `0`이 아니면). 화면 서버가 `/api`를 `MOM_BACKEND_URL`(기본 `http://127.0.0.1:8000`)로 넘긴다 — 브라우저는 같은 주소만 보므로 CORS가 필요 없고 배포(같은 주소 아래 `/api`)와 같은 모양 |
| 쓰는 쪽은 하나 | 시뮬레이터가 만드는 17개 표(설비 상태·실적·알람·로트·보류·검사·센서 …)는 **시뮬레이터 → 중계**만 쓴다. 사람이 그 표를 바꾸는 일(보류·해제, 공구 교체, 정비 시작·끝, 설비 복귀, 시연 조작)은 백엔드가 권한을 본 뒤 **시뮬레이터에 넘긴다** |
| DB가 주인인 기록은 백엔드가 | 작업지시서·작업기록서·간이 기록·알림 처리·보고서·입고·출하·설정 — 백엔드 API → DB 함수(업무 규칙은 DB가 막음) |
| DB 1개 = 공장 1개 | 모두가 같은 DB를 본다. 시연 조작(특히 [처음으로])은 모두의 10/1 기록을 지우므로 **진행자만** (`MOM_SIM_CONTROL_USERS`) |

### 2-1. 아직 화면(브라우저)에 남은 것 — 이유와 다음 설계

| 화면 저장 | 무엇 | 왜 아직 | 다음에 할 방법 |
|---|---|---|---|
| `qGauge`·`qManual`·`qPick` (품질) | 작업자 게이지·외관 합불, 수동 측정값, 반장의 재측정 고르기 | `inspection_result`는 **시뮬레이터가 주인인 표**(중계가 번호째 덮어씀). 백엔드가 직접 넣으면 번호가 겹친다 | 시연 서버에 `POST /api/quality/tablet`·`manual`·`select` → 시뮬레이터 상태에 넣고 중계로 DB에. 실제 시간 전환(시뮬레이터 = 설비만) 때는 백엔드 `POST /api/inspection/results`(이미 있음)로 바로 |
| `scrapProp`·`scrapOk` (로트) | 반장 폐기 제안 · 관리자 폐기 승인 | `lot_hold`도 시뮬레이터 표. 지금은 해제할 때 승인자만 시뮬레이터에 넘김 | 위와 같이 시연 서버에 제안·승인 입구 → 중계. 실제 시간에는 백엔드 `POST /api/lots/{lot}/scrap`·`/scrap/approve` |
| `pmOk` (예방 정비) | 시뮬레이터가 남긴 초안 실시 기록 확인 | `pm_record`도 시뮬레이터 표 | 시연 서버 입구 또는 실제 시간에 `POST /api/maint/pm-records/{id}/confirm` |
| 정지 사유 칸 | 설비 정지 사유 입력·확정 | `equipment_state_log`도 시뮬레이터 표 | 실제 시간에 `PATCH /api/downtimes/{id}` |
| `acked`·`handled`(Eve "처리 완료")·`briefChecks`·`invInCheck`·설정 화면 규칙 값 | 팝업 확인, 브리핑 체크(백엔드에도 저장), 입고 점검 진행, 반복 기준 숫자 | 사람·화면 단위 표시라 공유가 꼭 필요하지 않음. 규칙 값은 DB 칸이 없음 [선택 필요] | 필요해지면 표 추가 |

**정리:** 시뮬레이터가 "가짜 공장" 겸 "그 표의 주인"인 동안에는, 사람이 그 표에 넣는 값을 시뮬레이터에 넘겨야 한다. 실제 시간으로 바꾸면(시뮬레이터 = 설비 신호만) 위 값들은 이미 있는 백엔드 API로 바로 간다 — 그때 화면 쪽은 `backendApi.ts`에 길만 더하면 된다.

## 3. 진행 중 교대 보고서 = 미리보기

| 항목 | 내용 |
|---|---|
| 왜 | 시연 서버는 교대 중에도 보고서 초안을 계산해 보여 줬다. 백엔드는 교대가 끝나야 스케줄러가 초안을 만든다 → 백엔드 모드에서 진행 중 교대가 404 |
| 방법 | `GET /api/reports/shift/{id}`에 초안이 없고 교대가 시작했으면, **DB 저장점 안에서** 초안 함수(`fn_create_shift_report_draft`)를 돌려 읽고 되돌린다 → DB에는 아무것도 남지 않는다(알림·Cpk 판정·이월 포함). 응답 `preview: true`, `in_progress`. 목록에도 미리보기 줄(최근 2일, 시작한 교대) |
| 특이 사항 문장 | DB 초안은 `(비서 문장 대기)`라서, 백엔드가 읽을 때 기본 문장 5개(실적·필수 정지·병목·불량·알람)를 만든다 — 시연 서버 `shift_draft`와 같은 문장. 반장이 저장하면 그 문장이 저장된다 |
| 저장·확정 | 미리보기는 저장·확정할 수 없다 (화면: "교대가 끝나면 초안이 생겨 저장·확정할 수 있어요") |
| 초안 만들기 | 진행자 백엔드의 스케줄러 (`MOM_RUN_WORKERS=true`, `MOM_SCHEDULER_SECONDS=5` — 시연 ×60이면 5초 = 5분). 같은 DB에 여러 대가 떠도 DB 잠금으로 한 번만 |

## 4. 여러 명이 같이 볼 때 (배포 대비)

| 문제 | 실제로 본 것 (로컬 PostgreSQL, 2026-10-24) | 한 일 |
|---|---|---|
| 트윈이 무겁다 | 한 번에 쿼리 19개, 약 0.3초. 화면이 사람마다 1초에 한 번 → 20명이면 연결 줄이 꽉 차 **p50 3.3초**, 1초에 6.9건밖에 못 냄 | **트윈 함께 쓰기**: 계산 결과를 1초(`MOM_TWIN_CACHE_SECONDS`) 두고 모두가 같이 씀. 지난 값을 고치는 동안 다른 요청은 바로 앞 값을 받음(기다리지 않음) |
| 요청마다 DB 연결 | 트윈 요청도 로그인 확인에 DB 연결을 잡아, 50명이면 처리 스레드(40개)가 연결 기다리기로 막혀 **30초 TimeoutError** | 트윈만은 **토큰으로 로그인 확인**(서명·만료·역할) + 60초 기억한 권한표 → 앞 값으로 답하는 요청은 DB 연결을 아예 안 잡음 |
| 미들웨어가 같은 줄을 씀 | 접근 기록·가상 표시 읽기가 요청 연결을 쥔 채 같은 줄에서 또 연결을 기다려 서로 막힘 (원래 있던 문제) | **작은 연결 줄 따로** (`db.side_engine`, 1+1개) |
| 결과 | 20명 p50 0.12초 · 50명 0.24초 · 100명 0.50초, **오류 0**, DB 활성 연결 최대 1개 | 100명 지연은 큰 응답(약 28KB)의 JSON 처리 — 배포 때 gzip(리버스 프록시) 권장 |
| 누가 [처음으로]를 누름 | 모두의 10/1 기록·채팅 기록이 지워짐 | `MOM_SIM_CONTROL_USERS=U12`처럼 진행자만. 다른 사람 화면은 시연 버튼이 잠기고 안내 |
| 연결 수 한도 (Supabase 무료 15) | | 진행자 서버 1대: 앱 계정 4+2 + 옆 줄 1+1 + 실시간 1 = 최대 9. 팀원 서버는 띄우지 않고 진행자(또는 배포) 화면을 연다 |

## 7. 9월 데이터가 화면마다 맞게 나오는지 대조 (2026-10-24 저녁, 사용자 "다시 확인해줘")

방법: 생성기 `out/` CSV를 넣은 로컬 DB(공용 Supabase와 같은 적재 도구·잠그기) + 백엔드 + 시연 서버. 화면 코드(`backendApi.ts`) 그대로 백엔드를 불러 **① 생성기 CSV 원본**과 **② 예전 길(시연 서버) 응답**에 칸마다 대조했다.

| 화면 (주소) | 대조 | 결과 |
|---|---|---|
