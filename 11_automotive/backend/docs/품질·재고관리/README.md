### 2. 설비 추적 범위 — 부품별 OP-30 설비는 추적하지 않는다 (2026-10-13 결정)

| 무엇 | 정한 것 |
|---|---|
| 추적하지 않는 것 | OP-30 두 대(VF2-01·VF2-02) 중 **어느 설비가 만든 부품인지**. 로트가 두 대에 나뉘면 부품 단위로는 모름 |
| 알 수 있는 것 | 로트가 거친 공정·설비·작업자, **설비별 수량** (공정 실적 = 로트 × 공정 × 설비 × 교대) |
| 품질 이상 알림 | **공정 단위** — 예) "OP-30 정밀 가공 · 부싱 구멍 지름 관리 한계 밖". 원인은 알려 주지 않음. 항목 → 공정: 1·2·4·5·6·8 = OP-30, 3 두께 = 확인 필요, 7 외관 = 불량 코드별 (버 OP-40, 구성인선 OP-30, 찍힘·긁힘 운반·세척 중) |
| 화면 | 가공 설비 칸·설비별 Cpk를 쓰지 않음. SCR-19 시간표의 "순번 1~13 / 14~20"은 설비별 수량으로 바꿀 것 (시안은 아직 안 고침) |
| 그대로 되는 것 | 의심 로트 제안(알람·공구 수명 초과 때 그 설비에서 가공 중이던 로트 — 로트 전체 보류), 로트 추적의 설비 목록, 재고 전부 |

왜 안 하나:
- 요구사항 FR-PRD-05-02 "부품마다 일련번호는 붙이지 않는다"
- 부품마다 꼬리표·표시를 붙이면 OP-40(텀블러·초음파 세척, 30개 묶음)에서 유지할 수 없음
- 다른 방법은 생산 흐름을 바꿔야 함: ① 박스 칸을 "로트 + 설비"로 나누고 표지에 설비 표시 → OP-40 묶음 규칙·재공 한도(OP-30→40 60개)·대기 시간이 바뀜 ② 한 로트 = OP-30 한 대 → 처리량(라인 3.5분/개 = 7.0분 ÷ 2대)에 영향

향후 개선(생산 파트와 협의): 위 ① 또는 ②.

## 화면 원칙

- 화면마다 가장 중요한 질문을 그래프·3D로 보여 줍니다.
  - SCR-20 작업자: OP-50 태블릿 단계(측정 시작 확인 → CMM 측정 → 게이지·외관 → 다음 부품), 큰 버튼, 로트 진행 지도
  - SCR-20 반장·관리자: 부품 지도(순번 1~20 상태), 돌려 볼 수 있는 3D 부품 모식도(강화 3단 측정 위치·값), 공차 안 위치 막대
  - SCR-19: 설비별 시간표(설비 × 시각, 고른 로트·다른 로트 막대, 고장·정비 띠, 병목, 보류·지금 선, 맨 아래 완제품 입고·출하), 수량(투입 → 판정 → 입고 → 출하). 관련 로트는 맨 위 로트 칸에
  - SCR-21: [재고] 탭 = 재고 여유 막대·완제품 흐름, [출하 등록] 탭 = 4단계(로트 고르기 → 수량 → 출하 전 확인 → 확정)
  - SCR-22: 공구 10개 목록(사용률 순) + 고른 공구 큰 게이지·누적/한도·교체 기록. 대상은 문서대로 OP-30 VF-2 공구만
- 3D는 라이브러리 없이 좌표를 계산해 그린 모식도입니다. 부품 형상(구멍·M6 위치)은 그림용 [가상]입니다.
- 화면에는 입력칸·버튼·상태·값·버튼이 막힌 이유·범례·[가상]/[참고] 표시만 둡니다. 한눈에 보기와 겹치는 표·칸은 뺐습니다 (SCR-19 비서 제안·상태·검사 결과 칸, SCR-20 측정 결과 표·로트 판정 칸, SCR-21 거르기·품목 표, SCR-22 공구 표).
- 규칙 설명과 자세한 기록(누가·언제·왜, 번호·코드, 계산 근거)은 비서 AI가 답합니다 (`비서AI_넘길일.md`). UI설계서와 달라진 점은 그 파일의 "팀 확인 필요"에 있습니다.
- 색: UI설계서 2.3을 따릅니다. 빨강 = 고장·긴급, 주황 = 막힘·재공·병목, 노랑 = 주의. 정상 값은 꾸미지 않습니다.
- 남색·파랑(머리 바, 섹션 표시, 주요 버튼, 선택 표시)은 시안용 강조색입니다. 색 코드는 2.3 규칙 7에 따라 기술 회의 뒤 스타일 가이드에서 정합니다.
