## 1. 목적과 범위

### 1.1 목적

| 항목 | 내용 |
|---|---|
| 왜 만드나 | 기획서의 기능 설명을 **개발·시험할 수 있는 단위**로 나눈다. UI 설계서·논리 ERD·API 명세·테스트 계획이 이 문서의 요구사항 ID를 기준으로 연결된다 (기획서 18장 1·10번) |
| 누가 보나 | 팀 5명 (AI 비서 2, 데이터·ML 1, 백엔드·DB 1, 프론트엔드 1), 심사위원 |
| 무엇을 담나 | 기능 요구사항(5장), AI 비서 공통 요구사항(6장), 비기능 요구사항(7장), 시연 연결(11장) |

### 1.3 제외하는 것 (기획서 8.1)

| 기능 | 제외 이유 |
|---|---|
| 자유 SQL 데이터 질문 | 3주 안에 안정화하기 어렵다. 정해진 조회 도구로 대신한다 |
| 자동 처리·되돌리기 (v2의 AST-03 안 B) | 비서 범위를 "문서 작성만 자동"으로 정했다. 수정 이력으로 대신한다 |
| 불량 원인 안내 | 근거 문서가 부족해 답을 지어낼 위험이 크다 |
| 구매·발주, 주문 접수, ERP 연동 | 범위 밖. 재고는 수량·사용·부족 알림과 완제품 입고·출하 기록까지만 (FR-INV-01-10) |
| 시뮬레이션(가정 실험), 사실적인 3D 모델링 | 모니터링형으로 정했다. 3D는 단순한 도형(상자·원기둥)의 조합으로만 그린다. **크기만 실제 치수**다 (FR-PRD-01-27) |
| 3D 라인 뷰의 마우스 호버 정보 | 현장 터치 화면에서 쓸 수 없다. 마우스를 올려도 아무것도 뜨지 않고, 설비를 클릭(탭)하면 하단 패널로 보인다 (FR-PRD-01-02·13). 출처 글씨의 요약 카드는 탭으로도 열리므로 예외 (FR-MNT-01-09) |
| 원문 출처 표시·원문 열기 | 원문 저작권. 비서 답·화면 어디에도 원문 출처를 보이지 않고, 출처는 사내 문서 이름·번호·§절만 쓴다 (FR-AST-COM-02, NFR-COPY-02) |
| 외부 LLM 서비스 | 비서는 로컬 LLM으로 돈다. 운영 데이터·사내 문서를 밖으로 보내지 않는다 (NFR-SEC-08) |
| **설비 원격 조작 (설비 제어)** | 안전 규정과 충돌 (원칙 6, 산업안전보건기준 규칙 제92조). 디지털 트윈 3단계 중 **모니터링형(디지털 섀도)까지만** 만든다 (기획서 6.2). 2026-10-06 회의에서 다시 확인, 변경 없음 (D-19). 잠금·표지 절차를 따른다 |

## 2. 용어와 표시 규칙

### 2.1 표시 규칙

| 표시 | 뜻 |
|---|---|
| **[실제]** | 공개 문서·데이터 그대로 |
| **[가상]** | 팀이 정한 값 |
| **[참고]** | 다른 회사·산업 값의 모양만 빌림 |
| **[제안]** | 팀 확정 전 제안 |
| **[선택 필요]** | 아직 정하지 않음. 뒤에 정할 곳을 적는다 (예: [선택 필요: 기술 회의], [선택 필요: UI 설계]) |

- 수용 기준의 숫자는 **기획서·설계서·DOC에 있는 값만** 쓴다. 근거 없는 숫자는 만들지 않고 [선택 필요]로 둔다.
- 요구사항 표의 "출처"는 절까지 적는다. 예: "기획서 9장 PRD-01", "설계서 15.2", "DOC-07 6.2".

### 2.2 주요 용어 (자세한 것은 [00_용어집.md](가상사내문서/00_용어집.md))
