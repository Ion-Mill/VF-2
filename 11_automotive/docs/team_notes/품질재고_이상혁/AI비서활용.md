# AI 비서의 품질·재고 활용 계획

- 담당: 이상혁 (품질 + 재고)
- 기준: 기획서 4장(AI 운영 비서), 5장(안 A / 안 B), 8장 AST-01·AST-02·MNT-01·MNT-03·PRD-02
- 함께 볼 문서: [기능구현계획.md](기능구현계획.md)

---

## 0. 원칙

기획서의 역할 구분을 품질·재고에도 그대로 적용합니다.

| 일 | 누가 | 이유 |
|---|---|---|
| 숫자 계산 (Cpk, 불량률, 재주문점, 가용 재고) | **프로그램** | 비서가 숫자를 지어내지 않게 |
| 판정 (합부, 보류 규칙 H1~H3, 재주문 여부, 알림 여부) | **규칙** | 같은 상황에 같은 결과 |
| 문장 (알림 문구, 브리핑 요약, 보고서 특이 사항, 답변) | **비서** | |
| 보류 확정·해제, 출하, 발주 | **사람** (반장·관리자) | 기획서 5.2 "보류 해제는 사람", 11장 권한 |

- 비서 문장에 들어간 숫자는 프로그램이 원래 값과 대조합니다(기획서 PRD-02와 같은 방식).
- 비서는 SQL을 쓰지 않고, 아래 3장의 **조회 도구**만 씁니다(기획서 4.2).
- 출처가 없는 답은 표시하지 않습니다. 가상 사내 문서에서 온 답은 "가상 사내 문서"라고 표시합니다(기획서 MNT-01).

## 1. 먼저 알리기 (AST-02)

알릴지 말지는 규칙이 정하고, 비서는 문장과 "관련 정보 한 줄"만 붙입니다. 중요도는 기획서 4.3을 따릅니다.

| 알림 | 조건 (규칙) | 중요도 | 받는 사람 | 비서가 붙이는 관련 정보 |
|---|---|---|---|---|
| 의심 로트 보류 제안 | 보류 규칙 H1(정지 알람), H2(불합격) | **긴급** | 반장, OP-50 작업자 | "992 직전 마지막 합격 부품은 #018입니다. #019~#027, 9개가 대상입니다" |
| 공정능력 미달 | Cpk < 1.33 (특별 특성 < 1.67) | 주의 | 반장, 관리자 | "BORE_D Cpk 1.21. 평균이 상한 쪽으로 이동 중, T09 보링 인서트 사용량 88%" |
| 관리도 이탈 | X̄ 또는 R이 3σ 밖 (규칙 1만) | 주의 | 반장 | 최근 5개 서브그룹 값 |
| 보류 처리 지연 | 보류 후 20시간 지나도 미해제 | 주의 | 반장, 관리자 | "처리 기한 24시간까지 4시간 남음, 재검사 7/9개 완료" |
| 원소재 성적서 이상 | 성분이 6061 한계 밖 | 긴급 | 관리자 | "RM-2609-07 Mg 1.25% (한계 0.8~1.2). 이 소재를 쓴 작업지시 2건" |
| 예비 부품 재주문 | 가용 ≤ 재주문점 | V 등급 주의 / E·D 등급 참고 | 보전 담당, 관리자 | "93-3584 축 윤활유 가용 1, 재주문점 2, 리드타임 5일" |
| 작업지시서 부품 없음 | MNT-03 필요 부품의 가용 = 0 | 주의 | 보전 담당 | "대체 가능: 없음. 마지막 입고 9/12" |
| 공구 재고 부족 | 새 것 ≤ 최소 | 주의 | 반장 | "M6 탭 03-1818 새 것 2개, 하루 교체 약 1.6개" |

- 같은 항목의 반복 알림은 하나로 묶습니다(기획서 4.3). 예: 같은 특성의 관리도 이탈이 1시간 안에 여러 번이면 1건으로 보냅니다.
- 안 A: 알림 + [보류 확정] 버튼 / 안 B: 보류 표시를 먼저 하고 알림. 중간안(기획서 5.4)은 로트 보류를 **제안**으로 둡니다.

## 2. 브리핑과 보고 (AST-01, PRD-02)

### 2.1 교대 시작 브리핑에 넣을 칸

| 칸 | 예시 | 데이터 |
|---|---|---|
| 지난 교대 품질 | 검사 162개, 불합격 1개(0.62%), BORE_D Cpk 1.84 | `inspection_result`, 공정능력 계산 |
| 보류 중 로트 | PO-2609-015 보류 (S1 충돌 의심), 재검사 7/9 | `lot_hold` |
| 먼저 챙길 일 (품질·재고) | ① PO-2609-015 보류 해제 판단 ② 93-3584 재주문 ③ M6 탭 교체 예정 2개 | 규칙이 고른 목록 |
| 출처 | 각 항목에 기록 번호 링크 | |

비서는 "가장 먼저 챙길 3가지"를 고르는 문장만 씁니다(기획서 AST-01). 순서는 **긴급 → 기한 임박 → 주의**입니다.

### 2.2 교대·일일 보고서에 넣을 칸

| 칸 | 만드는 쪽 |
|---|---|
| 불량 수·불량률, 불량 코드 상위 3개 | 프로그램 |
| 공정능력 미달 항목 | 프로그램 |
| 보류·해제한 로트 | 프로그램 |
| 재고 부족 품목 | 프로그램 |
| 특이 사항 (예: "충돌 의심 뒤 재검사에서 불합격 1개, BORE_D 상한 초과") | 비서 |

## 3. 조회 도구 (비서가 골라 쓰는 함수)

기획서 4.2의 "조회 도구 10여 개"에 품질·재고 도구를 더합니다. 모두 **읽기 전용**이고, 백엔드 API를 감싼 함수입니다.

| 도구 | 입력 | 출력 | 연결 API |
|---|---|---|---|
| `get_inspection_summary` | from, to, (product, equipment) | 검사 수, 불합격 수, 불량률, 불량 코드 상위 | `/api/quality/defects/summary` |
| `get_capability` | spec_code, (equipment) | Cpk, Ppk, 서브그룹 수, 기준, 판정 | `/api/quality/capability` |
| `get_inspection_records` | lot_id, (spec_code) | 부품별 측정값·합부 | `/api/quality/inspections` |
| `get_spec` | product, (spec_code) | 공칭값, 공차, 빈도, 근거 문서 | `/api/quality/specs` |
| `list_lot_holds` | status | 보류 목록, 사유, 진행률, 경과 시간 | `/api/lots?status=hold` |
| `trace_lot` | lot_id, direction | 연결된 원소재·완제품 로트 | `/api/lots/{id}/trace` |
| `get_spare_stock` | part_no 또는 keyword | 현재고, 예약, 가용, 재주문점, 리드타임 | `/api/spares/{pn}` |
| `list_reorder_items` | (class) | 재주문 대상 품목 | `/api/spares/reorder` |
| `forecast_spare_usage` | days | 예방 정비 예정 소요량, 부족 예상 | `/api/spares/forecast` |
| `get_tool_stock` | tool_item 또는 T번호 | 새 것·재연마 수량, 최소, 장착 공구 사용량 | `/api/tool-stock` |

**쓰기 도구는 제안만** 합니다. `propose_lot_hold(lot_id, reason, range)`는 상태 "제안됨"인 보류 기록만 만들고, 확정은 반장 버튼으로 합니다. 안 B를 고르면 `lot_hold`에 "자동 처리" 표시를 하고 AST-03 처리 기록에 남깁니다.

도구 정의 예시:

```json
{
  "name": "get_capability",
  "description": "검사 항목의 최근 125개(25×5) 기준 공정능력 Cpk·Ppk와 판정을 돌려준다. 숫자는 이 결과만 사용한다.",
  "input_schema": {
    "type": "object",
    "properties": {
      "spec_code": {"type": "string", "enum": ["BORE_D", "LEN", "THK", "HOLE_DIST"]},
      "equipment": {"type": "string", "description": "예: VF2-01. 비우면 전체"}
    },
    "required": ["spec_code"]
  }
}
```

## 4. 질문 답변 (MNT-01)

### 4.1 검색 대상에 넣을 문서

| 문서 | 형태 | 출처 표시 |
|---|---|---|
| 검사 기준서 (OP-50) | 가상 사내 문서 | "가상 사내 문서 · 검사 기준서 › 3. 검사 항목" |
| 관리계획서 | 가상 사내 문서 | 같은 방식 |
| 로트 보류·해제 절차서 | 가상 사내 문서 | 같은 방식 |
| 불량 사유 코드표 | 가상 사내 문서 | 같은 방식 |
| 예비 부품·공구 품목 마스터 | 가상 사내 문서 (표) | 같은 방식 |
| Haas 윤활유 표(RD0040), HCS-80 정비 장, 고장 대응 안내 | 실제 문서 | "Haas RD0040 Rev H › Mill lubricants" |

- 고객 요구사항(Ford, Nemak 등) 원문은 검색 대상에 넣지 않습니다. 저작권 문제가 있고, 현장 질문의 답은 사내 문서(검사 기준서 등)에 있어야 하기 때문입니다. 사내 문서 끝에 근거로만 적습니다.
- Curtiss-Wright·Kohler 문서는 이용 조건상 검색 대상에서 뺍니다.

### 4.2 질문 종류별 처리

| 질문 | 처리 | 답 예시 |
|---|---|---|
| "베어링 구멍 공차가 뭐야?" | 문서 검색 | "Ø45 H7, 45.000~45.025 mm (가상 사내 문서 · 검사 기준서 › 3.1)" |
| "보류 해제하려면 뭐 해야 해?" | 문서 검색 | 절차서의 해제 조건 + "해제는 반장·관리자만 가능" |
| "오늘 불량률 얼마야?" | `get_inspection_summary` | 숫자 + 기록 링크 |
| "BORE_D Cpk 왜 떨어졌어?" | `get_capability` + `get_tool_stock` + 문서 | "Cpk 1.21(기준 1.67). 평균이 상한 쪽으로 이동, T09 보링 인서트 88% 사용. 보링 치수 문제는 인서트 마모가 흔한 원인(Sandvik 보링 문제 해결 요약)" |
| "PO-2609-015 어떤 소재 썼어?" | `trace_lot` | "RM-2609-03, RM-2609-04 (성적서 번호 …)" |
| "축 윤활유 재고 있어?" | `get_spare_stock` | "93-3584 가용 1개, 재주문점 2개. 발주가 필요합니다" |
| "992 정비에 서보 앰프 필요하면 재고 있어?" | MNT-01 문서 + `get_spare_stock` | 앰프 P/N + 가용 수량 + 리드타임 |

### 4.3 하지 않는 것
- 불량 **원인을 단정**하지 않습니다. 기획서 7.1이 "불량 원인 안내"를 제외했기 때문입니다. "가능한 원인(출처)"과 데이터만 보여 줍니다.
- 보류 확정·해제, 출하, 발주를 직접 하지 않습니다.
- 공정능력·재고 숫자를 기억이나 문서에서 가져오지 않고, 항상 조회 도구 결과만 씁니다.

## 5. 정비 작업지시서와의 연결 (MNT-03)

비서가 작업지시서 초안을 만들 때 아래를 더합니다.

| 칸 | 비서가 하는 일 | 근거 |
|---|---|---|
| 필요 부품 | 고장 대응 안내의 교체 부품 P/N을 후보로 제안 → 담당자가 확정 | `tsg_*.txt` |
| 재고 | 확정된 부품마다 `get_spare_stock` 결과(가용, 리드타임) 표시 | INV-A |
| 품질 영향 | 정지 알람이면 "이 설비 가공 로트 보류 제안됨 (PO-…)" 한 줄 | 로트 보류 H1 |

## 7. 평가 질문 (MNT-01 평가 세트에 추가)
