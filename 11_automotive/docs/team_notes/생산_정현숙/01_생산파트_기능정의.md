## 1. 생산 파트가 맡는 범위

> **브래킷 1종(BRK-A100)이 5개 공정(OP-10~50)을 흐르는 모습, 그 위에서 내려오는 작업지시, 공정마다 쌓이는 생산실적을 한 화면 흐름으로 보여 준다.**

| 포함 | 제외 |
|---|---|
| 공정 흐름과 설비 상태, 작업지시 진행, 공정별 생산실적, 생산 지표, 정지 분석, 교대 보고서, 공정 병목 | 정비 작업지시서·알람 지침 카드(정비 파트), 자동 스케줄링 최적화, 자재·재고, 설비 원격 조작 |
| 품질·공구는 생산 화면에 **연결**만 한다 (불량 수량, 공구 수명 알림) | 불량 원인 AI 안내 (근거 문서 부족) |

시연 주인공은 **BRK-A100 하나**로 잡는다. BRK-B200은 작업지시 목록에 섞어 두는 정도로만 쓴다. [제안]

## 2. 공정 흐름 [가상 공정]

```
원자재(알루미늄 봉)
  │
OP-10 절단 → OP-20 황삭 → OP-30 정밀 가공 → OP-40 디버링·세척 → OP-50 측정 → 출하
SAW-01       MIL-01        VF2-01 / VF2-02      WSH-01             CMM-01
1.0분/개     3.5분/개      7.0분/개(2대=3.5)    25분/30개 묶음     2.5분/개
```

- 공정 순서와 시간은 팀이 정한 가상값이다. 설비 모델은 일부 실제(Haas HCS-80, VF-2). 근거 문서가 없는 사이클타임은 **[가정]** 으로 표시한다.
- OP-20과 OP-30을 약 3.5분으로 맞춰서, 한 설비가 멈추면 앞뒤 공정에 영향이 보이게 한다. OP-30이 라인 속도를 정하는 병목 후보다.
- 선택지: OP-20 뒤에 **중간검사**를 넣을지. 4TU 실제 기록은 작업지시의 약 75%가 가공 직후 중간검사를 거친다.

## 4. 기능별 상세

### PRD-04 공정 흐름도 화면 [제안, 필수]

| 항목 | 내용 |
|---|---|
| 하는 일 | OP-10~50을 왼쪽에서 오른쪽으로 놓고, 각 공정 카드에 설비 상태색, 현재 작업지시, 오늘 완료 수량, 공정 앞 대기 수량(재공품)을 보여 준다 |
| 화면 | ① 공정 카드 5개 + 화살표(수량 흐름) ② 카드를 누르면 설비 상태 시간 막대·최근 알람 ③ 상단에 오늘 목표 대비 완료 |
| 상태색 | RUN 초록 / IDLE 노랑 / SETUP 파랑 / DOWN 빨강 / MAINT 회색 ([기획서 PRD-01](../AUTOMOTIVE_MACHINING_MOM_PLATFORM_PLAN.md)) |
| 데이터 | equipment, equipment_state_log, operation_report |
| 시연 포인트 | VF2-01이 DOWN이 되면 OP-30 카드가 빨강, OP-40·50 앞 대기가 줄고 OP-20 뒤에 재공품이 쌓이는 것 |

### PRD-03 작업지시 목록·상세 [기획서, 필수]

| 항목 | 내용 |
|---|---|
| 하는 일 | 작업지시별 제품, 목표·완료·불량 수량, 현재 공정, 납기, 지연 여부를 보여 준다. 상세에서는 공정별 진행 막대와 실적 목록을 본다 |
| 상태 | 대기 → 진행 → 중단 → 완료 / 취소. OPC UA ISA-95 Job Order 상태(NotAllowedToStart, AllowedToStart, Running, Interrupted, Ended)를 단순화한 것 [실제 규격 참고] |
| 목록 칸 | 작업지시 번호(PO-2609-001 형식), 제품, 목표 수량, 완료 수량, 불량 수량, 현재 공정, 상태, 납기, 지연 표시 |
| 상세 칸 | 공정별 시작·끝 시각, 설비, 작업자, 양품·불량, 셋업 시간, 중단 사유 |
| 데이터 | production_order, operation_report. 30일 약 100건, 수량 중앙값 약 36 |
| 필터 | 상태, 제품, 날짜, 지연만 보기 |

### PRD-05 공정별 생산실적 [제안, 필수]

| 항목 | 내용 |
|---|---|
| 하는 일 | 공정 하나가 끝날 때마다 실적을 남기고 이력으로 본다. 작업자가 입력하는 화면(소량)과 설비에서 자동 집계되는 값을 구분한다 |
| 칸 | 작업지시, 공정, 설비, 작업자, 시작·끝, 완료 수량, 불량 수량, 재작업 수량, 불량 사유 코드, 셋업 시간, 사이클 시간 |
| 규칙 | 앞 공정 양품 수 ≥ 뒷 공정 투입 수. 작업지시 완료 수량 = 마지막 공정 양품 합. 불량은 주로 OP-50(검사)에서 기록 |
| 근거 | 칸 구성은 4TU 실제 생산 기록과 같다. 필드 이름은 B2MML V0700 OperationsPerformance, OPC UA Job Response, MTConnect PartCount(GOOD·BAD·TARGET)를 참고한다 [실제] |
| 입력 권한 | 작업자 OPR 입력, 반장 SUP 수정 |

### PRD-01 가동 현황·정지 분석 [기획서, 필수]

| 항목 | 내용 |
|---|---|
| 화면 | 라인 배치도와 설비 상태색, 설비별 상태 시간 막대, 정지 원인 순위(파레토), 지표 카드 |
| 지표 | 가동률 A, 성능 E, 양품률 QBR, OEE = A×E×QBR, MTTR, MTBF (NIST ISO 22400 정리 논문의 식) [실제] |
| 정지 사유 그룹 | 고장, 자재, 준비, 조작, 계획 (설계서 5.8). 코드 세부는 TeepTrak 17개 + Six Big Losses를 참고해 자체 정의 [가상 정의] |
| 경고 기준 | 가동률·MTTR 경고선은 근거 문서가 없으므로 **팀이 정한 가상 기준**으로 표시 |
| 주의 | RUN 비율(가공 시간 ÷ 계획 시간)과 OEE는 다른 값이다. 화면에서 구분해 쓴다 |

### PRD-02 교대·일일 보고서 [기획서, 필수]

| 칸 | 내용 | 만드는 쪽 |
|---|---|---|
| 요약 숫자 | 생산, 불량, 가동률, 정지 시간 | 프로그램 |
| 정지 상위 3건 | 설비, 원인, 시간 | 프로그램 |
| 공정별 실적 | 공정별 양품·불량·사이클 | 프로그램 |
| 특이 사항 | 3~5문장 | AI 비서 |
| 인계 사항 | 미완료 작업지시, 지연, 교체할 공구 | 프로그램 + AI 문장 |

### PRD-06 병목·납기 지연 표시 [제안, 권장]

| 항목 | 내용 |
|---|---|
| 병목 | 공정별 앞 대기 수량·가동률·실제 사이클을 비교해 가장 막힌 공정에 표시. 기본은 OP-30 |
| 지연 | (남은 수량 × 병목 사이클) 대비 납기까지 남은 시간으로 "지연 위험"을 계산. **단순 계산**이며 스케줄링 최적화는 하지 않는다 |
| 데이터 | operation_report, 설비 상태, 납기 |

### QLT-01 / ML-01 연결 [기획서, 권장·선택]

- 생산 화면의 "불량 수량"을 누르면 검사 기록(OP-50)으로 이동. 불량이 늘어나는 조건(공구 수명 90% 이후, 992·108 알람 직후)은 시연 시나리오 S1·S3로 보여 준다.
- 공구 수명 90% 이상이면 해당 작업지시에 "공구 교체 필요" 배지를 붙인다.

## 8. 시연 시나리오 (생산 파트 3분)

| 시간 | 장면 | 보여 줄 것 |
|---|---|---|
| 0:00 | 라인 정상 가동 | 공정 흐름도, 5공정 초록, 작업지시 진행 막대 |

## 9. 한계와 표시 원칙

- 공정 순서, 사이클타임, 정지 기준, 경고선은 **가상 또는 가정**이라고 화면과 발표에서 밝힌다.
- 근거가 있는 부분: 지표 계산식(NIST), 작업지시 상태·필드(OPC UA, B2MML, MTConnect), 생산 기록의 칸 구성과 분포(4TU), 정지 길이 분포(벽돌 라인).
- 한국어 작업표준서, 불량 코드표, 가공업체 실물 생산일보는 공개본을 찾지 못했다. 코드 체계는 자체 정의로 만든다.
