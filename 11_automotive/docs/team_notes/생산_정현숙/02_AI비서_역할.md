# 생산 파트 AI 비서 역할 정의서

> 문서 상태: 초안 v0.1 / 작성일: 2026-10-03

## 1. 한 줄 정의

> 생산 파트의 AI 비서는 **라인 숫자를 모아 주는 프로그램 위에서, "지금 무엇을 챙겨야 하는지"를 먼저 알려 주고, 교대 브리핑과 보고서를 문장으로 써 주고, 생산에 관한 질문에 기록을 근거로 답하는 도우미**다.

## 2. 지키는 원칙 [기획서 2.1 기준]

| # | 원칙 | 생산 파트에서의 뜻 |
|---|---|---|
| 1 | 계산은 코드가, 문장은 AI가 | 가동률·OEE·수량·지연 판정은 프로그램이 계산한다. 비서는 그 숫자를 문장으로 옮긴다 |
| 2 | 문장 속 숫자는 다시 확인 | 보고서·브리핑 문장의 숫자를 프로그램이 표와 대조한다. 맞지 않으면 문장을 버리고 표만 보여 준다 |
| 3 | 근거 없으면 답하지 않는다 | 답에 작업지시 번호·기록 링크를 붙인다. 기록에 없으면 "기록에 없음"이라고 한다 |
| 4 | 지어낸 기준값 금지 | 가동률 경고선, 사이클타임 기준은 "가상 기준"이라고 같이 표시한다 |
| 5 | 설비는 사람이 움직인다 | 설비 조작, 생산 계획 변경, 작업지시 취소는 비서가 하지 않는다 |

## 3. 비서가 하는 일

### 3.1 교대 시작 브리핑 — 생산 부분 (AST-01) [기획서 + 제안]

| 브리핑 칸 | 예시 | 만드는 쪽 |
|---|---|---|
| 지난 교대 실적 | "생산 162개, 불량 1개, 가동률 68%" | 프로그램 |
| 진행 중 작업지시 | "PO-2609-041 BRK-A100 36개 중 22개 완료, OP-30 진행 중" | 프로그램 |
| 지연 위험 | "PO-2609-043은 납기까지 남은 시간 대비 OP-30 처리량이 부족합니다" | 프로그램 판정 + 문장 |
| 먼저 챙길 3가지 | ① 지연 위험 작업지시 ② 어제 가장 길었던 정지 ③ 공구 수명 90% 이상 공구 | 비서가 순서 정리 |
| 오늘 예정 | 작업지시 4건, 예방 정비 4건 | 프로그램 |

### 3.2 먼저 알리기 — 생산 알림 (AST-02) [기획서 + 제안]

알릴지 말지는 **규칙**이 정하고, 비서는 문장과 "관련 정보 한 줄"만 붙인다. 아래 기준값은 모두 **[가상 기준]** 이다.

| 알림 | 조건 (예시) | 중요도 | 받는 사람 | 덧붙일 한 줄 |
|---|---|---|---|---|
| 작업지시 지연 위험 | 남은 처리 시간 > 납기까지 남은 시간 | 주의 | SUP | "병목은 OP-30입니다" |
| 병목 이동 | 공정 앞 대기가 기준 이상 증가 | 주의 | SUP | 직전 1시간 변화 |
| 설비 장시간 IDLE | 작업지시가 있는데 IDLE이 기준 시간 초과 | 참고 | SUP, OPR | 앞 공정 대기인지 소재 대기인지 |
| 셋업 장기화 | SETUP이 기준 시간 초과 | 주의 | SUP | 같은 작업의 평균 셋업 시간 |
| 불량 급증 | 최근 N개 불량률이 기준 초과 | 긴급 | SUP, MGR | 직전 공구 교환·알람 유무 |
| 공구 수명 임박 | 공구 사용 횟수 90% | 주의 | OPR, SUP | 해당 공구를 쓰는 다음 작업지시 |
| 정지 발생 (정지 등급) | 설비 DOWN | 긴급 | SUP | 정비 파트 지침 카드로 연결 |

- 같은 알림은 짧은 시간에 반복되면 하나로 묶는다. 중요도는 긴급·주의·참고 3단계 [기획서 4.3].

### 3.3 질문 답변 — 운영 조회 (MNT-01 중 운영 질문) [기획서 + 제안]

비서는 **SQL을 직접 쓰지 않고**, 미리 만든 조회 도구 중에서 골라 쓴다 [기획서 4.2]. 생산 파트용 도구 후보 [제안]:

| 조회 도구 | 반환 | 대답할 수 있는 질문 예 |
|---|---|---|
| `get_line_flow` | 공정별 상태·수량·재공품 | "지금 어느 공정이 막혔어?" |
| `get_order_progress` | 작업지시 진행·지연 | "PO-2609-041 어디까지 갔어?" |
| `get_orders_at_risk` | 지연 위험 작업지시 목록 | "오늘 납기 못 맞출 것 있어?" |
| `get_operation_reports` | 공정 실적 | "어제 OP-30 양품 몇 개야?" |
| `get_kpi` | 가동률, OEE, MTTR, MTBF | "이번 주 OEE는?" |
| `get_downtime_pareto` | 정지 원인 순위 | "어제 야간에 제일 오래 선 이유는?" |
| `get_state_timeline` | 설비 상태 구간 | "VF2-01 어제 몇 번 멈췄어?" |
| `get_defects` | 불량 수량·사유 | "이번 주 불량 가장 많은 공정은?" |
| `get_tool_life` | 공구 사용 횟수·한도 | "T05 언제 바꿔야 해?" |
| `get_shift_report` | 교대 보고서 | "지난 교대 인계 사항 알려줘" |

답변 형식: **답 + 근거 기록 번호 + 관련 정보 한 줄**. 예: "OP-30 양품은 어제 야간 78개입니다(operation_report 14건). 같은 시간대 VF2-01 정지 2회(48분)가 있었습니다."

섞인 질문("왜 어제 PO-2609-043이 늦었어?")은 조회 도구 여러 개를 합쳐서 답한다. 정비 문서가 필요한 질문은 정비 파트의 문서 검색으로 넘긴다.

### 3.4 교대·일일 보고서 문장 (PRD-02) [기획서]

- 숫자 표는 프로그램이 채우고, 비서는 **특이 사항 3~5문장**과 **다음 교대에 넘길 일**만 쓴다.
- 쓴 문장의 숫자는 프로그램이 표와 대조한다.

### 3.5 정지 사유 추천과 지연 원인 설명 [제안]

| 일 | 안 A | 안 B |
|---|---|---|
| 정지 사유 분류 | 비서가 추천하고 작업자가 선택 | 자동 분류하고 작업자가 틀리면 수정 |
| 지연 원인 설명 | "OP-30 정지 48분과 셋업 지연이 원인으로 보입니다" 문장으로 제시 | 같음 |
| 교대 보고서 | 반장이 [만들기] → 확인 → 발행 | 교대 끝에 자동 발행, 반장이 수정 |

**[선택 필요]** 안 A / 안 B / 중간안은 팀이 정한다. 기획서는 되돌리기 쉬운 일만 자동으로 하는 **중간안**(보고서 초안은 자동, 정지 사유 분류는 제안)을 3주 일정에 가장 무리가 적다고 봤다. 안 B를 고르면 처리 기록과 되돌리기 버튼(AST-03)이 필요하다.

### 3.6 차트 설명 [기획서]

화면 옆 비서 창에서 "이 차트 설명해 줘"를 지원한다. 차트가 보여 주는 숫자를 문장으로 읽어 주는 역할이다.

## 4. 비서가 하지 않는 일

| 하지 않는 일 | 이유 |
|---|---|
| 설비 원격 조작, 설정 변경 | 안전 원칙 (법 제92조, KOSHA B-M-25-2026) |
| 작업지시 취소·생산 계획 변경 | 사람이 결정 (관리자 권한) |
| 자유 SQL 질의 | 3주 안에 안정화하기 어려움. 조회 도구로 대신 |
| 불량 원인 단정 | 근거 문서 부족. "관련 기록"만 보여 준다 |
| 근거 없는 수치 제시 | 원칙 3, 4 |
| 일정 최적화 | 범위 밖 |

## 5. 정비 파트와 이어지는 지점

| 생산 쪽 사건 | 비서가 넘기는 곳 |
|---|---|
| 정지 등급 알람으로 DOWN | 정비 파트의 알람 지침 카드·작업지시서 초안 |
| 불량 급증 | 검사 기록(QLT-01), 최근 공구 교환·알람 이력 |
| 공구 수명 임박 | 공구 수명 화면(ML-01) |
| 정비 완료 | 설비 상태 복귀 → 병목·지연 위험 재계산 → 교대 보고서 반영 |

## 6. 시연에서 보여 줄 장면

| 장면 | 비서가 하는 일 |
|---|---|
| 교대 시작 | 브리핑: 지난 교대 실적, 지연 위험 작업지시, 챙길 3가지 |
| VF2-01 정지 | "OP-30이 멈췄고 PO-2609-043 납기 지연 위험이 생겼습니다" 알림 |
| 질문 | "오늘 납기 못 맞출 작업지시 있어?" → 지연 위험 목록 + 근거 |
| 교대 끝 | 보고서 특이 사항 문장, 숫자 대조 통과 표시 |

## 7. 평가 방법 [제안]

심사에서 "AI가 틀리면요?"에 숫자로 답하기 위해 **평가 질문 세트**를 만든다.

| 평가 | 방법 | 목표 |
|---|---|---|
| 조회 정확도 | 질문 30개에 대해 기대 도구·기대 숫자와 비교 | 정답 수와 비율 보고 |
| 보고서 숫자 일치 | 문장 속 숫자가 표와 일치하는 비율 | 100%가 되도록 대조 단계 둠 |
| 근거 표시 | 답변에 기록 번호가 붙은 비율 | 100% |
| 기록 없음 처리 | 없는 작업지시를 물었을 때 "없음"으로 답하는지 | 지어내지 않음 |

평가 질문 예: "PO-9999는 어디까지 갔어?"(없는 번호), "어제 VF2-02 가동률은?", "이번 주 정지 원인 1위는?", "불량이 제일 많은 날은?"
