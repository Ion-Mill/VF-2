## 2. 지금 상태와 바꾸려는 것

| 칸 (FR-QLT-01-01) | 지금 (사람 입력) | 바꾸려는 것 |
|---|---|---|
| 로트 번호, 부품 순번 | 작업자가 친다 | 플랫폼이 알고 있는 값을 측정기에 넘기고, 결과 파일에 같이 돌아오게 |
| 검사 방식 (초품/발췌/강화 + 강화 사유) | 작업자가 고른다 | 플랫폼 규칙(FR-QLT-01-03~05)으로 정해서 넘김 |
| 항목, 측정값·판정 | 작업자가 측정기 화면을 보고 옮겨 적는다 | 측정기 결과 파일에서 자동 |
| 측정기, 측정자, 시각, 측정실 온도 | 작업자가 친다 | 측정기·시각·온도는 자동, 측정자는 확인만 |

- 옮겨 적기는 시간이 들고 옮겨 적는 실수가 생긴다. 측정 공구 데이터를 PC로 바로 보내면 "옮겨 적는 실수가 없어진다"는 것이 Mitutoyo의 설명이다 [참고: Mitutoyo USB 입력 장치 보도자료].
- 측정 시간 2.5분/개, 게이지 0.5분/개, 강화 5.0분/개 [가상: DOC-06 3.4]은 이번 조사로 바뀌지 않는다. 자동 입력은 **입력 시간과 실수**를 줄이는 것이지 측정 시간을 줄이는 것이 아니다.

## 3. CMM 측정 결과를 다른 시스템으로 넘기는 방법

### 3.1 방법 비교

| # | 방법 | 무엇인가 | 장점 | 단점 | 구분 |
|---|---|---|---|---|---|
| A | **CMM 소프트웨어의 CSV·텍스트 출력** | 측정이 끝날 때마다 결과를 CSV·TXT·XLSX 파일로 씀 | 거의 모든 소프트웨어에 있음. 읽기 쉬움. 칸을 우리가 정할 수 있음 | 회사마다 양식이 달라 측정기를 바꾸면 읽는 프로그램도 고쳐야 함 | [실제: 아래 3.2] |
| B | **QIF Results (ISO 23952:2020)** | 측정 계획·결과·통계를 담는 국제 표준 XML. 8부 중 7부가 Results, 8부가 Statistics | 표준이라 회사가 달라도 같은 모양. 특성 실측값·특성 판정·부품 판정·일련번호·통계(Cp, Cpk)까지 담음 | 소프트웨어 지원이 버전마다 다름(PC-DMIS는 2024.2부터 출력). 파일이 큼(NIST 예시 1개 약 395 KB, 부품 20개). 우리 예시 파일에는 시각·측정기·온도 칸이 비어 있음 | [실제] |
| C | **DMIS 결과 출력 (.dmo)** | ISO 22093 DMIS 언어의 결과 파일 | 오래된 국제 표준 | DMIS는 원래 측정 프로그램 언어라 MES 쪽에서 읽는 예가 적음. 문법을 해석해야 함 | [실제: PC-DMIS DMIS 탭, ISO 22093] |
| D | **AQDEF (Q-DAS .dfq)** | 자동차 업계 통계 소프트웨어(Q-DAS)용 형식 | 자동차 협력사에서 많이 씀 | 형식 사양을 따로 구해야 함. 통계 프로그램 쪽 형식 | [실제: OPC 40210이 형식 예로 듦], 상세는 미조사 |
| E | **OPC UA 40210 (기하 측정 시스템)** | 측정기와 MES 사이의 OPC UA 표준. 결과의 **전달·관리만** 정하고 형식은 자유 | 실시간, 상태(측정 중·끝)도 함께 받음 | 측정기·소프트웨어가 지원해야 함. 도입 사례·비용 확인 필요 | [실제] |
| F | **MTConnect** | 공작기계 상태·데이터 표준(OP-30 Haas에서 이미 씀) | 라인 전체를 같은 방식으로 | CMM 측정 결과 전달용으로는 주류가 아님. 2012년 시연에서 QIF 결과 파일을 MTConnect로 보낸 예가 있음 | [실제: Quality Digest 2012] |
| G | **USB·키보드 흉내 입력** | 측정값을 키보드 입력처럼 화면 칸에 쳐 넣음 | 프로그램을 안 고쳐도 됨 | 커서가 다른 칸에 있으면 엉뚱한 칸에 들어감. CMM에는 맞지 않고 손 측정 공구용 | [실제: 3.4] |

### 3.2 CMM 소프트웨어별 파일 출력 [실제]

| 소프트웨어 (회사) | 출력 형식 | 확인한 내용 |
|---|---|---|
| **PC-DMIS** (Hexagon) | 보고서 탭 TXT·RTF·PDF / DMIS 탭 .dmo / Excel 탭 **XLS·XLSX·CSV** / Generic 텍스트(CSV) / XML / **QIF (2024.2부터)** / 사용자 파일 쓰기(FILE/WRITELINE) | Excel 탭: 머리말에 측정 프로그램 이름·부품 이름·개정·**일련번호**·통계 횟수, 날짜·시각 형식 선택, 기존 파일에 **덧붙이기/덮어쓰기**, **Auto Index**(FileName001, 002… 자동 번호). Generic 텍스트: 치수마다 이름·축·공칭값·+공차·−공차·측정값·편차·공차 밖 값. FILE/OPEN·READLINE·WRITELINE 등 파일 읽기·쓰기 명령이 측정 프로그램 안에 있음. COMMENT/INPUT으로 실행 중에 일련번호·이름을 입력받아 보고서에 넣음 |
| **CALYPSO** (ZEISS) | 표 파일 3종 `chr.txt`(특성), `hdr.txt`(머리말), `fet.txt`(형상) | "Results to File"에서 Table Files를 켜면 생김. 여러 번 측정을 한 파일로 합치는 Merge, 파일 이름 규칙 지정 가능 |
| **MCOSMOS** (Mitutoyo) | CSV 출력 | 측정 결과 전체 또는 고른 결과를 CSV로 내보냄. QIF 결과·통계 출력은 데이터 관리 프로그램 **MeasurLink** 쪽에서 지원 |

- 세 회사 모두 "측정이 끝나면 파일이 생기는" 방법이 있다 → 방법 A는 측정기 회사를 아직 안 정해도 쓸 수 있다.
- QIF는 ANSI/DMSC QIF 3.0이 2020년에 ISO 23952:2020으로 발행된 것이다 [실제: DMSC·MMS 기사]. PC-DMIS가 **읽는** QIF는 3.0.0만 지원 [실제: PC-DMIS 2023.1 도움말].

### 3.3 우리 폴더의 실제 QIF 결과 파일에서 확인한 것 [실제]

`docs/quality/nist_tdp/FAIR_Plate_Results.qif` (NIST SMS Test Bed, QIF 2.1.0)

| 들어 있음 | 들어 있지 않음 |
|---|---|
| 특성 정의(평면도·직각도·위치도·지름·거리·각도 38개), 공칭값·공차 | 측정 시각 |
| 부품 20개의 특성 실측값(`...CharacteristicActual` → `Value`) | 측정기 이름·번호 |
| 특성마다 판정 `CharacteristicStatusEnum` (PASS 등) | 측정자 |
| 부품마다 판정 `InspectionStatus`, 일련번호 `SerialNumber` | 측정실·부품 온도 |
| 특성별 통계(평균, 표준편차, Cp, Cpk, Pp, Ppk) | 로트 번호 |

- QIF 표준 자체에는 측정 자원·추적 정보를 담는 부분이 있지만(5부 Resources 등), **실제 파일에 들어오는지는 소프트웨어 설정에 달려 있다**. 그래서 QIF를 쓰더라도 로트·검사 방식·온도는 따로 확인해야 한다.
- 이 파일은 DOC-06 3.5에서 "특성마다 측정값과 판정을 따로 두는 구성"의 [참고]로 이미 쓰고 있다. 가상 데이터의 측정값 칸 모양을 정할 때 계속 쓸 수 있다.

### 3.4 게이지·손 측정 자동 입력 [참고]

| 장치 | 방식 | 우리 라인에 맞나 |
|---|---|---|
| Mitutoyo **USB 입력 장치(USB-ITN)** | Digimatic 출력이 있는 손 측정 공구(캘리퍼스·마이크로미터·인디케이터·보어 게이지 등)를 PC USB에 꽂으면 **키보드로 인식**, 측정값이 엑셀 칸 등에 바로 들어감. 별도 프로그램 USB-ITPAK로 들어갈 칸·방향 지정 | **지금은 해당 없음.** DOC-06의 치수 항목은 모두 CMM으로 재고, 손으로 재는 것은 M6 통과·정지 게이지(합격/불합격)와 육안뿐 |
| Mitutoyo **U-WAVE** (무선) | 공구에 송신기(U-WAVE-T), PC에 수신기(U-WAVE-R). 수신기 1개에 송신기 최대 100개. 키보드 입력 방식으로 엑셀·MeasurLink 등에 넣음 | 위와 같음. 나중에 손 측정 치수 항목이 생기면 [참고] |
| **M6 나사 통과·정지 게이지** | 숫자를 내는 공구가 아님. 사람이 "통과 들어감 / 정지 2회전 넘게 안 들어감"을 보고 판정 [DOC-06 2장] | 자동 측정 불가. **태블릿 "통과 OK / 불합격" 버튼** 한 번으로 넣게 한다 [제안] |

- 키보드 흉내 방식은 웹 화면 입력 칸에도 들어가지만, 커서 위치가 틀리면 다른 칸에 들어갈 수 있다. 나중에 손 측정 항목이 생기면 공급사 수집 프로그램(MeasurLink 등)의 파일 출력을 받는 쪽이 안전하다 [제안].

### 3.5 측정실 온도를 자동으로 받을 수 있나

| 온도 | 어디서 | 자동 가능 | 근거 |
|---|---|---|---|
| **측정기 스케일 온도 (X·Y·Z)** | 측정기 제어기 | 예. Hexagon 제어기에 연결된 측정기는 PC-DMIS가 제어기에서 **자동으로 읽음** | [실제: PC-DMIS 온도 보정 도움말 "Automatic Method"] |
| **부품 온도** | 부품에 붙이는 온도 센서 (보통 1개, 여러 개면 평균) | 예. 위와 같음. 다른 회사 측정기(제3자)는 수동 입력 방식 | [실제: 같은 도움말] |
| **방 공기 온도 (측정실 온도)** | 별도 환경 센서 | 예, **센서를 따로 달면**. Hexagon **PULSE**는 측정기 주변의 온도·진동·습도를 무선 센서로 기록하고 TIGO SF를 지원 목록에 올림. MES와 MQTT 연동은 검색 요약에서만 확인(원문 미확인) | [실제: Hexagon Nexus PULSE 쪽] |
| 6061 열팽창 계수 | 측정기 소프트웨어 재질 표 (MaterialCoefficients.xml) | 측정 프로그램에 23.6 µm/m·K로 넣어 둠 | [실제: PC-DMIS 도움말], 값은 DOC-06 6장 |

- 결론 [제안]: FR-QLT-01-01의 "측정실 온도" 한 칸을 **"측정실 온도(방 공기)"와 "부품 온도"** 두 칸으로 나누는 것을 권한다. DOC-06 6장이 "부품 온도 16~26 ℃ 확인 후 측정"을 요구하므로, 부품 온도가 기록에 있어야 이 규칙을 지켰는지 볼 수 있다.
- 온도 값을 결과 파일에 넣으려면 측정 프로그램 끝에 FILE/WRITELINE으로 같이 써야 한다. PC-DMIS가 온도 보정에 쓴 값을 측정 프로그램 안에서 꺼내 쓸 수 있는지(표현식 이름)는 공개 도움말에서 확인하지 못했다 → [선택 필요: 측정기 공급사에 확인]. 못 꺼내면 방 온도는 PULSE 같은 환경 센서에서 직접 받는다.
- TempComp-202 "온도 기울기 한계 초과" [DOC-02 5.8] 알람과 짝을 맞추려면 방 온도를 **시간대별로 계속** 받는 쪽(환경 센서)이 낫다.

## 5. 플랫폼이 받는 방식 [제안]

### 5.1 흐름

| 순서 | 무엇 | 누가 |
|---|---|---|
| 1 | 플랫폼이 OP-50에 도착한 로트를 보고 **측정 지시**를 만든다: 로트 번호, 다음 측정할 부품 순번(발췌면 1·5·10…), 검사 방식(초품/발췌/강화), 강화 사유, 측정 항목 묶음(보통/강화) | 플랫폼 (QLT-01 규칙) |
| 2 | 측정 지시를 **공유 폴더의 지시 파일**로 쓴다 (부품 1개에 1줄) | 플랫폼 |
| 3 | 작업자가 OP-50 태블릿에서 부품 꼬리표의 **로트 바코드를 찍고** 순번을 확인한다 (측정자 = 로그인한 사람) | 작업자 (확인 1번) |
| 4 | 측정 프로그램이 시작할 때 지시 파일을 읽는다 (PC-DMIS FILE/READLINE), 화면에 로트·순번을 보여 준다 | 측정기 |
| 5 | 측정이 끝나면 **결과 파일**을 공유 폴더 "들어옴" 칸에 쓴다 (부품 1개 = 파일 1개, 쓰는 중에는 임시 이름 → 다 쓰면 이름 바꿈) | 측정기 (FILE/WRITELINE 또는 Excel 탭 CSV + Auto Index) |
| 6 | 플랫폼이 폴더를 지켜보다 새 파일을 읽어 FR-QLT-01-01 칸에 넣고, 판정을 **DOC-06 2장 기준으로 다시 계산**해 측정기 판정과 맞춰 본다 | 플랫폼 |
| 7 | 다 읽은 파일은 "처리됨" 칸으로, 못 읽은 파일은 "오류" 칸으로 옮긴다. 원본 파일은 지우지 않는다 | 플랫폼 |
| 8 | M6 게이지·외관은 태블릿 버튼으로 같은 부품 기록에 붙인다 | 작업자 |

- 지시 파일(2·4번)은 선택 사항이다. 측정기 쪽이 지시 파일을 못 읽으면, 3번에서 작업자가 측정기 화면(PC-DMIS COMMENT/INPUT)에 로트 바코드를 찍는 방법으로 바꾼다 [실제: COMMENT/INPUT 기능].
- 폴더 이름·파일 이름 규칙·주기 등은 기술 선택 뒤 정한다 [선택 필요: 기술 회의].

|---|---|---|---|

| 검사 방식 (초품/발췌/강화) | **자동** | 플랫폼 규칙 (FR-QLT-01-03~05) | 없음 (바꾸려면 반장) |
| 강화 사유 | **자동** (복사) | 반장이 **보류할 때 적은 사유** (FR-PRD-05) | 사유 자체는 보류 단계에서 반장이 이미 입력 |

### 5.4 파일을 못 읽었을 때 [제안]

| 상황 | 플랫폼이 하는 일 | 사람 |
|---|---|---|
| 측정 시작 뒤 결과 파일이 오지 않음 | "결과 대기" 표시를 오래 두지 않고 작업자·반장에게 알림. 기다리는 시간은 측정 시간(2.5분/개, 강화 5.0분/개 [가상])보다 길게 → 값은 [선택 필요] | 측정기 화면 확인 |
| 파일 양식 오류 (열 빠짐, 숫자 아님) | 파일을 "오류" 칸으로 옮기고 기록하지 않음. 알림 | 반장이 확인 → 다시 출력 또는 수동 입력 |
| 로트·순번이 지시와 다름 | 기록을 "확인 필요"로 두고 로트 판정에 쓰지 않음 | 작업자가 맞는 로트를 고름 |
| 같은 부품 결과가 두 번 옴 | 두 번째는 "재측정"으로 따로 저장 (지우지 않음). 어느 것을 쓸지는 반장 | 반장 선택 |
| 항목 일부만 옴 | "불완전" 표시. 그 부품 판정 보류 | 다시 측정 |
| 측정기 판정 ≠ 플랫폼 판정 | 플랫폼 판정을 쓰고 "판정 불일치" 주의 알림 (공차·측정 프로그램 확인) | 반장 확인 |
| 공유 폴더·네트워크가 끊김 | 측정기 쪽에 파일이 남아 있으므로, 다시 연결되면 순서대로 읽음 | 없음 |
| 오래 고장 | **수동 입력 화면(지금의 FR-QLT-01-01)을 그대로 남겨** 대신 씀. 수동 입력 기록에는 "수동" 표시와 입력자를 남김 | 작업자 입력, 반장 확인 |

- 수동 입력과 자동 입력을 구분해 두면 나중에 Cpk(FR-QLT-01-08) 계산 때 수동 입력 값만 따로 볼 수 있다.

## 8. 못 찾은 것 / 남은 확인

| 항목 | 상태 |
|---|---|
| TIGO SF 공식 데이터시트 (외형·설치 여유) | Hexagon 쪽은 접속 거부(403)·다운로드 링크 못 찾음. 외형은 중고 목록·검색 요약 값 [참고] |

| PULSE의 MQTT·MES 연동 | 검색 요약에만 있음. 원문(보도자료)은 403으로 못 열어 확인 못 함 |
