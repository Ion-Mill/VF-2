# 발표 준비 — 프로젝트 기본 내용 (발표자 1인용 핵심 요약)

## 0. 30초 설명 (이 말부터 외우기)

> 자동차 부품(엔진 마운트 브래킷)을 깎는 가공 라인에서, **AI 운영 비서 "이브"** 가 설비와 생산을 지켜보다가 문제가 생기면 **"무엇이 문제인지 → 생산에 어떤 영향이 있는지 → 어떻게 안전하게 조치하는지"** 를 근거와 함께 **먼저 알려 주고**, 작업지시서·작업기록서·교대 보고서·일일 보고서의 **초안까지 써 주는** 플랫폼입니다. **초안은 AI가, 확정은 사람이** 합니다.

| 한 줄 | 내용 |
|---|---|
| 대시보드와 다른 점 | 대시보드는 "빨갛게 바뀜"에서 끝나지만, 이 플랫폼은 **사건 → 지침카드 → 작업지시서 → 작업기록서 → 교대·일일 보고서**로 비서가 다음 일을 이어서 준비한다 |
| 구성 | 5명(AI 비서 2 · 데이터/ML 1 · 백엔드/DB 1 · 프론트 1), 개발 2주(10/12~10/23), 발표 10/26 |
| 데이터 | 문서는 **실제 자료 기반**, 운영 데이터는 **가상**(실제 공개 기록의 모양을 따라 생성) |

## 1. 기획

**주제를 왜 이렇게 골랐나 [기준]** — 근거 자료가 충분해서 "지어내지 않고" 만들 수 있는 주제를 골랐다.

| 기준 | 상태 |
|---|---|
| 공식 고장 문서 | Haas 알람 865개·고장 대응 안내 53편 → 알람·원인·조치를 실제 문서로 만들 수 있음 |
| 한국어 문서 | 알람 번역 809개, 조작 매뉴얼 498쪽, KOSHA 안전 문서 36개 |
| 작업자가 몸으로 개입(안전 중요) | 전원 차단·잠금·표지 → "AI가 안전 절차를 빠뜨리면 안 되는" 이유가 뚜렷함 |
| 설비 데이터를 꺼내는 공식 방식 | MTConnect(포트 8082) → 실제 설비에 붙일 길이 있음 |
| 지표 계산식 근거 | OEE·MTTR 등 NIST 논문(ISO 22400) |
| 실제 운영 데이터 | **없음** → 가상으로 만들되 실제 기록의 모양을 따른다 |

**가상 공장**: 한국 자동차 부품 협력사 1곳, 제품 **BRK-A100 엔진 마운트 브래킷 1종**(알루미늄 6061), 5공정(OP-10 절단 → 20 황삭 → **30 정밀가공(병목, Haas VF-2 2대)** → 40 디버링·세척 → 50 측정), 주·야 2교대. 제품을 하나로 둔 이유: 설명하기 쉽고, OP-30 작업이 풍부해서 공구·알람·검사가 모두 의미가 생기며, 품종 교체 대신 **로트 단위** 추적을 보여 줄 수 있어서.

**진행 원칙 6가지** (질문 나오면 이 중에서 답)

| # | 원칙 | 한마디 |
|---|---|---|
| 1 | 근거 없으면 답하지 않는다 | 답마다 사내 문서 이름·번호·§절 출처, 없으면 "문서에 없음" |
| 2 | 숫자는 지어내지 않는다 | 알람 기준 온도·압력은 문서에 없으니 만들지 않음 |
| 3 | **계산은 코드가, 문장은 AI가** | 손실 수량·예측·**보고 순서**는 프로그램이 정하고 AI는 문장으로만 옮김 |
| 4 | AI는 초안만, 확정은 사람이 | 모든 AI 문서는 "AI비서 초안", 수정 이력 남김 |
| 5 | 안전 절차는 항상 들어간다 | 잠금·표지·보호구는 **고정 서식**, AI가 쓰지 않음 |
| 6 | 설비는 사람이 움직인다 | 원격 조작 기능 없음(산안기준 제92조) |

**기능 범위**: 필수 10 + 권장 7. 일정이 밀리면 권장부터 줄이기로 정했다. 처음부터 뺀 것: 자유 SQL 질문, 불량 원인 안내, 설비 원격 조작, 주문·구매·ERP 연동, AI의 자동 처리.

**사용자 4역할**: 현장 작업자(OPR) · 보전 담당(MNT) · 라인 반장(SUP) · 공장 관리자(MGR). 역할마다 보는 화면·권한·비서가 해 주는 일이 다르다.

**비서의 행동 범위 [기준]** — 나누는 기준 3가지: *되돌릴 수 있나 / 책임자가 필요한가 / 안전과 관련 있나*.

| 등급 | 내용 |
|---|---|
| 자동 | 알림, 지침카드, 브리핑, 지표·손실 계산 |
| AI 초안 + 사람 확정 | 작업지시서, 작업기록서, 교대·일일 보고서 |
| 사람만 | 승인, 담당자 지정, 로트 보류·해제, 출하, 설비 조작, 잠금·표지, 정비 |

**문서 흐름**: 지침카드(알람+원인+먼저 할 일+안전) → 작업지시서(AI 초안→MNT 수정→**SUP 승인**) → 작업기록서(실제 한 일, **MNT 확정**) → 교대 보고서(18:00·06:00, **SUP 확정**) → 일일 보고서(야간 보고서 확정 즉시~07:00, **MGR 확정**). 알람 등급별로 다르다: 조작 안내=카드만 / 주의=카드+간이 작업기록 / **정지=전체 흐름**(OP-30에서만 작업지시서).

**알림 3가지 전달 방식 + "전부 보고" 순서**
- ① **긴급**(정지 등급 알람): 화면 가운데 팝업 + 소리, 로그인한 전원 (처리 책임은 그 설비 작업자·보전)
- ② **고장·확인**(주의 알람, 반복 알람, 병목, 목표 미달, 재고 등): 이브 아이콘 숫자 + 알림 탭
- ③ **문서 알림**(초안 검토, 보고서 확정 요청): 이브 말풍선 → 그 문서 페이지
- 비서가 몇 개만 골라 말하지 않는다. **프로그램이 문제를 전부 모아 정해진 순위로 정렬**한다: 안전(잠금 중) → 오래 방치 → 긴급 → 생산 위험 → 주의 → 참고. 화면 머리에 "전체 N건"을 항상 보인다. *(근거: ISA-18.2 알람 우선순위, 교대 인수인계 연구)*

**고장 ≠ 병목**: 고장은 설비가 알람으로 멈춘 것(고장 손실), 병목은 설비는 도는데 한 공정이 느려 앞에 재공이 쌓이는 것(속도 손실). 병목 원인 4가지(공구 마모 / 설비 1대만 가동 / 검사 강화로 OP-50 이동 / 묶음 대기)를 모두 데이터에 넣었고, 원인별 조치는 **제안만** 하고 사람이 실행한다.

## 2. 데이터 제작 (가상 데이터 생성기)

| 왜 가상인가 [기준] | 설비 상태+알람+생산 로트+정비+검사+재고가 **한 라인에서 함께** 있는 공개 기록이 없음. 조각 자료(NIST 설비 기록, 4TU 생산 기록, Haas 원시 데이터 표본 등)에서 **숫자의 크기와 모양만 빌림** |

## 3. 사내 문서 (RAG의 지식)

**무엇**: 흩어진 실제 문서(Haas·Siemens 매뉴얼, KOSHA, 법령)에서 **이 프로젝트에 필요한 내용만 뽑아 한국어로 다시 만든 사내 문서 7종 + 용어집**. 비서는 이 문서만 검색한다.

| 번호 | 문서 | 번호 | 문서 |
|---|---|---|---|
| 00 | 용어집(쿨런트→절삭유 등 현장말 사전) | DOC-04 | 예방 정비 기준서 |
| DOC-01 | 공정별 운영 매뉴얼 | DOC-05 | 안전 작업 기준서(잠금·표지, 고전압 대기, 보호구) |
| DOC-02 | 알람 코드집 | DOC-06 | 검사 기준서 |
| DOC-03 | 고장 대응 매뉴얼 | DOC-07 | 설비 데이터·지표 정의서(계산식·보고 순서·병목 규칙) |

**왜 이렇게 만들었나 [기준]**
1. **필요한 것만**: 기능과 시연에 쓰이는 내용만 번역 → 영어 원문을 한국어 질문으로 찾는 문제를 없앰.
2. **우선순위**: 법령 > KOSHA > 제조사 문서 > 공식 규격 > 타사 사례 > 팀 가정. 안전은 **더 엄격한 쪽**을 따른다(예: Haas의 고전압 5분 대기 + KOSHA 잠금·표지 둘 다 넣음).
3. **안전 절차·알람 설명은 바꾸지 않는다**: 번역만 하고 새로 쓰지 않음.
4. **출처 관리**: 본문 항목마다 원문 출처와 [실제]/[참고]/[가상] 표시(사람이 추적용). 비서 답·화면에는 **사내 문서 이름·번호·§절만** 표시, 원문은 표시 안 함(저작권).
5. 문서 번호·개정 번호(Rev)로 관리, 수정 이력 남김. Haas·Siemens 원문/번역본은 공개 저장소에 올리지 않음(사내 문서는 가능).

⚠ 팀이 만든 문서라서 "그 문서에 답을 잘하는 건 당연"하다는 지적 가능 → 실제 자료 기반 재구성 + 튜닝에 안 쓴 **보류 평가 세트**로 쟀다고 답한다. 새 회사 문서는 용어 사전 보강 필요.

## 4. 프론트엔드 (화면)

| 항목 | 내용 |
|---|---|
| 기술 | **Next.js 14 + React 18 + TypeScript**, 3D는 **three.js**, 글꼴 Pretendard |
| 선정 기준 [기준] | 팀 자료·예제가 React 기준이고 3D 예제가 이미 three.js였음. 2D 배치도는 SVG(도형에 색·숫자 붙이기 쉬움) |
| 3D 라인 뷰 | **실제 크기**(공장 28×8m)로 그린 모니터링형 디지털 트윈. 설비 색·동작·재공·병목이 데이터 값 그대로. 숫자는 2D 패널, 3D가 느리면 2D 배치도로 전환. **보기만** 하고 설비 조작 없음(안전). 지난 일을 3D로 다시 보기 |
| 이브 | 모든 화면 우하단 아이콘 → 오른쪽 사이드바(브리핑·알림·채팅·채팅 기록). 말풍선은 문서 알림·브리핑 준비 때만 |
| 갱신 방식 | 3D·라인은 1초, 작업지시서·알림은 4초마다 **폴링**(푸시 통로 SSE는 서버에 만들어 두었고 화면은 아직 연결하지 않음). 3번 연속 실패하면 "연결 끊김" 띠 |
| 역할별 | 현장 작업자 첫 화면 = 큰 모니터용 **현장 보기**, 나머지 = 3D 라인 뷰 |
| 화면 표시 | 운영 응답에 `is_synthetic` 표시를 붙여 가상 값을 실제처럼 보이지 않게 함 |

## 5. 백엔드 (서버)

| 항목 | 내용 |
|---|---|
| 기술 | **FastAPI(파이썬) + Pydantic**, DB 연결은 SQLAlchemy·psycopg, SQL은 `app/sql/*.sql`에 이름 붙여 모음. 서버 → 화면 실시간은 SSE(DB의 `LISTEN/NOTIFY` 사용) |
| 선정 기준 [기준] | 비서·생성기가 모두 **파이썬이라 언어를 통일**, 요청 모델이 입력 검사 역할, 자동 API 문서(`/docs`)로 화면 담당과 주소 맞추기 쉬움 |
| 규모 | API **168개**(10/27 코드의 주소·방식 수. 시뮬레이터·비서·QR용 포함), API 명세서에는 73개 번호(ID)를 정리, 역할별 권한표 |
| 권한 [기준] | 버튼 숨기기만이 아니라 **3겹**: ① 서버가 역할별로 주소를 막음 ② 내 것·담당 공정 범위 확인 ③ 승인·보류·출하 같은 "사람만 하는 일"은 DB 함수가 한 번 더 막음. 로그인은 JWT(12시간), 비밀번호는 scrypt 해시 |
| 데이터 방향 | **설비 → 플랫폼 한 방향.** 백엔드는 설비에 아무것도 보내지 않음. 설비/생성기는 서비스 키로 `/api/ingest`에 데이터를 보냄 |

## 7. 서버·배포·시연 프로그램

**시연 프로그램(= 시연 서버)**: 가상 데이터 생성기가 공장 역할을 하며 값을 만들고, 그 값이 **화면에 바로 쓰이는 동시에 DB 중계(`db_relay`)로 3초마다 DB에 저장**된다. 배속(×1~×180)·일시정지·처음으로·사건 버튼은 시연 모드에서만 보인다. *"녹화가 아니라 지금 만들어지는 데이터"* 라고 답한다.

| 흐름 | 설명 |
|---|---|
| ① 생성 → ② DB 저장 → ③ 규칙 작동 → ④ 화면 → ⑤ AI 비서 | 비서의 이력·수량은 DB, **지금 센서·설비 상태·병목은 시연 서버의 현재 값**으로 답해서 채팅 숫자와 화면 숫자가 같다 |

| 구분 | 영상용 | 발표용(평가자 서버) |
|---|---|---|
| 목적 | 시연 영상 촬영 | 평가자가 직접 접속 |
| DB | **내 PC 로컬 Docker DB** | **공용 Supabase** |
| 시각 | 10/24 09:00 시작(배속) | 10/26 09:00 미리 짠 사건 → **15:00부터 실제 시각** |

**배포**: AWS EC2 1대 + Docker Compose 컨테이너 5개(**caddy**=HTTPS·접속 비밀번호·주소 분배, **web**, **sim**, **backend**, **assistant**), 바깥에는 80·443만 열고 SSH는 내 IP만. `./mom.sh up` 한 줄로 켠다. **[기준] 쿠버네티스 대신 Compose**: 2주·5명 규모에서 재현이 쉬운 방식.
- 발표 당일 비상: ① `./mom.sh rollback` ② 비상 태그(`emergency-1024-deploy`) ③ 노트북 + Cloudflare 터널 ④ 시연 녹화본.
- ⚠ **서버 재시작 금지(발표 중)**: 시연 서버를 다시 켜면 공용 DB가 기준 시각으로 되돌아가 사람이 한 기록(승인, 작업기록서, 보고서 확정, 채팅)이 지워진다. 그래서 **15:00 전에 켜 두고 발표 중에는 건드리지 않는다.**

## 8. LLM (AI 비서) — 어떤 규칙으로 도는가

**모델과 전환 이력** [기준]

| 항목 | 내용 |
|---|---|
| 지금 | **Claude Haiku 5.5**(채팅의 모든 호출, API 방식). Claude가 실패하면 **Gemini로 즉시 대체**, 둘 다 안 되면 규칙·기본 문장(공장 화면·기록은 AI 없이도 동작) |
| 이력 | 10/08 로컬 Qwen3.5-9B 시작 → 10/14 같은 평가 질문으로 비교 → **10/17 Claude로 확정**(한국어 용어 오류·GPU 필요) → 10/23 CLI 구독에서 API 호출로 |
| Haiku를 고른 이유 | 정답 절 인용 Haiku 73/75 = Sonnet 73/75(같음), 토큰 단가 **20배 저렴**(실측 호출당 약 1/17). 응답은 느려서 제한 130초 |

**실행 규칙 (이것만 외우면 됨)**
1. **질문을 길로 나눈다**: 문서 질문 → 문서 검색(RAG) / 운영 질문 → 조회 도구 / 안전 절차 → 고정 서식 / 섞인 질문 → 둘 다.
2. **숫자는 DB에서**: 운영 질문은 읽기 전용 계정의 **조회 도구 14개** 중에서 골라 쓴다(자유 SQL 없음). AI가 숫자를 지어내지 않는다.
3. **문서 검색은 BM25(낱말 일치) + 한국어 2-gram + 용어 사전**: 알람 번호·설비 코드처럼 글자가 정확히 맞아야 해서. 문서 195조각. 임베딩 검색은 만들어 두고 꺼 둠(이득 미확인). 답에는 **문서·§절 출처**, 없으면 **"문서에 없음"**.
4. **안전 문구는 AI가 쓰지 않는다**: 잠금·표지 단계, 고전압 대기, 보호구는 DOC-05 §7 원문을 프로그램이 글자 그대로 붙이고 "AI 작성 아님" 표시. 풀이가 단계를 빠뜨리면 풀이는 버리고 원문만.
5. **숫자 대조**: AI가 고친 문장의 숫자·기록 번호가 프로그램 기본 문장과 일치해야 하고, "해도 됩니다"·"리셋하세요" 같은 허락·지시 문구는 거부 → 기본 문장 사용.
6. **정해진 형식(JSON 스키마)으로 답받고** 받은 뒤 코드가 한 번 더 검사.
7. **무엇을·언제·누구에게 알릴지는 프로그램(DB 규칙)이 정한다.** LLM은 모인 목록을 읽기 좋은 문장으로 정리만 → LLM이 실패해도 알림은 빠지지 않음.
8. **권한**: 권한 밖 정보는 값 없이 "보전 담당·관리자만 볼 수 있습니다"만 답한다(예: 작업자의 MTTR·센서 질문).
9. **외부로 나가는 것**: 질문, 사내 문서 조각, 가상 운영 값뿐. 보내기 직전에 이름·사번·토큰·키·DB 주소를 가림. `EXTERNAL_LLM_APP=0`이면 한 글자도 안 나감.
10. **자율 에이전트 아님**: 읽기와 초안 쓰기만. 실제 조치는 사람.

**평가**: 질문 유형별 세트(보류 세트, 모르는 질문 세트, 안전 재현 세트, 길 나누기 세트)를 개선마다 다시 돌려 기존 질문이 깨지지 않았는지 확인. 음성 입력(faster-whisper, 글자 오류율 21%→4%)도 있음.
⚠ 프롬프트 인젝션 전용 테스트 없음(읽기 전용 계정+도구 14개로 피해 범위만 제한), 공장 소음 음성 미시험.

## 11. 솔직하게 말할 한계 (먼저 인정하는 편이 좋다)

- 운영 데이터는 **가상**이다(문서·알람 번호는 실제). 실제 현장 효과(MTTR 감소 등)는 측정하지 못했다 — Rockwell 등의 수치는 시장 방향을 보인 것이지 우리 성과가 아니다.
- 기획서와 구현이 다른 곳: 로컬 LLM → Claude, CLI → API 호출, 외부 전송 필터 구현 완료. **측정 결과로 바꿨고 이유는 수정 기록에 있다.**
- 프롬프트 인젝션 전용 테스트, 공장 소음 음성, 처음 보는 회사 문서에서의 성능은 검증하지 못했다.
- 서버는 한 대(이중화 없음), 발표 중 시연 서버 재시작 금지.
- 실제 라인에 붙이려면: 생성기 자리에 실제 설비 데이터(PLC·MTConnect 수집)를 같은 형식으로 연결 + 사내 문서를 실제 작업 표준으로 교체 + 서버 이중화·모니터링·사내망 배포.
