========================== 아래부터 붙여 넣기 ==========================

너는 이 저장소(`semi-ai`, `Ion-Mill/VF-2`)에서 **배포 서버(AWS, `11_automotive/deploy`)의 비서가 사내 문서를 공용 Supabase에서 읽게 할지 점검**하는 일을 돕는다. 아래를 **순서대로** 하고, 모르는 것은 추측하지 말고 "모름"이라고 적는다. **서버 설정을 바꾸거나 서버를 다시 켜는 것은 사람이 정한 뒤 사람이 한다.** 너는 확인하고 제안만 한다.

## 지켜야 할 것
- 비밀값(`MOM_ASSISTANT_KEY`, DB 주소·비밀번호, 외부 LLM 키)을 화면, 문서, 커밋에 쓰지 않는다. `deploy/*.env`는 읽더라도 **키 이름과 줄 유무**만 보고 값은 출력하지 않는다.
- 비서에 질문(`/chat`)을 보내서 확인하지 않는다. 공용 DB `chat_log`·`access_log`에 기록이 남고 외부 Claude로 질문이 나간다.
- 공용 DB에 쓰지 않는다. 서버를 끄거나 다시 켜지 않는다(제안만).
- **`./mom.sh up`·`./mom.sh update`는 권하지 않는다.** 시연 서버까지 다시 켜서 **공용 DB가 시연 기준점으로 되돌아간다**(`deploy/배포_안내.md` 4장). 비서·백엔드만 바꿀 때는 `docker compose up -d --build <서비스>`처럼 그 서비스만 다시 만든다.

## 배경 (알아 둘 것)
- 서버의 비서 컨테이너는 지금까지 이미지 안의 `/srv/가상사내문서/*.md` 파일을 읽는다(`deploy/Dockerfile.assistant`).
- 새 스위치 `DOCS_SOURCE`(`files` 기본 | `db`)를 만들었다(PR #168, #171, `main`에 합쳐짐). 서버 `assistant.env`는 `../assistant/.env.example`을 복사해 만드는 것이 팀 기준이라(`배포_안내.md` 4장), 새로 만들면 `DOCS_SOURCE=files`가 들어 있다. `db`이면 비서가 시작할 때 한 번 백엔드의 `GET /api/assistant/docs`(읽기 전용, 서비스 키)로 공용 DB의 문서 조각을 받아, 파일로 만든 것과 **같은 조각**으로 다시 만든다(창민 PC에서 195/195 글자 그대로 확인). 백엔드가 안 되면 파일로 돌아가고 `/health`에 이유가 나온다.
- 서버에서는 백엔드가 이미 Supabase를 보므로 `-SupabaseDocs`/`DOCS_BACKEND_URL`은 필요 없다(비워 둔다). 필요한 것은 `deploy/assistant.env`의 **`DOCS_SOURCE`를 `db`로 하는 한 줄**이다. 예전에 만든 `assistant.env`에는 이 줄이 아예 없을 수 있다(없으면 `files`로 동작).

## 할 일
1. **서버 코드가 최신인지**: 서버 저장소의 `git log --oneline -8`에 `#168`, `#171` 합치기 커밋이 있는지 본다. 없으면 사람이 `git pull --ff-only`를 한 뒤 **백엔드와 비서 이미지만** 다시 만들어야 한다고 알린다(예: `docker compose up -d --build backend assistant`). **`./mom.sh update`/`up`은 쓰지 않는다**(위 주의). 새 API(`GET /api/assistant/docs`)는 백엔드 이미지를 다시 빌드해야 생긴다.
2. **`deploy/assistant.env` 점검** (서버에만 있는 파일): `DOCS_SOURCE` 줄이 있는지, 값이 `db`인지 `files`인지(이 한 줄만 출력해도 된다). 없거나 `files`면 `DOCS_SOURCE=db`를 더하자고 제안한다.
3. **적용 방법 제안** (사람이 실행): `assistant.env`의 `DOCS_SOURCE` 줄을 `db`로 하고(없으면 더하고) **비서만** 다시 켠다: `docker compose up -d assistant`(이 파일만 바꿨을 때, `배포_안내.md`). 백엔드가 아직 옛 이미지면 먼저 백엔드부터 새로 빌드한다. 시연 서버는 건드리지 않는다.
4. **적용 뒤 확인** (읽기만, 서버 안쪽에서): 비서 `/health`의 `corpus.docs`를 본다. 서비스 키를 화면에 찍지 않도록 컨테이너 안 환경변수를 쓴다.
   ```
   docker compose exec -T assistant python -c "import os,json,urllib.request as u; r=u.Request('http://127.0.0.1:8100/health',headers={'X-Service-Key':os.environ['MOM_ASSISTANT_KEY']}); print(json.dumps(json.load(u.urlopen(r))['corpus'],ensure_ascii=False))"
   ```
   기대값: `"status": "ok"`, `"chunks": 195`, `docs.source`가 `"db"`, `docs.via`가 `"main_backend"`, `fallback` 없음, `revisions` 8개. `source`가 `"files"`이고 `fallback`이 있으면 이유(예외 종류 이름)를 그대로 적는다(백엔드 이미지가 옛것이면 `HTTP 404`).
5. **실패하면 되돌리기**: `assistant.env`의 `DOCS_SOURCE` 줄을 지우거나 `files`로 바꾸고 비서를 다시 만든다. 문서는 이미지 안 파일로 돌아간다(내용은 같다).

## 보고 (이 형식으로)
| 확인 | 결과 | 비고 |
|---|---|---|
| 서버 코드가 최신(#168·#171 포함) | 예 / 아니오 / 모름 | 갱신이 필요하면 `./mom.sh`가 아니라 서비스별 `docker compose up -d --build`로 제안 |
| `deploy/assistant.env`의 `DOCS_SOURCE` | 없음 / files / db | 값 외 다른 줄은 출력하지 않음 |
| 백엔드 이미지에 새 API가 있음 | 예 / 아니오 / 모름 | 모르면 `GET /api/assistant/docs`를 키 없이 불러 401이면 있음, 404면 없음 |
| 적용 뒤 `/health` `corpus.docs` | source / via / fallback / chunks | 적용 전이면 "미적용" |

마지막에 **사람이 정해야 할 것**을 따로 적는다. 예: "`DOCS_SOURCE=db`를 켤지(최종용은 Supabase 문서를 쓰려면 필요)", "백엔드 이미지를 다시 빌드할 시각". 네가 대신 실행하지 않는다.
