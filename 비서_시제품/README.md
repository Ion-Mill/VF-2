> 상태: **시제품 [제안]** (2026-10-15). 기획서의 "로컬 LLM 확정(2026-10-06)"을 바꾸는 것이 아니라, **비교·시험용**으로 Claude를 붙여 본 것이다. 채택 여부는 기술 회의에서 정한다.

## 1. 무엇을 하나

| 단계 | 하는 일 | 근거 |
|---|---|---|
| ① 검색용 사본 | 사내 문서 md 8개에서 "원문 대응표" 절, `\| 원문 \|` 줄, `← 원문 이름`, 링크·파일 경로를 뺀 사본과 절 단위 조각 200개를 만든다. 원본 md는 그대로 둔다 | 입출력형식 메모 2.2, FR-MNT-01-10, D-03 |
| ② 역할 확인 | `X-User-Id` → `생성기/masters/app_user.csv`의 역할 (OPR·MNT·SUP·MGR) | NFR-SEC-05 |
| ③ 알람 번호 정확 일치 | 질문에 알람 번호가 있으면 DOC-02 해당 절을 먼저 넣고, **첫 출처는 프로그램이 넣는다** | FR-MNT-01-02 |
| ④ Claude 실행 | `claude -p` (구독 로그인). 쓸 수 있는 도구는 문서 읽기(Read·Grep·Glob)와 운영 조회 도구 15개뿐이다. 명령 실행·파일 수정·웹은 막는다 (`--restricted`) | FR-AST-COM-11·14 |
| ⑤ 조회 도구 권한 | MTTR·센서 추세는 **도구 서버가** 역할을 보고 OPR·SUP에게 값을 주지 않는다 → 상태 "권한 밖" | FR-MNT-01-04 |
| ⑥ 답 검사 | 정해진 JSON 칸(형식 강제), 출처 절이 실제로 있는지, 원문 이름, 근거 없는 답 → 틀리면 한 번 다시 요청, 그래도 틀리면 프로그램이 정리 | 입출력형식 메모 3.5 |
| ⑦ 저장 | 질문·답을 사용자별로 30일 저장 (SQLite). 본인 기록만 보이고, 앞 대화에 이어 물을 수 있다 | FR-MNT-01-01 |

답 모양 (API-AST-02 POST):

```json
{
  "chat_id": 12,
  "answer": "…",
  "sources": [{"doc_name": "알람 코드집", "doc_no": "DOC-02", "rev": "Rev.2", "section": "§4.1"}],
  "related": ["MR-0903", "알람 기록 #358"],
  "status": "ok",
  "is_synthetic": true
}
```

`status` = `ok` / `문서에 없음` / `거부` / `권한 밖` / `응답 없음` (응답 없음이면 `error.code` = `ASSISTANT_UNAVAILABLE`).
출처의 이름·개정은 프로그램이 조각 목록에서 채운다 (비서가 쓴 값을 그대로 쓰지 않음).

## 2. 실행

준비: 이 컴퓨터에서 Claude Code(VS Code 확장 또는 CLI)에 **구독 계정으로 로그인**되어 있어야 한다. Python 3.10 이상, 외부 패키지 없음.

```powershell
python 비서_시제품/문서조각.py                     # 사내 문서를 고쳤으면 다시 실행
python 비서_시제품/비서.py "992 뜨면 뭐부터 봐?" --user U07
python 비서_시제품/지침카드.py --prepare           # 저장본이 없거나 DOC-03이 개정된 알람의 "먼저 할 일"을 만듦
python 비서_시제품/서버.py                          # http://127.0.0.1:8765 시험 화면 (채팅·지침카드 탭)
python 비서_시제품/시험.py                          # 기본 시험 (Claude 안 부름)
python 비서_시제품/시험.py --live                   # 실제 질문 12개 (구독 사용량 씀)
```

| 환경 변수 | 기본값 | 뜻 |
|---|---|---|
| `EVE_MODEL` | `claude-opus-5-5` | 모델 |
| `EVE_EFFORT` | `medium` | 생각 깊이 (low ~ max) |
| `EVE_NOW` | 실시간 데이터의 `now_at` (2026-10-02T08:00) | 조회 도구의 "지금" (시연 시계) |
| `CLAUDE_CLI` | 자동으로 찾음 | `claude` 실행 파일 경로 |

시험용 사용자: U02 작업자(OPR), U07 보전(MNT), U10 반장(SUP), U12 관리자(MGR).

## 5. 알아 둘 점

- **구독은 개인 시험용이다.** 여러 사람이 쓰는 서비스를 구독 로그인으로 돌리는 것은 약관상 문제가 될 수 있다. 팀 시연·배포 때는 Claude API 키(Claude Console, 사용한 만큼 결제)로 바꾼다. 이 경우 `비서.run_claude()`만 Anthropic SDK 호출로 바꾸면 되고 나머지(검사·권한·저장)는 그대로 쓴다.
- **구독 사용 한도를 함께 쓴다.** 질문 하나에 15~40초, 다시 요청하면 그 두 배.
- **검색 방식**: 임베딩 검색이 아니라 Claude가 Grep으로 찾고 Read로 읽는다. 문서 8개(약 500 KB)라서 이 방식으로 충분하다. 로컬 LLM으로 가면 입출력형식 메모 2.2의 조각·임베딩 검색이 필요하다.
- **원문 이름**: 사본에서 원문 대응표·원문 줄은 뺐지만, 본문 근거 설명 속 원문 이름(예: "서비스 매뉴얼 29.1")은 남아 있다. 답에 나오면 프로그램이 잡아 다시 요청하고, 그래도 남으면 그 줄을 지운다.
- **아직 없는 것**: 평가 질문 세트 40~50문항 (FR-MNT-01-11), 실제 로그인(API-AUTH-01), 시뮬레이터 시계 실시간 연동, 브리핑·지침카드·문서 초안.

## 6. 알람 지침카드 (MNT-02, API-MNT-01)

`GET /api/maint/guide-card/{alarm_event_id}`. 원칙은 **칸은 프로그램, 문장만 비서**다. 비서가 쓰는 칸은 [5] 하나다.

| 칸 | 채우는 쪽 | 어디서 | 요구사항 |
|---|---|---|---|
| [1] 알람 · [2] 심각도 · [3] 누가 | 프로그램 | `alarm_master.csv` (DOC-02를 뽑은 표), 번호로 정확히 조회 | FR-MNT-02-02~04·06 |
| [4] 연쇄 알람 | 프로그램 | 알람 기록의 앞 알람 연결(`prev_alarm_event_id`)이 코드집 순서와 같을 때만, 마지막 알람 카드에 | FR-MNT-02-14 |
| [5] 먼저 할 일 3~5줄 | **비서** | DOC-03 해당 절 (`alarm_guide_map.csv`). 줄마다 근거 절 | FR-MNT-02-05 |
| [6] 안전 | 프로그램 | 잠금 등급 FULL → DOC-05 §7 블록 그대로(`{ }` 칸만 채움, OP-30 밖은 고전압 줄 대신 "§3 저장 에너지 확인") / 보충 알람 → §2.4 해당 줄(작업·판단·할 일 칸) / 조작 안내 → "적용 대상 아님" | FR-MNT-02-07·08, FR-AST-COM-13 |
| [7] 생산 영향 | 프로그램 | 그 알람에 연결된 정지 구간 시간 ÷ 기준 사이클 = 손실 수량(추정), 의심 로트 | FR-MNT-02-09, DOC-07 §5.3 |
| [8] 지난 기록 | 프로그램 | 같은 설비·같은 알람의 이번 주 횟수, 지난번 작업기록 원인, 반복 알람 1·2단계 | FR-MNT-02-10 |
| [9] 버튼 · [10] 출처 | 프로그램 | OP-30 정지 → 작업지시서, 주의·다른 공정 정지 → 간이 작업기록, 조작 안내 → 없음 | FR-MNT-02-11~13 |

**[5] 비서 칸 검사**: 3~5줄인가, 근거 절이 그 알람의 DOC-03 절인가, 잠금 단계(6.1~7.3·자물쇠)를 다시 썼나, 원문 이름이 있나 → 틀리면 한 번 다시 요청. 그래도 틀리거나 비서가 응답하지 않으면 **DOC-03 점검 순서 표의 작업자(★) 줄을 그대로** 보인다 (UI설계서 SCR-09 "비서 응답 없음").

**준비**: "먼저 할 일"은 알람 번호와 DOC-03 개정에만 달려 있으므로 알람 번호마다 한 번 만들어 **`지침카드_먼저할일.json`에 저장하고 git에 올린다.** 팀이 비서 문장을 직접 읽고 검토할 수 있다. 고치고 싶은 줄은 이 파일을 고치면 되고, 다시 만들려면 그 알람 항목을 지우고 `--prepare`를 돌린다. 그래서 알람이 뜬 뒤 카드는 바로 열린다 (FR-MNT-02-01 "자동으로 준비", NFR-PERF-01). DOC-03이 개정되면 다시 만든다.
